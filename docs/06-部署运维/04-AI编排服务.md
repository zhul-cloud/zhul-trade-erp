# AI 编排服务

询盘的「AI 解析」、型号描述的英文翻译和联系人名音译由 AI 编排服务完成。后端把任务连同**当前租户的 AI 配置**提交给它，它通过 Claude/OpenAI API 或部署者个人的 Claude Code/Codex 订阅执行，再回调后端。服务名 `ai-orchestrator`，容器名 `zhul-erp-ai-orchestrator`，属于 `app` profile，单机部署时随 `--profile app` 一起启动。

```
后端 ──提交任务（带租户的 AI 配置）──▶ ai-orchestrator ──调用──▶ API 或个人订阅（含联网搜索）
  ▲                                         │
  └──────────────回调结果───────────────────┘   （双向都校验 AI_TASK_CALLBACK_TOKEN）
```

## 在系统里配置（每个租户各自维护）

服务商、API Key、模型、思考强度、搜索上限、运行方式都在 **业务设置 → AI 设置** 页面中维护，每个租户一份，互不可见，**不继承平台的 API Key 配置**。页面按服务商列出「本公司 API Key」与「平台订阅」两种用法，选中哪一行就用哪一种；Claude 与 OpenAI 的 Key 和模型各自保存，切换不会互相覆盖。修改后下一个任务立即生效，不需要重启任何服务。查看需要该菜单，修改需要「编辑 AI 设置」按钮权限（升级时自动加进所有套餐和内置管理员角色）。

| 项目 | 说明 |
| --- | --- |
| 运行方式 | 本公司 API Key（按用量计费）或平台订阅。平台订阅只有平台租户和**套餐中勾选了「使用平台订阅」的公司**能选，见下文 |
| 服务商 | Claude（Anthropic）或 OpenAI，默认 Claude |
| API Key | API 方式必填，填所选服务商的 Key：Claude 在 Anthropic Console 创建，OpenAI 在 OpenAI Platform 创建。加密保存，页面只显示首尾几位（如 `sk-ant-••••••••••••••••abcd`）；留空保存表示不修改，更换时需二次确认 |
| 询盘解析模型 / 翻译模型 | 可从下拉列表选择（首次展开时按 Key 读取服务商的模型列表），也可直接输入；留空用下表默认值 |
| 解析 / 翻译思考强度 | 低、中、高、很高、最高，留空为中。越高越准，但更慢、费用更高 |
| 单次解析最多联网搜索 | 1–100 次，默认 20；API 为服务商工具调用上限，订阅为下文的保守操作事件阈值 |

模型留空时使用的默认模型（API 与订阅方式相同）：

| 服务商 | 询盘解析 | 翻译 |
| --- | --- | --- |
| Claude | `claude-opus-5-5` | `claude-haiku-5-5` |
| OpenAI | `gpt-6.1-sol` | `gpt-6-luna` |

**测试连接**：用页面当前填写的值测试，不需要先保存（Key 留空时用已保存的 Key）。API 方式只查询 Key 能否访问两个模型，不产生调用费用；订阅方式检查对应 CLI 是否已登录。

**没有配置时**：用户主动发起的 AI 操作（询盘解析、追加型号的 AI 解析、型号描述翻译）直接提示「AI 未配置，请在「业务设置 → AI 设置」中填写」，不创建任务；保存商机时顺带触发的联系人名音译会跳过并记录日志，商机照常保存。

**生产升级到此版本后**：AI 在平台租户填写配置之前不可用。以平台账号进入「业务设置 → AI 设置」，填写服务商与 Key，点「测试连接」确认通过，再试一次询盘解析。旧版本 `.env` 里的 `AI_ORCHESTRATOR_PROVIDER`、`AI_ORCHESTRATOR_API_KEY` 等配置项不再读取，可以删除（确认不再回退旧版本后再删）。

## 部署配置（`.env`）

`.env` 只保留服务之间的连接与部署级参数：

| 变量 | 说明 |
| --- | --- |
| `AI_ORCHESTRATOR_MODE` | `api`（默认）启动真实编排服务；`stub` 启动假数据服务，不管询盘内容都返回固定的西门子、施耐德型号，只用于页面联调，**生产不要用**。旧取值 `subscription` 按 `api` 处理 |
| `AI_ORCHESTRATOR_TIMEOUT_SECONDS` | 单次调用超时，默认 900 秒 |
| `AI_TASK_CALLBACK_TOKEN` | 后端与编排服务共用的令牌：后端调用编排服务、编排服务回调后端都要校验，不一致时请求被拒（401） |
| `AI_ORCHESTRATOR_BASE_URL` / `AI_TASK_CALLBACK_BASE_URL` | 后端调用编排服务、编排服务回调后端的地址。同一 Compose 部署保持默认 |

改完 `.env` 后执行 `docker compose up -d ai-orchestrator` 生效。

`scripts/docker-dev.sh` / `.ps1` 首次生成 `.env` 时设为 `stub`。**用 `stub` 联调时，租户仍需在「业务设置 → AI 设置」填写一份配置**（Key 可随意填写），否则会提示 AI 未配置、不创建任务。

## 平台订阅

平台订阅使用部署者在容器内登录的个人订阅账号。平台租户始终可以使用；其他公司要由平台在**套餐管理**里勾选「AI 设置 → 使用平台订阅」才能使用，取消勾选即收回，同一套餐的公司同时生效（需要单独控制时给该公司单独的套餐）。该权限不会自动加进任何现有套餐。

获授权的公司只能选平台已登录的服务商，模型、思考强度和搜索次数用平台为该服务商设置的值（租户页面只读）；租户页面只显示「可用 / 不可用」，不显示登录命令和原因。所选订阅不可用时，用户发起的 AI 操作提示「AI 暂不可用」，不会自动切换到另一家或付费 API。

**风险**：Anthropic、OpenAI 的个人订阅条款一般不允许多人共用账号，开放给其他公司可能导致账号被限制或封禁，被封的是平台账号，平台自己的订阅也会停用。只把权限授予确有必要的公司，正式使用优先让各公司填写自己的 API Key。项目不提供第三方登录界面、不代收 OAuth token，也不会把订阅认证失败自动切换成付费 API。

镜像已安装官方 `openai-codex==0.163.0`（含同版 Codex CLI）与 Claude Code `2.1.311`，无需给宿主机安装 CLI。服务启动后，由部署者本人在容器内完成官方认证：

```bash
# Codex：按终端显示的网址和设备码，在自己的浏览器中登录。
docker compose exec ai-orchestrator codex login --device-auth
# Claude Code：按官方登录引导选择自己的 Claude 订阅。
docker compose exec ai-orchestrator claude auth login
```

生产服务器上执行时，在 `docker compose` 后加上 `-f docker-compose.yaml -f docker-compose.prod.yaml`。登录后到「业务设置 → AI 设置」，在对应服务商下选中「平台订阅」并保存。平台账号在列表里能看到每家订阅已登录还是未登录，选中未登录的一行会显示登录命令；右侧为该服务商设置的订阅模型供获授权的公司共用。

登录状态由官方 CLI 保存在专用 `/home/zhul/codex`、`/home/zhul/claude`，不挂载或复制宿主机的 `.codex`、`.claude`；租户填写的 API Key 和宿主机已有 API/OAuth 环境变量不参与订阅调用。Claude 必须是 `claude.ai` 登录，Codex 必须是 ChatGPT 账户；API Key 登录按未登录订阅处理。

登录状态保存在 Docker 命名卷 `ai-orchestrator-home`（挂在 `/home/zhul`，完整卷名带 Compose 项目名前缀，如 `zhul-trade-erp_ai-orchestrator-home`），容器停止、重启、重建或重新构建镜像后都保留，只需登录一次；本机开发与生产（两个 Compose 部署方式）均继承这一配置。卷在首次挂载时继承镜像中 `/home/zhul` 的属主 `10001` 和 `0700` 权限，不放在 `./storage/` 下，因此不进入上传文件备份，也不会提交仓库。要清除登录，在容器内执行 `codex logout` 或 `claude auth logout`，或停止服务后执行 `docker volume rm <项目名>_ai-orchestrator-home`；`docker compose down -v` 也会删除它。卷内是个人凭据，不要复制或共享。

没有登录、订阅额度不足、账号无模型权限或 CLI 失败时，任务使用既有失败回调展示错误。容器健康检查仅代表服务进程可接收任务，不证明已登录或剩余订阅额度。

订阅执行支持 Docker/Linux。Windows 开发机请使用 Docker。Linux 本机运行需要安装相同版本的 CLI/依赖，并设置独立的 `AI_ORCHESTRATOR_HOME`，让登录命令的 `HOME`、`CODEX_HOME`、`CLAUDE_CONFIG_DIR` 与服务专用目录一致；不要直接复用自己的日常 CLI 主目录。

### 订阅方式的执行边界

- 一个服务实例同时只执行一个订阅任务，忙碌时新任务回调失败，可稍后重试。每次任务使用新的临时工作目录、无会话复用；任务结果通过相同后端回调返回，不新增数据库事务。
- Codex 使用官方 Python SDK、只读沙箱、拒绝交互审批，关闭 shell、应用、hooks、子代理、远程插件与图片读取工具；图片直接作为输入。Claude 使用原版 CLI 的 `--safe-mode --restricted`、空 MCP 配置、无交互审批和仅搜索工具白名单，不授予 shell/编辑/文件读取工具。不会为了容器兼容关闭 Codex 沙箱；宿主内核/容器策略不支持沙箱时任务失败。
- 图片和 PDF 均实际交给模型。PDF（含扫描件）按页渲染为 PNG，最长边最多 2000 像素；单任务附件总大小最多 25 MiB，PDF 最多 20 页，所有附件合计最多 20 张图片/PDF 页，超限或加密/损坏会明确失败。GIF 使用首帧。
- 「单次解析最多联网搜索」在订阅方式为保守的操作事件阈值：Codex 包括搜索、打开网页、页内查找；Claude 包括 WebSearch/WebFetch。同一操作 ID 只计一次，观察到第 N 次开始事件就终止并回调失败，因此成功任务需要少于 N 次。设为 1 会在第一次搜索时停止。事件出现时可能已有在途请求；这不是服务商的硬计费上限。翻译不开放搜索工具。
- 超过 `AI_ORCHESTRATOR_TIMEOUT_SECONDS` 会终止本任务整个 Linux 进程组（含 SDK/CLI 子进程）；退出后也清理残留子进程。只有完整、符合 JSON Schema 的结果才允许成功回调。CLI 的认证信息与原始 stderr 不进入后端回调。

认证与能力依据：[Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)、[Codex 认证](https://learn.chatgpt.com/docs/auth)、[Claude CLI 参数](https://code.claude.com/docs/en/cli-reference)、[Claude 个人使用与合规](https://code.claude.com/docs/en/legal-and-compliance)。套餐、模型与登录能力以官方实际账户为准。

## 两家服务商的区别

两家 API 均支持图片/PDF 输入、联网搜索、按约定结构返回结果，切换服务商时后端和前端不需改动。区别：

- 联网搜索次数上限：Claude 只统计搜索；OpenAI 把打开网页、页内查找也算在内，同样的上限下，实际搜索次数可能更少。
- 拒答兜底：Claude 因安全策略拒答时由服务商自动改用备用模型重试；OpenAI 没有这个功能，拒答时任务直接失败。

切换服务商时，**同时把 API Key 换成那一家的 Key**；填写过的模型名要换成那一家的模型，清空则用默认值。

## API Key 的安全

旧版（如 v1.3.11）的 API Key 来自部署环境变量，不存入业务库。自 v1.3.12 起，[#53](https://github.com/zhul-cloud/zhul-trade-erp/pull/53) 引入 AES-256-GCM，[#54](https://github.com/zhul-cloud/zhul-trade-erp/pull/54) 引入按租户 AI 配置；[V1.3.17__sys_ai_config.sql](../../zhul-erp-backend/src/main/resources/db/migration/V1.3.17__sys_ai_config.sql) 创建每租户一行的配置表。因此，旧部署模式的「Key 不入业务库」描述不再适用于当前租户配置，当前规则是按租户隔离、加密保存和脱敏读取。迁移编号与应用发布版本独立。

- `sys_ai_config.api_key` 由现有 `AesUtils` 按 [system/data-encryption](../../openspec/specs/system/data-encryption/spec.md)（AES-256-GCM）加密保存，更换 Key 时重新加密；租户各自按权限维护。后台管理查询对 Key 只返回 `hasKey` 和 `apiKeyMasked`，不返回明文。
- 后端为生成管理查询的脱敏值，或提交任务、测试连接、获取模型列表等必要调用，可在内存中解密；管理查询不向前端返回 Key 明文。内部编排请求为完成调用可短暂携带明文，经受鉴权的受控通道传输，不持久化含 Key 的请求体；AI 任务记录不保存任务输入，后端与编排服务日志、任务失败原因均不输出 Key 明文，异常中的 Key 做脱敏处理。
- 加密主密钥 `AES_KEY` 由部署侧安全配置管理，不与密文同库存储，不写入代码、Git、文档或 Wiki；真实 API Key、密码及其他凭据也不得记录到这些位置或日志。系统用户登录密码使用 BCrypt 单向哈希，不使用 API Key 的可逆加密方式。
- 编排服务不映射宿主机端口，所有接口校验 `AI_TASK_CALLBACK_TOKEN`；不要自行把 8899 端口暴露到公网。

## 费用

API 方式每次「AI 解析」都会产生 API 费用，费用记在该租户填写的 Key 所属账号上；询盘型号越多、需要搜索验证的越多，费用越高。API 没有「单次最多花多少钱」的开关，靠「单次解析最多联网搜索」和输出长度上限间接控制。API 调用完成后，编排服务日志会打印输入、输出 token 数和联网搜索次数。订阅方式消耗个人套餐额度，不记录或承诺 API 账单金额：

```bash
docker compose logs -f ai-orchestrator
```

可以在服务商后台（Anthropic Console、OpenAI Platform）为 API Key 所在的工作区或项目设置月度用量上限，作为最后一道保护。

## 附件怎么传给编排服务

询盘的 Excel、CSV 附件由后端抽成文本，随正文一起发送。图片和 PDF 附件则由后端签发 **60 分钟有效的临时链接**，编排服务按链接下载，再发给模型：

- 文件存在 OSS 时（见 [对象存储](07-对象存储.md)），链接指向 OSS，编排服务需要能访问外网。
- 文件存在本地时，链接指向后端的 `AI_TASK_CALLBACK_BASE_URL`（Compose 内默认是 `http://backend:8080`），编排服务需要能访问这个地址，回调本来也依赖它。

编排服务不再读取后端的上传目录。`docker-compose.yaml` 里给它挂载的 `private-uploads` 只是为了兼容旧版本后端而保留，新版本不依赖它。

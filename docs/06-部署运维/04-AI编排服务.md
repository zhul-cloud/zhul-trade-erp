# AI 编排服务

询盘的「AI 解析」和型号描述的英文翻译由 AI 编排服务完成。后端把任务提交给它，它通过 Claude/OpenAI API 或部署者个人的 Claude Code/Codex 订阅执行，再回调后端。服务名 `ai-orchestrator`，容器名 `zhul-erp-ai-orchestrator`，属于 `app` profile，单机部署时随 `--profile app` 一起启动。

```
后端 ──提交任务──▶ ai-orchestrator ──调用──▶ API 或个人订阅（含联网搜索）
  ▲                      │
  └──────回调结果─────────┘   （回调携带 AI_TASK_CALLBACK_TOKEN）
```

## 三种模式

| `AI_ORCHESTRATOR_MODE` | 行为 | 费用 |
| --- | --- | --- |
| `api`（默认） | 调用 AI 服务商的 API 真实解析，每个型号联网搜索验证 | 按 API 用量计费 |
| `subscription` | 部署者本人通过官方 CLI 登录后，使用 Claude Code 或 Codex 执行任务 | 占用个人订阅额度，仍受套餐/模型/速率限制 |
| `stub` | 不管询盘内容，固定返回西门子、施耐德的假型号 | 免费，只用于页面联调 |

`scripts/docker-dev.sh` / `.ps1` 只在首次生成 `.env` 且没有 API Key 时设为 `stub`；已有模式配置会保留。**生产不要用 `stub`**，假数据会被当成真实解析结果写进询盘。

个人订阅模式面向部署者本人的独立自用实例。不要把个人凭据共享给多个使用者、做订阅池或对外提供商业托管；多人系统继续使用 API。项目不提供第三方登录界面、不代收 OAuth token，也不会把订阅认证失败自动切换成付费 API。

### Docker 中使用个人订阅

镜像已安装官方 `openai-codex==0.163.0`（含同版 Codex CLI）与 Claude Code `2.1.311`，无需给宿主机安装 CLI。将 `.env` 的 `AI_ORCHESTRATOR_MODE` 设为 `subscription`，`AI_ORCHESTRATOR_PROVIDER` 设为 `openai`（Codex/ChatGPT 订阅）或 `claude`。切换自 API 时把两个模型变量清空，避免沿用不适用的 API 模型。

先启动服务，再由部署者本人在容器内完成官方认证：

```bash
docker compose --profile app up -d --build --no-deps ai-orchestrator
# Codex：按终端显示的网址和设备码，在自己的浏览器中登录。
docker compose exec ai-orchestrator codex login --device-auth
# Claude Code：按官方登录引导选择自己的 Claude 订阅。
docker compose exec ai-orchestrator claude auth login
```

上面的 `--build` 用于本地源码部署，确保旧镜像被更新。生产使用已发布的新版本镜像，按生产发版流程获取镜像；启动用 `docker compose -f docker-compose.yaml -f docker-compose.prod.yaml --profile app up -d --no-deps ai-orchestrator`，不在生产构建；登录命令也增加这两个 `-f` 参数。登录状态由官方 CLI 保存在专用 `/home/zhul/codex`、`/home/zhul/claude`，不挂载或复制宿主机的 `.codex`、`.claude`。`AI_ORCHESTRATOR_API_KEY` 和宿主机已有 API/OAuth 环境变量不参与订阅调用。Claude 必须是 `claude.ai` 登录，Codex 必须是 ChatGPT 账户；API Key 登录会按未登录订阅处理。

默认 `/home/zhul` 为 tmpfs，容器停止、重启或重建后均需重新登录。需保留登录时，先创建只有部署者可访问的 `./storage/ai-orchestrator`（Linux owner `10001:10001`、mode `0700`），按 `docker-compose.yaml` 注释删掉该 tmpfs 并增加目录映射，然后重建并登录。目录含个人凭据，不能提交仓库或共享。两个 Compose 部署方式均继承这一配置。更改 `.env` 需重建容器；先决定是否持久化，再登录。

本机开发（不带 `-f` 运行 `docker compose`）想让登录在重启、重建、重新构建后保留，不需要改 `docker-compose.yaml`：在仓库根目录新建 `docker-compose.override.yaml`（已被 `.gitignore` 忽略，Compose 会自动叠加），内容如下，然后执行 `docker compose --profile app up -d --no-deps ai-orchestrator` 并登录一次。

```yaml
services:
  ai-orchestrator:
    tmpfs: !reset []
    volumes:
      - ai-orchestrator-home:/home/zhul

volumes:
  ai-orchestrator-home:
```

登录状态存在 Docker 命名卷 `zhul-trade-erp_ai-orchestrator-home` 中，继承镜像里 `/home/zhul` 的属主 `10001` 和 `0700` 权限；Windows 上不要改用 `./storage/` 目录映射，宿主机目录的属主和权限在容器内不生效。`docker compose down -v` 或 `docker volume rm zhul-trade-erp_ai-orchestrator-home` 会清除登录。生产部署显式指定两个 `-f` 文件，不读取该覆盖文件。

没有登录、订阅额度不足、账号无模型权限或 CLI 失败时，任务使用既有失败回调展示错误。容器健康检查仅代表服务进程可接收任务，不证明已登录或剩余订阅额度。退出订阅用 `codex logout` 或 `claude auth logout`；切回 `api` 时重新填写对应 Key 和模型并重建。

订阅执行支持 Docker/Linux。Windows 开发机请使用 Docker；原来的本机 API/stub 运行方式保留。Linux 本机运行需要安装相同版本的 CLI/依赖，并设置独立的 `AI_ORCHESTRATOR_HOME`，让登录命令的 `HOME`、`CODEX_HOME`、`CLAUDE_CONFIG_DIR` 与服务专用目录一致；不要直接复用自己的日常 CLI 主目录。

### 订阅模式的执行边界

- 一个服务实例同时只执行一个订阅任务，忙碌时新任务回调失败，可稍后重试。每次任务使用新的临时工作目录、无会话复用；任务结果通过相同后端回调返回，不新增数据库事务。
- Codex 使用官方 Python SDK、只读沙箱、拒绝交互审批，关闭 shell、应用、hooks、子代理、远程插件与图片读取工具；图片直接作为输入。Claude 使用原版 CLI 的 `--safe-mode --restricted`、空 MCP 配置、无交互审批和仅搜索工具白名单，不授予 shell/编辑/文件读取工具。不会为了容器兼容关闭 Codex 沙箱；宿主内核/容器策略不支持沙箱时任务失败。
- 图片和 PDF 均实际交给模型。PDF（含扫描件）按页渲染为 PNG，最长边最多 2000 像素；单任务附件总大小最多 25 MiB，PDF 最多 20 页，所有附件合计最多 20 张图片/PDF 页，超限或加密/损坏会明确失败。GIF 使用首帧。
- `AI_ORCHESTRATOR_MAX_WEB_SEARCHES` 在订阅模式为保守的操作事件阈值：Codex 包括搜索、打开网页、页内查找；Claude 包括 WebSearch/WebFetch。同一操作 ID 只计一次，观察到第 N 次开始事件就终止并回调失败，因此成功任务需要少于 N 次。设为 1 会在第一次搜索时停止。事件出现时可能已有在途请求；这不是服务商的硬计费上限。翻译不开放搜索工具。
- 超过 `AI_ORCHESTRATOR_TIMEOUT_SECONDS` 会终止本任务整个 Linux 进程组（含 SDK/CLI 子进程）；退出后也清理残留子进程。只有完整、符合 JSON Schema 的结果才允许成功回调。CLI 的认证信息与原始 stderr 不进入后端回调。

认证与能力依据：[Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)、[Codex 认证](https://learn.chatgpt.com/docs/auth)、[Claude CLI 参数](https://code.claude.com/docs/en/cli-reference)、[Claude 个人使用与合规](https://code.claude.com/docs/en/legal-and-compliance)。套餐、模型与登录能力以官方实际账户为准。

## 配置

都在根目录 `.env`：

| 变量 | 说明 |
| --- | --- |
| `AI_ORCHESTRATOR_PROVIDER` | AI 服务商：`claude`（默认）或 `openai`。写了其他值时编排服务启动即报错退出 |
| `AI_ORCHESTRATOR_API_KEY` | `api` 模式必填，填当前服务商的 Key：Claude 在 Anthropic Console 创建，OpenAI 在 OpenAI Platform 创建。为空时任务会直接回调失败，日志里有提示 |
| `AI_ORCHESTRATOR_PARSE_MODEL` | 询盘解析模型；API 默认见下表，订阅 Claude 默认 `opus`、Codex 默认使用账户配置 |
| `AI_ORCHESTRATOR_TRANSLATE_MODEL` | 翻译模型；API 默认见下表，订阅 Claude 默认 `haiku`、Codex 默认使用账户配置；翻译不联网 |
| `AI_ORCHESTRATOR_PARSE_EFFORT` / `AI_ORCHESTRATOR_TRANSLATE_EFFORT` | 询盘解析、翻译的思考强度：`low`、`medium`、`high`、`xhigh`、`max`，留空为 `medium`。越高越准，但更慢、费用更高。写了其他值时启动即报错退出 |
| `AI_ORCHESTRATOR_MAX_WEB_SEARCHES` | 默认 20；API 为服务商工具调用上限，订阅为上述保守操作事件阈值 |
| `AI_ORCHESTRATOR_TIMEOUT_SECONDS` | 单次调用超时，默认 900 秒 |
| `AI_TASK_CALLBACK_TOKEN` | 与后端共用，不需要单独配置 |
| `AI_ORCHESTRATOR_BASE_URL` / `AI_TASK_CALLBACK_BASE_URL` | 后端调用编排服务、编排服务回调后端的地址。同一 Compose 部署保持默认 |

改完 `.env` 后执行 `docker compose up -d ai-orchestrator` 生效。启动日志会列出服务商、两类任务的模型和思考强度。

模型留空时使用的推荐模型：

| 服务商 | 询盘解析 | 翻译 |
| --- | --- | --- |
| `claude` | `claude-opus-5-5` | `claude-haiku-5-5` |
| `openai` | `gpt-6.1-sol` | `gpt-6-luna` |

### 切换服务商

同一时间只用一家。API 模式把 `AI_ORCHESTRATOR_PROVIDER` 改成另一家时，**同时把 `AI_ORCHESTRATOR_API_KEY` 换成那一家的 Key**。订阅模式改用另一家后，在容器内为那一家完成官方登录；持久化目录中的两家凭据分别保留，不会自动登出。填写过模型名的要换成对应模式/服务商的模型，清空则使用各自默认值。更改后执行 `docker compose up -d ai-orchestrator`，临时登录目录会在停止、重启或重建时清空。后端和前端不需改动，目标回调契约一致。

两家 API 均支持图片/PDF 输入、联网搜索、按约定结构返回结果。订阅适配也覆盖这些输入与目标契约，实际账号上的识别效果和额度仍需部署者登录后验收。API 的区别：

- 联网搜索次数上限：Claude 只统计搜索；OpenAI 把打开网页、页内查找也算在内，同样的 `AI_ORCHESTRATOR_MAX_WEB_SEARCHES` 下，实际搜索次数可能更少。
- 拒答兜底：Claude 因安全策略拒答时由服务商自动改用备用模型重试；OpenAI 没有这个功能，拒答时任务直接失败。

## 费用

API 模式每次「AI 解析」都会产生 API 费用，询盘型号越多、需要搜索验证的越多，费用越高。API 没有「单次最多花多少钱」的开关，靠 `AI_ORCHESTRATOR_MAX_WEB_SEARCHES` 和输出长度上限间接控制。API 调用完成后，编排服务日志会打印输入、输出 token 数和联网搜索次数。订阅模式消耗个人套餐额度，不记录或承诺 API 账单金额：

```bash
docker compose logs -f ai-orchestrator
```

可以在服务商后台（Anthropic Console、OpenAI Platform）为 API Key 所在的工作区或项目设置月度用量上限，作为最后一道保护。

## 附件怎么传给编排服务

询盘的 Excel、CSV 附件由后端抽成文本，随正文一起发送。图片和 PDF 附件则由后端签发 **60 分钟有效的临时链接**，编排服务按链接下载，再发给模型：

- 文件存在 OSS 时（见 [对象存储](07-对象存储.md)），链接指向 OSS，编排服务需要能访问外网。
- 文件存在本地时，链接指向后端的 `AI_TASK_CALLBACK_BASE_URL`（Compose 内默认是 `http://backend:8080`），编排服务需要能访问这个地址，回调本来也依赖它。

编排服务不再读取后端的上传目录。`docker-compose.yaml` 里给它挂载的 `private-uploads` 只是为了兼容旧版本后端而保留，新版本不依赖它。

## 部署位置

- 方式一、三、四：随后端一起用 Docker 部署。API 模式填写 `AI_ORCHESTRATOR_API_KEY`；订阅模式按上文在容器内登录，两者均可用 `AI_ORCHESTRATOR_PROVIDER=openai` 切到 OpenAI。
- 方式二（本机开发）：API 直接运行 `python scripts/ai-orchestrator/server.py`，Key 由当前终端环境变量提供，见 [部署场景 · 方式二](01-部署场景.md#方式二数据库用-docker前后端和-ai-编排在本机运行)。订阅推荐使用上文 Docker 流程。

编排服务不映射宿主机端口，不对外提供访问。它接收任务的接口没有单独鉴权，不要自行把 8899 端口暴露到公网。

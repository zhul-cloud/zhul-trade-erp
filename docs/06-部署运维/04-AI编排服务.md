# AI 编排服务

询盘的「AI 解析」和型号描述的英文翻译由 AI 编排服务完成。后端把任务提交给它，它调用 Anthropic API 处理完后回调后端。服务名 `ai-orchestrator`，容器名 `zhul-erp-ai-orchestrator`，属于 `app` profile，单机部署时随 `--profile app` 一起启动。

```
后端 ──提交任务──▶ ai-orchestrator ──调用──▶ Anthropic API（含联网搜索）
  ▲                      │
  └──────回调结果─────────┘   （回调携带 AI_TASK_CALLBACK_TOKEN）
```

## 两种模式

| `AI_ORCHESTRATOR_MODE` | 行为 | 费用 |
| --- | --- | --- |
| `api`（默认） | 调用 Anthropic API 真实解析，每个型号联网搜索验证 | 按 API 用量计费 |
| `stub` | 不管询盘内容，固定返回西门子、施耐德的假型号 | 免费，只用于页面联调 |

`scripts/docker-dev` 在没有 API Key 时自动使用 `stub`。**生产不要用 `stub`**，假数据会被当成真实解析结果写进询盘。

## 配置

都在根目录 `.env`：

| 变量 | 说明 |
| --- | --- |
| `ANTHROPIC_API_KEY` | `api` 模式必填，在 Anthropic Console 创建。为空时任务会直接回调失败，日志里有提示 |
| `AI_ORCHESTRATOR_MODEL` | 留空使用默认模型 `claude-opus-5-5` |
| `AI_ORCHESTRATOR_MAX_WEB_SEARCHES` | 单次解析最多联网搜索次数，默认 20，用于控制费用 |
| `AI_ORCHESTRATOR_TIMEOUT_SECONDS` | 单次调用超时，默认 900 秒 |
| `AI_TASK_CALLBACK_TOKEN` | 与后端共用，不需要单独配置 |
| `AI_ORCHESTRATOR_BASE_URL` / `AI_TASK_CALLBACK_BASE_URL` | 后端调用编排服务、编排服务回调后端的地址。同一 Compose 部署保持默认 |

改完 `.env` 后执行 `docker compose up -d ai-orchestrator` 生效。

## 费用

每次「AI 解析」都会产生 API 费用，询盘型号越多、需要搜索验证的越多，费用越高。API 没有「单次最多花多少钱」的开关，靠 `AI_ORCHESTRATOR_MAX_WEB_SEARCHES` 和输出长度上限间接控制。每次调用完成后，编排服务日志会打印输入、输出 token 数和联网搜索次数：

```bash
docker compose logs -f ai-orchestrator
```

可以在 Anthropic Console 为 API Key 所在的工作区设置月度用量上限，作为最后一道保护。

## 附件怎么传给编排服务

询盘的 Excel、CSV 附件由后端抽成文本，随正文一起发送。图片和 PDF 附件则由后端签发 **60 分钟有效的临时链接**，编排服务按链接下载，再发给模型：

- 文件存在 OSS 时（见 [对象存储](07-对象存储.md)），链接指向 OSS，编排服务需要能访问外网。
- 文件存在本地时，链接指向后端的 `AI_TASK_CALLBACK_BASE_URL`（Compose 内默认是 `http://backend:8080`），编排服务需要能访问这个地址，回调本来也依赖它。

编排服务不再读取后端的上传目录。`docker-compose.yaml` 里给它挂载的 `private-uploads` 只是为了兼容旧版本后端而保留，新版本不依赖它。

## 部署位置

- 方式一、三、四：随后端一起用 Docker 部署，地址、令牌和附件目录都已在 Compose 里配好，只需要在 `.env` 填写 `ANTHROPIC_API_KEY`。
- 方式二（本机开发）：直接在本机运行 `python scripts/ai-orchestrator/server.py`，Key 通过当前终端的环境变量 `ANTHROPIC_API_KEY` 提供，其余使用默认值即可，见 [部署场景 · 方式二](01-部署场景.md#方式二数据库用-docker前后端和-ai-编排在本机运行)。

编排服务不映射宿主机端口，不对外提供访问。它接收任务的接口没有单独鉴权，不要自行把 8899 端口暴露到公网。

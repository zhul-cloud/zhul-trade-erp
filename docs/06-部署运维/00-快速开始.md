# 快速开始

## 准备

- Docker Desktop（Windows、macOS）或 Docker Engine + Compose V2（Linux）。Windows 使用 **Linux containers**。
- 建议给 Docker 至少 6 GB 内存。默认的临时存储也占用内存。
- 首次构建要联网下载镜像、Maven 与 npm 依赖，需要几分钟。宿主机不需要安装 Java、Maven 或 Node。

以下命令都在项目根目录执行。

## 一键启动开发环境

Linux / macOS：

```bash
scripts/docker-dev.sh
```

Windows PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\docker-dev.ps1
```

脚本做了这些事：

1. 没有 `.env` 时从 `.env.example` 复制一份，并改成开发配置：导入演示账号，AI 编排服务用 stub 假数据。
2. `JWT_SECRET`、`AES_KEY`、`AI_TASK_CALLBACK_TOKEN` 为空时各生成一个独立的随机值。
3. 构建并启动全部五个服务，等待后端就绪后打印访问地址。

就绪后打开 `http://localhost:8000`，用演示账号 `platform` / `admin123` 登录。登录平台后配置套餐、创建租户，再用租户管理员账号开展业务。

再次运行脚本时，已有的 `.env` 只会补上空着的密钥，其他配置不动。AI 的服务商和 API Key 在系统里按租户填写：登录后进入「业务设置 → AI 设置」（用 stub 联调时也要填一份，Key 可随意填写）。想用真实 AI 解析，把 `.env` 的 `AI_ORCHESTRATOR_MODE` 改成 `api` 再运行一次脚本，并在系统中填写真实的 Key，见 [AI 编排服务](04-AI编排服务.md)。

> 开发环境同样不持久化：停止或重建容器后数据清空，下次启动是一个全新的库。需要保留开发数据，按 [数据持久化与备份](03-数据持久化与备份.md) 启用。

## 手动启动（不用脚本）

```bash
cp .env.example .env            # Windows：Copy-Item .env.example .env
# 编辑 .env：填写 JWT_SECRET、AES_KEY、AI_TASK_CALLBACK_TOKEN（生成方法见 02-配置说明.md）
docker compose --profile app up -d --build
docker compose --profile app ps
```

手动启动默认**不导入**演示账号，正式迁移只建表结构、菜单、角色和字典。本地体验需要演示账号时，在**空库第一次启动后端之前**设置：

```dotenv
FLYWAY_LOCATIONS=classpath:db/migration,classpath:db/dev-data
```

生产环境保持默认值，首次账号见 [生产环境首次账号](06-生产环境首次账号.md)。

## 检查是否正常

```bash
curl http://localhost:8000/healthz
curl http://localhost:8000/api/v1/public/health
```

Windows PowerShell 使用 `curl.exe`。前端 `/healthz` 只检查 Nginx；后端健康接口在应用启动完成、MySQL 和 Redis 可访问后返回 `UP`，未就绪返回 HTTP 503。健康不代表已有可登录账号。

## 只跑数据库，前后端在本机开发

只用 Docker 运行 MySQL、Redis，后端、前端、AI 编排服务在本机运行，改代码后不用重新构建镜像。步骤见 [部署场景 · 方式二](01-部署场景.md#方式二数据库用-docker前后端和-ai-编排在本机运行)。

# 对象存储（阿里云 OSS）

上传的文件（询盘附件、发货与验货照片和视频、水单、合同、商品图片等）默认存在后端容器的目录里。生产环境建议存到阿里云 OSS：不占服务器磁盘，备份和扩容交给 OSS，浏览器直接从 OSS 取文件。

存储方式由 `.env` 的 `STORAGE_TYPE` 决定，不用改代码：

| 值 | 文件存在哪里 | 适用 |
| --- | --- | --- |
| `local`（默认） | 后端容器的 `/app/private-uploads`（私有）和 `/app/uploads`（公开） | 本机体验、开发 |
| `oss` | OSS 的私有存储桶和公开存储桶 | 生产 |

两种方式下行为一致：

- 私有文件（业务附件、凭证）只能在登录、并通过单据权限校验后拿到 **10 分钟有效的签名链接**，过期后要重新打开。
- 公开文件（共享商品库图片、登录页外观图片）使用固定地址。

## 一、准备 OSS

1. **创建两个存储桶，必须在同一地域**：
   - **私有存储桶**，读写权限选「私有」，例如 `zhul-erp-private`；
   - **公开存储桶**，读写权限选「公共读」，例如 `zhul-erp-public`；可以绑定自定义域名或 CDN。
2. **创建 RAM 子账号**：只开启「OpenAPI 调用访问」，生成 AccessKey。**不要使用主账号的 AccessKey。**
3. **给子账号授权**，只授予这两个存储桶的读写权限。自定义策略示例：

   ```json
   {
     "Version": "1",
     "Statement": [
       {
         "Effect": "Allow",
         "Action": ["oss:GetObject", "oss:PutObject", "oss:DeleteObject"],
         "Resource": ["acs:oss:*:*:zhul-erp-private/*", "acs:oss:*:*:zhul-erp-public/*"]
       }
     ]
   }
   ```

4. **跨域规则（CORS）**：在两个存储桶上各添加一条：

   | 项 | 值 |
   | --- | --- |
   | 来源 | 前端访问地址，例如 `https://erp.example.com` |
   | 允许 Methods | `GET`、`HEAD` |
   | 允许 Headers | `*` |
   | 暴露 Headers | `Content-Disposition`、`Content-Length`、`Content-Range`、`Accept-Ranges` |

   页面里用 `<img>`、`<video>` 直接加载签名链接时并不需要跨域规则。配置它，是为了避免以后前端用脚本读取文件内容时失败。

### 开发环境与生产环境分开

开发和生产**各用一套存储桶和 RAM 子账号**，每个子账号只授权自己环境的两个存储桶。这样开发环境的密钥碰不到生产文件，开发时误删或试跑迁移都不会影响生产：

| 环境 | 私有存储桶 | 公开存储桶 | RAM 子账号 | 配置写在 |
| --- | --- | --- | --- | --- |
| 开发 | `zhul-erp-dev-private` | `zhul-erp-dev-public` | `zhul-erp-dev` | 本机 `zhul-erp-backend/src/main/resources/application-dev.yml`（已被 Git 忽略） |
| 生产 | `zhul-erp-prod-private` | `zhul-erp-prod-public` | `zhul-erp-prod` | 生产服务器的 `.env` |

存储桶名称在阿里云全局唯一，被占用时加上公司缩写。开发桶可以在 OSS 控制台设置生命周期规则（例如 90 天后删除），避免测试文件长期计费。

不建议共用一套存储桶、只用 `OSS_KEY_PREFIX` 区分：前缀只分目录，同一个密钥仍能读写两边的文件。

本机直接运行后端（`scripts/dev-up.sh`）时不读取 `.env`，开发环境的 OSS 配置写在 `application-dev.yml`：

```yaml
zhul:
  storage:
    type: oss
    oss:
      endpoint: https://oss-cn-hangzhou.aliyuncs.com
      region: cn-hangzhou
      access-key-id: 开发子账号的 AccessKey ID
      access-key-secret: 开发子账号的 AccessKey Secret
      private-bucket: zhul-erp-dev-private
      public-bucket: zhul-erp-dev-public
```

## 二、配置

在 `.env` 中填写（各项说明见 `.env.example`）：

```bash
STORAGE_TYPE=oss
OSS_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
OSS_REGION=cn-hangzhou
OSS_ACCESS_KEY_ID=子账号的 AccessKey ID
OSS_ACCESS_KEY_SECRET=子账号的 AccessKey Secret
OSS_PRIVATE_BUCKET=zhul-erp-private
OSS_PUBLIC_BUCKET=zhul-erp-public
# 选填：公开存储桶绑定的域名或 CDN；多个环境共用存储桶时的键前缀
OSS_PUBLIC_DOMAIN=https://static.example.com
OSS_KEY_PREFIX=prod
```

然后执行 `docker compose up -d backend` 重建后端容器。

- `STORAGE_TYPE=oss` 但缺少必填项时，后端会**启动失败**，日志会写明缺少哪一项。
- AccessKey 只来自环境变量，不会写入数据库，也不会出现在日志和接口响应里。

## 三、目录划分

文件在存储桶中按业务环节分目录，文件名是随机生成的，不使用上传时的原文件名：

| 目录 | 内容 |
| --- | --- |
| `tenant/{租户}/inquiry/{年月}/` | 客户询盘附件 |
| `tenant/{租户}/opportunity/{年月}/` | 商机附件 |
| `tenant/{租户}/sourcing/{年月}/` | 询价回价附件、询价导入文件 |
| `tenant/{租户}/supplier/{年月}/` | 供应商资质与合同 |
| `tenant/{租户}/purchase/{年月}/` | 采购合同、采购发票 |
| `tenant/{租户}/shipment/{年月}/` | 供应商发货图片与视频 |
| `tenant/{租户}/receipt/{年月}/` | 验收入库照片与视频 |
| `tenant/{租户}/media/{品牌}/{型号}/` | 实拍任务素材（`media/unsorted/{年月}/` 为未能对应型号的） |
| `tenant/{租户}/logistics/{年月}/` | 出运单面单 |
| `tenant/{租户}/finance/{年月}/` | 水单、付款与退款凭证、报销与费用凭证 |
| `tenant/{租户}/document/{年月}/` | 单据模板 |
| `tenant/{租户}/system/`（公开） | 站点外观图片 |
| `shared/product/{品牌}/{型号}/`（公开） | 共享商品库的图片与视频 |

配置了 `OSS_KEY_PREFIX` 时，以上目录前面还会多一层前缀。

## 四、压缩与转码

- **图片**（包括水单截图）：上传时会：
  - 按拍摄方向转正，去掉拍摄位置等信息；
  - 长边缩到 2048 像素；
  - 照片转为质量 85 的 JPG，PNG 截图保持无损。
- **视频**：先保存原视频；后端再在后台用 ffmpeg 转成 1080p 的 MP4，转完替换原视频。
  - 转码期间和转码失败时都能正常播放原视频，页面上分别标「压缩中」「未压缩」。
  - 同一时间只转一个视频，用 `STORAGE_TRANSCODE_THREADS` 调整。
  - 后端 Docker 镜像构建时会自动安装 ffmpeg（如果安装失败，镜像会构建失败，不会悄悄漏装）。部署后可以用 `docker compose logs backend | grep 视频转码` 确认，正常时日志为「ffmpeg 可用」。不用 Docker、直接运行后端时，需要先安装 ffmpeg（Ubuntu：`apt install ffmpeg`）。

## 五、从本地切换到 OSS（已有数据时）

1. 先发布新版本，`STORAGE_TYPE` 仍为 `local`，确认各页面的预览和下载正常。
2. 按第一、二节准备 OSS 并配置，设置 `STORAGE_TYPE=oss`，再重建后端容器。之后新上传的文件都写入 OSS，旧文件仍从本地读取。
3. **预演迁移**：只统计各表的文件数、迁移前后的大小，以及找不到的文件，不改动任何数据：

   ```bash
   docker compose --profile app run --rm backend java -jar /app/app.jar --zhul.storage.migrate=dry-run
   ```

4. **正式迁移**：把本地文件按上面的目录上传到 OSS。迁移时图片会压缩，视频会在下次启动后转码。迁移可以重复执行，已迁移的文件会跳过；退出码为 1 表示有失败的文件，可以再执行一次。

   ```bash
   docker compose --profile app run --rm backend java -jar /app/app.jar --zhul.storage.migrate=run
   ```

5. 抽查各模块（询盘、商机、供应商、采购、仓库、财务、商品）的文件，确认都能打开。
6. **清理本地文件**：先预演，再正式执行。清理前会逐个确认 OSS 上存在、且大小与迁移时一致，然后才删除本地文件。没有任何记录引用的本地文件不会删除，只列在报告里，由人工决定如何处理。

   ```bash
   docker compose --profile app run --rm backend java -jar /app/app.jar --zhul.storage.cleanup=dry-run
   docker compose --profile app run --rm backend java -jar /app/app.jar --zhul.storage.cleanup=run
   ```

**回退**：第 6 步之前，把 `STORAGE_TYPE` 改回 `local` 即可。新上传的文件会写回本地，已迁移的文件仍从 OSS 读取，只要 OSS 配置保留着。第 6 步之后，本地副本已经删除，不能再回退。

本机直接运行后端时，在启动命令后面加同样的参数，例如 `mvn spring-boot:run -Dspring-boot.run.arguments=--zhul.storage.migrate=dry-run`。

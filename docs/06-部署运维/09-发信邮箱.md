# 发信邮箱（SMTP）

「忘记密码」时，系统把 6 位验证码发到账号绑定的邮箱。发信走标准 SMTP，服务商在 `.env` 里配置，不用改代码，以后换服务商也只改配置。

| 情况 | 找回密码时 |
| --- | --- |
| 配置了 `MAIL_HOST` | 真实发邮件；发送失败时页面提示「验证码邮件发送失败，请稍后重试」，可以马上重试 |
| 没配置 `MAIL_HOST`（生产） | 页面提示「系统未配置发信邮箱……请联系管理员重置密码」 |
| 没配置、本地开发与测试开了 `zhul.mail.log-only` | 不发邮件，验证码写在后端日志里，便于联调 |

## 一、选择发信服务

常用的几种都支持 SMTP：

| 服务 | SMTP 地址 | 端口 | 账号与密码 |
| --- | --- | --- | --- |
| 飞书邮箱（公司当前使用） | `smtp.feishu.cn` | 465（SSL） | 邮箱地址与「IMAP/SMTP 专用密码」（见下文，不是飞书登录密码） |
| 阿里云邮件推送（DirectMail） | `smtpdm.aliyun.com` | 465（SSL） | 控制台创建的「发信地址」与它的 SMTP 密码 |
| 阿里云企业邮箱 | `smtp.qiye.aliyun.com` | 465（SSL） | 邮箱地址与登录密码（开了安全登录的用客户端专用密码） |
| 腾讯企业邮箱 | `smtp.exmail.qq.com` | 465（SSL） | 邮箱地址与客户端专用密码 |
| QQ 邮箱 / 163 邮箱 | `smtp.qq.com` / `smtp.163.com` | 465（SSL） | 邮箱地址与「授权码」（在邮箱设置里开启 SMTP 后生成，不是登录密码） |

建议：

- 用**公司域名下的专用发信地址**，如 `noreply@你的域名`，不要用个人邮箱。
- 阿里云邮件推送需要先在控制台验证发信域名（添加 SPF、DKIM 等 DNS 记录），否则容易进垃圾箱或被拒收。
- 云服务器一般封了 25 端口，统一用 **465（SSL）** 或 587（STARTTLS）。

### 飞书邮箱：生成 SMTP 专用密码

1. 管理员在**飞书管理后台 → 邮箱 → 设置**里允许成员使用第三方邮件客户端（IMAP/SMTP），没打开时下一步看不到入口。
2. 用发信邮箱（建议单独开一个，如 `noreply@你的域名`）登录飞书，进入**邮箱 → 设置 → 第三方邮件客户端**，开启 IMAP/SMTP 并**生成新密码**。
3. 这个密码只显示一次，填到 `MAIL_PASSWORD`；`MAIL_USERNAME` 填完整邮箱地址，`MAIL_FROM` 留空（飞书要求发件人与登录账号一致）。
4. 换人或泄露时在同一页面删除这个密码重新生成，不影响飞书登录。

## 二、填写 .env

```bash
MAIL_HOST=smtp.feishu.cn
MAIL_PORT=465
MAIL_SSL=true
MAIL_STARTTLS=false
MAIL_USERNAME=noreply@你的域名
MAIL_PASSWORD=飞书生成的 IMAP/SMTP 专用密码
# 发件人地址，留空用 MAIL_USERNAME（多数服务商要求两者一致）
MAIL_FROM=
MAIL_FROM_NAME=烛龙ERP
```

使用 587 端口时改为 `MAIL_SSL=false`、`MAIL_STARTTLS=true`。

改完重启后端：

```bash
docker compose -f docker-compose.yaml -f docker-compose.prod.yaml --profile app up -d backend
```

本地开发不走 Docker 时，把同样的值写进 `zhul-erp-backend/src/main/resources/application-dev.yml`（该文件不进仓库）：

```yaml
spring:
  mail:
    host: smtp.feishu.cn
    port: 465
    username: noreply@你的域名
    password: 飞书生成的 IMAP/SMTP 专用密码
```

## 三、验证

1. 打开登录页的「忘记密码」，填一个**已绑定邮箱**的账号和它的邮箱，点发送。
2. 邮箱收到主题为「【烛龙ERP】找回密码验证码」的邮件，验证码 10 分钟内有效。
3. 后端日志有 `邮件已发送，to=no***@…`（邮箱脱敏）；发送失败时有 `邮件发送失败 … 原因=…`，按原因排查：

| 日志里的原因 | 处理 |
| --- | --- |
| `535 Authentication failed` / `authentication failed` | 账号或密码（授权码）不对；飞书邮箱确认用的是生成的专用密码、管理后台已允许第三方客户端 |
| `Could not connect to SMTP host` / 超时 | 地址或端口不对，或服务器出网被拦；确认 465 端口可以连出 |
| `550` / `553` 发件人被拒 | `MAIL_FROM` 与登录账号不一致，或发信域名未验证 |

## 四、注意

- 密码只写在服务器 `.env` 或本地 `application-dev.yml`，**不要提交到仓库**。
- 验证码发到**用户管理里该用户的邮箱**；用户必须在找回密码页填对这个邮箱才会发送。改邮箱后立即生效。
- 同一账号 60 秒内只能发一次；邮件没发出去不计入这 60 秒。
- 账号不存在或邮箱不对时页面同样提示「已发送」，不会暴露账号是否存在；没绑定邮箱的账号提示联系管理员重置密码。

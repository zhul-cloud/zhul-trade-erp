# 部署场景

支持以下四种部署方式。除方式二外，都在对应服务器的项目根目录用同一份 `docker-compose.yaml`，通过指定服务名决定这台服务器跑哪些服务。

| 方式 | MySQL / Redis | 后端、AI 编排服务 | 前端 | 启动命令 |
| --- | --- | --- | --- | --- |
| [一](#方式一全部服务部署在一台服务器) | Docker | Docker | Docker | `docker compose --profile app up -d --build` |
| [二](#方式二数据库用-docker前后端和-ai-编排在本机运行) | Docker | 本机运行 | 本机运行 | `docker compose up -d`，其余用本机命令 |
| [三](#方式三数据库用云服务一台服务器部署前后端和-ai-编排) | 云服务 | Docker | Docker（同一台） | `docker compose up -d --build backend ai-orchestrator frontend` |
| [四](#方式四数据库用云服务a-部署后端和-ai-编排b-部署前端) | 云服务 | Docker（服务器 A） | Docker（服务器 B） | A：`docker compose up -d --build backend ai-orchestrator`<br>B：`docker compose up -d --build frontend` |

> AI 编排服务通过后端签发的临时链接下载询盘附件，不需要和后端共享目录；只要它能访问后端地址（`AI_TASK_CALLBACK_BASE_URL`），文件存在 OSS 时还要能访问 OSS。

## 通用规则

- **启动哪些服务由命令决定，`.env` 只决定连接目标。** 用云数据库时只写需要的服务名，不要运行启动全部服务的 `--profile app up`，否则会把本地 MySQL、Redis 也启动起来。
- 前端、后端、AI 编排服务都没有 `depends_on`，指定服务名时不会顺带启动数据库。
- 不要设置 `COMPOSE_PROFILES=app`，否则会改变默认启动范围。
- 命令不会停止已经运行、但本次没有写到的服务。切换方式见 [运维与排障](05-运维与排障.md)。
- **只用 `docker compose`，不要用 `docker run` 单独启动容器**，原因见本文最后一节。
- 每台服务器都需要一份同版本的代码和自己的 `.env`。密钥的填写方法见 [配置说明](02-配置说明.md)。
- **时间统一按北京时间存储。** Compose 已给 MySQL 和后端设置 `TZ=Asia/Shanghai`，MySQL 另加 `--default-time-zone=+08:00`。用云数据库时，把实例参数 `time_zone` 设为 `+08:00`（或 `Asia/Shanghai`）。早于 2026-10-22 部署、时间存成 UTC 的库，用 `sql/build/fix/2026-10-22-UTC改北京时间.sql` 修正一次（按脚本里的步骤，先备份）。

## 方式一：全部服务部署在一台服务器

MySQL、Redis、后端、AI 编排服务、前端都运行在 Docker 里。

1. 准备 `.env`：填写三个后端密钥和 `AI_ORCHESTRATOR_API_KEY`，数据库连接保持默认（`DB_HOST=mysql`、`REDIS_HOST=redis`）。
2. 生产环境先按 [数据持久化与备份](03-数据持久化与备份.md) 启用持久化。
3. 生产不要用默认的 `root` / `root`：用 `MYSQL_USER` / `MYSQL_PASSWORD` 初始化应用账号，把 `DB_USER` / `DB_PASSWORD` 设为同一账号，`MYSQL_ROOT_PASSWORD` 单独设置。这些初始化变量只在数据库第一次创建时生效。
4. 启动：

```bash
docker compose --profile app up -d --build
docker compose --profile app ps
```

浏览器访问 `http://服务器地址:8000`。首次登录账号见 [生产环境首次账号](06-生产环境首次账号.md)。

本机开发想一键完成以上步骤，用 `scripts/docker-dev`，见 [快速开始](00-快速开始.md)。

## 方式二：数据库用 Docker，前后端和 AI 编排在本机运行

适合开发调试：MySQL、Redis 跑在 Docker 里，后端、前端、AI 编排服务直接在本机运行，改代码后不用重新构建镜像。本机需要 JDK 17、Maven 3.9+、Node.js ≥ 20、Python 3.10+。

**1. 启动 MySQL、Redis**

```bash
docker compose up -d
```

**2. 启动后端**（新终端）

```bash
cd zhul-erp-backend
cp src/main/resources/application-dev.yml.example src/main/resources/application-dev.yml
mvn spring-boot:run
```

**3. 启动 AI 编排服务**（新终端）

真实解析需要 API Key：

```bash
pip install -r scripts/ai-orchestrator/requirements.txt
export AI_ORCHESTRATOR_API_KEY=你的Key  # PowerShell：$env:AI_ORCHESTRATOR_API_KEY="你的Key"
python scripts/ai-orchestrator/server.py
```

只联调页面、不想产生费用时，改为启动假数据服务：

```bash
python scripts/ai-orchestrator-stub/server.py
```

**4. 启动前端**（新终端）

```bash
cd zhul-erp-frontend
npm install
npm run dev
```

浏览器访问 `http://localhost:8000`，开发配置会导入演示账号 `platform` / `admin123`。

注意：

- 本机运行的程序**不读取根目录 `.env`**。后端读 `application-dev.yml`，AI 编排服务读当前终端的环境变量。后端与 AI 编排服务之间的地址（`localhost:8899`、`localhost:8080`）和回调令牌默认值是一致的，不需要额外配置。
- 修改了 `.env` 里的 `MYSQL_HOST_PORT`、`REDIS_HOST_PORT` 或数据库密码时，同步修改 `application-dev.yml`。
- 数据库默认不持久化，停止或重建 MySQL 容器后清空，重启后端即可重新建表。
- 之前用方式一启动过全部容器时，先执行 `docker compose --profile app stop frontend backend ai-orchestrator`，否则 8000、8080 端口会冲突。
- macOS 可以用 `scripts/dev-up.sh` 一次启动以上全部（依赖 Homebrew 安装的 MySQL / Redis 与 JDK 17）。

## 方式三：数据库用云服务，一台服务器部署前后端和 AI 编排

1. 在云服务侧准备好 MySQL 和 Redis，见下文 [连接云 MySQL / Redis](#连接云-mysql--redis)。
2. `.env`：填写三个后端密钥、`AI_ORCHESTRATOR_API_KEY`，以及云数据库的连接配置。`BACKEND_URL` 保持默认 `http://backend:8080`。
3. 启动：

```bash
docker compose up -d --build backend ai-orchestrator frontend
docker compose ps
```

浏览器访问 `http://服务器地址:8000`。本地的 MySQL、Redis 容器不会启动，`MYSQL_*` 初始化变量在这种方式下不起作用。

## 方式四：数据库用云服务，A 部署后端和 AI 编排，B 部署前端

以下假设服务器 A 的内网地址是 `10.0.0.20`。两台服务器各自准备代码和 `.env`，分别执行命令；Compose 不会从一台服务器去部署另一台。

**服务器 A：后端和 AI 编排服务**

`.env` 填写三个后端密钥、`AI_ORCHESTRATOR_API_KEY`、云数据库连接，并让后端监听内网地址：

```dotenv
BACKEND_BIND_ADDRESS=10.0.0.20
BACKEND_HOST_PORT=8080
```

```bash
docker compose up -d --build backend ai-orchestrator
```

`BACKEND_BIND_ADDRESS` 必须是 A 自己的地址，并且 B 能访问到。用防火墙或云安全组只允许 B 访问 A 的 8080 端口。AI 编排服务只在 A 内部使用，不需要对外开放。

**服务器 B：前端**

`.env` 只需要两项，不需要数据库、密钥等后端配置：

```dotenv
WEB_PORT=8000
BACKEND_URL=http://10.0.0.20:8080
```

```bash
docker compose up -d --build frontend
```

浏览器访问 B。页面里的 `/api/`、`/uploads/` 请求由 B 的 Nginx 转发到 A，浏览器始终访问同一个域名，不涉及跨域。

- `BACKEND_URL` 只能是 `http(s)://主机[:端口]`，不能带用户名密码、`/api`、其他路径、查询串或末尾斜杠，否则前端容器会拒绝启动。
- 跨服务器不能使用 Docker 服务名 `backend` 或容器 IP，要用 A 实际可达的地址。
- A 使用 HTTPS 时证书必须有效且受信任，不要关闭证书校验。

## 连接云 MySQL / Redis

方式三、方式四的后端服务器 `.env` 示例（替换所有占位值）：

```dotenv
DB_HOST=mysql-endpoint.example
DB_PORT=3306
DB_NAME=zhul_erp
DB_USER=实际应用账号
DB_PASSWORD='实际数据库密码'
REDIS_HOST=redis-endpoint.example
REDIS_PORT=6379
REDIS_USERNAME=实际ACL用户名
REDIS_PASSWORD='实际Redis密码'
REDIS_DATABASE=0
REDIS_SSL_ENABLED=true
```

端口、用户名和 TLS 开关以云实例要求为准；不使用 Redis ACL 用户名时留空。

**先在云服务侧创建数据库。** 创建 `zhul_erp` 并给应用账号权限。后端启动时会执行 Flyway 迁移建表，需要 DDL 权限，只有读写权限不够。

### JDBC URL 与 TLS

`DB_URL` 非空时完全覆盖 `DB_HOST` / `DB_PORT` / `DB_NAME` 拼出的地址，用户名密码仍由 `DB_USER` / `DB_PASSWORD` 提供：

```dotenv
DB_URL='jdbc:mysql://mysql-endpoint.example:3306/zhul_erp?sslMode=VERIFY_IDENTITY&serverTimezone=Asia/Shanghai&connectTimeout=5000&socketTimeout=30000'
```

证书链和主机名必须匹配。默认拼接的连接串不会强制关闭 TLS，也不会自动建库；生产应按云服务要求明确配置 TLS 验证。

### 私有 CA 证书

云服务使用 JVM 不信任的私有 CA 时，按服务商要求准备 Java truststore，放在 `storage/certs/`，在 `docker-compose.yaml` 的 backend `volumes` 列表里追加只读挂载（不要重复定义 `volumes` 键）：

```yaml
      - ./storage/certs/cloud-truststore.p12:/app/certs/cloud-truststore.p12:ro
```

然后在 `.env` 配置：

```dotenv
JAVA_TOOL_OPTIONS='-Djavax.net.ssl.trustStore=/app/certs/cloud-truststore.p12 -Djavax.net.ssl.trustStoreType=PKCS12 -Djavax.net.ssl.trustStorePassword=实际证书库密码'
```

自定义 truststore 要包含连接所需的全部受信证书，不要关闭主机名或证书校验。部署后从后端容器内实际验证连接，宿主机能连通不代表容器网络也可达。

当前配置面向 MySQL 兼容的 JDBC 服务和 Redis 单端点服务；Redis Cluster、Sentinel 或云厂商的特殊代理模式需要另行配置，未经验证。

## 为什么不用 docker run

单独部署某个服务时，用 `docker compose up -d <服务名>` 就够了，不要改用 `docker run`，两者不等价：

- **变量名不同。** `.env` 是给 Compose 读的，Compose 会转换一部分变量再交给容器（例如 `FLYWAY_LOCATIONS` 变成容器里的 `SPRING_FLYWAY_LOCATIONS`）。用 `docker run --env-file .env` 时这些转换不会发生，实测后端会因迁移目录不对而启动失败。
- **前端需要 Docker 自定义网络。** 前端 Nginx 通过 Docker 内置 DNS 解析后端地址，只有自定义网络里才有。用 `docker run` 放在默认网络时，实测页面能打开，但所有接口都返回 502。Compose 会自动创建自定义网络。
- 端口、挂载、健康检查、临时存储警告等配置也都写在 Compose 文件里，`docker run` 需要逐项重写，容易遗漏。

# 运维与排障

## 更新版本

拉取新代码后，重新构建需要更新的服务：

```bash
docker compose up -d --build frontend
docker compose up -d --build backend
docker compose up -d --build ai-orchestrator
```

重建 backend 会清空临时存储里的上传文件，生产先启用持久化。数据库服务不会因为上述命令被重建。

只改了 `.env` 里的地址或密钥时，不需要重新构建，重建容器即可：

```bash
docker compose up -d backend
```

单纯 `docker compose restart` 不会加载新的环境变量。

## 切换与停止

| 目的 | 命令 |
| --- | --- |
| 从完整部署切回本机开发（保留数据库） | `docker compose --profile app stop frontend backend ai-orchestrator` |
| 停止本地数据库（确认云数据库已就绪、数据已迁移后） | `docker compose stop mysql redis` |
| 停止全部服务 | `docker compose --profile app stop` |
| 删除容器与网络，保留 `storage/` 下的数据 | `docker compose --profile app down` |

临时存储模式下，`stop` 时数据就已经丢失；不能把「没有加 `-v`」理解为数据安全。启用持久化后，不要手工删除 `storage/` 下的目录。

## 检查

```bash
docker compose --profile app config --quiet
docker compose --profile app ps -a
docker compose logs --tail=100 mysql redis backend frontend ai-orchestrator
```

容器日志输出到标准输出，由 Docker 的日志策略管理，`storage/` 不收集日志。健康状态变为 `unhealthy` 不会触发 Docker 重启；`restart: unless-stopped` 只处理进程退出。数据库短暂不可用时先看网络和日志，不要反复删除容器。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 后端启动报 `Set JWT_SECRET/AES_KEY/... in .env` | 填写对应密钥后 `docker compose up -d backend` |
| 日志里有 `[警告] ... 是临时存储（tmpfs）` | 默认行为；需要保留数据见 [数据持久化与备份](03-数据持久化与备份.md) |
| 停止后数据消失 / MySQL 重启后业务表消失 | 临时存储被清空；重启后端重新建表，或启用持久化 |
| 前端健康但接口 502 | `BACKEND_URL` 在容器里是否可达、后端端口是否开放、后端是否就绪 |
| 健康正常但无法登录 | 正式迁移不创建账号；核对演示配置或 [生产环境首次账号](06-生产环境首次账号.md) |
| `Unknown database` / 权限不足 | 云数据库是否预先建库，应用账号是否有迁移所需的 DDL 权限 |
| 数据库认证失败 | `.env` 的 `DB_USER` / `DB_PASSWORD` 是否与实际一致；修改 `MYSQL_*` 不会改已有密码 |
| Redis SSL / 认证失败 | 云端端口、TLS、ACL 用户名与密码；本地 Redis 默认无密码 |
| 端口被占用 | 调整 `*_HOST_PORT` / `WEB_PORT`，同步本机或远端访问地址 |
| 上传目录 `Permission denied` | Linux 上 `storage/uploads`、`storage/private-uploads` 属主是否为 `10001:10001` |
| 「AI 解析」报 `ConnectException` | `ai-orchestrator` 是否启动、`AI_ORCHESTRATOR_BASE_URL` 是否可达 |
| 「AI 解析」报未配置 `AI_ORCHESTRATOR_API_KEY` | 填写当前服务商的 Key，或开发时改用 `AI_ORCHESTRATOR_MODE=stub` |
| `ai-orchestrator` 反复重启，日志里有「配置错误」 | `AI_ORCHESTRATOR_PROVIDER` 或思考强度写了不支持的值，按日志里列出的可选值改正 |
| 「AI 解析」失败，原因是认证错误 | `AI_ORCHESTRATOR_API_KEY` 与 `AI_ORCHESTRATOR_PROVIDER` 不是同一家，切换服务商时要一并更换 Key |
| 「AI 解析」一直停在解析中直到超时 | 编排服务回调后端失败：看 `docker compose logs ai-orchestrator` 里的 `callback FAILED`，核对 `AI_TASK_CALLBACK_BASE_URL` 与 `AI_TASK_CALLBACK_TOKEN` |
| 带附件的询盘解析失败「附件文件不存在」 | backend 与 ai-orchestrator 是否挂载同一个私有上传目录 |
| 用 `docker run` 单独启动后，后端迁移校验失败或前端接口 502 | 改用 `docker compose up -d <服务名>`，原因见 [部署场景](01-部署场景.md#为什么不用-docker-run) |
| 新增演示迁移报校验或未解析错误 | 不要改生产历史或开启乱序迁移；演示必须从独立空库开始 |

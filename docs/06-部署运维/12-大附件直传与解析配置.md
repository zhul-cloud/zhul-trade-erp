# 大附件直传与解析配置

询盘附件单个最大 500MB、每张询盘合计最多 2GB（不限个数），浏览器直接分片传到阿里云 OSS，不经过 Cloudflare 和后端；AI 解析时大文件分批处理。功能说明见 OpenSpec 变更 `inquiry-large-attachments`。

> **状态：** 本功能尚未上线。下面的配置要在**包含本功能的版本合并到 `main` 之前**完成；版本号上线时确定。没配置好时，上传会在浏览器跨域这一步失败，页面提示「上传服务暂时不可用，请联系管理员」；其他功能不受影响。
>
> 本文已按实现核对（2026-11-10）：权限对应后端实际调用的 OSS 接口，配置项对应代码实际读取的环境变量。

需要有阿里云 RAM 和 OSS 管理权限的人操作，共五步：

| 步骤 | 在哪里做 | 生产要做 | 开发要做 |
| --- | --- | --- | --- |
| 一、给 RAM 子账号加权限 | RAM 控制台 | 是 | 是（开发子账号） |
| 二、私有存储桶加跨域规则 | OSS 控制台 | 是 | 是（开发私有桶） |
| 三、私有存储桶加生命周期规则 | OSS 控制台 | 是 | 是（开发私有桶） |
| 四、补配置项 | 服务器 `.env` | 按需（都有默认值） | 不需要 |
| 五、确认编排服务的临时磁盘 | 服务器 | 是 | 不需要 |

当前生产的取值（只读查看，2026-11-07）：私有存储桶 `zhul-erp-prod-private`，地域 `cn-hangzhou`，`OSS_KEY_PREFIX` 为空，网站地址 `https://erp.zhulcloud.com`。下文以这些值为例。

## 一、给 RAM 子账号加权限

分片上传需要中止分片上传的权限；后端启动时会只读检查存储桶的跨域规则，所以需要读取跨域配置的权限。在[对象存储](07-对象存储.md)第一节的自定义策略基础上，改成下面这样（存储桶名换成实际名称）：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:GetObject",
        "oss:PutObject",
        "oss:DeleteObject",
        "oss:AbortMultipartUpload"
      ],
      "Resource": ["acs:oss:*:*:zhul-erp-prod-private/*", "acs:oss:*:*:zhul-erp-prod-public/*"]
    },
    {
      "Effect": "Allow",
      "Action": ["oss:GetBucketCors"],
      "Resource": ["acs:oss:*:*:zhul-erp-prod-private"]
    }
  ]
}
```

说明：

- 发起分片上传、上传分片、合并分片都属于 `oss:PutObject`，已有。
- 存储桶内部复制（临时文件挪到正式位置）需要源文件的 `oss:GetObject` 和目标的 `oss:PutObject`，已有。
- 读取文件大小、读取文件头（核对文件类型）属于 `oss:GetObject`，已有。
- 新增的只有 `oss:AbortMultipartUpload`、`oss:GetBucketCors` 两项，不需要修改存储桶配置的权限。

## 二、私有存储桶加跨域规则

OSS 控制台 → 存储桶 `zhul-erp-prod-private` → 数据安全 → 跨域设置。[对象存储](07-对象存储.md)第一节原有的规则（只允许 `GET`、`HEAD`）改成下面这样，或者新加一条：

| 项 | 值 |
| --- | --- |
| 来源 | `https://erp.zhulcloud.com` |
| 允许 Methods | `GET`、`HEAD`、`PUT` |
| 允许 Headers | `*` |
| 暴露 Headers | `ETag`、`Content-Disposition`、`Content-Length`、`Content-Range`、`Accept-Ranges` |
| 缓存时间（秒） | `600` |

- **`ETag` 必须暴露。** 浏览器要读取每个分片的 ETag，合并时交给后端；不暴露就无法完成上传。
- **来源只写网站地址**，不要写 `*`。
- **开发私有桶**的来源写本机前端地址，如 `http://localhost:8000`、`http://localhost:8001`。
- **公开存储桶**不需要改。

配好后可以用这条命令检查。返回头里有 `Access-Control-Allow-Origin: https://erp.zhulcloud.com`，并且 `Access-Control-Allow-Methods` 包含 `PUT`，就是配好了：

```bash
curl -s -i -X OPTIONS "https://zhul-erp-prod-private.oss-cn-hangzhou.aliyuncs.com/tmp/cors-check" -H "Origin: https://erp.zhulcloud.com" -H "Access-Control-Request-Method: PUT" | grep -i "access-control"
```

## 三、私有存储桶加生命周期规则

上传到一半放弃、取消、校验没通过，以及传完但没有保存到询盘的文件，都留在临时目录 `tmp/`（保存询盘时才转到正式位置），由生命周期规则自动清理。

OSS 控制台 → 存储桶 `zhul-erp-prod-private` → 数据管理 → 生命周期 → 创建规则：

| 项 | 值 |
| --- | --- |
| 规则名称 | `zhul-upload-tmp-cleanup` |
| 状态 | 启用 |
| 策略 | 按前缀匹配 |
| 前缀 | `tmp/`（如果设置了 `OSS_KEY_PREFIX`，例如 `prod`，就写 `prod/tmp/`） |
| 文件过期策略 | 指定天数：**1** 天后删除 |
| 碎片过期策略 | 指定天数：**1** 天后删除 |

- **前缀必须准确**，规则只作用于临时目录，不会动正式文件（正式文件在 `tenant/...` 下）。
- **碎片过期**用来清理开始了、但从未合并的分片上传，不配会一直占用存储、产生费用。

## 四、补配置项（服务器 `.env`）

新增两项，都有默认值，不填也能启动。只有想改默认值时才写进 `/opt/zhul-trade-erp/.env`：

| 配置项 | 用于 | 默认 | 说明 |
| --- | --- | --- | --- |
| `AI_TASK_MAX_MINUTES` | 后端 | `180` | 一个 AI 任务最长处理多少分钟；超过后即使还在报告进度，也判为超时失败 |
| `AI_ORCHESTRATOR_MAX_SECONDS` | AI 编排服务 | `10200` | 编排服务处理一个任务的总期限；到期不再发起新的批次 |

已有的两项含义有变化，数值不用改：

| 配置项 | 原来 | 上线后 |
| --- | --- | --- |
| `AI_TASK_TIMEOUT_MINUTES`（默认 20） | 从任务创建算起，超过即失败 | 从**最近一次进度报告**算起，多久没有动静就判超时 |
| `AI_ORCHESTRATOR_TIMEOUT_SECONDS`（默认 900） | 整个任务的期限 | **单次模型调用**的期限 |

四个值之间的关系，改任何一个时都要满足：

- `AI_ORCHESTRATOR_MAX_SECONDS` ≤ `AI_TASK_MAX_MINUTES` × 60 − 600。默认 10200 = 180 × 60 − 600，留 10 分钟给结果回调重投。
- `AI_ORCHESTRATOR_TIMEOUT_SECONDS` 至少比 `AI_TASK_TIMEOUT_MINUTES` × 60 短 180 秒，这一条和原来一样。

改完执行：

```bash
docker compose up -d backend ai-orchestrator
```

## 五、确认编排服务的临时磁盘

AI 解析大文件时，编排服务会把附件和渲染出来的页面写到容器的临时目录。附件逐个处理、处理完就删，占用只取决于最大的单个文件，**Docker 所在磁盘留至少 2GB 空闲**：多个询盘同时解析时按同时解析的数量相应增加。

```bash
df -h /var/lib/docker
```

## 存储方式为本地时

`STORAGE_TYPE=local`（开发、体验或不用 OSS 的部署）时，上面第一到三步都不用做。分片直接传到后端，每片 16MB，经过 Cloudflare 和 Nginx 也没问题。要注意的只有三点：

1. **私有上传目录必须在磁盘上。** 默认 Compose 的 `private-uploads` 是 tmpfs，文件存在内存里，重启就丢。要收大附件，先按[数据持久化与备份](03-数据持久化与备份.md)把它换成磁盘目录；没换时后端启动日志会警告。
2. **留够磁盘空间。** 每个附件按原大小占用，上传时如果剩余空间不够「文件大小 + 1GB」，系统会拒绝并提示「服务器存储空间不足」。
3. **不用配清理规则。** 后端每小时自动删除 `tmp/` 下超过 1 天的文件（未完成的上传、传完没保存到询盘的文件），位置在私有上传目录下。

## 不需要改的

- **Cloudflare**：上传不再经过 Cloudflare，网站入口和 Nginx 的 100MB 限制保持不变。
- **办公网络**：浏览器直接连接 `zhul-erp-prod-private.oss-cn-hangzhou.aliyuncs.com` 上传。公司网络如果限制访问外部域名，要放行这个地址。
- **下载**：仍是签名链接，不用改。

## 上线后验收

1. 新建询盘，上传一个 200MB 以上的 PDF：能看到进度，传完后可以提交。
2. 对这个询盘发起 AI 解析：「解析中」显示「已解析 x / y」，完成后确认页的型号完整。
3. 上传到一半取消，1 天后在 OSS 控制台确认 `tmp/` 下对应的文件已被清理。

## 回滚

重新部署上一版即可（见[生产发版](08-生产发版.md)「重新部署与回滚」）。跨域规则、生命周期规则和新增的 RAM 权限不影响旧版本，可以保留。

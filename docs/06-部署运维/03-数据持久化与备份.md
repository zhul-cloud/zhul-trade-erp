# 数据持久化与备份

## 默认是临时存储

为了让本机体验和测试环境「用完即清」，默认所有数据都放在 tmpfs 临时存储里：

| 数据 | 位置 | 默认 |
| --- | --- | --- |
| MySQL 数据库 | mysql 容器 `/var/lib/mysql` | tmpfs |
| Redis 缓存与 AOF | redis 容器 `/data` | tmpfs |
| 公开上传（图片等） | backend 容器 `/app/uploads` | tmpfs |
| 私有上传（询盘附件等） | backend 与 ai-orchestrator 共享的卷，挂在 `/app/private-uploads` | tmpfs 类型的卷 |
| AI 个人订阅登录状态 | ai-orchestrator 容器 `/home/zhul`，命名卷 `ai-orchestrator-home` | **持久**（普通 Docker 卷，不在 `storage/`，不需要备份；见 [AI 编排服务](04-AI编排服务.md)） |

**停止、重启、删除或重建对应容器，数据就会清空。** 只要某个目录是临时存储，对应服务启动时都会在日志里打印一行 `[警告] ... 是临时存储（tmpfs）`，任何模式都会提示：

```bash
docker compose logs mysql redis backend | grep 警告
```

单独重启 MySQL 会清空数据库，而仍在运行的后端不会重新执行建表迁移。临时环境需要重置时，同时重启后端：`docker compose restart mysql backend`。只在确认数据可以丢弃时这样做。

云数据库不会替后端保存上传文件，上传目录仍需按下文启用持久化。

## 启用持久化

启用后数据保存在当前服务器项目目录的 `storage/` 下：

```text
项目根目录/
└── storage/
    ├── mysql/             # MySQL 数据
    ├── redis/             # Redis AOF
    ├── uploads/           # 后端公开上传
    ├── private-uploads/   # 后端私有上传（AI 编排服务只读）
    └── certs/             # 可选：云服务证书
```

这些是相对 Compose 文件的 bind mount，不同服务器不会共享数据。不要在尚未初始化的 `storage/mysql/` 里放任何文件，MySQL 首次初始化要求空目录。

### 1. 创建目录

Linux / macOS：

```bash
mkdir -p storage/mysql storage/redis storage/uploads storage/private-uploads
# Linux：后端与 AI 编排服务以 UID/GID 10001 运行，只给两个上传目录授权
sudo chown -R 10001:10001 storage/uploads storage/private-uploads
sudo chmod 750 storage/uploads storage/private-uploads
```

Windows PowerShell：

```powershell
New-Item -ItemType Directory -Force storage/mysql, storage/redis, storage/uploads, storage/private-uploads
```

Docker Desktop 需要允许访问项目所在磁盘。MySQL、Redis 的官方镜像会处理自己数据目录的权限，不要改成后端的 UID。

### 2. 在 `.env` 打开持久化开关

不需要修改 `docker-compose.yaml`。在项目根目录的 `.env` 加入以下两行：

```dotenv
COMPOSE_PATH_SEPARATOR=;
COMPOSE_FILE=docker-compose.yaml;docker-compose.persist.yaml
```

Docker Compose 会读取这两个变量，之后所有 `docker compose` 命令（包括 `scripts/docker-dev.*`）都会自动叠加 `docker-compose.persist.yaml`：MySQL、Redis、公开上传、私有上传改存上面的 `storage/` 目录，backend 与 ai-orchestrator 的私有上传指向同一目录。`COMPOSE_PATH_SEPARATOR=;` 让 Windows、Linux、macOS 使用同一种写法。

关闭持久化：删除这两行后重建容器，容器回到 tmpfs，`storage/` 里的数据保留在磁盘上，再次打开开关后继续使用。命令行显式指定 `-f` 时不读取 `COMPOSE_FILE`；生产用 `docker-compose.prod.yaml`，不受这个开关影响。

用 `docker compose config --volumes` 或 `docker compose config | grep storage` 可以确认开关是否生效。

### 3. 重建容器

```bash
docker compose --profile app up -d --force-recreate
```

分服务器时只重建本机的服务，例如 `docker compose up -d --force-recreate backend ai-orchestrator`。之后日志里不再出现对应目录的临时存储警告，说明已生效。

## 备份与恢复

### 数据库

备份：

```bash
docker compose exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers --databases zhul_erp' > zhul_erp-backup.sql
```

恢复到当前 MySQL（会覆盖同名库里的同名表）：

```bash
docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' < zhul_erp-backup.sql
```

Windows PowerShell 的 `>` / `<` 会改变文件编码，请在 Git Bash 或 WSL 中执行以上两条命令。云数据库使用云服务自带的备份能力。

### 上传文件

```bash
docker compose cp backend:/app/uploads ./backup-uploads
docker compose cp backend:/app/private-uploads ./backup-private-uploads
```

恢复时把目录拷回 `storage/uploads`、`storage/private-uploads`（Linux 上注意属主 `10001:10001`）。

### 迁移已有数据时

切换挂载不会把临时存储、旧命名卷或旧服务器的数据自动复制到 `storage/`。**重建容器之前**先停止业务写入，按上面的方法备份数据库和上传文件，切换后再恢复。

- 不要用 `docker compose down -v` 清理已有环境。
- 旧版 Compose 使用过的 `zhul_erp_mysql_data` 卷不会被自动导入，也不要直接删除；先用 `docker volume ls` 和旧容器的挂载信息核对实际卷名，再安排迁移。
- 改 `.env` 连接云数据库也不会迁移旧数据。

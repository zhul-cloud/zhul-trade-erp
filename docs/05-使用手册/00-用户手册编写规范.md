# 用户手册编写规范

> 版本：V1.0  
> 适用范围：`docs/05-使用手册/` 下的所有业务模块手册  
> 目标读者：第一次使用烛龙 ERP 的内部员工

## 1. 写作目标

用户手册要让员工不问同事，也能完成一个完整任务。每一章回答三个问题：

1. 我什么时候需要用它？
2. 我应该点哪里、填什么？
3. 保存后系统会发生什么？

## 2. 固定章节结构

每个重要流程按以下顺序编写：

1. **这是什么**：用一句白话说明功能用途。
2. **什么时候使用**：说明触发场景。
3. **你会看到什么**：放页面截图，并标出关键区域。
4. **按步骤操作**：一个步骤只说一个动作。
5. **填写示例**：给出完整、具体的示例。
6. **完成后会发生什么**：说明状态、提醒、阶段或记录变化。
7. **容易出错的地方**：写必填项、权限和常见误操作。

## 3. 图文规范

- 关键流程必须配截图；截图来自产品原型或已核对的实际页面。
- 图片下方必须有图注，说明“看哪里、做什么”。
- 截图中用编号、箭头或高亮框指向操作位置；编号要和步骤对应。
- 图片只保留完成任务所需的区域，重复页面优先使用局部图。
- 不使用真实客户隐私、密码、Token、API Key 或其他生产敏感数据。
- 页面或按钮变化后，必须同步更新图片、图注和步骤。

## 4. 语言规范

- 面向小白写作，先讲目的，再讲按钮。
- 使用短句和常用词，避免开发、数据库和接口术语。
- 把“配置相关参数”改成具体动作，例如“选择客户、填写下一步日期”。
- 每个字段都给填写示例；第一次出现的专业词要解释。
- 重要提示用“注意”“为什么”说明，不在正文堆叠所有内部规则。

## 5. 体验与维护规范

- 同时兼顾用户体验、开发体验和 AI Agent 使用体验：内容要易懂、与实际页面一致、标题和步骤稳定可检索。
- Markdown 是源文件，PDF 是发布版本；两者内容和版本号必须一致。
- 每份手册标明适用角色、适用系统版本、最近更新时间和截图来源。
- 新模块优先复用本规范，不自行发明章节格式。
- 功能改变时提升手册版本并重新生成 PDF。

## 6. PDF 发布规范

- PDF 包含封面、目录、章节标题和页码。
- 使用支持中文的字体，图片清晰且适合电脑阅读和打印。
- 每章围绕一个明确任务，避免连续大段文字。
- 末尾提供常见问题和一页速查表。

# 售后管理使用手册

> 文档版本：V1.1
> 适用版本：含数据库迁移 V1.5.27 的版本（补发订单从 V1.4.4 起，处理时限从 V1.4.5 起，退货单据化从 V1.5.27 起）
> 面向角色：业务员 · 仓管 · 采购员 · 财务 · 老板 / 租户管理员
> 最近更新：2026-11-11（退货改为「销售退货单 → 退货入库单 → 采购退货单」，新增「处理方式」「采购退货」）

客户收货后出了问题（质量、少发、发错、使用咨询），统一登记**售后单**，跟进记录、退货、退款和费用都挂在售后单上，结案时能看到这次售后一共花了多少。

售后单上的「**处理方式**」有四种，按需要选，可以选多次：

| 处理方式 | 生成的单据 | 谁做 |
|----------|-----------|------|
| 仅退货 | 销售退货单（TH）→ 退货入库单（RR）→ 去向，退回供应商时再生成采购退货单（PR） | 业务员发起并确认，仓库验收，采购员处理去向和寄回供应商 |
| 退货退款 | 同上，另外生成退款申请（RA），默认验收后才能退款 | 同上，财务执行退款 |
| 仅退款 | 退款申请（RA）→ 退款单（TK） | 业务员申请，（可选审批，）财务执行 |
| 补发 | 售后补发订单（SO，0 元） | 业务员发起，采购、仓库、物流照常处理 |

每张单据都有自己的详情页，可以写备注、上传附件（图片、视频、PDF、Excel，点开就能预览），单据之间点「来源单号」或单号互相跳转。

缺货、客户取消部分型号请用订单的「部分取消」，不走售后（见《销售订单部分取消使用手册》）。

## 1. 登记售后单

位置：**销售管理 → 售后管理 → 新建售后单**，或在**销售订单详情点「售后」**（已完成的订单也有这个按钮），客户、订单与型号自动带出。

- **有订单**：选订单，勾选有问题的型号并填数量；
- **没有订单**：只选客户，手填型号、品牌、数量，用于客户说不清订单号时的追溯。
- **问题等级**：待确认、S1 安全或重大风险、S2 设备停机、S3 功能受限、S4 外观附件、S5 使用咨询。S1 先提醒客户停机断电，不等资料齐全。
- 现象（必填）、客户诉求、收到时间、证据附件（照片、视频、PDF）。
- **负责人**默认订单业务员；**下一步行动**与**下次更新客户时间**选填。系统会按等级自动算出首次响应的截止时间（见下一节「处理时限」）。

## 2. 跟进与处理

售后单详情：

- **跟进记录**：每次和客户、供应商沟通后写一条，可附图片或文件。**这次向客户说明了进展时，勾选「已告知客户」**，系统据此算首次响应和下次更新客户的时间；内部备注（如「已转供应商排查」）不要勾。退货、退款、费用、等级和状态变化会自动写进时间线。
- **处理**（右侧「编辑」）：
  - 改等级必须写原因，时间线记「等级 S3 → S2：原因」；
  - 原因与责任：调查中、产品质量、运输包装、选型兼容、安装使用、超保或正常损耗；
  - 处理方案可多选：远程指导、补寄配件、当地维修、退回检测或维修、换货、退款、其他；
  - 负责人、下一步、下次更新客户时间。
- 方案给客户后点「改为待客户确认」，客户回复后再改回处理中。

列表顶部四张卡片：处理中、待客户确认、**需要更新客户**（已过截止时间，点击只看这些单）、本月结案。

### 处理时限

按售后流程（SOP）的等级时限自动提醒，时限固定：

| 等级 | 首次响应 | 之后更新客户 | 计时方式 |
|------|----------|--------------|----------|
| S1 | 1 小时 | 每 2 小时 | 自然时间（含非工作时间） |
| S2、待确认 | 2 个工作小时 | 每个工作日 | 工作时间 |
| S3 | 1 个工作日 | 每 2 个工作日 | 工作时间 |
| S4 | 1 个工作日 | 每 3 个工作日 | 工作时间 |
| S5 | 1 个工作日 | 只看手填的下次更新时间 | 工作时间 |

- **工作时间**：周一至周五 9:00–18:00，不考虑节假日和调休；1 个工作日 = 9 个工作小时。例：周五 17:30 收到 S2 反馈，首次响应截止下周一 10:30。
- **首次响应**从售后单的「收到时间」起算，第一次勾「已告知客户」即完成；之后从最近一次「已告知客户」起算下次更新客户。
- 负责人手填的**下次更新客户时间更早**时以手填为准（截止事项显示「手填时间」）；手填时间不能推迟等级截止。
- **改等级**立即按新等级重算；**待客户确认**期间不按等级计时，只看手填时间；改回处理中从那一刻重新起算；已结案、已撤销不再提醒。
- 提醒位置：售后单详情顶部的时限条；列表「下一步 · 截止」列（已逾期标红、1 小时内到期标橙），勾「只看逾期」筛选；工作台业务员「我的待办」的「售后要更新客户」（本人负责的已逾期或快到期），业务负责人「待跟进」的「售后逾期」。
- 升级前已有的售后单：先只按手填的下次更新时间提醒，下次勾「已告知客户」后开始按等级计时。

## 3. 退货

### 3.1 业务员：选「仅退货」或「退货退款」

1. 售后单详情的「处理方式」卡片点「**仅退货**」（客户寄回，不退钱）或「**退货退款**」（寄回后退钱）。没有已出运的型号时这两个按钮是灰的，鼠标移上去会显示原因。
2. 勾选要退的型号，填退回数量（不超过已出运数量减去其他没作废的退货单的数量），客户寄回的快递单号可以后补。
3. 选「退货退款」时，需要不等货到就先退钱的，勾「**先退款**」。
4. 保存后生成**销售退货单**（TH…），状态「待确认」，在**销售管理 → 销售退货**也能找到。

### 3.2 业务员：确认退货

打开销售退货单详情，核对型号和数量后点「**确认退货**」。退货退款的单据会列出每个型号的退款金额，默认「退货数量 × 成交单价」（四舍五入到分），可以改小。确认后：

- 销售退货单变为「待入库」，同时生成**退货入库单**（RR…）交给仓库；
- 选了「退货退款」的，同时生成退款申请：没勾「先退款」时为「**待验收**」，财务暂时不能执行；勾了「先退款」直接进入「待财务处理」（开了审批的进入「待审批」）。

确认前可以改型号、数量；确认后只能补填快递信息（仓库验收前）。客户不退了，点「作废」并写原因：还没验收的退货入库单一起作废，没执行的退款申请自动撤回；退款已经执行的，要先请财务作废退款单。已入库的退货单不能作废。

### 3.3 仓库：验收退货入库单

**仓库管理 → 退货入库**「待入库」页签点单号进入详情，点「验收」，每个型号填实收与合格数量，可以拍照。

- 验收后，销售退货单变为「已入库」，「待验收」的退款申请进入下一步；
- 实收少于退货数量时，退款申请上会提示财务核对金额；
- 录错了可以「撤回入库」重新验收（还没处理去向时），退款申请（没执行的）回到「待验收」。

### 3.4 采购员：处理去向

退货入库单「待处理」时，在详情里逐行点「处理去向」，一行的数量可以拆到不同去向，合计等于实收，可以分几次处理：

- **退回供应商**：选供应商（默认原采购订单的供应商），保存后自动生成**采购退货单**，寄出和退款在采购退货单上登记（见 4.3「采购退货」）；同一次处理退给同一个供应商的合成一张；
- **转闲置库存**：只能是合格品，生成闲置库存，来源显示退货入库单号；
- **报废**：填原因。

处理后不能撤回。

## 4. 退款

### 4.1 申请退款

- **退货退款**：确认退货时自动生成，见 3.2。
- **仅退款**：售后单详情「处理方式」点「**仅退款**」（没有售后单时也可以在订单详情点「申请退款」）：金额（不超过可申请金额 = 已到账 − 已退款 − 其他待处理申请）、原因、建议去向（转客户余额、银行汇款、原路退回平台；平台收款的订单只能原路退回）、客户收款信息。

每张退款申请都有明细：退货退款按型号一行，仅退款一行「退款」，合计等于申请金额。

### 4.2 财务执行

**财务管理 → 退款管理 →「退款申请」页签**，列表显示来源单号（销售退货单号或售后单号）：

- 「待验收」页签只能查看，等仓库验收；
- 「执行」：打开登记退款的表单，按申请带出金额、原因、去向，按原来的规则填实际退出人民币和凭证，保存后生成售后退款单并关联售后单；
- 「驳回」：填原因。

退款单作废后，申请回到「待财务处理」。财务直接登记退款的入口保留，登记时可以选这张订单的售后单。

### 4.3 采购退货（退给供应商）

**采购管理 → 采购退货**列出所有退给供应商的货，来源有四种，都由系统自动生成：

| 来源 | 从哪里来 |
|------|---------|
| 售后退货 | 退货入库单去向选「退回供应商」 |
| 到货不良 · 退货换货 | 采购入库的到货差异选「退货换货」 |
| 到货不良 · 退货不补 | 到货差异选「退货不补」 |
| 多发退回 | 到货差异选「退回供应商」 |

采购员（需要「维护采购退货单」按钮权限）在详情页操作：

1. **寄出**：填寄出日期、快递公司和单号；有运费时填金额并选垫付人（默认自己），这笔运费会进入垫付人的待报销「退货运费」；勾「公司支付」的不进待报销。寄出前可以减少数量，减掉的回到来源待处理。
2. **完成**：供应商签收后填签收日期；售后退货来源**必须**填供应商退款或抵扣金额（采购订单的币种，没有就填 0）。
3. **作废**：只有待寄出时可以，来源回到待处理（到货差异回到「待处理」）。
4. **重新打开**：已完成的金额填错了，重新打开回到「已寄出」，改好后重新完成。

售后退货来源完成后，退款或抵扣金额冲减该采购订单的应付；已经付清的，多付的部分成为**供应商欠款**，由财务在应付管理里用退款或抵扣处理。到货差异来源不另外冲减应付，仍按差异处理方式计算。采购订单详情也会列出它的采购退货单。

## 5. 售后费用

补寄运费、维修费、检测费等：

- 售后单详情点「登记费用」（有费用单维护权限的人才看到），分摊到所选型号，自动关联售后单；
- 或在**财务管理 → 费用管理**新建费用单，分摊到订单型号后，在「关联售后单」里选。

费用照旧计入原订单成本，售后单上汇总显示。

## 6. 补发（换货、补寄配件）

需要再给客户发一次货时，在售后单详情点「**补发**」（售后单要关联订单）：

1. 勾选原订单里要补发的型号，填数量（不超过订单数量）；要补寄配件时点「手填型号（补寄配件）」，填型号、品牌、数量。
2. **申报单价**：原订单型号默认原单价，配件必须填。只用于商业发票（CI）和装箱单（PL），订单金额仍是 0。
3. 采购员默认原订单型号的采购员，可以改；可以写一句说明。
4. 点「生成补发订单」，系统生成一张销售订单，标「售后补发」，售后单时间线记一条「补发订单 SO…」。

补发订单：

- 客户、币种、事业部、业务员取原订单；**不出 PI、不收款**，收款状态「无需收款」，不能登记收款、余额抵扣和退款；
- 照常生成采购需求，采购、入库、出库、出运和普通订单一样；需要时可以整单取消或部分取消；
- 出 CI / PL 时按申报单价出金额，型号描述后注明「Free of charge replacement, no commercial value」；
- 销售订单列表可以按「来源：售后补发」筛选，编号下显示原订单号。

补发订单还没出运（也没取消）时，售后单不能结案。补发的货又出问题时，可以对补发订单再登记售后、再补发，成本仍计入最初的订单。

## 7. 结案与撤销

- **结案**：选最终原因与责任（不能是「调查中」），填处理结果。有没处理完的销售退货单、退货入库单、采购退货单，待处理的退款申请或还没出运的补发订单时不能结案，会提示具体单据。结案后只能添加跟进记录。
- **撤销**：误建的售后单，没有销售退货单（作废的不算）、退款申请（撤回的不算）、退款单和费用单时才能撤销。

## 8. 对订单利润的影响

| 动作 | 对原订单 |
|------|---------|
| 售后退款（含转客户余额） | 冲减订单收入，计入经营统计「退款」 |
| 售后费用 | 计入订单成本 |
| 退回供应商 | 采购退货单完成后按供应商退款或抵扣金额冲减订单成本；寄出后运费计入订单成本 |
| 转闲置库存 | 按原采购成本（采购订单不含税人民币单价，按合格入库加权）冲减订单成本 |
| 报废 | 不冲减 |
| 售后补发 | 补发订单的采购货款、开票成本、采购费用、运费和费用单都计入原订单成本；补发订单没结算时原订单也是「未结算」 |

订单详情的成本明细里有「售后退货冲减」，可以点到采购退货单或退货入库单；有补发时列出「售后补发」，可以点到补发订单。补发订单自己不算收入和毛利，也不计入销售统计、利润统计和经营统计的销售收入与订单数。

## 9. 管理员设置

- **退款申请审批**：系统管理 → 系统设置 →「退款申请需要审批」，默认关闭。打开后，业务员提交的申请先进「待审批」，由有「审批退款申请」按钮权限的人（默认只有租户管理员）在退款管理 → 退款申请页签通过或驳回，通过后才交财务。
- 菜单与权限：
  - 「售后管理」默认给有销售订单菜单的角色；「**销售管理 → 销售退货**」默认给有售后管理的角色；
  - 「退货入库」给有采购入库或采购订单菜单的角色，验收需要「退货验收」，处理去向需要「退货去向处理」；
  - 「**采购管理 → 采购退货**」和按钮「维护采购退货单」默认给有「退货去向处理」或「处理到货差异」按钮的角色；
  - 租户管理员默认都有。

## 10. 常见问题

**Q：客户只是咨询怎么用，要建售后单吗？**
建议建，等级选 S5 使用咨询，方便统计工作量；确认是产品故障后再调整等级，原记录保留。

**Q：换货怎么做？**
需要寄回旧货时先「发起退货」，再点「补发」生成补发订单，新货走正常的采购和出运；补发的成本计入原订单。用闲置库存直接补发暂不支持，请先照常走采购。

**Q：节假日期间售后单显示逾期怎么办？**
系统不识别节假日。放假前给客户说明进展并勾「已告知客户」，节后按实际情况更新；逾期提醒只是提醒，不影响任何操作。

**Q：供应商答应退款但钱还没到，怎么登记？**
在采购退货单上「完成」时填供应商同意的金额，应付和订单成本按这个金额冲减；采购订单已经付清的，差额成为供应商欠款，钱到账后财务在应付管理登记供应商退款。

**Q：退货退款为什么财务点不了「执行」？**
退款申请还在「待验收」，要等仓库验收退货入库单。确实需要先退钱的，在建退货单时勾「先退款」。

**Q：以前的退货单去哪了？**
升级时已经自动拆成销售退货单和退货入库单，退回供应商的去向和已处理的到货差异退货也补了已完成的采购退货单，订单成本、应付和待报销的数字不变。

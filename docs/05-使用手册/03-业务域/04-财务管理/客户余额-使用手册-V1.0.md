# 客户余额使用手册

> 文档版本：V1.0
> 适用版本：ver 1.4.0
> 面向角色：财务 · 业务员 · 老板 / 租户管理员
> 最近更新：2026-11-01

客户余额记录**暂存在公司的客户的钱**，有三个来源：

- **售后退款转余额**：质量问题等售后退款，不退现金，留作下一单抵扣；
- **代收款**：客户请我们在 PI 上多做一笔金额，收到后转回给客户；
- **多收**：客户付的钱超过 PI 合计的部分。

余额可以在**下一张 PI 上抵扣**，也可以**转给客户**（支付宝、银行等）。每一笔进出都记流水，月底能和银行流水、支付宝记录逐笔核对。

## 1. 余额管理页面

位置：**财务管理 → 余额管理**（财务角色默认有这个菜单）。

- 顶部四张卡片：各币种可用余额、已被 PI 占用、本月转给客户（含汇兑损益）。
- 「客户余额」页签：每行是一个**余额账户**（客户 + 币种，设置了事业部的再加事业部）。
  - **可用余额**：现在能用的钱；
  - **PI 占用中**：已经填在还没转订单的 PI 上的抵扣，已从可用余额扣除，关闭这张 PI 后退回；
  - **人民币价值**：可用余额的人民币，转入时锁定，之后结汇不再变。
- 点「流水」看这个账户的全部进出：时间、类型、金额、人民币价值、来源单据（可点开）、经办人。
- 客户详情页右侧也会显示这个客户的余额（只读）。

> 余额按事业部分开：在中国制造网事业部的余额，不能抵扣阿里事业部的 PI。

## 2. 售后退款转客户余额

位置：**财务管理 → 退款管理 → 登记退款**，或订单详情的退款入口。

1. 选订单、原因、金额。
2. 「去向」选 **转客户余额**：不需要上传凭证，人民币按这张订单现金收款的加权到账汇率折算并锁定。
3. 保存后客户余额增加，这张订单的毛利照样扣减（它仍是售后退款）。

**平台收款的订单**（信保、中国制造网）售后退款只能「原路退回平台」，另外两个去向不能选。

退款单作废时，转进余额的那笔会撤回；如果这笔余额已经被某张 PI 用掉，系统会提示被哪张 PI 占用，需要先调整那张 PI。

## 3. PI 上抵扣余额

位置：**销售管理 → 形式发票 → 编辑**。

1. 客户在 PI 的币种（和事业部）下有可用余额时，费用区下方出现 **用客户余额抵扣**，显示可用金额。
2. 填本次抵扣金额（或点「全部使用」）。不能超过可用余额，也不能超过「合计 − 代收款」。
3. **保存草稿就会占用**这笔余额，别的 PI 不能再用。
4. 合计区显示 **Less: Credit** 和 **Amount Due（应付）**；导出的 Excel / PDF / 图片在合计行下面同样多两行。
5. PI **发送后**，抵扣金额作为一笔「余额抵扣」计入已到账：客户付清应付金额，PI 就是「已到账」。
6. PI **关闭、作废或删除草稿**时，抵扣自动作废、余额退回。PI **过期不会自动释放**，需要关闭 PI。

余额抵扣记录不能在收款面板上单独作废，要改金额就修改 PI 出新版本。

**手动订单**（没有 PI 的订单）：在订单详情的收款卡片点 **抵扣客户余额**，填金额即可；作废这条记录或取消订单时余额退回。

## 4. 代收款

客户请我们在 PI 上多做一笔金额、收到后转回给他（比如转到他的支付宝）时：

1. 在 PI 的费用区加一行，**类型选「代收款」**，名称按给客户看的写（如 Other Charges）。导出时它就是一行普通费用，不出现「代收」字样。
2. 代收款计入 PI 合计（客户按合计付款），但**不计入销售额、净利润和毛利率**。
3. PI **收齐**后，系统自动把代收转入客户余额，并**扣掉客户承担的平台手续费**：
   代收承担的手续费 = 平台手续费合计 × 代收款 ÷ 合计。
   例：合计 USD 1,300（其中代收 300），信保手续费 39 → 代收承担 9，转入余额 291。
4. 收款面板显示「代收 USD X 已转入客户余额」和 **转给客户** 按钮，财务据此把钱转回客户（见第 6 节）。
5. 只部分到账时代收显示「待收齐」，不转入。代收已经转给客户后，那张 PI 的到账不能再作废。

## 5. 客户多付（待处理多收）

到账加手续费差额超过 PI（或手动订单）合计时，超出的部分叫**多收**：

- 多收**不算订单收入**；
- 出现在 **财务管理 → 收款管理 → 待处理多收**，订单 / PI 的收款面板也会提示「去处理」。

处理方式（需要「登记到账」权限）：

| 方式 | 做什么 |
|---|---|
| 转客户余额 | 多收转入客户余额，以后可抵扣或转给客户 |
| 退回客户 | 一步完成「转入余额 + 转给客户」，填实际转出人民币、方式和凭证 |

可以分几次处理，每次不超过剩余的多收。

## 6. 转给客户与汇兑损益

位置：**余额管理 → 某一行的「转给客户」**（需要「退款单维护」权限）。

1. 填转出金额（默认全部可用余额）、日期、转出方式（支付宝、微信、银行汇款等）、收款账户、**实际转出人民币**，上传转账截图。
2. 弹窗实时算出差额：**账面价值 − 实际转出**。差额自动记为「其他收入 · 汇兑损益」，正数是收益、负数是损失，为 0 时不生成。
3. 保存后生成一张 **余额提现** 退款单（不挂订单，不影响任何订单的利润），在退款管理里能看到、能作废；作废后余额恢复，汇兑损益一起作废。

系统生成的汇兑损益在其他收入页显示「系统生成」，不能手动修改或作废；手动登记其他收入时也不能选这个类别。

## 7. 手工调整与旧系统余额

位置：**余额管理 → 手工调整**（需要「调整客户余额」权限）。

- 用于把旧 ERP 里的客户余额录进来，或者更正。
- 金额正数为增加（要填人民币价值，按旧系统账面价值填），负数为减少（不能超过可用余额，人民币价值自动按先转入的先用）。
- **调整原因必填**；调整后不能修改，录错了再录一笔反向调整。

## 8. 月度核对

位置：**余额管理 → 月度核对**。

- 选月份（默认上月）、币种（和事业部），每个客户一行：期初、售后退款转入、代收转入、多收转入、调整、抵扣、提现、期末。每格上面是原币，下面是人民币。
- 「抵扣」= 本月占用 − 本月释放。
- 顶部显示「期初 + 转入 − 抵扣 − 提现 = 期末，已平衡」；不平衡时显示红色提示，请联系管理员。
- **导出 Excel** 与页面一致，用来对银行流水、支付宝转账记录。

## 9. 对利润和报表的影响

| 情况 | 订单收入 | 经营统计「退款」 | 其他收入 |
|---|---|---|---|
| 售后退款（现金或转余额） | 扣减 | 计入，悬停可看到其中转余额的金额 | — |
| 余额提现 | 不影响 | 不计入 | 汇兑损益 |
| 代收款 | 不算收入 | — | — |
| 多收 | 不算收入 | — | — |
| 余额抵扣 | 按锁定的人民币价值计入新订单收入 | — | — |

- 代收承担的平台手续费由客户承担，不计入订单成本。
- 余额抵扣不参与结汇，不出现在「收款记录」与报税统计中。
- 退款管理顶部分别汇总「售后退款（其中转客户余额）」和「余额提现」。

## 10. 上线前要做的事

**以前有多收的订单，上线后收入会减少多收的部分**，对应月份的经营统计随之变化。上线前由管理员在生产库运行只读脚本列出受影响的 PI 与订单，确认后再上线：

```
scripts/sql/customer-credit-overpaid-check.sql
```

清单列出单据、销售月份、多收金额和收入减少的人民币估算。上线后，这些多收会出现在「待处理多收」，财务按实际情况转余额或退回客户。

上线以前已经做过的代收（PI 上没有「代收款」标记）不追溯；如有旧系统余额，用「手工调整」录入。

## 11. 常见问题

**PI 过期了，余额还被占着？**
过期只是提醒，不改 PI 状态。确定客户不付款时关闭 PI，余额自动退回。

**为什么「PI 占用中」的 PI 已经付清了还显示？**
「PI 占用中」只看 PI 有没有转成订单。PI 转成订单后，这笔抵扣就不再显示为占用。

**余额的人民币价值和现在的汇率对不上？**
价值在转入时锁定（按当时的到账汇率），之后结汇不改它。转给客户时实际人民币与价值的差额记汇兑损益。

**可以把 USD 余额抵扣 EUR 的 PI 吗？**
不可以。余额按币种分开，只能抵扣同币种、同事业部的 PI 或订单。

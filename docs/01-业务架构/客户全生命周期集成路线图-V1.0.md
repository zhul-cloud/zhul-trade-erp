# 客户全生命周期集成路线图 V1.0

2026-11-03 定稿。依据：《Fouwell 客户全生命周期运营思维导图》和五份 SOP（客户主动开发、商机成交、订单履约、售后与评价、客户经营与复购，均为 v1.0）。

## 目标

业务围绕客户经营展开。系统要让业务员每天打开一个页面，就知道今天该跟谁、跟什么、怎么跟；SOP 在系统里指导业务员做事，而不是放在 Excel 里。

做法分两步：先把客户档案补完整，再做「客户跟进」工作台。

## 现状对照

| SOP 阶段 | 系统现状 | 缺口 |
| --- | --- | --- |
| 1 主动开发 D1–D7 | 没有；商机从 S1 开始 | 开发账户池、D 阶段、触达记录、培育与停止 |
| 2 商机成交 S1–S7 | 商机阶段与 SOP 一致；询盘、报价、PI、收款已打通 | 培育结果、下一步行动、到账自动赢单 |
| 3 订单履约 F1–F7 | 订单、采购、发货跟踪、入库、出库出运、客户收货都有 | 按 F1–F7 看进度的提醒视图 |
| 4 售后评价 A1–A7 | 售后单、时限提醒、退货、补发（A3、A4） | 签收确认、使用确认、满意度、邀请评价、案例沉淀 |
| 5 客户经营 G1–G7 | 客户档案（G2）正在做；等级为手工标记 | 分层依据、采购规律、复购提醒、交叉销售、战略客户 |

## 已定的原则

1. **客户是轴心**：商机、询盘、报价、订单、售后都挂在客户上，客户详情能看到全部往来。
2. **「客户跟进」工作台**（销售管理下的菜单）是业务员干活的地方，和左上角按角色的「工作台」看板分开。核心动作是「记一次跟进」：
   - 每次跟进记录渠道、内容、新信息、结果；
   - **下一步行动、日期、负责人必填**，这是 SOP 的硬规则；
   - 跟进内容里的新信息，由 AI 提取成档案字段建议，确认后写入档案。背调补一部分，跟进补一部分，档案越用越全。
3. **SOP 做成作战卡**：客户在哪个阶段，就显示那个阶段的目标、核心动作、Gate、常见场景 Playbook。
   - BAU 可以勾选，但不强制，主要用来辅导新人；
   - Gate 必须满足才能推进：能用数据判断的由系统判断，判断不了的由业务员确认；
   - Playbook 接现有技能，如价格异议处理、催单跟进、解读客户、英文回复；
   - SOP 内容在系统里维护，可以从 Excel 导入。
4. **赢单标准**：按 SOP，实际约定款项到账才算赢单。客户任一 PI 收款确认到账，商机**自动赢单**；业务员不能手动赢单（2026-11-04 调整，原为「收款到齐」）。
5. **两个评级分开**：
   - **潜力评级**：1–5 星，回答「值不值得跟」，所有客户都能评，可以采纳背调的综合评分；
   - **经营等级**：S / A / B / C，就是 SOP 的 G1 分层，只对成交过的客户。按《成交客户表》的 RFM 规则每天自动计算：
     - 综合分数 = 0.3 × 近度 + 0.4 × 频次 + 0.3 × 金额；
     - 业务员可以参考潜力上调或下调一级，必须写原因；
     - 等级决定建议跟进频率：S 7 天、A 14 天、B 30 天、C 60 天。
   
   两个评级都在 P0 实现。
6. **触发器生成待办**：
   - 新询盘进入 → S1 任务；
   - 报价发出后第 1、3、7、14 天提醒跟进，14 天后建议转培育（2026-11-04 调整，原为「3 天没回复」）；
   - PI 发出后按客户说的付款日期提醒，没有日期的每 2 天提醒；
   - 签收后 7 天 → 使用确认；
   - 90 天没有新商机 → 客户激活；
   - 距预计采购 30 天 → 复购提醒。
7. **主管 Review**：看逾期的下一步、在某阶段停留过久的对象、各阶段积压，并抽查跟进质量。

## 「客户跟进」工作台的结构（2026-11-04 原型定稿）

原型见 `docs/03-产品原型/03-业务域/03-销售管理/07-客户跟进/`（K1–K9 第一期，K10–K13 第二期），规格见 OpenSpec `customer-followup`、`customer-followup-fulfillment`。

1. **五板块链路**：页面顶部是「今日待办」卡片，加五个板块卡片：主动开发 → 商机成交 → 订单履约 → 售后评价 → 客户经营。
   - 卡片标「第 n 步」，用渐变箭头连成链路；
   - 下方进度轨道，末尾标「复购回到第 2 步」；
   - 每张卡片显示客户数、各阶段构成、逾期数。
2. **板块内按 SOP 阶段导航**：每个板块按自己的 SOP 阶段分组切换，例如商机成交分「报价前（S1–S3）/ 报价后（S4–S6）/ PI 后（S7）」，另有「培育中」。
   - 新客户跟商机阶段走；
   - 老客户的新需求走询盘，阶段按单据推导：询盘 S3、报价 S4、记跟进 S5/S6、PI S7。
3. **按客户价值分层排序**：所有跟进列表统一排序：
   - 先比经营等级（S→C，未成交在后）；
   - 再比潜力等级；
   - 再比金额档，金额取 PI 金额，没有取报价金额，再没有取询盘预估价值；分 20 万以上、5–20 万、1–5 万、1 万以下四档；
   - 最后逾期久的在前。

   今日待办先分「已逾期」「今天」两组，组内同样按价值排。
4. **记一次跟进**：粘贴聊天或邮件，AI 整理情况、卡点、下一步和档案补充，业务员核对后保存；勾选「客户给了反馈 / 在谈条件」自动推进到 S5/S6，发 PI 自动推进到 S7。
5. **客户详情**：主栏最上面加「跟进」分区（可收起 / 展开），显示当前阶段、下一步和跟进时间线；商机详情去掉手动赢单，输单原因用 SOP 卡点，默认转入培育。

## 分期

| 期 | 内容 | 状态 |
| --- | --- | --- |
| P0 | 客户档案（五个模块、多联系人、国家资料、系统推导、完整度、合并、潜力评级、RFM 经营等级）+ AI 背调（一键背调、上传报告、报告存档与导出、字段采纳、用量、档案补全） | 已合入 develop |
| P1 ① | 客户跟进框架 + 商机成交：五板块链路、今日待办、按价值排序、记一次跟进（AI 整理、档案补充）、SOP 作战卡、报价后与 PI 后提醒节奏、转培育、客户详情跟进分区、发 PI 自动推进 S7、收款到账自动赢单 | 已开发，待合入 develop（OpenSpec `customer-followup`） |
| P1 ② | 订单履约 F1–F6 + 售后评价 A1–A6：阶段从订单、采购、入库、出库、出运单据自动推导，履约节点提醒与异常，预计送达估算，签收 / 使用确认，「有问题」直接建售后单，满意度与邀请评价，售后结案「案例沉淀」；团队视图（本期结果、按负责人、卡在哪一步、需要主管看一眼） | 已开发，待走查（原型 K10–K13，OpenSpec `customer-followup-fulfillment`；依赖第一期先合入） |
| P1 ③ | 客户经营 G4–G7：成交客户自动进入需求挖掘，按历史订单推算采购规律，按经营等级间隔提醒联系，有新需求直接建询盘（复购机会），交叉销售建议，战略客户年度计划与季度回顾，沉睡标记与激活；团队视图增加老客户指标 | 已开发并走查，待合入 develop（原型 K14–K16，OpenSpec `customer-followup-account`；依赖第二期先合入） |
| P1 ④ | 主动开发 D1–D7：新建开发对象（查重后可直接加入已有客户）或从客户详情加入，阶段按潜力、背调结论、联系人、触达与回复自动推导；按潜力和背调优先级排序；触达序列第 1 / 4 / 9 / 16 天提醒，发完建议转培育或停止；记跟进的触达结果，明确拒绝接着停止开发；出现采购信号后转为商机；停止后可重新开发；团队视图增加开发指标 | 已开发并走查，待合入 develop（原型 K16–K18，OpenSpec `customer-followup-develop`；依赖第三期先合入） |

原 P2–P4 已并入 P1 ②–④（2026-11-04 调整）：先做商机成交，因为报价后和 PI 后的跟进最影响成交；主动开发放最后。

每一期开始时，按 OpenSpec 写提案，用 OpenPencil 出原型，确认后再开发。

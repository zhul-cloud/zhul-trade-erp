# 供应链全生命周期运营图与 SOP 制作注意事项

## 本次问题复盘

### 1. 底部内容被截断
原因：底部 Playbook、Trigger 区域最初按单列计算高度，但实际条目数量超过了单列可容纳的行数；文字继续绘制到模块边界之外，随后又被底部横条覆盖。

改进：

- 底部模块先统计条目数量，再决定单列或双列布局。
- 所有文字必须在模块内完成渲染，不能只依赖固定 y 坐标。
- 在输出前检查最后一行文字的 y 坐标是否小于模块底边。
- 底部模块与页脚之间预留安全间距，禁止重叠。

### 2. 图片看起来模糊
原因：第一版先以 1536×1024 的位图绘制，再进行放大。放大只能增加像素尺寸，不能恢复原始绘制时丢失的细节。

改进：

- 优先使用矢量源文件作为主文件。
- PNG/JPG 应从高分辨率画布直接输出，不能先低分辨率绘制再放大。
- 最终 PNG 建议至少 3072×2048；JPG 质量不低于 95。
- 输出后检查文字边缘、细线、图标和小字号内容，不只检查文件尺寸。

### 3. 与参考图版式不一致
原因：第一版把任务理解成“绘制供应链流程图”，只复用了业务内容，没有严格复刻参考图的版式结构、信息密度和模块层级。

改进：

- 先锁定参考图的结构：品牌区、标题区、五列主流程、阶段条目、关键目标、底部三块信息区、页脚。
- 只替换业务语义，不随意改变列数、比例、视觉层级和信息密度。
- 需要新增内容时，优先在现有模块内重排，不直接把内容堆到画布底部。

## 固定验收清单

- [ ] 图片尺寸符合要求，PNG/JPG 均可打开。
- [ ] 顶部标题、品牌区、五列主流程完整。
- [ ] 每列所有阶段条目都显示。
- [ ] 每列关键目标完整显示。
- [ ] Playbook、Trigger、KPI 三个底部模块的所有条目完整显示。
- [ ] 没有文字超出卡片边界、被页脚覆盖或相互重叠。
- [ ] 小字号文字在 100% 查看比例下仍可辨认。
- [ ] 图片与参考图的整体结构、列宽、间距和信息密度一致。
- [ ] Excel 的阶段、编码、字段、Gate 与图片保持一致。
- [ ] 交付前必须实际打开并目视检查最终 PNG/JPG，而不是只检查生成脚本成功。

## 后续制作原则

先确定内容数量和布局约束，再绘制；先生成高分辨率主文件，再导出 PNG/JPG；每次修改后重新进行完整视觉验收，不以“文件成功生成”作为完成标准。

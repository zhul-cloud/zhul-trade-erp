# 操作日志 PRD V1.0

> 文档版本：V1.0 | 创建日期：2026-05-29 | 产品：烛龙ERP（外贸业财一体化中台）

---

## 1. 功能概述

### 1.1 功能目标

操作日志模块记录系统内所有用户对业务数据的增删改操作轨迹，提供可追溯、可审计的操作记录查询能力。帮助系统管理员快速定位异常操作、追查数据变更来源，满足企业内控合规要求。

### 1.2 使用角色

| 角色 | 权限说明 |
|------|----------|
| 超级管理员 | 查看所有租户操作日志、导出 |
| 租户管理员 | 查看本租户下所有用户的操作日志、导出 |
| 普通管理员（具备日志查看权限） | 查看本租户操作日志、导出 |

> 操作日志为只读模块，任何角色均不可编辑或删除日志记录。

### 1.3 入口路径

```
顶部导航 → 系统管理 → 操作日志
菜单路由：/system/operation-log
```

## 2. 数据字段定义

底层数据表：`sys_log`（type = 2）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 主键ID | id | BIGINT | 是 | 自增主键 |
| 租户ID | tenant_id | VARCHAR(64) | 是 | 多租户隔离，由后端从 Token 注入 |
| 操作人工号 | operator_code | VARCHAR(64) | 是 | 操作人唯一标识 |
| 操作人姓名 | operator_name | VARCHAR(128) | 是 | 操作人显示名 |
| 操作时间 | operate_time | DATETIME | 是 | UTC 存储，前端按用户时区展示 |
| 操作模块 | menu | VARCHAR(128) | 是 | 功能模块名称，如"订单管理" |
| 操作名称 | operation | VARCHAR(128) | 是 | 具体操作描述，如"新增订单" |
| 操作内容 | content | JSON | 否 | 包含操作前（before）和操作后（after）的数据快照 |
| 操作结果 | result | TINYINT | 是 | 0=失败，1=成功 |
| 操作IP | ip | VARCHAR(64) | 是 | 客户端 IP 地址 |
| 日志类型 | type | TINYINT | 是 | 固定值 2（操作日志） |
| 创建时间 | created_at | DATETIME | 是 | 同 operate_time，UTC |
| 更新时间 | updated_at | DATETIME | 是 | 系统维护字段 |
| 删除标记 | deleted_at | DATETIME | 否 | 软删除，NULL 表示有效记录 |

### content 字段结构说明

```json
{
  "before": { /* 操作前数据快照，新增操作时为 null */ },
  "after":  { /* 操作后数据快照，删除操作时为 null */ },
  "params": { /* 额外请求参数（可选） */ }
}
```

## 4. 页面流程

```
用户进入 [操作日志列表页 OL-01]
         │
         ├─ 默认加载：当前租户最近 7 天操作日志（分页，20条/页，按操作时间降序）
         │
         ├─ [搜索区域]
         │       ├─ 输入/选择筛选条件
         │       ├─ 点击 [查询] → 重置分页至第1页，刷新表格数据
         │       └─ 点击 [重置] → 清空所有条件，恢复默认时间范围，刷新列表
         │
         ├─ [表格区域]
         │       ├─ 点击行操作列 [详情]
         │       │       └─ 打开 [操作详情弹窗 OL-02]
         │       │               ├─ 展示基本信息（操作人/时间/模块/结果/IP）
         │       │               ├─ 展示操作前 JSON（before）
         │       │               ├─ 展示操作后 JSON（after）
         │       │               └─ 点击 [关闭] → 关闭 Modal，回到列表
         │       │
         │       └─ 切换分页 / 切换每页条数 → 请求对应数据
         │
         └─ [导出按钮]
                 ├─ 点击 [导出 Excel]
                 ├─ 校验：当前筛选结果 > 50,000 条 → 拦截，提示缩小范围
                 └─ 通过校验 → 后端按当前筛选条件生成 xlsx → 浏览器下载
```

## 6. 异常与边界处理

| 场景 | 处理方式 |
|------|----------|
| 搜索结果为空 | 表格显示空状态，文案：「未找到符合条件的操作日志」 |
| 查询时间范围超过 90 天 | 允许查询，表格顶部显示 Warning：「查询范围较大（> 90天），可能影响响应速度」 |
| 导出数据超过 50,000 条 | 拦截请求，Toast 错误提示：「当前数据量超过5万条，请缩小查询时间范围后再导出」 |
| 导出请求超时（> 30s） | 提示「导出超时，请缩小范围重试」，按钮恢复可用 |
| 导出请求失败（服务端异常） | Toast 错误提示：「导出失败，请稍后重试」 |
| content JSON 格式损坏 | 详情弹窗降级显示原始字符串 + Warning Banner |
| content 字段为 null | 详情弹窗 JSON 区域显示灰色提示文字（见 5.2.3） |
| 网络请求失败（列表加载） | 表格区域显示「加载失败，请刷新重试」，含【重试】链接，点击重新发起请求 |
| 操作模块下拉接口失败 | 下拉显示空列表 + 错误提示「模块列表加载失败，请刷新页面」，不阻断列表页正常使用 |
| 无查看权限 | 路由守卫拦截，跳转至 403 页面 |
| 查询时间范围开始 > 结束 | DateRangePicker 组件自身校验阻止选择，不允许提交 |
| operate_time 无时区配置 | 按 UTC+8（中国标准时间）展示 |
| 日志数据超出保留期（已归档） | 列表顶部 Info Banner：「所选时间范围内部分数据已归档，当前仅显示在线数据」；查询结果正常返回热数据 |

## 7. 默认假设

1. **日志保留策略**：生产环境热存储保留不少于 15 天；超期日志由系统自动归档至冷存储，前端查询范围仅限热存储数据。
2. **分页默认值**：默认每页 20 条，可切换 20 / 50 / 100 条。
3. **权限隔离**：多租户场景下，tenant_id 由后端从 JWT Token 解析注入查询条件，前端不传递，防止越权访问其他租户数据。
4. **操作模块下拉**：从 sys_log 表的 menu 字段去重动态生成，不维护固定枚举，随系统模块增减自动更新。
5. **导出权限**：与查看权限相同，有查看权限即可导出，无需单独配置导出权限。
6. **操作日志写入**：由后端 AOP 切面自动拦截记录，前端无需关注写入逻辑。
7. **content 脱敏**：密码、Token、证件号等敏感字段在 AOP 写入 content 前由后端统一替换为 `***`，PRD 不涉及脱敏规则定义。
8. **默认查询时间**：页面初始化加载最近 7 天（当天 00:00:00 ~ 23:59:59），避免全量扫描导致性能问题。

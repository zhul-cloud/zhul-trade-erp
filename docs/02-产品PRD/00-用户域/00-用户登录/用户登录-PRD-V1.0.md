## 1. 功能概述

### 1.1 功能目标

为烛龙ERP多租户SaaS平台提供统一的身份认证入口，支持用户名+密码本地登录，实现"记住我"长效免登录、邮箱验证码找回密码、安全退出以及Token失效自动跳转，保障账户安全与用户体验。

### 1.2 使用角色

| 角色 | 说明 |
|------|------|
| 普通用户 | 租户内的业务操作人员，通过登录页进入系统 |
| 租户管理员 | 租户内的管理员账号，权限高于普通用户 |
| 平台超级管理员 | 跨租户管理，使用同一登录页，Token中携带特殊角色标识 |

### 1.3 入口路径

| 场景 | 路径 |
|------|------|
| 直接访问登录页 | `/login` |
| 访问需认证页面时未登录重定向 | `/login?redirect=<目标路径>` |
| Token失效后自动跳转 | `/login?redirect=<当前路径>&reason=token_expired` |
| 退出登录后跳转 | `/login?reason=logout` |

## 4. 页面流程

### 4.1 主登录流程

```
用户访问系统
      │
      ▼
 检查本地Cookie/SessionStorage中是否有 refresh_token
      │
   ┌──┴──┐
  有      无
  │        │
  ▼        ▼
POST /auth/refresh    显示登录页（P01）
  │                       │
  ├─成功─► 进入系统        │ 用户填写用户名+密码
  │                       ▼
  └─失败────────────► POST /auth/login
                          │
              ┌───────────┼────────────┐
              │           │            │
           成功        密码错误     账号异常
              │           │            │
              ▼           ▼            ├─禁用 → 弹禁用提示
        存储 Token    显示错误提示     └─锁定 → 弹锁定+解锁时间
        跳转目标页    累计失败次数
```

### 4.2 忘记密码流程

```
点击「忘记密码?」
      │
      ▼
  P02 输入账号和邮箱
      │
      ▼
  POST /auth/password/send-code
      │
  ┌───┴───┐
成功      失败（服务异常）
  │           │
  ▼           ▼
P03 输入6位验证码   显示错误提示，留在P02
      │
  POST /auth/password/verify-code
      │
  ┌───┴───┐
成功      失败（验证码错误/超时）
  │           │
  ▼           ▼
P04 设置新密码   显示"验证码错误"提示，可重新发送
      │
  POST /auth/password/reset
      │
  ┌───┴───┐
成功      失败（token已过期）
  │           │
  ▼           ▼
P05 重置成功    提示"链接已失效"，引导返回P02
3秒后跳转/login
```

### 4.3 Token失效自动跳转流程

```
前端发起任意API请求
        │
        ▼
   HTTP响应码 401
        │
        ▼
  本地是否有 refresh_token？
        │
   ┌────┴────┐
  有          无
   │           │
   ▼           ▼
POST /auth/refresh   清除本地凭证
   │                 跳转 /login?redirect=<当前路径>&reason=token_expired
  成功    失败
   │       │
   ▼       ▼
重放原请求  清除本地凭证
            跳转 /login?reason=token_expired
```

### 4.4 退出登录流程

```
点击顶部头像 → 「退出登录」菜单项
        │
        ▼
弹出 Modal 确认对话框
「确定要退出登录吗？」
        │
   ┌────┴────┐
 确定（危险色）  取消
   │               │
   ▼               ▼
POST /auth/logout  关闭对话框
   │
   ▼
清除本地 Token/Cookie/SessionStorage
跳转 /login（不带reason参数，静默跳转）
```

#### 5.1.5 交互细节

- 页面打开后自动聚焦用户名输入框。
- 密码框按回车键等同于点击登录按钮。
- 登录按钮点击后进入loading状态，同时禁用所有表单控件，防止重复提交。
- 请求结束（无论成功失败）后退出loading，恢复控件可用。
- 登录失败时密码输入框内容**保留**（不清空），焦点移至密码框便于重试。
- 登录成功后：
  - URL含`redirect`参数且为同域路径 → 跳转至对应路径。
  - URL含`redirect`参数但为跨域URL → 忽略，跳转`/dashboard`（防止开放重定向）。
  - URL不含`redirect` → 跳转`/dashboard`。
- `remember_me=true`：RefreshToken写入HttpOnly Cookie（名称`rft`；Secure；SameSite=Strict；MaxAge=604800秒）；AccessToken存内存变量（页面刷新后通过Cookie中的RefreshToken换取）。
- `remember_me=false`：AccessToken存SessionStorage（`akt`键）；Tab关闭后失效；无RefreshToken。
- URL含`reason=token_expired`时，卡片上方显示蓝色提示条："登录状态已过期，请重新登录"（可手动关闭）。
- URL含`reason=logout`时，不显示任何提示（静默）。

#### 5.3.1 整体布局


#### 5.3.3 交互细节

- 进入页面立即开始60秒倒计时（计算当前时间与发送时间差）。
- 6格全部填入后自动调用 `POST /auth/password/verify-code` 验证，无需手动点按钮（按钮作为备用入口）。
- 验证码错误：输入框整体加抖动动画（CSS keyframes shake）；清空全部格；聚焦第1格；显示红色错误提示文案"验证码错误，请重新输入"。
- 验证码过期（后端返回`RESET_TOKEN_EXPIRED`）：清空全部格；显示提示"验证码已过期，请重新发送"；重新发送按钮立即恢复可点击（忽略倒计时）。
- 验证成功后，将后端返回的`verify_token`存入sessionStorage（`fpVerifyToken`键），跳转P04。
- 点击"上一步"清除sessionStorage中的`fpUsername`，返回P02。

## 6. 异常与边界处理

| 场景 | 处理方式 | 提示文案 |
|------|----------|----------|
| 用户名或密码错误（fail_count < 4） | 显示红色Alert，fail_count+1 | "用户名或密码错误，还可尝试 N 次" |
| 用户名或密码错误（fail_count = 4，最后1次机会） | 显示橙色警告Alert，fail_count+1后锁定 | "用户名或密码错误，再失败1次账号将被锁定30分钟" |
| 连续失败5次，账号被锁定 | status=3，unlock_at=now+30min；显示红色Alert | "账号已被锁定，请于 HH:mm 后重试或联系管理员" |
| 账号锁定期间尝试登录 | 不校验密码，直接返回锁定提示，fail_count不累加 | "账号已被锁定，请于 HH:mm 后重试" |
| 锁定到期后首次登录 | 后端自动解锁（status=1，fail_count=0），正常登录 | 无 |
| 账号被禁用（status=2） | 返回禁用提示，记录登录日志 | "该账号已被禁用，请联系管理员" |
| 账号软删除（deleted_at非空） | 视为不存在，同密码错误处理 | "用户名或密码错误" |
| redirect参数为跨域URL | 忽略redirect，跳转/dashboard | 无 |
| 忘记密码-邮箱未绑定 | 不实际发送，统一显示发送成功提示（防枚举） | "如果该账号存在且邮箱匹配，验证码已发送，请查收" |
| 忘记密码-60秒内重复发送 | 接口返回错误，前端提示等待 | "发送过于频繁，请 N 秒后再试" |
| 验证码连续错误3次 | 当次reset_token作废，提示重新发送 | "验证码错误次数过多，请重新发送验证码" |
| 验证码10分钟超时 | 前端10分钟倒计时+后端验证双重保障 | "验证码已过期，请重新发送" |
| 设置新密码与原密码相同 | 后端校验，返回错误 | "新密码不能与原密码相同" |
| 重置密码时verify_token已过期 | 提示并引导重新发起 | "重置凭证已失效，请重新发起找回密码" |
| 并发重复提交登录请求 | idempotency_key去重，返回第一次结果 | 无 |
| refresh_token被服务端吊销 | 清除本地存储，跳转登录页 | "登录已过期，请重新登录" |
| Redis不可用（Token存储失败） | 登录接口返回503 | "服务繁忙，请稍后重试" |
| 页面从缓存恢复（bfcache）时Token已过期 | 监听visibilitychange事件，检测Token有效性 | 静默跳转登录页 |
| 无邮箱账号找回密码 | P02提示无法找回，引导联系管理员 | "该账号未绑定邮箱，请联系管理员重置密码" |

## 7. 默认假设

1. **多租户识别**：当前PRD假设通过子域名区分租户（`{tenant}.zhulongerp.com`）；平台超管使用固定域名 `admin.zhulongerp.com`。租户码输入方案作为备选，待架构确认后更新。

2. **HTTPS强制**：所有页面仅通过HTTPS提供服务，HTTP请求服务端301重定向至HTTPS，Cookie设置Secure标记。

3. **邮件服务依赖**：忘记密码功能依赖外部邮件服务商（如阿里云邮件推送）。邮件服务不可用时接口返回错误，用户看到"邮件发送失败，请稍后重试"提示，不影响正常登录功能。

4. **图形验证码**：V1.0版本不引入图形验证码，通过fail_count机制防御暴力破解；后续根据安全审计结果决定是否引入。

5. **SSO/第三方登录**：当前版本仅支持本地账号+密码，第三方登录（钉钉、企业微信、Google OAuth）预留扩展点，代码层面account.auth_type字段已有设计，不在本PRD实现范围。

6. **密码初始化**：新账号首次登录不强制修改密码（V1.0），后续可在用户管理PRD中增加"首次登录强制改密"功能开关。

7. **多设备同时在线**：同一账号可在多个设备同时保持登录状态，各设备Token相互独立；退出登录只吊销当前设备Token，不影响其他设备（管理员强制下线功能见系统监控PRD）。

8. **时区处理**：所有时间戳以UTC存储；页面展示时按用户配置的时区转换，默认使用浏览器本地时区。锁定解除时间提示格式为用户本地时区的"HH:mm"。

9. **浏览器兼容性**：支持Chrome 90+、Edge 90+、Safari 14+、Firefox 88+；不支持IE。

## 1. 功能概述

### 1.1 功能目标

为平台超级管理员提供系统运行状态的实时监控能力，涵盖三个维度：在线用户管理（查看当前会话、支持强制下线）、服务器资源监控（CPU / 内存 / 磁盘 / JVM）、缓存监控（Redis运行信息）。通过集中的监控视图辅助管理员快速判断系统健康状况、处置安全异常。

### 1.2 使用角色

| 角色 | 说明 | 权限范围 |
|------|------|----------|
| 平台超级管理员 | 唯一使用角色，通过 `admin.zhulongerp.com` 访问 | 可查看所有租户在线用户；可强制下线任意用户；可查看服务器与缓存信息 |

> 租户管理员不可访问系统监控模块，路由守卫校验角色后返回403。

### 1.3 入口路径

| 场景 | 路径 |
|------|------|
| 左侧菜单 → 系统监控 → 在线用户 | `/admin/monitor/online-users` |
| 左侧菜单 → 系统监控 → 服务器信息 | `/admin/monitor/server` |
| 左侧菜单 → 系统监控 → 缓存监控 | `/admin/monitor/cache` |

## 2. 数据字段定义

### 2.1 在线用户（来源：account_access_token + account + sys_log）

| 字段名 | 字段标识 | 类型 | 说明 |
|--------|----------|------|------|
| Token ID | `token_id` | BIGINT | account_access_token.id |
| 账号ID | `account_id` | BIGINT | 关联 account.id |
| 用户名 | `username` | VARCHAR(50) | account.username |
| 昵称 | `nickname` | VARCHAR(50) | account.nickname；无则显示"-" |
| 租户ID | `tenant_id` | BIGINT | account.tenant_id；0=超管 |
| 租户名称 | `tenant_name` | VARCHAR(100) | 关联租户表；超管显示"平台超管" |
| 登录IP | `login_ip` | VARCHAR(45) | account_access_token.login_ip |
| IP归属地 | `ip_location` | VARCHAR(100) | 通过IP库查询，离线库；无法解析时显示"-" |
| 登录时间 | `login_time` | DATETIME | account_access_token.created_at，UTC存储 |
| Token过期时间 | `expires_at` | DATETIME | account_access_token.expires_at，UTC存储 |
| 设备信息 | `device_info` | VARCHAR(200) | User-Agent摘要；格式"Chrome 120 / Windows 10" |
| 操作 | — | — | 强制下线按钮 |

### 2.2 服务器信息（来源：后端实时采集，Java OSHI库）

#### 2.2.1 CPU信息

| 字段名 | 字段标识 | 类型 | 说明 |
|--------|----------|------|------|
| CPU核心数 | `cpu_num` | INT | 逻辑核心数 |
| CPU型号 | `cpu_model` | STRING | 如"Intel(R) Xeon(R) CPU E5-2650" |
| 系统CPU使用率 | `cpu_sys` | DOUBLE | 系统占用百分比，保留1位小数，如12.5 |
| 用户CPU使用率 | `cpu_user` | DOUBLE | 用户进程占用百分比 |
| 等待CPU使用率 | `cpu_wait` | DOUBLE | IO等待占用百分比 |
| 空闲率 | `cpu_free` | DOUBLE | 空闲百分比 |

#### 2.2.2 内存信息

| 字段名 | 字段标识 | 类型 | 说明 |
|--------|----------|------|------|
| 总内存 | `mem_total` | LONG | 字节数，展示时转换为GB/MB |
| 已用内存 | `mem_used` | LONG | 字节数 |
| 剩余内存 | `mem_free` | LONG | 字节数 |
| 内存使用率 | `mem_usage` | DOUBLE | 百分比，保留1位小数 |

#### 2.2.3 JVM信息

| 字段名 | 字段标识 | 类型 | 说明 |
|--------|----------|------|------|
| JVM总内存 | `jvm_total` | LONG | 字节数 |
| JVM已用内存 | `jvm_used` | LONG | 字节数 |
| JVM剩余内存 | `jvm_free` | LONG | 字节数 |
| JVM最大内存 | `jvm_max` | LONG | -Xmx设置值，字节数 |
| JVM使用率 | `jvm_usage` | DOUBLE | jvm_used/jvm_max，百分比 |
| JDK版本 | `java_version` | STRING | 如"17.0.9" |
| JDK厂商 | `java_vendor` | STRING | 如"Eclipse Adoptium" |
| JVM启动时间 | `start_time` | STRING | 格式"2026-05-29 08:00:00"，服务器本地时区 |
| JVM运行时长 | `run_time` | STRING | 如"2天3小时15分钟" |
| JVM安装路径 | `java_home` | STRING | 如"/usr/local/jdk-17" |
| 主机名 | `host_name` | STRING | 服务器主机名 |
| 项目路径 | `user_dir` | STRING | 应用工作目录 |

#### 2.2.4 磁盘信息

| 字段名 | 字段标识 | 类型 | 说明 |
|--------|----------|------|------|
| 盘符路径 | `dir_name` | STRING | 如"/"，"/data" |
| 盘符类型 | `sys_type_name` | STRING | 如"ext4"，"xfs" |
| 文件类型 | `type_name` | STRING | 如"LocalDisk" |
| 总大小 | `total` | LONG | 字节数，展示转换为GB |
| 剩余大小 | `free` | LONG | 字节数 |
| 已用大小 | `used` | LONG | 字节数 |
| 使用率 | `usage` | DOUBLE | 百分比，保留1位小数 |

### 2.3 缓存监控（来源：Redis INFO命令）

| 字段名 | 字段标识 | 类型 | 说明 |
|--------|----------|------|------|
| Redis版本 | `redis_version` | STRING | 如"7.2.3" |
| 运行模式 | `redis_mode` | STRING | "standalone"或"cluster" |
| 操作系统 | `os` | STRING | Redis所在系统 |
| 架构位数 | `arch_bits` | STRING | "64"或"32" |
| 客户端连接数 | `connected_clients` | INT | 当前连接数 |
| 已用内存 | `used_memory_human` | STRING | 如"128.50M"（Redis原始格式） |
| 内存峰值 | `used_memory_peak_human` | STRING | 历史峰值 |
| 内存配置上限 | `maxmemory_human` | STRING | maxmemory配置值；0表示无限制 |
| 内存使用率 | `mem_usage` | DOUBLE | used/max百分比；maxmemory=0时不显示 |
| 内存碎片率 | `mem_fragmentation_ratio` | DOUBLE | 保留2位小数；>1.5时标橙 |
| AOF是否开启 | `aof_enabled` | STRING | "yes"/"no" |
| RDB上次保存 | `rdb_last_save_time` | STRING | 格式化本地时间 |
| Key总数 | `total_keys` | LONG | 所有DB的key数量之和 |
| 过期Key数 | `expired_keys` | LONG | 历史累计过期key数 |
| 命中次数 | `keyspace_hits` | LONG | 累计命中 |
| 未命中次数 | `keyspace_misses` | LONG | 累计未命中 |
| 命中率 | `hit_rate` | DOUBLE | hits/(hits+misses)，保留2位小数；无请求时显示"-" |
| 启动时长 | `uptime_in_days` | INT | Redis已运行天数 |
| TCP端口 | `tcp_port` | INT | Redis端口 |

### 2.4 Key详情（缓存监控子功能）

| 字段名 | 字段标识 | 类型 | 说明 |
|--------|----------|------|------|
| Key名称 | `key` | STRING | Redis Key的完整名称 |
| 数据类型 | `type` | STRING | string/hash/list/set/zset |
| 剩余TTL | `ttl` | LONG | 秒；-1=永不过期；-2=已过期 |
| 大小（字节） | `size_bytes` | LONG | 序列化后字节数（MEMORY USAGE命令） |

```

        │
        ▼

        ▼

   ┌────┴──────────────────────────┐
搜索/筛选/翻页                点击「强制下线」按钮
   │                               │
   ▼                               ▼
重新请求列表（带筛选参数）     弹出确认 Modal
                               「确定要将用户 XXX 强制下线吗？」
                                   │
                              ┌────┴────┐
                            确定        取消
                              │           │
                              ▼           ▼
                    DELETE /admin/monitor/online-users/{token_id}
                              │
                         ┌────┴────┐
                        成功      失败
                          │          │
                          ▼          ▼
                    列表自动刷新   message.error 提示

### 4.2 服务器信息自动刷新流程

```
进入服务器信息页（M02）
        │
        ▼
GET /admin/monitor/server（首次加载，显示Skeleton骨架屏）
        │
   ┌────┴────┐
  成功      失败
   │           │
   ▼           ▼
渲染各信息卡片   显示全屏错误状态+重试按钮
记录最后更新时间
        │
        ▼
根据用户选择的刷新间隔启动定时器（默认30秒）
        │
        ▼
每N秒 GET /admin/monitor/server
        │
   ┌────┴────┐
  成功      失败
   │           │
   ▼           ▼
更新数据     保留上次数据
更新时间戳   顶部显示黄色警告条
        │
        ▼
用户离开页面 → clearInterval，清除定时器
```

```

        │
        ▼

        │
        ▼

        │
        ▼

        │
        ▼

        │
        ▼

        │
        ▼
从右侧滑出 Drawer 展示 Key 详情

#### 5.1.7 自动刷新行为

- 页面进入时启动60秒倒计时自动刷新。

- 用户手动点击"立即刷新"后，重置倒计时为60秒。
- 用户离开页面时清除定时器。

## 7. 默认假设

1. **访问控制**：系统监控模块仅限平台超级管理员（tenant_id=0，role=SUPER_ADMIN）访问。后端API通过JWT Token中的角色字段鉴权；前端路由守卫作为第二道防线，两者均需校验。

2. **在线用户定义**：在线用户 = account_access_token表中满足 `deleted_at IS NULL AND expires_at > NOW()` 的记录；RefreshToken（remember_me=true产生）不单独计入在线用户数，只计AccessToken活跃会话。

3. **服务器信息采集**：后端使用OSHI库采集CPU/内存/磁盘/操作系统信息，JVM信息通过`Runtime.getRuntime()`和`java.lang.management.ManagementFactory`获取。采集在独立线程执行，接口响应SLA设为5秒。

4. **Redis Key列表安全**：V1.0 Key列表及详情仅提供只读查看，不提供修改/删除/TTL重置等写操作，防止误操作影响业务数据。

5. **Key内容展示**：Key内容如为Java序列化对象或加密数据，按原始字节字符串展示，不尝试反序列化或解密。展示内容截断为500字符，超出部分不传输到前端。

6. **IP归属地解析**：使用ip2region等离线IP库解析，不发出外部HTTP请求；库文件随应用打包，版本随应用升级周期更新；解析失败时显示"-"不影响其他功能。

7. **磁盘监控范围**：仅展示本地文件系统分区（Local FileSystem），过滤NFS/CIFS等网络挂载分区，避免因网络分区异常导致采集超时。

8. **自动刷新频率控制**：后端对监控接口做防频控，同一客户端调用间隔不得低于5秒，低于5秒时直接返回上次缓存数据（Redis缓存，TTL=5秒）。

9. **多实例部署**：服务器信息来自处理该请求的具体实例，多实例部署下每次刷新可能命中不同实例。V1.0不做实例聚合，在页面增加提示"数据来自当前负载均衡实例，多实例部署时每次结果可能不同"。Redis监控来自共享Redis，各实例数据一致。

10. **告警通知**：V1.0监控视图仅做视觉告警（颜色/图标标注），不集成邮件/短信/钉钉告警推送；告警通知功能列入后续迭代规划。

11. **时区处理**：所有时间戳在数据库存UTC；页面展示时按当前管理员浏览器本地时区转换显示；服务器JVM启动时间使用服务器本地时区（在接口响应中注明时区）。

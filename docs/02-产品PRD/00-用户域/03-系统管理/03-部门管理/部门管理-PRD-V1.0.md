# 部门管理 PRD V1.0

> 文档版本：V1.0 | 创建日期：2026-05-29 | 产品：烛龙ERP（外贸业财一体化中台）

---

## 1. 功能概述

### 1.1 功能目标

提供企业组织架构的树形可视化管理能力，支持多级部门的新增、编辑、删除与状态管理，为用户管理、岗位分配等模块提供部门数据支撑。

### 1.2 使用角色

| 角色 | 操作权限 |
|------|---------|
| 超级管理员 | 全部操作 |
| 租户管理员 | 全部操作（仅限本租户数据） |
| 普通管理员 | 查看（增删改权限视角色授权而定） |

### 1.3 入口路径

顶部导航 → 系统管理 → 部门管理（路由：`/system/department`）

## 2. 数据字段定义

### 2.1 部门表（department）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|---------|------|------|------|
| 主键 | id | BIGINT | 是 | 自增主键 |
| 租户ID | tenant_id | BIGINT | 是 | 多租户隔离，自动写入当前登录租户 |
| 部门编码 | dept_code | VARCHAR(32) | 是 | 系统自动生成，规则：DP + id（如 DP1001），租户内唯一 |
| 部门简称 | dept_name | VARCHAR(64) | 是 | 常用名称，如"销售一部"，同父节点下唯一 |
| 部门全称 | dept_full_name | VARCHAR(128) | 否 | 正式完整名称，如"国际贸易销售一部" |
| 上级部门ID | parent_id | BIGINT | 否 | NULL 表示顶级部门；外键关联 department.id |
| 祖先路径 | ancestors | VARCHAR(512) | 是 | 存储祖先ID链，如"0,1,5"，由后端维护，用于快速查询子孙节点 |
| 负责人用户ID | leader_user_id | BIGINT | 否 | 关联 sys_user.id |
| 负责人姓名 | leader_name | VARCHAR(64) | 否 | 冗余存储，减少关联查询 |
| 联系电话 | phone | VARCHAR(20) | 否 | 部门联系电话 |
| 排序号 | sort_order | INT | 是 | 同级部门排序，升序展示，默认 0 |
| 状态 | status | TINYINT | 是 | 0=禁用，1=启用；默认 1 |
| 备注 | remark | VARCHAR(256) | 否 | 部门描述或补充说明 |
| 创建人ID | created_by | BIGINT | 是 | 操作人用户ID |
| 创建时间 | created_at | DATETIME | 是 | UTC 时间 |
| 更新人ID | updated_by | BIGINT | 是 | 操作人用户ID |
| 更新时间 | updated_at | DATETIME | 是 | UTC 时间 |
| 删除时间 | deleted_at | DATETIME | 否 | 软删除标记，NULL 表示未删除 |

**索引规范：**
- `idx_tenant_parent`：(tenant_id, parent_id)
- `idx_tenant_code`：(tenant_id, dept_code)，唯一索引
- `idx_deleted_at`：(deleted_at)

**左侧部门树交互细节：**
- 使用 Ant Design `Tree` 组件，默认展开第一级。
- 搜索框实时过滤：匹配节点高亮，路径自动展开，无匹配时显示"未找到相关部门"。
- 禁用状态的部门节点名称变灰（color: #999），并在节点后附加标签`[禁用]`。
- 点击节点选中，再次点击不取消选中。

**右侧操作按钮规则：**

| 按钮 | 显示条件 | 权限控制 |
|------|---------|---------|
| 新增顶级部门 | 始终显示 | 有 `dept:add` 权限 |
| 新增子部门 | 选中树节点后显示 | 有 `dept:add` 权限 |
| 编辑 | 选中树节点后显示 | 有 `dept:edit` 权限 |
| 禁用/启用 | 选中树节点后显示，文本随状态切换 | 有 `dept:edit` 权限 |
| 删除 | 选中树节点后显示 | 有 `dept:delete` 权限 |

### 5.2 新增 / 编辑部门弹窗

**弹窗规格：** 宽度 560px，居中展示，遮罩不可关闭（需点击按钮）。

**表单布局：** 单列，Label 右对齐，宽度 80px。

| 字段 | 组件类型 | 必填 | 校验规则 |
|------|---------|------|---------|
| 上级部门 | TreeSelect | 否 | 新增子部门时自动回填并只读；编辑时可修改但不可选自身及子孙节点 |
| 部门简称 | Input | 是 | 1~64字符；同一父节点下不可重名 |
| 部门全称 | Input | 否 | 最多128字符 |
| 负责人 | Select（远程搜索） | 否 | 输入2字符后触发搜索，按姓名/工号匹配本租户有效用户 |
| 联系电话 | Input | 否 | 允许数字、+、-、空格，最多20字符 |
| 排序号 | InputNumber | 是 | 整数，范围0~9999，默认0 |
| 状态 | RadioGroup | 是 | 启用 / 禁用，默认启用 |
| 备注 | TextArea | 否 | 最多256字符，显示字符计数 |

**编辑模式额外展示：**
- 部门编码：只读 Input，灰色背景，展示系统生成的编码值。

**底部按钮：** [取消]（普通）[确定]（Primary）

### 5.3 删除确认弹窗

触发：点击"删除"后，前端先请求 `GET /api/dept/{id}/check-delete`。

| 检查项 | 命中时的提示（Toast Error） |
|--------|--------------------------|
| 存在子部门 | "该部门下存在子部门，请先删除或迁移子部门后重试" |
| 存在关联用户 | "该部门已分配 N 名用户，请先移除关联用户后重试" |

通过检查后弹出 Confirm：
- 标题："确认删除"
- 内容："确认删除部门「{dept_name}」？此操作不可撤销。"
- 按钮：[取消] [确认删除]（danger 样式，红色）

## 6. 异常与边界处理

| 场景 | 错误码 | 处理方式 |
|------|--------|---------|
| 同父节点部门名称重复 | `DEPT_NAME_DUPLICATE` | 表单"部门简称"字段行内报错"同级部门名称已存在" |
| 删除有子部门的节点 | `DEPT_HAS_CHILDREN` | 前端预检阻断；后端兜底返回此错误码，Toast 提示 |
| 删除已关联用户的部门 | `DEPT_HAS_USERS` | 前端预检阻断；后端兜底返回此错误码，Toast 提示 |
| 编辑时将上级部门设为自身 | `DEPT_CIRCULAR_REFERENCE` | 前端 TreeSelect 过滤不可选项；后端兜底校验 |
| 部门层级超过10级 | `DEPT_MAX_DEPTH_EXCEEDED` | 新增按钮置灰并 Tooltip 提示"已达最大层级（10级）限制" |
| 禁用部门时该部门下有启用用户 | — | 允许禁用，弹窗警告"该部门下存在 N 名在职用户，禁用后这些用户的部门信息将不可通过该部门筛选，请确认" |
| 并发提交（重复点击确定） | — | 提交后按钮置 loading 状态，防止重复请求 |
| 接口超时/网络错误 | — | Toast 提示"网络请求失败，请稍后重试"，Modal 不关闭 |
| 无任何部门数据 | — | 左侧树显示空状态插图+"暂无部门数据"，右侧显示"新增顶级部门"引导按钮 |
| 无操作权限 | `FORBIDDEN` | 操作按钮不渲染或置灰；接口返回403时 Toast 提示"无操作权限" |

## 7. 默认假设

1. 同一租户内部门编码全局唯一，跨租户数据完全隔离。
2. 部门编码由后端在记录插入后回填（`DP` + 自增 ID），前端不参与生成，编辑界面只读展示。
3. 负责人候选范围：本租户内 `status=1` 且 `deleted_at IS NULL` 的用户。
4. `ancestors` 字段完全由后端维护；移动部门（修改 parent_id）时，后端递归更新该节点及其全部子孙节点的 ancestors。
5. 禁用部门不级联禁用子部门；但禁用状态的部门不允许再新增子部门。
6. 删除操作为软删除（写入 `deleted_at`），所有查询接口默认过滤 `deleted_at IS NOT NULL` 的记录。
7. 所有 DATETIME 字段后端存储 UTC，前端按用户浏览器时区转换显示，格式 `YYYY-MM-DD HH:mm`。
8. 本 PRD 不涵盖部门与角色的授权绑定，该功能由角色管理模块负责。
9. 树节点排序规则：同级按 `sort_order` 升序，`sort_order` 相同时按 `created_at` 升序。

## 1. 功能概述

### 1.1 功能目标

为租户管理员提供对本租户内用户账号的全生命周期管理能力，包括用户创建、信息维护、权限角色分配、状态控制（启用/禁用）及密码重置，确保人员权限与组织结构保持一致。

### 1.2 使用角色

| 角色 | 操作范围 | 说明 |
|------|----------|------|
| 租户管理员（super_admin） | 全部操作 | 可管理本租户所有用户 |
| 系统管理员（sys_admin） | 全部操作（除修改自身角色） | 由租户管理员授权 |

### 1.3 入口路径

顶部导航 → 系统管理 → 用户管理
路由：`/system/users`

### 5.1 P-USR-01 用户列表页

**布局：**

```
+--------------------------------------------------------------+
| 面包屑：系统管理 / 用户管理                                   |
+--------------------------------------------------------------+

+--------------------------------------------------------------+
| [+ 新增用户]                              右上角：刷新按钮    |
+----+------+------+------+------+------+------+--------------+
|序号|用户  |用户名|手机号|部门  |角色  |状态  |操作          |
|    |编码  |      |      |      |      |      |              |
+----+------+------+------+------+------+------+--------------+
| 1  |DP000 |admin |138...|销售部|销售员|启用  |详情|编辑|    |
|    |001   |      |      |      |      |      |重置密码|禁用 |
+----+------+------+------+------+------+------+--------------+
| 2  |...   |...   |...   |...   |...   |禁用  |详情|编辑|    |
|    |      |      |      |      |      |      |重置密码|启用 |
+----+------+------+------+------+------+------+--------------+
|  共 XX 条记录                    每页 20 v   < 1 2 3 ... >  |
+--------------------------------------------------------------+
```

**搜索栏组件：**
- 姓名：Input，模糊匹配（LIKE %keyword%）
- 手机号：Input，精确匹配
- 部门：TreeSelect，展示部门树，选择父部门时包含全部子部门用户
- 状态：Select，选项：全部 / 启用 / 禁用

**表格列说明：**
- 序号：当前页内自动序号（非全局ID）
- 用户编码：DP+数字，点击可复制到剪贴板
- 姓名：文字链接，点击打开详情抽屉（P-USR-04）
- 用户名：账号登录名
- 手机号：中间4位脱敏展示（138\*\*\*\*8888）
- 部门：显示直属部门名称，多级路径用 `/` 分隔
- 角色：多角色用逗号分隔，超出一行则显示省略号，hover显示完整列表Tooltip
- 状态：Tag组件，启用=绿色，禁用=灰色
- 操作列：详情、编辑、重置密码、禁用（启用状态时显示）/启用（禁用状态时显示）

**交互细节：**
- 列表默认按 created_at 倒序排列
- 搜索点击搜索按钮触发，不实时查询
- 操作列宽度固定180px
- 禁用状态行整行背景色使用浅灰（#FAFAFA）
- 分页默认每页20条，可切换10/20/50/100

### 5.2 P-USR-02 新增用户抽屉

**抽屉宽度：** 480px，从右侧滑入

**布局：**

```
+------------------------------------+
| 新增用户                    [x关闭]|
+------------------------------------+
| 基本信息                           |
| 姓名 *     [________________]      |
| 用户名 *   [________________]      |
| 手机号 *   [________________]      |
| 邮箱       [________________]      |
| 部门       [部门树选择       v]    |
| 岗位       [________________]      |
|                                    |
| 权限设置                           |
| 角色       [多选角色         v]    |
| 状态 *     (*)启用  ( )禁用        |
|                                    |
| 账号安全                           |
| 初始密码 * [________________] [眼] |
| 确认密码 * [________________] [眼] |
| 密码强度:  [===弱===]              |
|                                    |
+------------------------------------+
|              [取消]  [确认创建]    |
+------------------------------------+
```

**字段校验规则：**
- 姓名：必填，2-64字符
- 用户名：必填，4-32字符，字母开头，仅允许字母/数字/下划线，blur时调用 `GET /api/system/users/check-username` 校验唯一性
- 手机号：必填，正则 `/^1[3-9]\d{9}$/`，blur时调用接口校验唯一性
- 邮箱：选填，合法邮箱格式，blur时校验唯一性（若已填写）
- 部门：TreeSelect，可选任意层级
- 岗位：选填，最长64字符，纯文本
- 角色：MultiSelect，仅展示本租户内状态为启用的角色
- 初始密码：必填，8-32字符，至少含1个大写字母、1个小写字母、1个数字，右侧显示/隐藏切换，密码强度实时显示
- 确认密码：必填，须与初始密码完全一致，blur时触发比对

**提交逻辑（接口：POST /api/system/users）：**
1. 前端校验全部通过后，提交按钮置灰防重复点击
2. 后端事务：创建 user_basic → 创建 account → 创建 account_local_auth（BCrypt哈希） → 批量插入 account_role
3. 成功：抽屉关闭，列表刷新第一页，顶部显示 Message "用户创建成功"
4. 失败：抽屉保持打开，显示具体错误信息，提交按钮恢复

### 5.3 P-USR-03 编辑用户抽屉

**标题：** "编辑用户 - {real_name}"

与新增抽屉相同布局，差异点：
- 用户编码只读展示于标题下方（灰色文本）
- 用户名字段：展示为只读文本，不可编辑
- 不显示"账号安全"分区（初始密码/确认密码）
- 手机号、邮箱编辑后校验唯一性时需排除当前用户（`exclude_id` 参数）
- 角色变更：展示当前已分配角色，支持增删

**提交逻辑（接口：PUT /api/system/users/{id}）：**
1. 后端事务：更新 user_basic → 差量更新 account_role（删除移除的，插入新增的）
2. 成功：抽屉关闭，列表刷新当前页，显示"用户信息已更新"

### 5.5 P-USR-05 重置密码弹窗

**弹窗宽度：** 400px

**布局：**

```
+----------------------------------+
| 重置密码 - 张三            [x]   |
+----------------------------------+
| 新密码 *    [__________________] |
| 确认密码 *  [__________________] |
|                                  |
| ! 重置后该用户将被强制下线，      |
|   下次登录使用新密码             |
+----------------------------------+
|                   [取消] [确认]  |
+----------------------------------+
```

**校验规则：** 与新增用户密码字段一致（8-32字符，含大小写字母+数字）

**提交逻辑（接口：POST /api/system/users/{id}/reset-password）：**
- 请求携带 `idempotency_key`（UUID，前端生成）
- 后端：更新 account_local_auth.password_hash，记录 last_changed_at
- 使该账号所有 Session/JWT Token 失效（Token版本号机制）
- 成功：弹窗关闭，显示"密码已重置"

### 5.6 P-USR-06 禁用/启用确认弹窗

**禁用弹窗文案：**
- 标题：确认禁用用户
- 内容：确认禁用用户「张三」？禁用后该用户将立即无法登录，所有在线会话将被终止。
- 按钮：[取消] [确认禁用]（红色）

**启用弹窗文案：**
- 标题：确认启用用户
- 内容：确认启用用户「张三」？启用后该用户可正常登录使用系统。
- 按钮：[取消] [确认启用]（蓝色）

**提交逻辑：**
- 禁用：`PUT /api/system/users/{id}/disable`，同步将 account.status=0，清除在线 Session
- 启用：`PUT /api/system/users/{id}/enable`，同步将 account.status=1

## 6. 异常与边界处理

| 场景 | 处理方式 | 用户提示 |
|------|----------|----------|
| 用户名已存在 | blur实时校验 + 提交时后端再次校验 | "用户名已被使用，请更换" |
| 手机号已存在 | blur实时校验 | "该手机号已注册，请更换" |
| 邮箱已存在 | blur实时校验 | "该邮箱已被使用，请更换" |
| 禁用唯一管理员 | 后端拦截，前端提示 | "无法禁用，系统至少保留1名可用管理员" |
| 密码强度不足 | 前端实时校验，提交时再次校验 | 密码强度条提示 + 具体要求说明 |
| 两次密码不一致 | 确认密码 blur 时校验 | "两次输入的密码不一致" |
| 分配不存在的角色 | 后端返回400 | "所选角色不存在或已被删除，请刷新后重试" |
| 编辑已删除用户 | 后端返回404 | "用户不存在或已被删除" |
| 并发重复提交 | 提交按钮置灰 + idempotency_key | 后端返回相同成功响应，前端正常处理 |
| 网络异常/超时 | 通用错误处理 | "操作失败，请检查网络后重试" |
| 无权限访问 | 后端返回403，前端拦截 | "您没有权限执行此操作" |
| 用户有进行中业务被禁用 | 仅提示警告，不阻断操作 | 弹窗内增加黄色警告"该用户有进行中的业务单据，请确认" |

## 7. 默认假设

1. 本期仅覆盖**本地账号**（account_type=1），第三方OAuth账号不在范围内。
2. 用户删除采用软删除（设置 deleted_at），不提供物理删除入口。
3. 用户编码（DP+6位数字）由后端自动生成，管理员不可手动指定。
4. 初始密码由管理员设置并口头告知用户，系统本期不发送邮件/短信通知（后续迭代）。
5. 重置密码通过 Token 版本号机制强制踢出所有在线会话。
6. 角色选择器仅展示本租户内**状态为启用**的角色。
7. 部门树最深5级，由业务侧约束。
8. 手机号脱敏：前3位 + `****` + 后4位；邮箱脱敏：@前保留前2字符 + `***` + @domain。
9. 列表不展示已软删除用户。
10. 所有时间存储为UTC，页面展示时转换为当前用户的本地时区（东八区默认）。

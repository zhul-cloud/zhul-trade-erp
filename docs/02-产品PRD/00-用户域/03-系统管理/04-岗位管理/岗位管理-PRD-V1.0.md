# 岗位管理 PRD V1.0

> 文档版本：V1.0 | 创建日期：2026-05-29 | 产品：烛龙ERP（外贸业财一体化中台）

---

## 1. 功能概述

### 1.1 功能目标

提供企业岗位的统一维护能力，支持岗位的增删改查、启用/禁用管理。岗位作为用户的职能标签，用于权限分配和业务流程中的职责识别（如审批节点的岗位匹配）。

### 1.2 使用角色

| 角色 | 操作权限 |
|------|---------|
| 超级管理员 | 全部操作 |
| 租户管理员 | 全部操作（仅限本租户数据） |
| 普通管理员 | 查看（增删改权限视角色授权而定） |

### 1.3 入口路径

顶部导航 → 系统管理 → 岗位管理（路由：`/system/position`）

## 2. 数据字段定义

### 2.1 岗位表（position）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|---------|------|------|------|
| 主键 | id | BIGINT | 是 | 自增主键 |
| 租户ID | tenant_id | BIGINT | 是 | 多租户隔离，自动写入当前登录租户 |
| 岗位编码 | position_code | VARCHAR(32) | 是 | 手动填写，租户内唯一；大写字母+数字+下划线，2~32字符 |
| 岗位名称 | position_name | VARCHAR(64) | 是 | 岗位展示名称，如"销售经理"，租户内唯一 |
| 排序号 | sort_order | INT | 是 | 列表展示排序，升序，默认 0 |
| 状态 | status | TINYINT | 是 | 0=禁用，1=启用；默认 1 |
| 备注 | remark | VARCHAR(256) | 否 | 岗位说明或补充信息 |
| 创建人ID | created_by | BIGINT | 是 | 操作人用户ID |
| 创建时间 | created_at | DATETIME | 是 | UTC 时间 |
| 更新人ID | updated_by | BIGINT | 是 | 操作人用户ID |
| 更新时间 | updated_at | DATETIME | 是 | UTC 时间 |
| 删除时间 | deleted_at | DATETIME | 否 | 软删除标记，NULL 表示未删除 |

**索引规范：**
- `idx_tenant_code`：(tenant_id, position_code)，唯一索引
- `idx_tenant_name`：(tenant_id, position_name)，唯一索引
- `idx_tenant_status`：(tenant_id, status)
- `idx_deleted_at`：(deleted_at)

## 5. 页面详细说明

### 5.1 岗位列表页

**整体布局：**

```
+-------------------------------------------------------------+
| 面包屑：系统管理 / 岗位管理                                   |
+-------------------------------------------------------------+
| 搜索区                                                       |
|  岗位名称: [____________]  状态: [全部 v]  [搜索] [重置]      |
+-------------------------------------------------------------+
| 工具栏                                                       |
|  [+ 新增岗位]                                                |
+--------+------------+------+------+----------+-------------+
| 岗位编码| 岗位名称   | 排序 | 状态 | 创建时间  | 操作        |
+--------+------------+------+------+----------+-------------+
| MGR001 | 销售经理   |  1   | 启用 |2026-01-01| 编辑 禁用 删除|
| STF001 | 销售专员   |  2   | 启用 |2026-01-02| 编辑 禁用 删除|
| PUR001 | 采购主管   |  3   | 禁用 |2026-01-05| 编辑 启用 删除|
+-------------------------------------------------------------+
|                        共 12 条    < 1 2 >  每页 10 条       |
+-------------------------------------------------------------+
```

**搜索栏：**
- 岗位名称：Input，支持模糊匹配（LIKE %keyword%）。
- 状态：Select，选项：全部 / 启用 / 禁用。
- 点击[搜索]触发查询，回到第1页。
- 点击[重置]清空所有搜索条件并重新查询。

**列表表格列定义：**

| 列名 | 字段 | 说明 |
|------|------|------|
| 岗位编码 | position_code | 文本展示 |
| 岗位名称 | position_name | 文本展示 |
| 排序 | sort_order | 数字展示 |
| 状态 | status | Badge：启用（绿色）/ 禁用（灰色） |
| 创建时间 | created_at | 格式 YYYY-MM-DD HH:mm，用户时区 |
| 操作 | — | 编辑 / 禁用（或启用） / 删除，文字链接样式 |

**分页：** 默认每页10条，支持切换每页条数（10/20/50）。

**操作列权限控制：**
- 无 `position:edit` 权限时，"编辑"和"禁用/启用"链接不渲染。
- 无 `position:delete` 权限时，"删除"链接不渲染。

---

### 5.2 新增 / 编辑岗位弹窗

**弹窗规格：** 宽度 480px，居中展示，遮罩不可关闭。

**表单字段：**

| 字段 | 组件类型 | 必填 | 校验规则 |
|------|---------|------|---------|
| 岗位编码 | Input | 是 | 大写字母、数字、下划线，2~32字符；租户内唯一；编辑时只读 |
| 岗位名称 | Input | 是 | 1~64字符；租户内唯一 |
| 排序号 | InputNumber | 是 | 整数，范围 0~9999，默认 0 |
| 状态 | RadioGroup | 是 | 启用 / 禁用，默认启用 |
| 备注 | TextArea | 否 | 最多256字符，显示字符计数器 |

**编辑模式：** 岗位编码字段只读（灰色背景），其余字段可修改。

**底部按钮：** [取消]（默认）[确定]（Primary）

**提交逻辑：**
- 前端校验通过后 loading 锁定确定按钮，防止重复提交。
- 成功：关闭 Modal → Toast 提示"新增成功" / "编辑成功" → 刷新列表（保持当前搜索条件和页码）。
- 失败：Modal 不关闭，Toast 显示后端错误信息。

---

### 5.3 禁用 / 启用操作

- 点击"禁用"：弹出气泡确认（Popconfirm）：
  - 内容："确认禁用岗位「{position_name}」？禁用后该岗位不可被分配给新用户。"
  - 按钮：[取消] [确认]
- 点击"启用"：弹出气泡确认：
  - 内容："确认启用岗位「{position_name}」？"
  - 按钮：[取消] [确认]
- 确认后调用 `PATCH /api/position/{id}/status`，成功则刷新当前行，无需整页刷新。
- 若该岗位下有在职用户，禁用时 Popconfirm 额外提示："当前有 N 名用户持有此岗位，禁用后新建用户将无法选择此岗位，已分配用户不受影响。"

---

### 5.4 删除确认弹窗

**触发流程：**
1. 点击"删除"，前端请求 `GET /api/position/{id}/check-delete`。
2. 接口返回该岗位关联的有效用户数量。

| 检查结果 | 处理方式 |
|---------|---------|
| 关联用户数 > 0 | Toast Error："该岗位已分配 N 名用户，请先解除关联后再删除"，流程终止 |
| 关联用户数 = 0 | 弹出 Confirm Modal |

**Confirm Modal：**
- 标题："确认删除"
- 内容："确认删除岗位「{position_name}」（编码：{position_code}）？此操作不可撤销。"
- 按钮：[取消] [确认删除]（danger 样式，红色）

## 6. 异常与边界处理

| 场景 | 错误码 | 处理方式 |
|------|--------|---------|
| 岗位编码重复 | `POSITION_CODE_DUPLICATE` | 表单"岗位编码"行内报错"岗位编码已存在" |
| 岗位名称重复 | `POSITION_NAME_DUPLICATE` | 表单"岗位名称"行内报错"岗位名称已存在" |
| 岗位编码格式不合法 | — | 前端实时校验，行内提示"编码仅支持大写字母、数字和下划线，长度2~32位" |
| 删除已关联用户的岗位 | `POSITION_HAS_USERS` | 前端预检阻断；后端兜底校验，Toast Error 提示 |
| 禁用已关联用户的岗位 | — | 允许操作，Popconfirm 中额外展示警告信息 |
| 并发重复提交 | — | 提交后按钮 loading，接口响应后恢复 |
| 接口超时/网络错误 | — | Toast 提示"网络请求失败，请稍后重试" |
| 列表无数据 | — | 表格空状态："暂无岗位数据，点击「新增岗位」创建" |
| 搜索无结果 | — | 表格空状态："未找到符合条件的岗位" |
| 无操作权限 | `FORBIDDEN` | 操作按钮不渲染；接口返回 403 时 Toast 提示"无操作权限" |

## 7. 默认假设

1. 岗位编码在同一租户内全局唯一，跨租户不做约束。
2. 岗位编码一经创建不可修改（编辑时只读），保证外部系统引用的稳定性。
3. 同一用户可同时拥有多个岗位（多对多关系，中间表 user_position）。
4. 岗位与部门无强绑定关系，部门和岗位是用户的两个独立属性维度。
5. 删除操作为软删除（写入 `deleted_at`），已删除岗位在用户管理的岗位选择下拉中不展示。
6. 禁用岗位后，已分配该岗位的用户数据不受影响（历史数据保留），但新建/编辑用户时禁用岗位不出现在可选项中。
7. 列表默认按 `sort_order` 升序，`sort_order` 相同时按 `created_at` 升序。
8. 所有 DATETIME 字段后端存储 UTC，前端按用户时区转换显示，格式 `YYYY-MM-DD HH:mm`。

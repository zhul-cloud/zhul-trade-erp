## 一、功能概述

**功能目标：** 维护成交客户和重点跟进客户的档案，作为报价单、形式发票（PI）、商业发票（CI）、装箱单（PL）、订单与应收的统一客户数据来源。档案中的交易条件与单证信息在后续单据中自动带出，减少业务员重复录入和单据抬头写错的风险。

**与小满的分工：** 线索开发、日常跟进、公海流转仍在小满完成；本系统的客户档案面向"要开始做单"的客户，重点是单据和财务需要的结构化信息（见第七节默认假设）。

**使用角色：**
- 业务员：维护自己负责的客户
- 业务主管：查看、维护本部门业务员负责的客户，可转移负责人
- 管理员：查看、维护全部客户

**入口路径：** 客商管理 → 客户管理（`/partner/customers`）

## 二、数据字段定义

字段按使用场景分为五组。标 ★ 的为必填；"单据"列标 ✓ 的字段会打印在报价单 / PI / CI 等对外单据上，**必须使用英文**。

### 2.4 默认交易条件

报价单、PI、合同创建时自动带出，**可在单据上修改**，不作为强制约束。

| 字段名 | 字段标识 | 类型 | 必填 | 单据 | 说明 |
|--------|---------|------|------|------|------|
| 默认币种 | currency | 枚举 | ★ | ✓ | USD / EUR / GBP / JPY / CNY，默认 USD（后续接入币种主数据） |
| 贸易术语 | incoterm | 枚举 | | ✓ | Incoterms 2020：EXW / FCA / FOB / CFR / CIF / CPT / CIP / DAP / DPU / DDP |
| 术语地点 | incoterm_place | 文本 | | ✓ | 与贸易术语配套的港口或地点，如 FOB **Shanghai**、CIF **Hamburg**，最长 100 字符；选了贸易术语时必填 |
| 付款方式 | payment_method | 枚举 | | ✓ | T/T 全额预付 / T/T 定金 + 发货前付尾款 / T/T 定金 + 见提单副本付尾款 / L/C 即期 / L/C 远期 / D/P / D/A / O/A 赊销 / 其他 |
| 定金比例（%） | deposit_ratio | 数字 | | ✓ | 0–100 的整数；付款方式为"T/T 定金 + …"时必填 |
| 账期（天） | payment_days | 数字 | | ✓ | 0–365 的整数；付款方式为 L/C 远期、D/A、O/A 时必填 |
| 信用额度 | credit_limit | 金额 | | | 非负，两位小数（HALF_UP）；**与"信用额度币种"成对保存**，只填其一时不允许保存 |
| 信用额度币种 | credit_currency | 枚举 | | | 默认与默认币种相同 |
| 运输方式 | shipping_method | 枚举 | | | 海运整柜 / 海运拼箱 / 空运 / 国际快递 / 铁路 / 陆运 |
| 目的港 | destination_port | 文本 | | ✓ | 最长 100 字符（港口主数据上线前为文本） |

**说明：**
- 信用额度当前**只做记录，不做占用和超限拦截**；应收模块上线后启用额度管控，届时按当日汇率折算本位币比较
- 交易条件修改只影响之后新建的单据，已生成的单据不回写

| 城市 | city | 文本 | | 最长 100 字符 |
| 邮编 | postcode | 文本 | | 最长 20 字符 |
| 详细地址（英文） | address | 文本 | ★ | 最长 300 字符 |
| 联系人 | contact_name | 文本 | | 最长 100 字符 |
| 电话 | phone | 文本 | | 国际格式，同 2.3 |
| 邮箱 | email | 文本 | | Email 格式 |
| 税号 | tax_id | 文本 | | 进口国清关要求的税号，最长 50 字符 |

## 三、数据权限与负责人

客户按"负责业务员"划分可见范围，复用系统管理 → 角色上已有的「数据权限范围」配置：

| 角色的数据权限范围 | 可以看到、维护的客户 |
|------|------|
| 仅本人 | 负责业务员是自己的客户 |
| 自定义（指定部门） | 负责业务员属于这些部门的客户，加上自己负责的客户 |
| 全部 | 全部客户 |

- 列表、详情、编辑、删除、导出、询盘里的客户选择器都按此范围过滤；越权访问详情地址时提示"客户不存在或无权查看"
- **新增**：负责业务员默认是自己；数据权限为"自定义"或"全部"的人可以指定为范围内的其他业务员
- **转移负责人**：单条或批量，需要「转移客户」按钮权限，只能转给自己数据范围内的业务员；转移记录写入操作日志（原负责人、新负责人、操作人、时间）
- **业务员离职**：由主管或管理员批量转移，本期不做自动回收（公海规则仍在小满）
- **查重（撞单提示）**：新增或改名时，按"客户名称 + 国家"做规范化比较（忽略大小写、空格、标点和 Co. / Ltd. / GmbH / Inc. 等公司后缀）。命中已有客户时**阻止保存**，并提示"该客户已存在，负责业务员：张三"；如果对方客户不在自己的数据范围内，也只显示负责人姓名，不展示客户详情

## 六、页面详细说明

### 6.1 客户列表页

**① 页面标题区**：标题「客户管理」，说明「维护成交客户与重点跟进客户的档案，报价单、PI、CI 从这里带出客户信息。」面包屑：客商管理 / 客户管理

**② 筛选区**（多行网格，查询 + 重置放在最后一行右侧）
- 客户编码：文本，模糊
- 客户名称：文本，同时匹配英文名称、中文名称、简称，模糊
- 国家/地区：下拉，可搜索
- 客户角色：下拉
- 客户等级：下拉（A / B / C / 未分级）
- 客户来源：下拉
- 负责业务员：下拉，**仅数据权限为"自定义"或"全部"时显示**
- 状态：下拉

**③ 操作行**：左侧「共 N 条记录」；右侧「新增客户」（主按钮）、「导入」（本期置灰，悬停提示"批量导入即将上线"）、「导出」

**④ 数据表格**

| 列名 | 宽度 | 说明 |
|------|------|------|
| 复选框 | 40px | 批量操作 |
| 序号 | 64px | 当前页序号 |
| 客户编码 | 120px | |
| 客户名称 | 240px | 英文名称（加粗）+ 下方中文名称（弱色），超长省略，悬停显示全称 |
| 国家/地区 | 130px | 中文名 |
| 客户角色 | 110px | 标签 |
| 等级 | 70px | A 绿 / B 蓝 / C 橙 / 未分级 灰 |
| 客户来源 | 120px | 文本 |
| 负责业务员 | 100px | 姓名 |
| 主联系人 | 200px | 姓名 + 下方邮箱 |
| 状态 | 80px | 开关；禁用前确认「禁用后该客户将无法在新的询盘、报价、订单中被选择，已有单据不受影响。」 |

- 分页：默认 10 条，可选 10 / 20 / 50
- **批量操作条**（勾选后出现）：「已选 N 条」+「批量转移」+「批量删除」+「取消选择」

### 6.2 新增 / 编辑客户页面

独立页面，五张分组卡片，双列布局，底部吸底操作栏（取消 / 保存）：

1. **基本信息**：客户编码、客户名称（英文）★、中文名称、客户简称、客户角色 ★、应用行业、官网、客户等级、客户来源、负责业务员 ★、小满客户编号、状态 ★、备注（跨两列）
2. **注册地址与税务**：国家/地区 ★、州/省、城市、邮编、详细地址（英文，跨两列）、税号、时区（选择国家后自动带出，可改）
3. **主联系人**：联系人姓名、职位、邮箱、电话、WhatsApp、其他联系方式
4. **默认交易条件**：默认币种 ★、贸易术语、术语地点、付款方式、定金比例、账期、信用额度 + 信用额度币种（同一行）、运输方式、目的港
   - 定金比例、账期按付款方式显示或隐藏：选"T/T 定金 + …"才出现定金比例；选 L/C 远期、D/A、O/A 才出现账期
5. **收货与单证信息**：按类型分三组（收货人 / 通知方 / 发票抬头）展示卡片列表，每张卡片显示公司名、国家、地址摘要和"默认"标记；「新增」打开右侧抽屉填写 2.5 的字段；卡片上有「设为默认」「编辑」「删除」
   - 提供「从注册信息复制」按钮：把客户英文名称、注册地址、税号、主联系人一键填入抽屉，适合收货人就是客户本身的情况

**校验与提交：**
- 失焦时校验，错误显示在字段下方；提交时有两处及以上错误，在页顶显示可点击的错误汇总
- 英文字段（客户名称、各处英文地址、单证公司名）只允许 ASCII 可打印字符，输入中文时提示"单据字段请使用英文"
- 查重命中：客户名称字段下提示"该客户已存在，负责业务员：张三"
- 编码重复：编码字段下提示"客户编码已存在，请更换"
- 成功：新增提示"新增客户成功"并返回列表；编辑提示"保存成功"并返回来源页面（列表或详情）
- 取消：有未保存修改时确认"确认离开？当前填写内容将不会保存。"

**编辑页差异：**
- 客户编码只读，带锁形图标，提示"创建后不可修改"
- 负责业务员在编辑页只读，改负责人走「转移」（保证留有转移记录）
- 底部显示创建人、创建时间、最后修改人、最后修改时间

### 6.3 客户详情页面

单页分组卡片，只读：
- 顶部：客户名称（英文）大标题 + 中文名称 + 等级、角色、状态标签；右上角「返回」「编辑」「转移」（按权限）
- 卡片：基本信息 / 注册地址与税务（国家旁显示"当地时间 14:32"）/ 主联系人（邮箱、电话、WhatsApp 可点击直接发起）/ 默认交易条件（显示为一句话摘要，如"USD · FOB Shanghai · T/T 30% 定金 + 见提单副本付尾款"）/ 收货与单证信息 / 系统信息
- 未填写的字段显示「—」

### 6.4 转移负责人弹窗

- 标题：单条「转移客户」/ 批量「批量转移 N 个客户」
- 内容：当前负责人（批量时显示"多个"）、新负责人（下拉，只列数据范围内的在职业务员）、转移原因（选填，最长 200 字符）
- 确认后提示"已转移给李四"，列表刷新；如果新负责人不在自己的数据范围内（例如仅本人权限转出后），该客户从当前列表中消失

### 6.5 删除确认弹窗

- 单条：「确认删除客户「[英文名称]（[客户编码]）」吗？删除后不可恢复。如只是暂停合作，建议改为禁用。」
- 批量：「确认删除已选的 N 个客户吗？」；有被引用的客户时跳过，结果提示"已删除 X 个，Y 个已有询盘或单据记录，不能删除，可改为禁用"
- 删除为软删除

## 七、单据取数规则

后续报价单 / PI / CI / 装箱单 / 提单创建时，按下表从客户档案带出默认值（均可在单据上修改）：

| 单据字段 | 取数来源 |
|------|------|
| 买方（Buyer）名称、地址、税号 | 默认「发票抬头」；没有发票抬头时取客户英文名称 + 注册地址 + 税号 |
| 收货人（Consignee） | 默认「收货人」；没有时同买方 |
| 通知方（Notify Party） | 默认「通知方」；没有时打印 `SAME AS CONSIGNEE` |
| 币种、贸易术语及地点、付款方式、定金比例、账期 | 2.4 默认交易条件 |
| 目的港 | 收货人上的目的港，其次 2.4 的目的港 |
| 买方联系人、电话、邮箱 | 2.3 主联系人 |

**信用证订单例外**：信用证项下提单的收货人常为 `TO ORDER` 或 `TO ORDER OF [开证行]`，按信用证条款在单证模块填写，不取客户档案。

## 八、异常与边界处理

| 场景 | 处理方式 |
|------|---------|
| 客户编码重复 | 编码字段下提示「客户编码已存在，请更换」 |
| 客户名称 + 国家与已有客户重复 | 阻止保存，提示「该客户已存在，负责业务员：[姓名]」 |
| 英文字段输入了中文 | 字段下提示「单据字段请使用英文」 |
| 选了贸易术语但没填术语地点 | 提示「请填写术语地点，如 FOB 的装运港」 |
| 付款方式要求定金比例 / 账期但未填 | 对应字段提示必填 |
| 信用额度与币种只填了一个 | 提示「信用额度需要同时填写金额和币种」 |
| 单证信息超过 20 条 | 「新增」按钮置灰，提示「每个客户最多 20 条单证信息」 |
| 删除已被询盘、报价、订单引用的客户 | 不允许删除，提示「该客户已有询盘或单据记录，不能删除，可改为禁用」 |
| 访问数据范围外的客户 | 提示「客户不存在或无权查看」，提供返回列表 |
| 转移给数据范围外的业务员 | 下拉中不出现；接口层同样拦截 |
| 询盘等场景快速创建客户 | 只要求英文名称和国家；客户角色记为"未设置"、负责业务员为创建人、默认币种 USD，其余可以之后在客户管理补全 |
| 导出 | 按当前筛选和数据权限导出，上限 5000 条，超出提示缩小范围 |
| 网络异常 | 表格区域显示「加载失败」+ 重试 |
| 无操作权限 | 对应按钮不显示 |

## 九、默认假设（请核对）

- **与小满的关系**：小满仍是线索开发、跟进、公海的主系统；本系统客户档案在"开始做单"时建立，暂不与小满同步，只预留「小满客户编号」字段。如需从小满批量导入或接口同步，另行立项
- **联系人**：本版本每个客户一个主联系人；多联系人等联系人管理模块上线时迁移
- **客户等级**：手工标记，订单模块上线后改为自动计算
- **信用额度**：属于限额配置而非交易金额，只保存原币金额和币种，不存本位币；应收模块使用时按当日汇率折算
- **删除规则与现状不同**：目前系统允许删除已被询盘引用的客户（历史询盘不受影响）；本版改为"已被引用不允许删除，只能禁用"，需要同步调整现有删除接口
- **查重规则**：以"规范化名称 + 国家"判重并阻止保存；现有询盘快速创建中的"同名提示、可选复用或仍然新建"改为同样的阻止规则，命中时引导选择已有客户
- **数据权限**：复用角色上已有的「数据权限范围」配置，客户是第一个按它实际过滤的业务数据
- **枚举值**：客户角色、应用行业、客户来源、付款方式、运输方式的选项为首版，建议后续转为字典维护
- **单证子表**：收货人 / 通知方 / 发票抬头放在客户档案内维护，不单独建菜单

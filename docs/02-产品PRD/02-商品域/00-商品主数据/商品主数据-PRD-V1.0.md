## 1. 功能概述

### 1.1 功能目标

建立统一的商品档案（品牌、品类、系列、商品、规格、型号关系、技术资料、应用场景、FAQ、图片视频、物流、海关、平台参考价），让询盘、报价、采购、订单以及独立站引用**同一个商品标识**，而不是各自存一份自由文本的"品牌 + 型号"。

背景：询盘明细里的品牌、品类、型号目前都是自由文本，同一个商品会有多种写法（如 `6ES7 214-1BD23-0XB0` 与 `6ES7214-1BD23-0XB0`），无法跨询盘、跨供应商、跨订单聚合。

两条已确认的原则：

- **商品单层**：一个「品牌 + 型号」= 一个商品，不设 SPU/SKU。系列只是品牌下的可选分组，不是 SKU 层。
- **平台共享**：所有租户共用一份商品库，由平台统一维护。

### 1.2 使用角色

| 角色 | 说明 |
|------|------|
| 平台管理员 | 具备商品维护权限码、且属于平台账号（`tenantId=0`，已确认，见 design.md 决策 2）的用户；维护品牌、品类、系列、商品及其规格/型号关系 |
| 租户用户（业务员/采购员） | 只读：查询、选择商品；在询盘等业务里引用 |

### 1.3 入口路径

| 场景 | 路径 |
|------|------|
| 品牌列表 | `/product/brands` |
| 品类列表 | `/product/categories` |
| 系列列表 | `/product/series` |
| 商品列表 | `/product/products` |
| 商品档案（详情/编辑） | `/product/products/:id`，可带 `?focus=` 直接滚动到某张卡片：`info` / `media` / `specs` / `logistics` / `customs` / `price` / `relations` / `documents` / `applications` / `faq` |
| 新建商品（5 步向导） | `/product/products/new` |

### 1.4 范围

**做：** 品牌、品类、系列、商品的增删改查与启停；规格参数；型号关系（替代/兼容/交叉引用）；型号去重；商品选择器组件；从独立站 `js/data.js` 一次性迁移；技术资料、应用场景、FAQ（FAQ 含发布审核）；图片与视频（可上传）、物流、海关、平台参考价；新建商品 5 步向导；档案完整度与缺项快捷筛选。

**不做：**

- 各租户自己的采购价、售价、库存、成色、MOQ、交期（属租户级数据，见 design.md 决策 3、Q1）；平台共享的参考价在范围内
- 独立站 SEO 发布字段（`seo_slug`/`index_status`/`page_tier`）
- BOM、组合商品、图片视频的批量上传（一次上传一个文件）
- 技术资料文件的上传与存储（本模块只保存文件地址）
- 新建向导草稿的服务端保存与跨设备同步（草稿只存在当前浏览器，见第 8 节）
- 卖家自己的质保、库存、发货、联系方式类 FAQ（属租户级内容，不进平台共享表，见 design.md 决策 12）
- 询盘明细关联商品的改造（本期只提供接口，改造另起 OpenSpec change）

## 2. 数据字段定义

> 技术字段（`id`/`tenant_id`/`deleted_at`/审计字段）不重复列出。所有表 `tenant_id` 固定为 0。

### 2.9 FAQ（`product_faq`）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 商品 | `product_id` | BIGINT | 是 | |
| 问题 | `question` | VARCHAR(256) | 是 | 同一商品下不可重复（忽略大小写和首尾空格） |
| 答案 | `answer` | TEXT | 是 | 纯文本。只描述商品本身，**不含卖家自己的质保、库存、发货、联系方式承诺** |
| 来源 | `source` | TINYINT | 是 | 见 3.5；管理员手动新增恒为 2 |
| 审核人 / 审核时间 | `reviewed_by` / `reviewed_at` | VARCHAR(32) / DATETIME | 系统生成 | 待审核 FAQ 被确认时填写 |
| 排序 | `sort_order` | INT | 否 | |

**`source=3` 的 FAQ 只有平台管理员看得到**，租户用户读不到，由服务端过滤；管理员确认后才对所有租户可见。

### 2.10 图片与视频（`product_media`）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 商品 | `product_id` | BIGINT | 是 | |
| 媒体类型 | `media_type` | TINYINT | 是 | 1-图片、2-视频 |
| 文件地址 | `file_url` | VARCHAR(512) | 是 | 上传后由系统生成站内路径；外链只允许 `http://`、`https://` 或单个 `/` 开头 |
| 存储方式 | `storage_type` | TINYINT | 系统生成 | 1-平台上传、2-外部链接 |
| 视频封面 | `cover_url` | VARCHAR(512) | 否 | 仅视频使用，地址规则同文件地址 |
| 标题 | `title` | VARCHAR(128) | 否 | 图片时同时作为替代文字 |
| 来源 | `source` | VARCHAR(128) | 否 | 如 Manufacturer Website |
| 是否主图 | `is_main` | TINYINT | 是 | 0-否、1-是；仅图片可为主图，同一商品最多一张 |
| 文件大小 | `file_size` | BIGINT | 系统生成 | 字节，仅上传时记录 |
| 排序 | `sort_order` | INT | 否 | |

上传限制：图片仅 `jpg`、`jpeg`、`png`、`webp` 且不超过 5MB；视频仅 `mp4`、`webm` 且不超过 100MB。系统同时校验扩展名和文件头，两者不一致的文件一律拒绝，SVG 一律拒绝；保存时不使用客户端提供的文件名。设某张图片为主图时，原主图自动取消。商品列表的缩略图取主图，没有主图时显示品类占位图。

### 2.11 物流信息（`product_logistics`）

一个商品最多一份，整体保存。重量固定为 kg、尺寸固定为 mm。

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 净重 | `net_weight_kg` | DECIMAL(10,3) | 否 | kg |
| 毛重 | `gross_weight_kg` | DECIMAL(10,3) | 否 | kg，含包装；填写时不得小于净重 |
| 单品长 / 宽 / 高 | `length_mm` / `width_mm` / `height_mm` | DECIMAL(10,1) | 否 | mm |
| 包装类型 | `package_type` | VARCHAR(32) | 否 | 如 盒装、箱装、托盘 |
| 包装长 / 宽 / 高 | `package_length_mm` / `package_width_mm` / `package_height_mm` | DECIMAL(10,1) | 否 | mm |
| 每包装件数 | `package_quantity` | INT | 否 | |
| 是否危险品 / 限运品 | `is_dangerous` | TINYINT | 是 | 0-否（默认）、1-是；含电池等 |
| 运输备注 | `shipping_note` | VARCHAR(255) | 否 | 如 需防潮、含锂电池 |

所有数值必须大于 0；未填写显示为空，**不是 0**。

### 2.12 海关信息（`product_customs`）

一个商品最多一份，整体保存。

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| HS 编码 | `hs_code` | VARCHAR(10) | 否 | 去掉点和空格后须为 6–10 位数字，只存数字；一个商品一个 |
| 申报品名（中 / 英） | `customs_name_cn` / `customs_name_en` | VARCHAR(128) | 否 | |
| 默认原产国 | `origin_country` | CHAR(2) | 否 | ISO 3166-1 两位大写国家码，如 DE、CN |
| 申报要素 | `declaration_elements` | VARCHAR(500) | 否 | |
| 监管条件 | `supervision_conditions` | VARCHAR(32) | 否 | 监管条件代码，如 A、B |
| 出口退税率 | `export_rebate_rate` | DECIMAL(5,2) | 否 | %，0–100；政策会调整，以最近一次维护为准 |

**原产国是默认值**：同一型号不同批次可能产自不同国家，实际以货物单据为准，界面上要写明。

### 2.13 平台参考价（`product_reference_price`）

一个商品最多一份。**这是平台层面的参考价，不是任何租户的报价或售价**；各租户自己的采购价和售价不在本模块。

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 参考价（原币） | `price_original` | DECIMAL(18,2) | 是 | 必须大于 0 |
| 币种 | `currency_code` | CHAR(3) | 是 | ISO 4217，如 USD；金额必须带币种 |
| 汇率 | `exchange_rate` | DECIMAL(18,6) | 系统生成 | 原币→本位币 CNY；币种为 CNY 时为 1；保留 6 位 |
| 参考价（本位币） | `price_cny` | DECIMAL(18,2) | 系统生成 | 保存时由原币与汇率计算，HALF_UP 保留 2 位；汇率未维护时为空，界面显示"未计算"，**不是 0** |
| 价格来源 | `price_source` | VARCHAR(128) | 否 | 如 厂商官网目录价、eBay 参考价 |
| 取价日期 | `price_date` | DATE | 否 | |

本位币金额只在保存时按当时汇率计算，不随汇率变化自动重算；界面同时显示所用汇率。
### 2.14 档案完整度（计算值，不落库）

每个商品有 10 个模块，满足条件的模块记为完成，**完整度 = 已完成模块数 / 10**。它只用来提示"还缺什么"，**不阻止创建、启用或被引用**。

| # | 模块 | 视为完成的条件 | 在哪里补 |
|---|------|----------------|----------|
| 1 | 基本信息 | 品牌、型号、品类已填（创建时即完成） | 新建向导 / P05「基本信息」 |
| 2 | 图片视频 | 至少 1 张图片，且已设主图 | P05「图片与视频」 |
| 3 | 规格参数 | 至少 1 条 | P05「规格参数」 |
| 4 | 物流 | 净重或任一尺寸已填 | P05「物流与海关」 |
| 5 | 海关 | HS 编码已填 | P05「物流与海关」 |
| 6 | 参考价 | 已填写 | P05「平台参考价」 |
| 7 | 型号关系 | 至少 1 条 | P05「型号关系」 |
| 8 | 技术资料 | 至少 1 条 | P05「技术资料」 |
| 9 | 应用场景 | 至少 1 条 | P05「应用场景」 |
| 10 | FAQ | 至少 1 条**已确认**（待审核的不算） | P05「FAQ」 |

- 完整度**只对平台账号显示**，租户用户看不到。
- 展示方式：10 段进度条，一段对应一个模块；列表里 8 段及以上为绿色，其余为强调色（蓝）；档案页的大进度条用蓝到青的渐变。缺项清单按上表顺序排列，点击直达对应卡片，并标注预计用时。
- 列表的快捷筛选（缺图片 / 缺物流 / 缺海关 / 缺参考价）就是模块 2、4、5、6 未完成的商品。

## 3. 状态与枚举

### 3.1 数据状态 `status`

0-禁用、1-启用。禁用后：商品选择器不再出现，已有业务单据里的历史引用仍可正常展示。

### 3.2 生命周期 `lifecycle_status`

| 值 | 含义 | 说明 |
|----|------|------|
| 1 | 在产 Active | |
| 2 | 现行 Current | |
| 3 | 旧款 Legacy | |
| 4 | 已停产 Discontinued | 必须填生命周期依据 |
| 5 | 停产无替代 Obsolete | 必须填生命周期依据 |
| 6 | 未知 Unknown | 默认值 |

生命周期是**事实描述，不是流程**：任意值之间可切换，不设状态机。是否有替代型号查型号关系表判定，不在本字段重复建模。若设为 5 但存在关系类型 1/2/3 的记录，保存时给出**警告**（不阻止）。

### 3.3 关系类型 `relationship_type`

| 值 | 含义 | 是否对称 |
|----|------|----------|
| 1 | 官方直接替代 Direct Replacement | 否 |
| 2 | 厂商后续型号 Manufacturer Successor | 否 |
| 3 | 功能性替代 Functional Alternative | 是 |
| 4 | 兼容 Compatible | 是 |
| 5 | 交叉引用 Cross Reference | 是 |
| 6 | 同系列 Same Series | 是 |

### 3.4 置信度 `confidence`

1-已验证、2-高、3-中、4-低、5-未知。置信度为 4/5 的关系，下游展示不得使用"推荐替代"这类强断言。

### 3.5 FAQ 来源 `source`

| 值 | 含义 | 谁能看到 |
|----|------|----------|
| 1 | 品类通用模板生成 | 所有租户 |
| 2 | 人工撰写，或待审核 FAQ 经人工确认 | 所有租户 |
| 3 | AI 辅助生成，待审核 | 仅平台管理员 |

审核确认只适用于来源为 3 的 FAQ，确认后来源变为 2，并记录审核人和审核时间；修改 FAQ 内容不改变来源。批准后无法再区分"曾由 AI 起草"，只保留审核痕迹。

## 5. 页面流程

### 5.1 新建商品（5 步向导，含去重与草稿）

入口：P04 的「新建商品」→ `/product/products/new`。向导占满整页（没有侧栏），顶部是步骤条：型号 → 分类 → 图片 → 补充资料 → 完成。**只有前 2 步是必须的**，第 3、4 步可以跳过。

| 步骤 | 问什么 | 必填 | 说明 |
|------|--------|------|------|
| 1 认识这个商品 | 品牌、型号 | 是 | 见下"去重" |
| 2 选分类 | 品类（6 选 1）、系列、生命周期 | 品类必填 | 系列只列所选品牌下已有的，可就地新建；生命周期默认"未知"。**点「创建并继续」时创建商品** |
| 3 上传图片 | 主图 | 否 | 规则同 M09；可跳过 |
| 4 补充资料 | 产品名称、规格摘要、简介；物流、海关、参考价折叠为"稍后补充" | 否 | 按钮为「完成」 |
| 5 完成 | — | — | 显示完整度和 4 张"下一步"卡片 |

**为什么在第 2 步创建**：图片、资料都要挂在一个已存在的商品下，所以第 3、4 步是对已创建商品的补充。中途退出不会丢内容，商品和已保存的资料都在。

**第 1 步的去重**：
1. 选好品牌并输入型号（停止输入 300ms 或失焦），前端调用匹配接口，用归一化型号查同品牌下是否已有商品。
2. 命中且未删除 → 型号框变红"已存在"，下方给出该商品卡和"查看这个商品"，"下一步"置灰。
3. 命中且**已被软删除** → 型号框变橙"曾被删除"，主操作为"恢复这个商品"，不允许新建。
4. 未命中 → 型号框变绿"可以新建"，显示归一化结果；同时列出同品牌下最多 3 个相近型号（前缀匹配），提示"确认不是同一个"。
5. 后端在创建时再次校验（唯一键兜底，防并发）；若此时才发现重复，停留在第 1 步并给出同样的"已存在"提示。

**草稿**：第 1、2 步的输入自动保存在**当前浏览器**（右上角显示"草稿已自动保存"）。刷新、关闭标签页后再进入，提示"继续上次未完成的新建？6ES7…"。商品创建后草稿即清除。第 3、4 步的内容点"下一步"时保存到商品。

**退出**：点左上角关闭时，若第 1、2 步有未创建的输入，提示"草稿已保存，确定离开？"；已创建的商品直接离开。

### 5.2 停用 / 删除商品

1. 管理员点"停用"：二次确认，`status` 置 0。
2. 点"删除"：后端先检查是否被业务单据引用。
   - 有引用 → 拒绝，提示"已被 N 处引用，请改为停用"。
   - 无引用 → 二次确认后软删除。
3. 已删除的商品可在列表筛选"已删除"后恢复。

### 5.3 维护型号关系

1. 在 P05 的"型号关系"卡片点"添加关系"，打开 M05。
2. 可以"从商品库选择"（同时写 `related_mpn` 与 `related_product_id`），也可以"手动输入型号"（仅 `related_mpn`）。
3. 关系类型为对称类型（3/4/5/6）时，可勾选"同时创建反向关系"；类型 1/2 不提供该选项（A 替代 B 不等于 B 替代 A）。
4. 置信度选"已验证"时，必须填核实人。

### 5.4 询盘明细关联商品（设计，本期不改询盘模块）

1. 询盘单详情页对每条明细调用匹配接口：先按"品牌 + 归一化型号"精确匹配。
2. 精确命中 → 建议关联；未命中但归一化型号在其他品牌下存在 → 列为候选；都没有 → 保持 `product_id` 为空。
3. 明细上原有的品牌、品类、原始型号、确认型号**保持不变**，作为历史快照；关联商品只新增一个 `product_id`。

### 5.5 FAQ 审核

1. 迁移或批量导入的 FAQ 来源为 3（待审核）。管理员进入 P05 的 FAQ 卡片，待审核行显示"待审核"标签和"确认"按钮。
2. 点"确认"，二次确认后来源变为 2，记录审核人和审核时间，行内标签消失；租户用户此后可读到这条 FAQ。
3. 可以先编辑答案再确认；编辑本身不改变待审核状态。
4. 租户用户打开同一商品时，看不到任何待审核 FAQ。

### 5.6 上传图片或视频

1. 管理员在 P05 的"图片与视频"卡片点"上传"，或把文件拖进虚线区域，一次一个文件。也可以点"添加链接"登记外部地址。
2. 前端先按类型和大小预检，不合规立即提示原因，不发请求；通过后显示上传进度条，可取消。
3. 服务端再次校验（扩展名与文件头、大小）。成功后出现在列表并提示"已上传"；失败给出具体原因，可以重试。
4. 点图片卡片上的"设为主图"，原主图自动取消；视频没有这个选项。

## 6. 页面详细说明

页面结构遵循 `.claude/context/ui-design-patterns.md`（标题区 → 筛选卡片 → 操作行 → 表格卡片；弹窗表单）。

### 6.1 P01 品牌列表

- 筛选：品牌名称（模糊）、状态
- 操作行：左侧"共 N 条记录"，右侧"新增品牌"（primary，仅平台管理员可见）
- 表格列：Logo+品牌名称 / 原产国 / 是否原厂正品（标签） / 商品数 / 状态 / 更新时间 / 操作（编辑、停用/启用、删除）
- 商品数 > 0 时，删除按钮置灰，悬停提示"已有商品使用，请先停用"

### 6.2 P02 品类列表

同 P01。表格列：品类编码 / 品类名称 / 排序 / 商品数 / 状态 / 操作。**品类编码在有商品后不可修改**（独立站 URL 依赖它）。

### 6.3 P03 系列列表

筛选增加"品牌"下拉。表格列：系列名称 / 品牌 / 商品数 / 状态 / 操作。

### 6.4 P04 商品列表

- **标题区**：标题 + 一句话说明；右侧主按钮「新建商品」（仅平台账号）
- **待补充提示条**（仅平台账号）：「N 个商品的档案还不完整」，右侧是快捷筛选：缺图片 / 缺物流 / 缺海关 / 缺参考价（各带数量），点击后列表只显示对应缺项的商品
- **搜索**：48px 高的搜索框，`/` 键聚焦；输入即搜（防抖 300ms），同时匹配归一化型号前缀和产品名称，输入 `6ES7 214` 与 `6es7214` 结果一致；框下提示"已按「6es7214」匹配"
- **品类**：药丸式切换（全部 + 6 个品类，带商品数），当前项高亮实心
- **二级筛选**：品牌、系列、生命周期、状态；平台账号额外有"包含已删除"
- **表格列**：复选框 / 商品（品类图标或主图 + 展示型号 + 规格摘要）/ 品牌（带标识）/ 系列 / 生命周期（胶囊）/ **档案完整度**（10 段小进度条 + n/10，仅平台账号，可排序）/ 状态（开关）/ 更新时间（可排序，默认降序）
- **批量操作**（仅平台账号）：勾选后表格上方出现操作条「已选 N 项 · 批量启用 / 批量停用 / 导出 / 取消选择」；批量停用前二次确认；**不提供批量删除**
- **交互**：整行悬停高亮；点整行进入 P05；状态开关切换前二次确认；记住上次的品类与筛选条件
- **加载**用骨架屏；**加载失败**显示原因和「重试」；表头吸顶；被截断的规格摘要悬停显示全文
- 无结果时显示 P04b 空状态：说明匹配规则，给出「清除搜索」和「新建 xxx」（带着型号进入向导第 1 步）

生命周期胶囊配色：

| 值 | 颜色 |
|----|------|
| 1 在产 / 2 现行 | 绿底绿字 |
| 3 旧款 | 橙底橙字 |
| 4 已停产 / 5 停产无替代 | 红底红字 |
| 6 未知 | 灰底灰字 |

### 6.5 P05 商品档案

商品详情不再分 Tab，而是**一页卡片**，往下滑就能看完整份档案。

- **顶部主卡**：缩略图、展示型号（大标题）、生命周期与状态胶囊、品牌 · 品类 · 系列；右侧「停用」和「更多」（内含「删除」，打开 M10）。被引用时下方有强调色提示条"已被 N 处询盘引用：品牌和型号已锁定，其余信息都可以改"，并带「查看引用」
- **档案完整度卡片**（仅平台账号）：大号"n / 10 项"、10 段进度条、"还差 N 项就完整了"，下方是**待补清单**（每项带预计用时），点击滚动到对应卡片。定义见 2.14
- **两栏布局**：主栏约 2/3，侧栏 340px
- **主栏卡片**（依次）：基本信息 / 图片与视频 / 规格参数 / 物流与海关 / 平台参考价 / 型号关系，最后是"更多内容"三张小卡（技术资料、应用场景、FAQ，各显示数量和状态，点「管理」就地展开为完整卡片）
- **侧栏**：状态（启用开关、生命周期、生命周期依据）、被引用（次数和入口）、信息（可见范围、创建、最近更新、数据来源）
- **每张卡片**：头部是图标 + 标题 + 状态徽章（绿色"已完成"或橙色"待补充"）+ 操作；**空卡片**用一句话说明"填了有什么用"，并给一个主操作
- **原地编辑**：点「编辑」后卡片就地变成表单；每张卡片**独立保存**（接口按模块拆分，没有"整页保存"）；有未保存修改时，页面底部浮出深色保存条（放弃 / 保存），离开页面前提示
- 品牌与原始型号在"已被引用"后显示锁形图标并只读

各卡片的内容：

- **基本信息**：品牌、原始型号、品类、系列、产品名称、规格摘要、简介、展示型号
- **图片与视频**：主图占最大位置，其余缩略图排在右侧，悬停可设主图或删除，拖动排序；顶部「上传」（打开 M09）和「添加链接」；上传中的项目就地显示进度；视频用深色底和播放图标区分
- **规格参数**：编辑态为可编辑表格（规格名称 / 规格值 / 单位 / 来源 / 已核实 / 拖动手柄），整体保存
- **物流与海关**：编辑态是左右两张表单卡片，单位写在输入框内（kg、mm、%）；HS 编码输入时实时显示"将保存为 …"；默认原产国旁注明"以货物单据为准"
- **平台参考价**：顶部注明"这是平台参考价，不是任何租户的报价或售价"；币种、金额、汇率、本位币金额（汇率未维护显示"未计算"）、来源、取价日期
- **型号关系**：行列表（关联型号 / 关系类型胶囊 / 目录内外 / 置信度），「添加关系」打开 M05
- **技术资料**：行列表，文件地址点击新窗口打开，「添加」打开 M06
- **应用场景**：卡片式，显示 emoji 图标、标题、说明，「添加」打开 M07
- **FAQ**：分段控件（全部 / 待审核 / 已确认）；待审核行用暖色底和橙色描边，「确认」为主按钮，点击弹出气泡"确认后所有租户都能看到"；确认后显示审核人和时间；「添加」打开 M08

**租户用户**进入 P05（原型 P05x）：只看内容，不显示完整度、状态栏和所有写操作；标题旁有"只读"标签；FAQ 看不到待审核条目。

### 6.6 W1–W5 新建向导

- **共同**：整页无侧栏；顶部步骤条（当前步骤强调色圆环，已完成强调色实心加勾）；右上角提示（第 1、2 步"草稿已自动保存"，第 3、4 步"商品已创建 · 改动自动保存"）；底部固定操作栏；右侧是"商品卡预览"，随输入实时变化
- **W1**：品牌用带标识的大卡片单选（常用 7 个 + 更多品牌搜索）；型号框 60px 高、20px 字号，框内即时给结果；下方是"相近型号"或"已存在 / 曾被删除"卡片；右侧提示"只有前 2 步是必须的"
- **W2**：品类用 6 张带图标和商品数的大卡片；系列用胶囊单选（可新建）；生命周期问"现在还在生产吗？"，不确定选"未知"。主按钮「创建并继续：添加图片」；右侧提示"选错了也没关系"
- **W3**：大拖放区（强调色虚线框）加「选择图片」「粘贴图片链接」；格式和大小写在拖放区下方；上传中显示进度条并可取消，传完标"主图"；「跳过这一步」为明显的文字按钮
- **W4**：产品名称、规格摘要、简介；物流、海关、参考价折叠成三行"稍后补充"；主按钮「完成」
- **W5**：绿色大勾 + "xxx 已创建"；档案完整度进度条；4 张"下一步"卡片（补规格、填重量尺寸、填 HS 编码、记参考价，各带预计用时和「去补充」）；出口：「查看商品档案」（主）、「继续新建下一个」（次）

### 6.7 C01 商品选择器

- 输入关键词远程搜索，只返回**启用且未删除**的商品，最多 20 条
- 选项展示：`展示型号 · 品牌 · 品类`；匹配归一化型号前缀
- 仅返回 ID 与展示所需字段，不返回规格等大字段

### 6.8 M06–M09 内容类与上传弹窗

- **M06 技术资料**：文档类型（下拉）、标题、文件地址（失焦即校验协议）、语言、版本、来源、已核实开关
- **M07 应用场景**：标题、说明、图标（emoji 选择）、已核实开关
- **M08 FAQ**：问题、答案（多行）。新增恒为"人工撰写"；编辑待审核 FAQ 时提示"保存不会改变待审核状态"
- **M09 上传图片/视频**：图片 / 视频分段切换；选择文件（或拖入）、标题（图片作替代文字）、来源、是否设为主图；显示文件名、大小和上传进度，预检不通过时在文件下方提示原因
- **M10 删除商品确认**：红色提示卡说明后果（软删除，之后新建同型号会提示可恢复），并提供「改为停用」作为更温和的选择；被引用的商品不会出现此弹窗，「删除」置灰并提示
### 6.9 通用状态与可访问性

规范见 `.claude/context/ui-design-patterns.md`「可访问性与规范补充」，这里只写对本模块的具体要求：

- **四种数据状态**：所有列表和卡片都要处理加载（骨架屏）、空、无结果、失败（原因 + 重试）。空状态已在 P04b 和各卡片中体现，加载和失败状态按规范实现
- **键盘**：全部功能可以只用键盘完成；焦点可见；新建向导每一步的 Tab 顺序与视觉顺序一致；关闭弹窗回到触发它的按钮
- **拖拽替代**：规格排序和图片排序除了拖动手柄，行内或卡片上要有「上移 / 下移」按钮（原型 D3 第 3 行）
- **错误汇总**：档案页某张卡片保存失败且有两处及以上错误时，卡片顶部显示可聚焦的错误汇总，每条链接到对应字段
- **减少动效**：系统设置了减少动效时，向导步骤切换、卡片展开、保存条滑入等动效全部关闭
- **数字**：列表和卡片里的数量、完整度、金额、汇率使用等宽数字；金额右对齐

## 8. 默认假设

1. **写权限 = 权限码 + 平台账号**：权限机制沿用现有 `@perm.has(...)`，但它不区分租户，所以还要求当前账号 `tenantId=0`。平台账号的 `tenantId=0` 已于 2026-09-19 确认（design.md 决策 2），仓库内无种子账号可对照，实现时用集成测试固化；若不做该校验，租户管理员可能通过分配权限修改全平台商品。
2. **只有平台管理员能新建商品**（Q3）。租户用户在询盘里遇到库中没有的型号，商品关联留空。
3. **商业数据不在本模块**：价格、库存、成色、交期由后续「租户商品扩展」承载（Q1）。
4. **品类只有英文名，商品无业务编码**（Q4、Q5）。
5. **首批数据来自独立站 `js/data.js`**，迁移规则见 design.md「Migration Plan」。
6. **本模块没有金额字段**，因此不涉及金额精度和汇率规则。
7. **权限码**沿用现有格式 `模块:资源:动作`（如 `system:dept:add`），本模块为 `product:brand:add/edit/delete`、`product:category:*`、`product:series:*`、`product:product:add/edit/delete`（恢复、状态切换归入 `edit`）；规格、型号关系、技术资料、应用场景、FAQ 的增删改以及 FAQ 审核确认同样归入 `edit`。
8. **卖家承诺不进共享表**：FAQ 只放关于零件本身的事实。独立站现有 FAQ 里夹带的质保、库存、发货、联系方式类条目，迁移时不导入（见 design.md 决策 12）。
9. **上传文件存储**：当前落服务器本地磁盘，按单实例部署；多实例部署或需要备份之前，必须先迁到 OSS（design.md Q13）。
10. **参考价不是报价**：这是平台层面的市场或厂商参考价；各租户自己的采购价和售价不在本模块（design.md 决策 3、13）。
11. **物流与海关的口径**：重量固定 kg、尺寸固定 mm；HS 编码一个商品一个，不按目的国分别维护；原产国是默认值，以货物单据为准。
12. **迁移**：独立站 56 条外部参考价迁入（USD，本位币为空）；福唯自己的 14 条采购报价和 52 张现货实拍图不迁；物流与海关没有可靠来源，迁移后为空。
13. **草稿只存在当前浏览器**（按登录账号区分），不跨设备；商品创建后即清除。这是本期的简化，需要跨设备再考虑服务端草稿。
14. **档案完整度是计算值**，不落库，只对平台账号显示；口径见 2.14。
15. **卡片独立保存**：档案页每张卡片各自保存，没有整页保存；因为后端接口按模块拆分。
16. **创建时机**在向导第 2 步结束；第 3、4 步是对已创建商品的补充（图片必须挂在已存在的商品下）。
17. **界面风格**采用 V3 方案 D：**信任蓝 + 中性灰配色，渐变只用于 Logo、主按钮、卡片顶线、关键数字、完整度进度条和向导背景**；**深色为默认主题，浅色主题并存**（用户可切换）。品牌主色仍为蓝色系，由 `#1677FF` 调整为 `#2563EB`。规范见 `.claude/context/ui-design-patterns.md`。全站外壳（侧栏、顶栏）需要统一升级，另立 change；升级前商品页沿用现有外壳，视觉上会有差异。

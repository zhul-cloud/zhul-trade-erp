## 1. 功能概述

### 1.1 功能目标

建立统一的商品档案（品牌、品类、系列、商品、规格、型号关系、技术资料、应用场景、FAQ），让询盘、报价、采购、订单以及独立站引用**同一个商品标识**，而不是各自存一份自由文本的"品牌 + 型号"。

背景：询盘明细里的品牌、品类、型号目前都是自由文本，同一个商品会有多种写法（如 `6ES7 214-1BD23-0XB0` 与 `6ES7214-1BD23-0XB0`），无法跨询盘、跨供应商、跨订单聚合。

两条已确认的原则：

- **商品单层**：一个「品牌 + 型号」= 一个商品，不设 SPU/SKU。系列只是品牌下的可选分组，不是 SKU 层。
- **平台共享**：所有租户共用一份商品库，由平台统一维护。

### 1.2 使用角色

| 角色 | 说明 |
|------|------|
| 平台管理员 | 具备商品维护权限码、且属于平台账号（`tenantId=0`，已确认，见 design.md 决策 2）的用户；维护品牌、品类、系列、商品及其规格/型号关系 |
| 租户用户（业务员/采购员） | 只读：查询、选择商品；在询盘等业务里引用 |

### 1.3 入口路径

| 场景 | 路径 |
|------|------|
| 品牌列表 | `/product/brands` |
| 品类列表 | `/product/categories` |
| 系列列表 | `/product/series` |
| 商品列表 | `/product/products` |
| 商品详情/编辑 | `/product/products/:id` |
| 新建商品 | `/product/products` 页面内弹窗 |

### 1.4 范围

**做：** 品牌、品类、系列、商品的增删改查与启停；规格参数；型号关系（替代/兼容/交叉引用）；型号去重；商品选择器组件；从独立站 `js/data.js` 一次性迁移；技术资料、应用场景、FAQ（FAQ 含发布审核）。

**不做：**

- 价格、库存、成色、MOQ、交期（属租户级数据，见 design.md 决策 3、Q1）
- 独立站 SEO 发布字段（`seo_slug`/`index_status`/`page_tier`）
- BOM、组合商品、商品图片的批量上传
- HS 编码、原产国、重量体积（Q8）
- 技术资料文件的上传与存储（本模块只保存文件地址）
- 卖家自己的质保、库存、发货、联系方式类 FAQ（属租户级内容，不进平台共享表，见 design.md 决策 12）
- 询盘明细关联商品的改造（本期只提供接口，改造另起 OpenSpec change）

## 2. 数据字段定义

> 技术字段（`id`/`tenant_id`/`deleted_at`/审计字段）不重复列出。所有表 `tenant_id` 固定为 0。

### 2.1 品牌（`product_brand`）

| 原产国/地区 | `country` | VARCHAR(64) | 否 | |
| Logo | `logo_url` | VARCHAR(256) | 否 | |

### 2.2 品类（`product_category`）

| 上级品类 | `parent_id` | BIGINT | 否 | 预留，当前只有一级，暂不使用 |
| 排序 | `sort_order` | INT | 否 | |

### 2.3 系列（`product_series`）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 品牌 | `brand_id` | BIGINT | 是 | |
| 系列名称 | `series_name` | VARCHAR(64) | 是 | 如 S7-1200；同品牌下唯一 |
| 简介 | `description` | VARCHAR(500) | 否 | |
| 状态 | `status` | TINYINT | 是 | 0-禁用、1-启用 |

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |

| 展示型号 | `mpn_display` | VARCHAR(128) | 是 | 默认等于原始型号，可人工修正大小写等展示问题 |
| 品牌 | `brand_id` | BIGINT | 是 | |
| 品类 | `category_id` | BIGINT | 是 | |
| 系列 | `series_id` | BIGINT | 否 | 必须属于所选品牌 |
| 产品名称 | `product_name` | VARCHAR(128) | 否 | 如 SITOP Power Supply |

| 生命周期 | `lifecycle_status` | TINYINT | 是 | 见 3.2，默认 6-未知 |

### 2.5 规格参数（`product_specification`）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 商品 | `product_id` | BIGINT | 是 | |

### 2.6 型号关系（`product_relationship`）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 商品 | `product_id` | BIGINT | 是 | 这条关系挂在哪个商品下 |

| 核实人/时间 | `verified_by`/`verified_at` | VARCHAR(32)/DATETIME | 条件必填 | 置信度为 1-已验证时必填 |
| 排序 | `sort_order` | INT | 否 | |

### 2.7 技术资料（`product_document`）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 商品 | `product_id` | BIGINT | 是 | 资料通过商品ID强绑定，结构上不可能"型号A页面显示型号B资料" |
| 文档类型 | `document_type` | TINYINT | 是 | 1-Datasheet、2-Manual、3-Installation Guide、4-User Manual、5-CAD、6-Drawing、7-Brochure、8-Certificate |
| 标题 | `title` | VARCHAR(128) | 是 | |
| 文件地址 | `file_url` | VARCHAR(512) | 是 | 只允许 `http://`、`https://`，或以**单个** `/` 开头的站内路径；`javascript:`、`data:`、`//host` 一律拒绝。本模块只存地址，不上传文件 |

### 2.8 应用场景（`product_application`）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 商品 | `product_id` | BIGINT | 是 | |
| 标题 | `title` | VARCHAR(64) | 是 | 如 Water & pump stations；同一商品下不可重复（忽略大小写和首尾空格） |
| 说明 | `description` | VARCHAR(500) | 否 | 必须基于真实产品用途，不得为 SEO 编造 |
| 图标 | `icon` | VARCHAR(16) | 否 | 直接存 emoji 或图标标识，展示方式由消费方决定 |
| 已核实 | `verified` | TINYINT | 是 | 0-未核实（默认）、1-已核实；仅为标记，不影响读取 |
| 排序 | `sort_order` | INT | 否 | |

### 2.9 FAQ（`product_faq`）

| 字段名 | 字段标识 | 类型 | 必填 | 说明 |
|--------|----------|------|------|------|
| 商品 | `product_id` | BIGINT | 是 | |
| 问题 | `question` | VARCHAR(256) | 是 | 同一商品下不可重复（忽略大小写和首尾空格） |
| 答案 | `answer` | TEXT | 是 | 纯文本。只描述商品本身，**不含卖家自己的质保、库存、发货、联系方式承诺** |
| 来源 | `source` | TINYINT | 是 | 见 3.5；管理员手动新增恒为 2 |
| 审核人 / 审核时间 | `reviewed_by` / `reviewed_at` | VARCHAR(32) / DATETIME | 系统生成 | 待审核 FAQ 被确认时填写 |
| 排序 | `sort_order` | INT | 否 | |

**`source=3` 的 FAQ 只有平台管理员看得到**，租户用户读不到，由服务端过滤；管理员确认后才对所有租户可见。

## 3. 状态与枚举

### 3.1 数据状态 `status`

0-禁用、1-启用。禁用后：商品选择器不再出现，已有业务单据里的历史引用仍可正常展示。

### 3.2 生命周期 `lifecycle_status`

| 值 | 含义 | 说明 |
|----|------|------|
| 1 | 在产 Active | |
| 2 | 现行 Current | |
| 3 | 旧款 Legacy | |
| 4 | 已停产 Discontinued | 必须填生命周期依据 |
| 5 | 停产无替代 Obsolete | 必须填生命周期依据 |
| 6 | 未知 Unknown | 默认值 |

生命周期是**事实描述，不是流程**：任意值之间可切换，不设状态机。是否有替代型号查型号关系表判定，不在本字段重复建模。若设为 5 但存在关系类型 1/2/3 的记录，保存时给出**警告**（不阻止）。

### 3.3 关系类型 `relationship_type`

| 值 | 含义 | 是否对称 |
|----|------|----------|
| 1 | 官方直接替代 Direct Replacement | 否 |
| 2 | 厂商后续型号 Manufacturer Successor | 否 |
| 3 | 功能性替代 Functional Alternative | 是 |
| 4 | 兼容 Compatible | 是 |
| 5 | 交叉引用 Cross Reference | 是 |
| 6 | 同系列 Same Series | 是 |

### 3.4 置信度 `confidence`

1-已验证、2-高、3-中、4-低、5-未知。置信度为 4/5 的关系，下游展示不得使用"推荐替代"这类强断言。

### 3.5 FAQ 来源 `source`

| 值 | 含义 | 谁能看到 |
|----|------|----------|
| 1 | 品类通用模板生成 | 所有租户 |
| 2 | 人工撰写，或待审核 FAQ 经人工确认 | 所有租户 |
| 3 | AI 辅助生成，待审核 | 仅平台管理员 |

审核确认只适用于来源为 3 的 FAQ，确认后来源变为 2，并记录审核人和审核时间；修改 FAQ 内容不改变来源。批准后无法再区分"曾由 AI 起草"，只保留审核痕迹。

## 5. 页面流程

### 5.1 新建商品（含去重）

1. 管理员点"新建商品"，填品牌、型号。
2. 输入型号并失焦后，前端调用匹配接口，用归一化型号查同品牌下是否已有商品。
3. 命中且未删除 → 提示"已存在"，并给出该商品链接，不允许提交。
4. 命中且**已被软删除** → 提示"该型号曾被删除"，提供"恢复"按钮，不允许新建。
5. 未命中 → 继续填品类、系列等，提交。
6. 后端再次校验（唯一键兜底，防并发），成功后跳转 P05。

### 5.2 停用 / 删除商品

1. 管理员点"停用"：二次确认，`status` 置 0。
2. 点"删除"：后端先检查是否被业务单据引用。
   - 有引用 → 拒绝，提示"已被 N 处引用，请改为停用"。
   - 无引用 → 二次确认后软删除。
3. 已删除的商品可在列表筛选"已删除"后恢复。

### 5.3 维护型号关系

1. 在 P05"型号关系"Tab 点添加，打开 M05。
2. 可以"从商品库选择"（同时写 `related_mpn` 与 `related_product_id`），也可以"手动输入型号"（仅 `related_mpn`）。
3. 关系类型为对称类型（3/4/5/6）时，可勾选"同时创建反向关系"；类型 1/2 不提供该选项（A 替代 B 不等于 B 替代 A）。
4. 置信度选"已验证"时，必须填核实人。

### 5.4 询盘明细关联商品（设计，本期不改询盘模块）

1. 询盘单详情页对每条明细调用匹配接口：先按"品牌 + 归一化型号"精确匹配。
2. 精确命中 → 建议关联；未命中但归一化型号在其他品牌下存在 → 列为候选；都没有 → 保持 `product_id` 为空。
3. 明细上原有的品牌、品类、原始型号、确认型号**保持不变**，作为历史快照；关联商品只新增一个 `product_id`。

### 5.5 FAQ 审核

1. 迁移或批量导入的 FAQ 来源为 3（待审核）。管理员进入 P05 的 FAQ Tab，待审核行显示"待审核"标签和"确认"按钮。
2. 点"确认"，二次确认后来源变为 2，记录审核人和审核时间，行内标签消失；租户用户此后可读到这条 FAQ。
3. 可以先编辑答案再确认；编辑本身不改变待审核状态。
4. 租户用户打开同一商品时，看不到任何待审核 FAQ。

## 6. 页面详细说明

页面结构遵循 `.claude/context/ui-design-patterns.md`（标题区 → 筛选卡片 → 操作行 → 表格卡片；弹窗表单）。

### 6.1 P01 品牌列表

- 筛选：品牌名称（模糊）、状态
- 操作行：左侧"共 N 条记录"，右侧"新增品牌"（primary，仅平台管理员可见）
- 表格列：Logo+品牌名称 / 原产国 / 是否原厂正品（标签） / 商品数 / 状态 / 更新时间 / 操作（编辑、停用/启用、删除）
- 商品数 > 0 时，删除按钮置灰，悬停提示"已有商品使用，请先停用"

### 6.2 P02 品类列表

同 P01。表格列：品类编码 / 品类名称 / 排序 / 商品数 / 状态 / 操作。**品类编码在有商品后不可修改**（独立站 URL 依赖它）。

### 6.3 P03 系列列表

筛选增加"品牌"下拉。表格列：系列名称 / 品牌 / 商品数 / 状态 / 操作。

### 6.4 P04 商品列表

- 筛选卡片（>4 项，多行网格）：关键词（型号/名称）、品牌、品类、系列、生命周期、状态；平台管理员额外有"包含已删除"
- 表格列：主图缩略 + 展示型号（13/600）与产品名称（12/textSub）合并一列 / 品牌 / 品类 / 系列 / 生命周期（胶囊标签） / 状态 / 更新时间 / 操作
- 关键词搜索同时匹配归一化型号前缀和产品名称，输入 `6ES7 214` 与 `6es7214` 结果一致

生命周期胶囊配色：

| 值 | 颜色 |
|----|------|
| 1 在产 / 2 现行 | 绿底绿字 |
| 3 旧款 | 橙底橙字 |
| 4 已停产 / 5 停产无替代 | 红底红字 |
| 6 未知 | 灰底灰字 |

### 6.5 P05 商品详情/编辑

- 顶部：展示型号（大标题） + 品牌 + 生命周期标签 + 状态；右侧操作：编辑、停用/启用、删除
- **基本信息**：M04 中的全部字段。品牌与原始型号在"已被引用"后只读，并显示"已被 N 处引用，不可修改"
- **规格参数**：可编辑表格（规格名称 / 规格值 / 单位 / 来源 / 已核实 / 排序），整体保存
- **型号关系**：表格（关联型号 / 关系类型标签 / 置信度 / 说明 / 核实人），点添加打开 M05
- **技术资料**：表格（类型标签 / 标题 / 文件地址，点击新窗口打开 / 语言 / 版本 / 已核实 / 操作），"添加"打开 M06
- **应用场景**：表格（图标 / 标题 / 说明 / 已核实 / 操作），"添加"打开 M07
- **FAQ**：列表（问题 / 答案摘要 / 来源标签 / 操作），`source=3` 的行显示"待审核"标签和"确认"按钮，"添加"打开 M08
- 租户用户进入 P05：所有写按钮不可见，FAQ 列表看不到待审核条目

### 6.6 M04 新建商品

分组：标识（品牌、原始型号、展示型号）→ 分类（品类、系列）→ 描述（产品名称、简介、规格摘要、主图）→ 生命周期。原始型号失焦触发重复检查（5.1）。

### 6.7 C01 商品选择器

- 输入关键词远程搜索，只返回**启用且未删除**的商品，最多 20 条
- 选项展示：`展示型号 · 品牌 · 品类`；匹配归一化型号前缀
- 仅返回 ID 与展示所需字段，不返回规格等大字段

### 6.8 M06–M08 内容类弹窗

- **M06 技术资料**：文档类型（下拉）、标题、文件地址（失焦即校验协议）、语言、版本、来源、已核实开关
- **M07 应用场景**：标题、说明、图标（emoji 选择）、已核实开关
- **M08 FAQ**：问题、答案（多行）。新增恒为"人工撰写"；编辑待审核 FAQ 时提示"保存不会改变待审核状态"

## 7. 异常与边界处理

| 场景 | 处理方式 | 提示文案 |
|------|----------|----------|
| 同品牌下归一化型号重复（如带空格与不带空格） | 拒绝创建，返回已存在商品链接 | "该型号已存在：{展示型号}" |
| 型号只含符号，归一化后为空 | 拒绝 | "型号至少包含一个字母或数字" |
| 同型号不同品牌 | 允许并存 | — |
| 新建时命中已软删除的同型号 | 拒绝新建，提示恢复 | "该型号曾被删除，可恢复" |
| 删除已被业务单据引用的商品 | 拒绝，引导停用 | "已被 N 处引用，请改为停用" |
| 修改已被引用商品的品牌或原始型号 | 拒绝 | "已被引用，不可修改品牌和型号" |
| 停用被引用的商品 | 允许，历史引用不受影响 | 二次确认 |
| 删除仍有商品的品牌/品类/系列 | 拒绝 | "已有 N 个商品使用，请先停用" |
| 系列不属于所选品牌 | 拒绝 | "所选系列不属于该品牌" |
| 生命周期 4/5 未填依据 | 拒绝 | "停产类状态必须填写依据" |
| 生命周期 5 但存在替代类关系 | 允许保存，给警告 | "存在替代型号记录，请确认是否应为'已停产'" |
| 关联型号与自身相同 | 拒绝 | "不能关联自己" |
| 同一商品下重复添加相同关联型号+类型 | 拒绝 | "该关系已存在" |
| 关联型号恰好命中目录内唯一商品 | 自动填 `related_product_id`；多个品牌下都有时不自动填，由用户选择 | — |
| 文件地址不是 `http://`、`https://` 或单个 `/` 开头（如 `javascript:`、`//host`） | 拒绝 | "文件地址必须以 http://、https:// 或 / 开头" |
| 同一商品重复添加相同文件地址 / 应用场景标题 / FAQ 问题 | 拒绝 | "该资料已存在" / "该应用场景已存在" / "该 FAQ 已存在" |
| 对已确认的 FAQ 再次点击确认 | 拒绝 | "该 FAQ 不是待审核状态" |
| 租户用户读取商品 FAQ | 不返回待审核条目 | — |
| 租户用户调用写接口 | 拒绝 | "仅平台管理员可维护商品主数据" |
| 两人同时创建相同型号 | 唯一键兜底，后到者收到"已存在"提示 | 同第 1 行 |

## 8. 默认假设

1. **写权限 = 权限码 + 平台账号**：权限机制沿用现有 `@perm.has(...)`，但它不区分租户，所以还要求当前账号 `tenantId=0`。平台账号的 `tenantId=0` 已于 2026-09-19 确认（design.md 决策 2），仓库内无种子账号可对照，实现时用集成测试固化；若不做该校验，租户管理员可能通过分配权限修改全平台商品。
2. **只有平台管理员能新建商品**（Q3）。租户用户在询盘里遇到库中没有的型号，商品关联留空。
3. **商业数据不在本模块**：价格、库存、成色、交期由后续「租户商品扩展」承载（Q1）。
4. **品类只有英文名，商品无业务编码**（Q4、Q5）。
5. **首批数据来自独立站 `js/data.js`**，迁移规则见 design.md「Migration Plan」。
6. **本模块没有金额字段**，因此不涉及金额精度和汇率规则。
7. **权限码**沿用现有格式 `模块:资源:动作`（如 `system:dept:add`），本模块为 `product:brand:add/edit/delete`、`product:category:*`、`product:series:*`、`product:product:add/edit/delete`（恢复、状态切换归入 `edit`）；规格、型号关系、技术资料、应用场景、FAQ 的增删改以及 FAQ 审核确认同样归入 `edit`。
8. **卖家承诺不进共享表**：FAQ 只放关于零件本身的事实。独立站现有 FAQ 里夹带的质保、库存、发货、联系方式类条目，迁移时不导入（见 design.md 决策 12）。

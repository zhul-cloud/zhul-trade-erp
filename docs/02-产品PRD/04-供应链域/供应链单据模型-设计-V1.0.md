# 供应链单据模型 — 设计 V1.0

> 2026-10-08 与业务讨论确定。作为采购、仓储、物流、应付几个后续变更共同的依据；每个变更的规格与原型以本文为准，有冲突时先改本文。

## 1. 背景与范围

当前流程：

1. 销售订单生成后，采购员找供应商谈判下单。
2. 供应商发货，提供发货图片、视频和快递单号。
3. 货到我们仓库后，仓库按入库单验收。
4. 拍摄人员拍拆箱、验货视频和 6 张实物图，发到 B2B 平台和独立站。
5. 打包后用国内快递发到深圳货代，记录快递单号和运费。
6. 货代收货后，我们提供 CI、PL，货代申报出运。
7. 货代回传运单号、面单和实际运费，由业务员登记。

本文借鉴仓储系统的单据设计，把这个流程整理成一套通用的单据模型。

**不在本期范围：** 库存（目前只有以销定采）、合箱、下单审批、报销审核、供应商发票。

## 2. 已确认的决策

| 主题 | 决策 |
|---|---|
| 库存 | 只有以销定采，不做库存表；多发的货用「暂存货」处理 |
| 采购单生成 | 订单行自动生成「采购需求」，并按「采购员 + 供应商」自动排入草稿采购单（跨订单合并）；其余需求在需求池一键生成；确认下单时才分配编号 |
| 采购申请单 | 不做单头；拆单、合单在需求行上完成；暂不需要下单审批 |
| 砍价 | 目标价为转订单时锁定的采购成本价；只比较下单价；不良折价不算砍价，单独统计为质量索赔 |
| 到货差异 | 存在，额外成本必须核算进订单成本 |
| 多发 | 退回供应商，或进暂存货 |
| 合并出运 | 同一客户的多张订单可以合并交给货代；CI、PL 可以合用一套，也可以分开 |
| 合箱 | 不考虑：一箱只装一张订单的货 |
| 运费分摊 | 按计费重，取实重和体积重的较大者；体积系数默认 5000 |
| 国际运费 | 我们按月付给货代，计入销售成本 |
| 资金 | 应付、付款、核销为主线；付款方式分「公司对公」和「员工垫付」 |
| 报销 | 保留报销单：随时提交、暂不审核、必须上传付款截图；不需要发票 |
| 国内快递 | 仓库人员垫付后走报销 |
| 少见的额外成本 | 例如我们出的补发运费，由财务做一张「费用单」 |
| 供应商合同 | 向供应商采购时，上传供应商开给我们的合同；选填，货值低的可以不传（2026-10-08 追加） |
| 采购对象 | 可以是老供应商，也可以是线上店铺（平台 + 店铺名）；临时合作的店铺不必先转为供应商，买多了可以一键转（2026-10-09 追加） |
| 采购需求页 | 按销售订单分组看：先看哪些订单要采购，再看每单的型号、向谁买、谁负责；采购员默认「我负责的」，采购负责人默认「全部」（2026-10-09 追加） |

## 3. 总体结构：三个层面

```
            ┌──────────── 物流层：货在哪、多少个 ────────────────────────┐
 销售订单行 → 采购需求 → 采购单 → 供应商发货单 → 入库单 → 出库单 → 出运单
            └──────────────────────────────────────────────────────────┘
                     │           │            │         │        │
            ┌────────▼───────────▼────────────▼─────────▼────────▼──────┐
            │ 费用层：额外成本挂在发生它的单据上，分摊到销售订单型号行       │
            └────────────────────────────┬──────────────────────────────┘
                                         │
            ┌────────────────────────────▼──────────────────────────────┐
            │ 资金层：应付（供应商、货代）→ 付款 → 核销；员工垫付 → 报销单  │
            └───────────────────────────────────────────────────────────┘
```

- **物流层**只管数量和位置。
- **费用层**只管成本。
- **资金层**只管钱的去向。

一个动作可以同时影响几层（比如入库验收：数量入库、产生差异费用、生成应付），但每层的数据各自独立。

2026-10-09 与业务梳理确认。✅ 已上线 · 🆕 第①期改造 · ⏳ 后续期次。

| 角色 | 主要职责 |
|---|---|
| 业务员 | 客户、询盘、报价、PI、收款登记、转订单、客户收货确认、出运登记 |
| 采购负责人 | 分配询价、指定采购成本价、分派采购员、看全部采购进度 |
| 采购员 | 回价、谈价下单、登记供应商发货 |
| 店铺负责人（现兼财务） | 确认线下到账 |
| 仓库 | 入库验收、打包出库、登记国内快递 |
| 拍摄人员 | 拍拆箱、验货视频与实物图，发布到平台 |
| 系统 | 自动生成需求与草稿、推进订单进度、计算砍价 |

### 询盘到报价 ✅

| # | 谁 | 什么时候 | 做什么 |
|---|---|---|---|
| 1 | 业务员 | 新客首次接触，或老客户提出新需求 | 登记商机与客户，或登记客户询盘（AI 解析型号） |
| 2 | 采购负责人 | 询盘确认后 | 把型号分给采购员或兼职采购（也可以按规则自动分配） |
| 3 | 采购员 | 收到询价任务后 | 向供应商或线上店铺问价，录入回价，每人标一条推荐 |
| 4 | 系统 / 采购负责人 | 回价提交后 | 自动取全新原装最低价为采购成本价；多人比价时负责人可以改选 |
| 5 | 业务员 | 询盘「可报价」后 | 建报价单，用定价策略定售价，发给客户 |

采购成本价就是后面采购需求的目标价与建议采购渠道。

### 成交到收款 ✅

| # | 谁 | 什么时候 | 做什么 |
|---|---|---|---|
| 6 | 业务员 | 客户接受报价 | 出 PI；必要时用议价测算让利、出新版本 |
| 7 | 业务员 | 客户说已付款 | 线下上传水单（默认填还差的金额），平台收款直接登记 |
| 8 | 店铺负责人 | 钱到账后 | 确认到账；钱先到的先登记，再由业务员认领 |
| 9 | 业务员 | 有水单或到账后 | 转成销售订单（PI 页或订单列表「新建销售订单」） |

### 采购 ✅ ＋ 🆕

| # | 谁 | 什么时候 | 做什么 |
|---|---|---|---|
| 10 | 系统 | 订单生成的同时 | 每个型号生成采购需求：目标价、采购员、建议渠道取自回价 |
| 11 | 系统 | 同上 | 有采购员、渠道已定的需求自动排入「采购员 + 采购对象」的草稿采购单，跨订单合并；🆕 采购对象可以是老供应商或线上店铺 |
| 12 | 采购员 | 每天开始工作时 | 🆕 打开采购需求，默认「我负责的、还有没下单的」，按订单逐单看要买的型号、向谁买、进行到哪 |
| 13 | 采购员 | 看到「还没定」的型号 | 🆕 当场选老供应商或填「平台 + 店铺」，选完自动进草稿 |
| 14 | 采购负责人 | 随时 | 🆕 默认看全部；指派没人负责的型号，或拆给两人 / 两家买 |
| 15 | 采购员 | 谈好价后 | 进草稿填单价（含税或不含税）、费用、付款条件，传合同（选填）；换渠道用「改到其他供应商」 |
| 16 | 采购员 | 向供应商下单或在平台付款后 | 确认下单：分配编号，订单型号自动「已下单」，算出砍价 |
| 17 | 采购员 | 下单后有变化 | 修改（留痕）；缺货则取消，数量回到需求池 |
| 18 | 业务员 | 随时 | 在订单详情看每个型号「已下单 x / y」、采购单与采购员 |

订单变更：业务员取消订单、PI 出新版本后重新转；没下单的需求关闭，已下单的由新订单自动接回。

| # | 谁 | 什么时候 | 做什么 | 期次 |
|---|---|---|---|---|
| 19 | 采购员 | 供应商发货后 | 登记发货单：快递单号、图片、视频，可以分批 | ② |
| 20 | 仓库 | 货到仓库 | 按发货单验收、处理差异；订单型号自动「已入库」 | ② |
| 21 | 拍摄人员 | 验收后 | 拍拆箱、验货视频与 6 张实物图（发布到 B2B 平台与独立站以后归运营管理） | ② |
| 22 | 采购员、仓库 | 付款、垫付、退款时 | 付款记录与核销；员工垫付走报销单，退款冲减报销 | ③ |

## 4. 单据清单

| 单据 | 编号类型代码 | 归属 | 主要经办人 | 说明 |
|---|---|---|---|---|
| 采购需求 | 无（行） | 采购 | 系统生成，采购员拆分 | 一条需求对应一个订单型号行的全部或部分数量 |
| 采购单 | PO（已有，对外单据） | 采购 | 采购员 | 一家供应商一张，可以含多张订单的需求；附供应商合同 |
| 供应商发货单 | SD（新增） | 采购 | 采购员 | 一张采购单可以分几批发货 |
| 采购入库单 | GR（新增） | 仓库 | 仓库人员 | 按供应商发货单验收 |
| 采购退货单 | RT（新增） | 采购 | 采购员 | 不良、多发退回供应商 |
| 暂存货 | 无（清单） | 仓库 | 仓库人员 | 多发且不退的货 |
| 拍摄任务 | 无（作业） | 仓库 | 拍摄人员 | 挂在入库单上；素材归商品型号 |
| 销售出库单 | OB（新增） | 仓库 | 仓库人员 | 一张订单一张；按箱打包；国内快递单号与运费 |
| 出运单 | SH（已有，「发货批次」） | 物流 | 业务员 | 同一客户的一张或多张出库单交给同一货代 |
| 单证组（CI、PL） | CI、PL（已有，共用主体） | 物流 | 业务员 | 一张出运单可以有一组或多组 |
| 应付单 | AP（新增） | 财务 | 系统生成 | 对供应商、货代 |
| 付款记录 | PY（新增） | 财务 | 采购员或财务 | 付款方式：公司对公、员工垫付 |
| 报销单 | BX（新增） | 财务 | 采购员、仓库人员 | 汇总员工垫付，冲减退回员工的退款 |
| 费用单 | FE（新增） | 财务 | 财务 | 少见的额外成本，可以关联订单 |

除采购单外，新增单据都是内部单据，不带租户前缀。编号规则沿用「单据编号格式」。

## 5. 物流层

### 5.1 单据关系：明细行记住上游行

```
销售订单行 ─1:N─▶ 采购需求 ─N:1─▶ 采购单行 ─1:N─▶ 发货单行 ─1:N─▶ 入库单行
                                                                    │
                       出运单 ◀─N:1─ 出库单（一张订单）◀─ 出库单行 ◀──┘
```

每张单都是「单头 + 明细行」。明细行记录上游行，一路可以追溯到销售订单行。

### 5.2 拆分与合并

```
销售订单 SO1                采购需求                          采购单
  A × 100  ──拆分──▶  R1  A × 60  张三  建议供应商甲  ──┐    PO1 供应商甲
                     R2  A × 40  张三  建议供应商乙  ──┼──▶   A × 60 (R1)
  B × 20   ───────▶  R3  B × 20  李四               │       C × 10 (R4) ← 跨订单
销售订单 SO2                                          │    PO2 供应商乙
  C × 10   ───────▶  R4  C × 10  张三  ──────────────┘──▶   A × 40 (R2)
```

- 需求按订单型号行自动生成，默认采购员和建议供应商取被选为采购成本价的那条回价。
- 采购员可以把一条需求按数量拆成几条，分别指定采购员和建议供应商。
- 订单生成时，有采购员和建议供应商的需求自动按「采购员 + 供应商」排入草稿采购单，同一采购员对同一供应商的草稿跨订单合并；草稿行可以改到其他供应商。
- 生成不了草稿的需求（没有采购员、只有淘宝等店铺名称、没有建议供应商），在需求池勾选后一键按供应商或店铺生成。
- 单价不预填目标价，谈好后填写；确认下单时才分配采购单编号。
- 缺货不补、退货的数量回到需求的「未满足数量」，可以改找其他供应商。

### 5.3 供应商合同

采购单上传供应商开给我们的合同（供应商盖章的合同或形式发票）：

- 选填：不上传也能确认采购单，之后可以随时补传；货值低的采购不需要合同，所以也不做缺合同提醒。

- 一张采购单可以有多个文件（合同常是几页照片），PDF、JPG、PNG，单个不超过 10MB，按文件内容校验格式。
- 可以填写合同编号、合同金额。合同金额与采购单合计不一致时提示，不拦截。
- 附件只能通过需要登录和采购单查看权限的接口预览、下载，规则与供应商附件一致。
- 与供应商主数据上「合同」类型的附件区分：那是长期框架合同，这里是单次采购合同。

### 5.4 数量与状态

采购单行记录：

```
订购数 ≥ 已发货数 ≥ 已收货数 ≥ 合格数 ≥ 已出库数
```

状态都由数量推出，不手动修改。销售订单型号行的进度按下表自动推进，取代现在的手动推进：

| 订单行进度 | 推进条件 |
|---|---|
| 待采购 | 需求还有未下单数量 |
| 已下单 | 全部数量已在已确认的采购单上 |
| 已入库 | 合格数达到订单数量；部分时显示「已入库 3/5」 |
| 已交货代 | 出库单已发出 |
| 已出运 | 出运单已登记运单号 |
| 已完成 | 业务员点「客户已收货」（沿用现规则） |

### 5.5 到货差异

| 情况 | 处理 | 数量 | 钱 |
|---|---|---|---|
| 少发 | 等补发 | 采购单行保持未完成 | 不变 |
| 少发 | 不补 | 剩余数量回需求池 | 应付按实收减少；已预付的形成「供应商欠款」 |
| 不良 | 退货 | 生成采购退货单，数量回需求池 | 冲减应付或待退款；退货运费记费用 |
| 不良 | 折价接收 | 按合格入库 | 折价冲减应付，计为质量索赔 |
| 多发 | 退回 | 采购退货单 | 退货运费记费用 |
| 多发 | 暂存 | 进暂存货清单 | 见 5.6 |

### 5.6 暂存货

暂存货不是库存，只是一张待处理清单：型号、数量、来源采购单、位置备注、成本单价。

- **用到订单**：某条采购需求直接由暂存货满足，不再下单。
- **退回供应商**：生成采购退货单。
- **报废或转样品**：成本计入损耗。

成本规则：

- 供应商白送的，成本为 0。用到订单时报表标「暂存货，零成本」，不计入砍价统计。
- 供应商收了钱的，按采购单价计成本，用到订单时成本跟着转过去。

### 5.7 拍摄任务

入库验收完成后，自动生成一条拍摄任务，检查清单如下：

- 拆箱视频；
- 验货视频；
- 实物图 6 张。

拍摄任务只负责拍摄（2026-10-09 确认）；发布到 B2B 平台、独立站以后统一归到运营管理。

素材保存在**商品型号**名下，同一型号下次可以复用。拍摄不改变货物数量，也不阻塞出库。

### 5.8 出库与出运

```
出库单 OB1 (SO1)  按箱打包：每箱长 × 宽 × 高、实重、箱内型号与数量
出库单 OB2 (SO2)
       └──────┬──────┘
              ▼
出运单 SH1（客户 X · 货代 Y）
   ├─ 单证组：CI/PL 合并（SO1 + SO2），或者每张订单各一组
   └─ 运单号、面单文件、实际运费
```

- 出库由业务员的「发货通知」发起：业务员勾选已入库的型号与数量、指定货代；仓库在「待打包」里看到后打包（2026-10-09 确认）。
- 一张订单可以分批出库，订单型号按各自数量推进「已交货代」「已出运」（2026-10-09 确认）。
- 出库单登记国内快递单号和运费，运费由仓库人员垫付，走报销。几张出库单可以共用一个快递单号和一笔运费，运费按计费重分到各出库单；也可以单独登记（2026-10-09 确认）。
- 供应商偶尔直发深圳货代：采购员登记发货时选「直发货代」；业务员在出运单上确认数量后，系统当作「入库 + 已交货代」，不拍摄，箱规按货代量的尺寸重量填写（2026-10-09 确认）。
- 国际运费：每票由业务员按货代回传登记（人民币）；月底货代给对账单，财务勾选当月出运单核对，差额记调整后标记已对账（2026-10-09 确认）。
- 出运单只能放同一客户的出库单。
- 同一单证组的 CI、PL 共用编号主体。PL 的箱数、毛重、净重、尺寸取打包记录，CI 的型号、数量、单价取订单。

## 6. 费用层

### 6.1 费用行

所有额外成本用同一种结构：挂在发生它的单据上，再分摊到销售订单型号行。

| 发生在 | 例子 | 收款方 | 分摊方式 |
|---|---|---|---|
| 采购单 | 供应商收的运费、包装费 | 供应商 | 按采购金额 |
| 入库单（正数） | 退货运费 | 快递 | 有差异的行 |
| 入库单（负数） | 不良折价、索赔 | 供应商（冲减） | 不良行 |
| 出库单 | 国内快递运费 | 快递（员工垫付） | 按计费重 |
| 出运单 | 国际运费 | 货代（月结） | 按计费重 |
| 费用单 | 我们出的补发运费等 | 任意 | 手工选择关联的订单行 |

### 6.2 按计费重分摊

```
体积重 = 长(cm) × 宽(cm) × 高(cm) ÷ 体积系数（默认 5000）
计费重 = max(实重, 体积重)

运费先按各箱计费重分到箱，再按箱内货值分到型号行
```

- 体积系数维护在服务商（货代、快递公司）主数据上，默认 5000。
- **精度**：中间过程保持完整精度，分摊结果按 HALF_UP 保留两位小数；尾差放到计费重最大的箱（箱内放到货值最大的行），保证分摊合计等于实际运费。

## 7. 资金层

### 7.1 应付

```
采购单（付款条件：预付 / 货到付款 / 先采后付）
   ├─ 预付到期 ─▶ 预付应付
   └─ 入库验收 ─▶ 应付（合格数 × 单价 ± 采购单与入库单的费用行）
                       │
                       ├─ 先用预付款核销
                       └─ 不足的部分到期付款；多付的形成「供应商欠款」（退款或下次抵扣）

出运单实际运费 ─▶ 应付（货代）─▶ 月结对账单勾选核销 ─▶ 对公付款
```

付款条件可以分期，例如 30% 预付 + 70% 到货后。每期写明到期时点：下单后、发货前、入库后、入库后 N 天。

### 7.2 付款与报销

每笔付款记录都要写明付款方式：

| 付款方式 | 后续 |
|---|---|
| 公司对公 | 财务付款，直接核销应付 |
| 员工垫付 | 核销应付的同时，公司欠这位员工一笔钱，进入他的报销单 |

报销单：

- 随时提交，暂不审核，每笔垫付必须有付款截图；不需要发票。
- 汇总本人未报销的垫付：采购货款、供应商收的费用、国内快递运费。
- 供应商退款退到员工手里时，员工登记「已收到退款」，下一张报销单里自动冲减。
- 有待退款超过 N 天还没登记的，提醒本人。
- 财务按报销单付款给员工后，报销单为「已报销」。

## 8. 成本、毛利与砍价

### 8.1 订单型号行实际成本

```
实际成本 = 实际采购单价 × 合格数量
         + 分摊到本行的采购费用、差异费用、费用单
         − 分摊到本行的折价、索赔
         + 分摊到本行的国内运费、国际运费

实际毛利 = 实收人民币 − 实际成本
```

各项费用还没全部发生时，订单毛利仍标「预计」，用报价时的采购成本补足缺少的部分。

### 8.2 砍价

```
目标价   = 转订单时锁定的采购成本价（之后改历史询价、回价不影响）
砍价金额 = (目标价 − 采购单价) × 订购数量        可以为负（涨价）
砍价率   = (目标价 − 采购单价) ÷ 目标价
```

- 换了供应商，仍然用原目标价考核。
- 不良折价不算砍价，单独统计为质量索赔；暂存货零成本的不计入。
- 报表维度：采购员、供应商、品牌、品类、月份。整体砍价率按目标金额加权，不对百分比做简单平均。
- 采购货款以人民币计。采购单以外币下单时，同样保存原币金额、汇率和本位币金额。

## 9. 事务边界

| 动作 | 同一事务内完成 |
|---|---|
| 确认采购单 | 采购单状态、需求的已下单数、订单行进度 |
| 入库验收确认 | 入库单行、采购单行收货与合格数、需求未满足数、差异费用、应付生成、订单行进度、拍摄任务生成 |
| 出库发出 | 出库单状态、采购单行已出库数、运费分摊、订单行进度 |
| 登记出运运单号 | 出运单、国际运费应付与分摊、订单行进度 |
| 付款 | 付款记录、应付核销；员工垫付时同时记入待报销 |

已确认的单据只能冲销后重做，不能直接修改数量和金额。

## 11. 分期

```
① 采购需求（拆分、指定采购员）+ 采购单（合并下单、砍价、付款条件、供应商合同）
② 供应商发货登记 + 入库验收 + 差异处理（补发、退货、折价、暂存）+ 拍摄任务
③ 应付、付款、核销 + 报销单 + 费用单 + 采购谈判报表
④ 出库打包（按箱）+ 出运单 + 单证组与 CI/PL 生成 + 计费重分摊 + 货代月结对账
⑤ 素材库与 B2B、独立站发布记录
```

- 做完 ①、②，订单进度的「已下单」「已入库」就能自动推进。
- 做完 ④，订单有了完整的实际毛利。

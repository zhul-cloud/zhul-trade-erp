# order-splitter · 拆单分类 Skill

## 任务目标
- **输入**：`inquiry-parser` 输出的产品明细 JSON 数组 + 询盘元信息（来源/发件人/日期/客户名称）
- **输出A（给 feishu-pusher）**：三层结构化数据对象（见步骤 3）
- **输出B（展示给用户）**：拆单汇总表 + 各询盘单明细列表
- **触发条件**：由 AGENTS.md 编排层在 `report-generator` 完成后、`feishu-pusher` 执行前调用

---

## 数据模型说明

```
客户询盘（1条）         ← 原始询盘全貌，记录客户信息、询盘状态
  └── 询盘单（N条）    ← 按品牌+品类拆分，每个组合一条，对应一个供应商维度
        └── 询盘单明细（N条）  ← 每个型号一条
```

---

## 操作步骤

### 步骤 1 · 确定拆单模式

本 Skill 固定采用**品牌 + 品类**组合拆单：
- 同一品牌 + 同一品类 → 归入同一张询盘单
- 不同品牌，或同品牌不同品类 → 各自独立询盘单

无需用户指定，直接执行。

**例外：** 若 JSON 数组为空，输出「无明细条目，跳过拆单」，终止本 Skill。

---

### 步骤 2 · 执行分组

扫描 JSON 数组，按 `brand` + `category` 字段组合进行分组：

```
分组键 = "{brand}|{category}"
```

**分组规则：**
- 每条明细只归属一个询盘单，不重复出现
- `待核实` 和 `未识别` 的条目正常参与分组，不单独隔离
- `brand` 为空时，分组键为 `"未知品牌|{category}"`
- `category` 为空或「其他」时，分组键为 `"{brand}|其他"`
- Excel 输入时，在每条明细的 `note` 字段追加原始行号（如「原始行号：Row 5」）

---

### 步骤 3 · 构建三层输出结构

将分组结果组装为以下结构（此结构作为 feishu-pusher 的输入）：

```json
{
  "master": {
    "客户名称": "{客户名称，未知时填空字符串}",
    "询盘来源": "{来源/发件人/渠道}",
    "询盘内容": "{原始询盘的文字内容摘要，不超过 200 字}",
    "询盘日期": "{YYYY-MM-DD}",
    "询盘状态": "待处理",
    "总产品数": {JSON 数组总条数},
    "已报价数": 0
  },
  "sub_inquiries": [
    {
      "sub_inquiry_id": "A",
      "brand": "施耐德",
      "category": "PLC",
      "item_count": 2,
      "inquiry_template": "您好，请帮忙查询以下施耐德产品的价格和货期：\n1. ATV312HU22M3 × 3台\n2. LC1D25M7C × 5只\n请注明：不含税价、货期、是否现货。谢谢！",
      "items": [
        { ...完整的明细条目 JSON... },
        { ...完整的明细条目 JSON... }
      ]
    }
  ]
}
```

**`sub_inquiry_id` 规则**：本次会话内按 A、B、C... 顺序分配，仅用于展示和追溯，不写入飞书。

---

### 步骤 3.5 · 为每张询盘单生成询价模版

在完成分组（步骤 2）之后、输出结构数据（步骤 3）之前，为每个 `sub_inquiry` 生成 `inquiry_template` 字段。

**生成原则：** 读起来像一个真实的业务人员发给熟悉供应商的消息，不要像套模板，不要每条都用同一个开头，不要用过于正式或生硬的表达。

---

**开头选取规则（根据条目数量选择）：**

| 条目数 | 开头风格示例（任选其一，可以自然变化） |
|--------|--------------------------------------|
| 1条 | `帮我查一下{品牌}的 {型号}，` / `{品牌} {型号} 现在什么价？` / `有没有 {品牌} {型号} 的货，` |
| 2～3条 | `有几款{品牌}{品类}要问一下价，` / `客户需要几个{品牌}的{品类}，帮忙看看：` / `{品牌}{品类}这几个型号麻烦查一下：` |
| 4条及以上 | `这边有批{品牌}{品类}的需求，型号如下，帮忙查一下价格和货期：` / `客户有{品牌}{品类}的采购计划，以下型号都要报价，麻烦看看：` |

**型号列表格式（开头之后）：**

单条时：直接接在开头句后，不换行不编号。
多条时：换行后按 `{型号} {数量}{单位}` 列出，不用序号前缀，简洁即可。

**结尾选取规则：**

| 情形 | 结尾示例（任选其一） |
|------|---------------------|
| 无待核实条目 | `麻烦报不含税价，有货的话货期也说一下，谢谢。` / `价格和货期都报一下，不含税，谢谢！` |
| 有待核实条目 | `标了「待核实」的型号如果有问题麻烦帮我核对一下，其余的先报不含税价和货期，谢谢。` |
| 有未识别条目 | `有几个型号我不太确定，标了出来，麻烦帮我确认一下型号对不对，对的话一起报价，谢谢。` |

**型号标注规则：**

| confidence | 显示方式 |
|-----------|---------|
| 确认 / 已纠正 | 直接写型号 |
| 待核实 | 型号后加 `（待核实）` |
| 未识别 | 用 `original_model`，后加 `（型号待确认）` |
| 数量为空或 0 | 写 `数量待定` |
| 单位为空 | 省略单位 |

---

**示例——单条，无待核实：**
```
帮我查一下西门子的 6ES7214-1AG40-0XB0，要 5 台，报不含税价，有货的话货期也说一下，谢谢。
```

**示例——3条，无待核实：**
```
西门子 PLC 这几个型号麻烦查一下：
6ES7214-1AG40-0XB0 5台
6ES7222-1BH32-0XB0 2块
6GK7243-1BX30-0XE0 1台
价格和货期都报一下，不含税，谢谢！
```

**示例——含待核实条目：**
```
有几款施耐德变频器要问价，麻烦看一下：
ATV312HU22M3 3台
ATV630D11N4（待核实） 1台
标了待核实的型号如果有问题麻烦帮我核对一下，其余的先报不含税价和货期，谢谢。
```

---

### 步骤 3.6 · 为每张询盘单生成邮件询价模版（中文 + 英文）

在步骤 3.5 完成后，为每个 `sub_inquiry` 额外生成两个邮件模版字段：`email_cn` 和 `email_en`。

---

#### 中文邮件模版（`email_cn`）

**适用场景**：向品牌中国官方或国内代理商发送询价邮件。

**模版格式：**
```
主题：采购询价 - {品牌} {品类} 产品

您好！

我司正在采购以下 {品牌} 产品，烦请提供官方报价：

产品清单：
{序号}. {确认型号} × {数量}{单位}
{序号}. {确认型号} × {数量}{单位}

询价要求：
- 请提供不含税单价（人民币）
- 请注明货期及是否有现货
- 如有替代型号，请一并告知

期待您的回复，谢谢！

[联系人姓名]
[公司名称]
[联系电话]
[邮箱地址]
```

**中文模版生成规则：**

| 情形 | 处理方式 |
|------|---------|
| 确认 / 已纠正条目 | 使用 `model` 填入 |
| 待核实条目 | 使用 `model` 填入，型号后追加 `（待核实）` |
| 未识别条目 | 使用 `original_model` 填入，型号后追加 `（请协助确认型号）` |
| 数量为空或 0 | 写 `数量待定` |
| 单位为空 | 省略单位 |

**示例输出：**
```
主题：采购询价 - 西门子 PLC 产品

您好！

我司正在采购以下西门子产品，烦请提供官方报价：

产品清单：
1. 6ES7214-1AG40-0XB0 × 5台
2. 6GK7243-1BX30-0XE0 × 2台

询价要求：
- 请提供不含税单价（人民币）
- 请注明货期及是否有现货
- 如有替代型号，请一并告知

期待您的回复，谢谢！

[联系人姓名]
[公司名称]
[联系电话]
[邮箱地址]
```

---

#### 英文邮件模版（`email_en`）

**适用场景**：向品牌海外官方或外国供应商发送英文询价邮件。

**模版格式：**
```
Subject: Request for Quotation – {Brand} {Category} Products

Dear {Brand} Sales Team,

We are interested in purchasing the following {Brand} products and would appreciate your official quotation:

Product List:
{No.}. {model} × {quantity} {unit}
{No.}. {model} × {quantity} {unit}

Please include in your quotation:
- Unit price (EXW, USD)
- Lead time and stock availability
- Alternative part numbers if applicable

We look forward to your prompt reply.

Best regards,
[Contact Name]
[Company Name]
[Phone]
[Email]
```

**英文模版生成规则：**

| 情形 | 处理方式 |
|------|---------|
| 确认 / 已纠正条目 | 使用 `model` 填入 |
| 待核实条目 | 使用 `model` 填入，型号后追加 `(pending verification)` |
| 未识别条目 | 使用 `original_model` 填入，型号后追加 `(please confirm part number)` |
| 数量为空或 0 | 写 `TBD` |
| 单位为空 | 省略单位 |
| 品牌为中文（如西门子）| 在 Subject 和正文中使用对应英文品牌名（西门子→Siemens，施耐德→Schneider Electric，ABB 保留，三菱→Mitsubishi，欧姆龙→Omron） |

**示例输出：**
```
Subject: Request for Quotation – Siemens PLC Products

Dear Siemens Sales Team,

We are interested in purchasing the following Siemens products and would appreciate your official quotation:

Product List:
1. 6ES7214-1AG40-0XB0 × 5 pcs
2. 6GK7243-1BX30-0XE0 × 2 pcs

Please include in your quotation:
- Unit price (EXW, USD)
- Lead time and stock availability
- Alternative part numbers if applicable

We look forward to your prompt reply.

Best regards,
[Contact Name]
[Company Name]
[Phone]
[Email]
```

> **单位英文化规则**：台→pcs，套→set(s)，只→pcs，个→pcs，米→m，千克→kg，其余默认 pcs。

---

**三层输出结构中新增的字段（在步骤 3 的 sub_inquiry 对象里追加）：**
```json
{
  "email_cn": "主题：采购询价 ...",
  "email_en": "Subject: Request for Quotation ..."
}
```

### 步骤 4 · 展示拆单汇总（给用户看）

在对话中按以下格式输出，供用户核认：

```
## 拆单结果

| 询盘单 | 品牌 | 品类 | 型号数 | 含待核实/未识别 |
|--------|------|------|--------|----------------|
| A | 施耐德 | PLC | 2 | 无 |
| B | 施耐德 | HMI | 1 | 1条待核实 |
| C | 施耐德 | 变频器 | 1 | 无 |
| D | 西门子 | PLC | 2 | 无 |
| **合计** | — | — | **6** | **1条需关注** |
```

汇总表之后，逐张询盘单输出明细列表：

```
### 询盘单 A · 施耐德 PLC（共 2 条）
| 原始型号 | 确认型号 | 数量 | 单位 | 置信度 |
|---------|---------|------|------|--------|
| 型号A   | 型号A   | 5    | 台   | 确认   |
| 型号B   | 型号B   | 3    | 台   | 已纠正 |

### 询盘单 B · 施耐德 HMI（共 1 条）
...
```

---

## 输出规范

- **输出A（结构化数据）**：交给 AGENTS.md 编排层，作为 `feishu-pusher` 的入参
- **输出B（对话展示）**：汇总表 + 各询盘单明细，给用户看
- **失败时**：输出「拆单失败：[原因]」，返回原始 JSON 数组，AGENTS.md 标记 feishu-pusher 降级为 2 层写入

## 错误降级

| 失败场景 | 降级处理 |
|----------|---------|
| 输入 JSON 为空 | 输出「无明细条目，跳过拆单」 |
| 分组过程出错 | 输出失败原因，返回原始 JSON 数组（feishu-pusher 将降级为 2 层写入）|
| 单个分组构建失败 | 跳过该分组，输出警告，其余分组正常处理 |

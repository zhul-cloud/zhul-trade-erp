# Design

## Context

- 资料任务（`/product/fact-tasks`）与营销任务（`/operations/products`）已能下载任务包（`ContentPackageService.build`），上传后由 `ContentImportService` 解析预览、确认写入；「资料与营销一起上传」会自动审核技术问答并标资料已核。
- 导入接口接收 Markdown 原文（`ContentFileRequest.files[].content`），AI 生成的结果可以直接送入，不需要新的解析器。
- AI 编排服务按技能运行，支持本公司 API Key 与平台订阅，按连接方式顺序自动切换（`ai-connection-failover`）；现有技能只给模型「联网搜索」，没有「打开网页」。
- 技能 `fouwell-product-content`（zhul-skills 仓库）要求：核实制造商型号页与手册、打开 eBay 挂牌页核对价格、在 hsbianma 查海关编码、建立关键词库，并自评达到 90 分再交付；输出两份规范 v2 Markdown。

## Goals / Non-Goals

**Goals:**
- 生成在后台进行，人只在确认环节介入；确认与手动上传共用同一套解析、校验和写入。
- AI 生成的内容必须经人确认、资料必须经人核对，避免把未核实的内容写进共享商品库。

**Non-Goals:**
- 不做图片、视频素材生成。
- 不改手动上传流程，线下生成上传照常可用。

## Decisions

1. **先做可行性验证（spike），再定实现细节**：用 2～3 个真实型号，分别在 Claude API、OpenAI API、Claude 订阅、OpenAI 订阅下运行技能，记录：能否打开网页核实、单个耗时、单个花费、输出能否通过现有解析。结论写入本 design 的附录后再进入实现；如果某种连接方式不能打开网页，该方式只用于不需要核实的部分，或在结果预览中把未核实项标为「待核实」。
2. **一条记录一个商品**：`product_content_ai_job` 记录商品、状态、AI 任务 ID、两份结果原文、失败原因、发起人、确认人与时间、来源技能版本。批量即一次建多条记录，各自提交 AI 任务；同一商品有未结束记录时拒绝重复发起。
3. **技能来源**：把 zhul-skills 中技能的 `SKILL.md` 与 `references/output-format.md` 固定一份放进编排服务的技能目录，文件头记录来源提交；线上线下用同一版本，技能更新时同步一次并记录版本。
4. **输入**：资料包与营销包（本公司启用的全部平台）都按现有任务包生成，作为技能输入；技能一次输出两份文件。
5. **确认**：「查看结果」用现有上传预览抽屉，预载两份原文；确认调用 `ContentImportService.confirm`，但**不走「一起上传」的自动审核**；按确认人的权限分别写入资料包、营销包。上传记录增加来源字段（手动上传 / AI 生成）。
6. **执行与超时**：每个商品一个 AI 任务，单个最长 30 分钟（实测后调整）；同一租户同时生成中的不超过 3 个，其余排队，避免占满订阅或产生突发费用。
7. **待确认超期**：每天按 `TenantScope.platform` 扫描，待确认超过 30 天的改为已取消。

## Risks / Trade-offs

- [模型打开网页的能力因连接方式而异] → spike 先验证；不能核实的内容在预览中标出，由人确认时把关。
- [单个花费高、批量费用不可控] → 单批最多 20 个、同时生成不超过 3 个；发起前提示数量和计费方式；实测后按实际花费调整上限。
- [AI 写错内容进入共享商品库] → 只在人工确认后写入，资料写入后仍为「资料待核」，技术问答保持待审核。
- [技能更新后线上线下版本不一致] → 编排服务内固定版本并记录来源提交，同步有记录。

## Migration Plan

- 新增表 `product_content_ai_job`，在 `TenantTables` 登记为私有表；回退时删表，已导入的内容属于正常导入数据，不受影响。

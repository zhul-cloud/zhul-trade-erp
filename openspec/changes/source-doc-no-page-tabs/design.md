## Context

- 前端是 Umi Max 4 + ProLayout，React 19，路由为 react-router 6.3。所有页面通过 `app.tsx` 的 `childrenRender(children)` 渲染在顶栏下面，菜单项由 `menuItemRender` 包成 `<Link>`。
- 上一版（v1.16.0）给商品档案做了单独的返回入口，做法是在链接上带 `from` / `fromLabel` 参数。别的详情页大多没有返回入口，只有客户、供应商、背调、商机几个页面各自写了「返回列表」。
- 页面里有 84 个文件用 `history.push` 跳转，这些代码本次都不改。
- 现在的「离开提示」只有报价单、形式发票、我的询价三处的 `beforeunload`，只在关闭或刷新浏览器时生效。
- 来源数据现状：
  - 形式发票详情已有 `quotations[{id, quotationNo}]`；
  - 销售订单已有 `piId/piNo`、`afterSalesId/afterSalesNo`、`originalSoId/originalSoNo`；
  - 采购、仓库、财务各列表大多已带上一单据的 ID 和单号；
  - 报价单只有 `inquiryCodes`（没有 ID），形式发票列表只有 `quotationNos`（没有 ID）。

## Goals / Non-Goals

**Goals:**
- 标签栏、页面缓存、返回条集中在页面框架一处实现，新页面不用写任何代码就能用。页面最多加一行代码登记自己的标题。
- 「来源单号」用一个公共组件显示，详情表头和列表列共用。

**Non-Goals:**
- 不支持同一个菜单开多个标签，也不支持把页面拖出成独立窗口。
- 不改浏览器前进、后退的行为，它仍按浏览器历史走。
- 不给没有来源单号列的列表新增该列，只统一已有的上一单据列。
- 不改导出、打印、发给客户的单据。

## Decisions

### 1. 标签与页面缓存在框架层实现，不引入第三方 keep-alive 库

在 `childrenRender` 里放一个 `PageTabs` 组件，结构是「标签栏 + 页面区」：
- 用 `useOutlet()` 取出当前地址对应的页面元素，按「标签 → 页面栈条目」缓存。
- 没激活的条目用 `display: none` 隐藏，不卸载。
- 每个缓存元素外面包一层 react-router 的 `UNSAFE_LocationContext.Provider`，传入它自己当时的地址。这样隐藏页面里的 `useLocation`、`useSearchParams`、`useParams` 读到的仍是自己的地址，不会因为别的标签换了地址就重新渲染成别的内容。

**不用 react-activation、umi-plugin-keep-alive 的原因**：它们依赖 React 内部实现，对 React 18、19 的兼容问题很多，而且和 ProLayout 的路由配合需要额外改造。自己实现大约 300 行，行为可控。

### 2. 每个标签维护一个页面栈，返回走这个栈

- 标签的数据是 `{ menuPath, stack: [{ key, url, title }] }`。
- 路由监听按导航来源分别处理：

| 导航来源 | 处理方式 |
|---|---|
| 点菜单 | 切到该菜单的标签；没有就新建。框架先置一个「切标签」标记，再跳到该标签栈顶的地址 |
| 页面内的 PUSH（`history.push`、`<Link>`） | 压入当前标签的栈 |
| REPLACE | 替换栈顶 |
| 点返回条 | 框架置一个「返回」标记后跳到栈里上一条，并弹出栈顶，上一条直接用缓存显示 |
| 浏览器后退、前进（POP） | 目标地址正好是当前标签栈的上一条时，按返回处理；否则按页面内 PUSH 处理 |
| 首次加载、F5、地址栏直接打开 | 按「路径前缀最长匹配的菜单」确定所属标签 |

- **为什么不直接用 `history.back()`**：切标签本身也会产生浏览器历史，`back()` 可能退到另一个标签。用自己的栈才能保证「返回」只在当前标签里退一步。
- **缓存上限**：每个标签只保留栈顶往下 5 个页面不卸载，更早的只留地址和标题，返回到它时重新加载。

### 3. 页面标题登记

- 新增 `usePageTitle(title)` 钩子，登记到当前页面所在的栈条目上。标签名和返回条的文字都用这个标题。
- 页面没登记时：
  - 地址正好是菜单路径，用菜单名（沿用 `utils/menuName`，跟随「菜单管理」改名）；
  - 否则用「所属菜单名 + 详情」。
- 单据详情页登记「单据类型 + 编号」，如 `销售订单 SO20261105003`，标签上只显示编号。
- 浏览器窗口标题跟随当前标签。

### 4. 返回条放在框架层

- 当前标签的栈长度大于 1 时，在页面区顶部、页面标题上方显示「← 返回 上一条的标题」。
- 页面不用自己写返回入口。原有的「返回列表」类按钮（客户、供应商、背调、商机、商品档案）删掉，避免出现两个返回。
- 商品档案链接不再带 `from` / `fromLabel`。旧链接带的这两个参数直接忽略，不报错。

### 5. 未保存修改

- 新增 `useTabDirty(dirty)` 钩子，报价单、形式发票、我的询价三处原有 `beforeunload` 的页面接入。
- 关闭标签、「关闭其他」「关闭右侧」时，遇到有未保存修改的标签弹确认；自动关最久没用的标签时跳过这些标签。
- 切标签和页面内跳转不需要提示，因为页面被缓存，修改不会丢。

### 6. 隐藏标签里的弹层

- 带遮罩的弹窗、抽屉打开时，遮罩挡住标签栏和菜单，用户切不了标签，所以不需要额外处理。
- 不带遮罩的抽屉、下拉、气泡框：每个页面区外面包一层 `ConfigProvider getPopupContainer`，把它们挂到页面区里，页面隐藏时一起隐藏。

### 7. 持久化

- 标签列表、当前标签、各栈的地址和标题存 `sessionStorage`，读写都包在 try/catch 里。
- 恢复时：
  - 按当前账号的菜单权限过滤；
  - 只渲染当前标签的栈顶，其他标签和栈条目只有元数据；
  - 返回条在刷新后仍可用，点返回会重新加载上一页。
- 退出登录时清空。

### 8. 来源单号公共组件

`components/DocFields/SourceNos.tsx` 有两种显示方式：
- `inline`：用在详情表头，写作「来源单号 A、B」；
- `cell`：用在列表，一个来源时显示单号；多个时显示「A 等 N 个」，悬停用 Popover 列出全部。

入参是 `{ no, href }[]`，没有可点开的页面时只显示文字；手动创建显示「手动创建」。

后端只补 ID：
- 报价单详情和列表加 `inquiries: [{id, code}]`；
- 形式发票列表加 `quotations: [{id, quotationNo}]`。

原有 `inquiryCodes`、`quotationNos` 保留，避免影响导出和其他用到它们的地方。

### 9. 列名逐个改，规则写进规范

各模块的列按 specs 里的上下游表逐个改名，并接到 `SourceNos`。目标页面没有详情路由的（如退货单、暂存）用该列表页加 `?id=` 打开详情抽屉，这些页面已有这种用法。

规范增加两条：
- `AGENTS.md` 的 ALWAYS：跳转页面必须能返回原页面，由框架统一提供，页面不另写；
- `ui-design-patterns.md`：上一单据统一叫「来源单号」，以及它的显示方式。

## Risks / Trade-offs

- **[风险] 隐藏页面里有定时轮询或全局键盘、粘贴监听，在后台继续执行。** 应对：框架提供 `useTabActive()`。已知的全局监听（`PasteToUpload`、工作台轮询）在页面不可见时暂停。走查时逐个菜单检查有没有遗漏。
- **[风险] 有的页面在渲染时直接读 `window.location`，隐藏后读到别的地址。** 应对：已用 grep 确认页面代码里没有读 `history.location`。`window.location` 的用法在实现时再查一遍，改成 `useLocation`。
- **[风险] 开 10 个标签、每个缓存 5 页，占用内存。** 应对：上限可调。超过上限的页面只留元数据，返回时重新加载。
- **[取舍] 浏览器后退可能切到上一个标签，而不是在当前标签里退一步。** 系统里的返回条是主入口，这一点在使用手册里说明。
- **[取舍] 上一版刚加的明细「来源询盘」列这次去掉。** 多来源的单据看不出每一行来自哪张单，需要时点开来源单据查看。

## Migration Plan

- 没有数据库迁移，也没有配置项变化。按正常的 feat → develop → release 流程发版。
- 回退方式是回滚前端镜像。后端新增的字段对旧前端没有影响。

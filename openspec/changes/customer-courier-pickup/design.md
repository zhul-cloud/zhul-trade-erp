# Design

## Context

- 货代就是类型为「服务商」的供应商，填了「归属客户」即为客户指定货代（`logistics/forwarder`「客户自有货代」）。
- 出运单登记时已有「交给谁：我们的货代 / 客户的货代」，客户的货代只必填交货日期、可填送货运费、不进运费账单（`logistics/shipment`「登记出运」）。
- 发货通知必须选货代，客户指定货代排在前面。

## Goals / Non-Goals

**Goals:**
- 不新增「发货方式」这类新概念，复用「客户指定货代」承载「客户自己约快递上门」，让发货通知、出库、出运三处说法一致。

**Non-Goals:**
- 不对接 DHL、FedEx 接口（不自动下单约取件、不查轨迹）。
- 不为公司货代增加上门取件（公司自己的快递已按「我们的货代」流程处理）。

## Decisions

1. **把「上门取件」做成客户指定货代的属性，而不是发货通知上的选项。** 客户用自己快递账号取件是这个客户固定的发货习惯，登记一次以后每次发货通知默认选中（已有「客户只有一家指定货代时默认选中」），业务员不用每次再选。
   - 备选：发货通知上加「客户自提 / 上门取件」开关、不选货代 —— 要改发货通知必须选货代的规则，出运单也要处理「没有货代」，牵动面大。
2. **交接方式只允许客户指定货代设置。** 公司货代的表单不显示该项；货代改为公司货代（清空归属客户）时交接方式回到「送到货代」。
3. **出运登记沿用「客户的货代」分支。** 上门取件一定是客户安排运输，所以默认且只能选「客户的货代」（不能切到「我们的货代」）；不填送货运费，因为没有国内送货；承运商从货代带出、可改；运单号选填，填了列表显示真实单号。出运单记下登记时的交接方式，之后改货代不影响已出运的单据（与现有「交给谁」快照一致）。
4. **客户快递账号不当作凭据。** 它是快递计费账号、会印在面单上，按普通业务字段存储和显示，不做加密；日志不额外记录。

## Risks / Trade-offs

- [同一客户既有送到货代、又有上门取件两种情况] → 登记成两家客户指定货代即可，发货通知时客户有两家指定货代就不默认，由业务员选。
- [运单号选填导致无法跟踪] → 登记弹窗在运单号为空时提示「填写运单号便于跟踪」，不强制。

## Migration Plan

Flyway 迁移给供应商表加三列，存量全部为「送到货代」，无数据回填；回退删列即可。

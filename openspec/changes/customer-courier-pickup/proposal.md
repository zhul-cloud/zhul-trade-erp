# Proposal

## Why

用户 2026-11-26 反馈：有的客户用自己的 DHL、FedEx 账号约快递上门取件，货不送到任何货代仓库。现在发货通知只能选货代，出运登记按「送到客户的货代」处理，要填送货运费、交货日期，和实际流程对不上；仓库也看不出这批货是等快递上门。

## What Changes

- 客户指定货代增加「交接方式」：送到货代（现状，默认）/ 上门取件；上门取件的另填承运商（DHL、FedEx、UPS 等）与选填的客户快递账号。客户用自己的快递账号取件时，就把它登记成一家上门取件的客户指定货代（如「ACROBOT · DHL 账号取件」）。
- 发货通知选到上门取件的货代时，在货代旁标「上门取件」并显示承运商与客户快递账号；销售出库单同样显示，仓库知道是等快递上门。
- 登记出运时，上门取件的出运单按「客户的货代」处理并调整：日期叫「取件日期」，不填送货运费（为 0），承运商默认带出货代上的承运商，运单号选填但提示填写便于跟踪；列表与详情运单号未填时显示「客户安排取件」。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `logistics/forwarder`：客户指定货代增加交接方式（送到货代 / 上门取件）、承运商与客户快递账号。
- `logistics/shipment`：登记出运支持上门取件（取件日期、无送货运费、承运商默认带出）。
- `warehouse/outbound`：发货通知与销售出库单标出上门取件。

## Impact

- 数据库：货代（供应商表中的服务商）增加交接方式、承运商、客户快递账号三列，存量均为「送到货代」，可回退。
- 后端：货代保存与选择接口返回新字段；出运登记校验按交接方式区分；出库单与发货通知接口返回货代交接方式。
- 前端：货代管理与客户详情「客户指定货代」表单、发货通知弹窗（`sales/orders/shipNotice.tsx`）、销售出库单、登记出运弹窗与出运单列表 / 详情。
- 与 `feat/ui-redesign` 分支同样改动出运单详情、发货通知弹窗，合并时需处理冲突。

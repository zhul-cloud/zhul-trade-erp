## Context

- **收款单**：`payment_receipt` 一张表存两种行：kind = 1 水单（业务员上传的付款凭证），kind = 2 到账（财务确认、未认领登记、平台收款、余额抵扣都生成 kind = 2）。没有编号；状态 1 有效、2 已作废；`file_keys` 存登记时上传的文件（JSON，最多 5 个），`slip_id` 指向对应水单；`note` varchar(300)。到账属于 PI 或手动订单，两者都为空表示未认领。外币到账由结汇单按先进先出分摊（`fin_fx_settlement_allocation.receipt_id`）。页面在「财务管理 → 收款管理」的四个页签：待确认、未认领到账、待处理多收、收款记录。
- **退款单**：`fin_customer_refund`（TK），类型 1 售后退款、2 余额提现；状态 1 有效、2 已作废；`remark` varchar(500)；附件归属 `REFUND`。售后退款现在由退款申请（RA，`fin_refund_request(_item)`）执行生成，早期有直接登记的。接口已有 `GET /api/v1/finance/refunds/{id}`。页面在「财务管理 → 退款管理」的「退款单」页签。
- **付款单**：`fin_payment`（PY），类型 1 付款、2 供应商退款；`void_at` 非空为已作废；核销明细 `fin_payment_allocation`（来源 0 实付、1 欠款抵扣、2 退款冲减）；附件归属 `PAYMENT`（截图）；`remark` varchar(500)。页面在「财务管理 → 付款管理」。
- 三张单据的操作写通用操作日志 `LogService`，单据上看不到。`DocumentType` 已有 TK、PY、RA，没有收款单的类型。
- 参照：单据页统一规范（`.claude/context/ui-design-patterns.md`）、`warehouse-logistics-docs` 的做法、退款申请详情页（财务里唯一已按规范做的详情页）。

## Goals / Non-Goals

**Goals:**
- 收款单有单号；三张单据都有独立详情页，列表按规范统一。
- 三张单据都能改备注、增删附件、看操作日志。
- 所有提到这三种单据的地方都能点进详情页。

**Non-Goals:**
- 不改任何金额规则：到账、认领、多收、结汇、退款冲减收入、付款核销、欠款抵扣、报销。
- 不给已生效的财务单据开放金额修改，不加草稿状态。
- 水单不做单据。
- 应付单、结汇单（第二批）与报销单、费用单、其他收入（第三批）不在这次范围。

## Decisions

### 0. 三张单据的结构

| 单据 | 表头 | 明细 | 详情页 | 负责人 |
|---|---|---|---|---|
| 收款单 SK | `payment_receipt`（kind = 2） | 金额构成（由表头字段算出，不另存）；外币另列结汇分摊 `fin_fx_settlement_allocation` | `/finance/receipts/:id` | 登记人 |
| 退款单 TK | `fin_customer_refund` | 来源退款申请的明细 `fin_refund_request_item`；没有退款申请的显示一行 | `/finance/refunds/:id` | 登记人 |
| 付款单 PY | `fin_payment` | `fin_payment_allocation` | `/finance/payments/:id` | 登记人（垫付时显示垫付人） |

「明细」按单据的性质取，不硬套型号表：收款单是一笔钱，明细就是这笔钱怎么构成、怎么结汇；付款单的明细是它核销的应付单；退款单退的是型号就列型号。

### 1. 收款单号

- 新增 `DocumentType.SK`（不加租户前缀，与 TK、PY 一样）。
- 迁移新增 `receipt_no varchar(24) NOT NULL DEFAULT ''`，普通索引 `(tenant_id, receipt_no)`（水单为空串，不能建唯一索引）。
- 补号：kind = 2 且未软删除的行，按 `tenant_id`、`DATE(create_time)` 分组，按 `id` 排序，`SK + yyyyMMdd + LPAD(n, 3, '0')`；同组写入 `document_sequence`（`ON DUPLICATE KEY UPDATE last_no = GREATEST(...)`），与 V1.5.27 的做法相同。已作废的到账也补号（作废也是一张单据）。
- 取号入口：确认到账、登记未认领、平台收款、余额抵扣（`CreditUsageService`）、历史迁移导入（`FinanceImporter`，按业务日期取号）。
- 认领、取消认领不换号。

### 2. 详情页布局

与销售订单、仓库物流单据相同：网格 `minmax(0, 2.6fr) minmax(340px, 1fr)`，左边基本信息、明细、单据自己的卡片、备注与附件；右边关联单据、操作日志。标题行单号 + 状态 + 操作，说明行「客户或收款方 · 来源单号 · 负责人 · 创建时间」。`usePageTitle` 登记单号；返回由标签页返回条提供。

**收款单**
- 状态：有效 / 已作废；未认领的有效收款单显示「未认领」。
- 操作：作废（有「登记到账」权限；有结汇分摊时按钮置灰并提示先作废结汇单 JHxxx）；取消认领（认领来的、还没结汇的）。
- 说明行：客户（未认领时显示付款人）· 来源单号（PI 或手动订单）· 登记人 · 创建时间。
- 基本信息：到账日期、收款账户、付款方式（线上 / 线下）、付款人、平台订单号（平台收款）、所属事业部（启用事业部时，收错账户时标橙）、认领人与认领时间、作废原因。
- 明细「金额构成」：到账金额（毛额）、平台手续费、银行中转手续费差额、实收、汇率与来源（系统汇率 / 实际入账反算 / 估算）、实收人民币；外币时下方「结汇」列出结汇单号、结汇日期、分摊金额、结汇汇率、人民币，以及未结汇余额。
- 附件分两组：「到账凭证与水单」（登记时的 `file_keys` 与对应水单的文件，只读预览）；「附件」（新归属 `PAYMENT_RECEIPT`，有效时可增删）。
- 关联单据：PI、销售订单、结汇单。水单的文件已在「到账凭证与水单」附件组里，不单列；客户余额流水没有独立单据页，不列。

**退款单**
- 状态：有效 / 已作废。操作：作废（「退款单维护」按钮权限，规则不变）。
- 说明行：客户 · 来源单号（退款申请；没有时为销售订单）· 登记人 · 创建时间。
- 基本信息：类型、退款日期、原因、去向（原路 / 银行 / 转客户余额 / 其他）、收款账户、币种与汇率、人民币、所属事业部、作废原因。
- 明细：有退款申请时列申请明细（品牌、型号、数量、单价、金额，行类型为运费等非货品时显示名称）；余额提现显示「余额提现」一行；早期直接登记的显示「原因 + 金额」一行。
- 附件：归属 `REFUND`，有效时可增删。
- 关联单据：销售订单、售后单、退款申请、销售退货单（退款申请来自退货时）。客户余额流水没有独立单据页，不列；余额流水里的退款单号可以点开退款单。

**付款单**
- 状态：有效 / 已作废。操作：作废（登记人或有「付款登记」权限的，规则不变，进了报销单的置灰并提示报销单号）。
- 说明行：收款方 · 来源单号（核销的应付单的来源单号：采购订单、运费账单等，去重）· 登记人 · 创建时间。
- 基本信息：类型、付款日期、付款方式、付款账户或付款个人账户、垫付人与报销状态、对方收款账户、币种与金额、实付人民币、实际汇率、欠款抵扣、作废原因。
- 明细：应付单号、来源单号、核销金额（原币）、核销人民币、来源（实付 / 欠款抵扣 / 退款冲减），合计行。
- 附件：归属 `PAYMENT`（付款截图），有效时可增删。
- 关联单据：应付单、采购订单或运费账单、报销单（垫付且已进报销单）。

### 3. 列表

- **收款单**（原「收款记录」页签改名）：收款单号 · 到账日期、客户、付款方式、到账金额、手续费、实收、实收人民币、结汇、状态、来源单号、登记人、审计四列、查看。汇总条、筛选不变，关键词加收款单号。默认按更新时间倒序（原来按到账日期），表头可切回到账日期排序。
- **退款单**：退款单号 · 退款日期、客户、类型、原因、金额、人民币、去向、状态、来源单号、审计四列、查看（登记人就是创建人，不另设一列）。原「凭证」列去掉（详情里看），「销售订单」列并入来源单号。
- **付款单**：付款单号 · 付款日期、收款方、类型、付款方式、付款账户 / 垫付人、金额、实付人民币、核销的应付单、状态、来源单号、审计四列、查看（登记人就是创建人，垫付人已在「付款账户 / 垫付人」列）。原「截图」列去掉。
- 退款单、付款单、退款申请的列表已有审计四列，收款单补上。
- 现有的行内操作（作废等）移到详情页，列表只留「查看」；工作队列页签（待确认、未认领到账、待处理多收、退款申请待处理）保留原有的行内操作，因为那里就是干活的地方。

### 4. 权限与数据范围

| 单据 | 能看全部、能改备注附件 | 只读查看 |
|---|---|---|
| 收款单 | 「收款管理」菜单 | 销售订单菜单：订单或 PI 在自己数据权限内的收款单（未认领的看不到） |
| 退款单 | 「退款管理」菜单 | 销售订单菜单：订单在自己数据权限内的 |
| 付款单 | 「付款管理」菜单 | 采购订单菜单：核销到自己数据权限内采购订单的应付单的付款单 |

接口：`GET /{id}` 返回详情；`POST /{id}/remark`、`POST /{id}/attachments`、`DELETE /{id}/attachments/{attachmentId}` 只给第一列；作废沿用原接口与权限。

### 5. 备注、附件、日志

- `payment_receipt.note` 放宽到 500，与另外两张一致；作废后备注与附件只读。
- `AttachmentService` 新增 `PAYMENT_RECEIPT`，下载权限同「收款管理」菜单与上表的只读范围（`AttachmentController` 的菜单映射、`AttachmentOwnerScope` 的归属校验一并补）。
- `DocLogs`：
  - 收款单：登记（确认到账 / 登记未认领 / 平台收款 / 余额抵扣）、认领、取消认领、作废、修改备注、上传附件、删除附件；
  - 退款单：登记（执行退款申请 / 余额提现 / 直接登记）、作废、修改备注、上传附件、删除附件；
  - 付款单：登记（付款 / 批量付款 / 供应商退款）、作废、进入报销单、修改备注、上传附件、删除附件。
- 历史单据没有单据日志，详情页显示「暂无」，不补造。

### 6. 链接到详情页的地方

- 收款单号：PI 详情与销售订单的收款面板、未认领到账（含最近认领）、结汇单的分摊明细。客户余额流水的来源只记 PI、订单与退款单，没有收款单号。
- 退款单号：销售订单、售后单、退款申请详情、客户余额流水的来源。
- 付款单号：采购订单付款面板、应付单详情的付款记录、报销单的垫付明细。
- `DOC_META` / `relatedRows` 补 SK、TK、PY 三种类型的名称、路径与状态色。

## Risks / Trade-offs

- **补号与新号冲突**：迁移写 `document_sequence` 后新号从当日最大流水往下排；迁移执行当天若有并发登记，`GREATEST` 保证不回退。生产在低峰期部署。
- **两套附件存储并存**：收款单登记时的文件在 `file_keys`，补充附件在 `biz_attachment`。不迁移旧数据（JSON 里只有私有存储 key，迁移要改下载与权限两处，风险大于收益）；详情页分组显示，用户感知为同一张卡片。
- **列表默认排序变化**：收款记录从按到账日期改为按更新时间，财务对账习惯按到账日期，保留表头排序切换。

## Migration Plan

1. 迁移：加列、放宽备注、补号、写序列；可重复执行（加列前判断列是否存在）。
2. 部署后端与前端。
3. 回退：前端、后端回到上一版；数据库删 `receipt_no` 列与 SK 序列行，备注改回 300 前确认没有超过 300 字的备注。

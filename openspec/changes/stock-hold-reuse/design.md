## Context

- 闲置库存 `stock_hold`：一行一批（型号、品牌、品类、数量、成本单价 CNY 不含税、来源、位置、状态 1 暂存中 / 2 已退回 / 3 已报废 / 4 已转样品）。`so_id`、`so_item_id` 记的是来源订单（部分取消、售后退货）。
- 订单型号的合格数量 = 有效采购入库单的合格数量 + 折价接收的不良数量；订单进度「已入库」、货物状态「在仓」、发货通知的可出库数量、订单成本的「已入库按实际计」都基于它。
- 采购需求：可下单数量 = 需求数量 − 草稿中数量 − 已下单数量。

**Goals:** 采购员把闲置库存分配给订单型号，打通出库、成本与撤回。
**Non-Goals:** 仓库侧主动分配、自动分配、盘点。

## Decisions

1. **分配记录就是闲置库存行本身**：新增字段 `used_so_id`、`used_so_item_id`、`used_requirement_id`、`used_at`、`used_by`，状态 5「已用到订单」。只用一部分时：原行数量减少，新插一行（复制型号、品牌、品类、成本单价、来源字段、位置）数量为本次用量、状态 5；全部用完时直接改原行。不另建分配表，闲置库存页天然能看到去向。
2. **需求数量**：采购需求新增 `hold_quantity`（已用闲置库存数量）。可下单数量 = 需求数量 − 草稿中 − 已下单 − 闲置库存。状态判断时闲置库存与已下单一样算「已安排」：全部被已下单 + 闲置库存覆盖为「已下单」，列表数量下方显示「闲置 3」。只能用可下单数量以内的部分（不动草稿与已下单）。
3. **合格数量**：订单型号合格数量 += 该型号状态 5 的闲置库存数量之和。统一改在计算合格数量的公共位置（`PurchaseLinks` 等读取处），订单进度在分配 / 撤回后按现有入库联动的同一方法重算。
4. **成本**：订单成本「采购货款」中，闲置库存部分 = Σ 成本单价 × 数量（人民币，汇率 1），视为已结算；不分摊采购订单的开票成本与采购费用。来源订单原本已经冲减或不计这部分（部分取消、退货转闲置、多发），成本不重不漏。HALF_UP 两位。
5. **撤回条件**：该订单型号「可出库数量」（合格数量 − 已在有效销售出库单上的数量）≥ 本次撤回数量。撤回时状态回到 1、清空使用字段；同来源且仍暂存中的拆分行不自动合并（保持简单，列表多一行）。需求 `hold_quantity` 减少。
6. **订单取消、部分取消**：在现有处理之前，先撤回该型号还没上销售出库单的闲置库存分配（部分取消只撤回到够取消数量为止），再走原逻辑（扣没排单 → 草稿 → 在仓转闲置 → 已下单）。避免把用来的闲置库存按采购订单价二次转入闲置库存。
7. **匹配与提示**：型号按去掉空格、转大写比较。采购需求列表按需求型号批量查暂存中的闲置库存数量（一次查询，按规范化型号聚合），显示「闲置库存有 N 个」。品牌不一致时弹窗内标黄提示。
8. **权限**：用闲置库存、撤回 = 能处理这条采购需求的人（需求的采购员或采购负责人，同下单）。写采购需求与闲置库存的操作日志。
9. **事务与并发**：分配在一个事务内：锁闲置库存行（`SELECT … FOR UPDATE`）→ 校验仍暂存中且数量足够 → 锁需求 → 校验可下单数量 → 拆分 / 更新 → 需求加数量 → 重算订单进度。撤回同理。

## Risks / Trade-offs

- 合格数量的计算点多（进度、货物状态、可出库、成本、补发出运判断），漏改会造成不一致 → 统一走一个方法并补测试覆盖发货通知与成本。
- 拆分后闲置库存行变多 → 接受；列表按状态筛选，默认只看暂存中。

## Migration Plan

迁移（版本以开发时最新为准）：`stock_hold` 加 `used_so_id`、`used_so_item_id`、`used_requirement_id`（bigint 默认 0）、`used_at`、`used_by` 与索引，状态注释加「5-已用到订单」；`purchase_requirement` 加 `hold_quantity int default 0`。回退：先把状态 5 的行改回 1，再删列（语句写在迁移注释中）。

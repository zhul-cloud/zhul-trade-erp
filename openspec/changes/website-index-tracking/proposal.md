## Why

独立站页面上线后，要等搜索引擎收录才有流量。现在 llm-wiki 用三张 Markdown 追踪表逐条跟进 fouwell.com 的收录：GSC 和 Bing 各有 214 条英文链接，Yandex 有 214 条俄文链接。Google 只能在 Search Console 里手工逐条提交。

独立站发布改由 ERP 完成之后（`website-publish`），收录跟踪也要跟着进 ERP：发布完成就自动生成跟踪记录，人工在 ERP 里提交和确认（用户 2026-11-26 定）。

## What Changes

- **收录任务（新）**：「运营管理 → 收录任务」，每个上线链接对每个搜索引擎各一条记录。
  - **Google**：待提交 → 已提交 → 已收录。页面提供「复制链接」「打开 Search Console 网址检查」；人工提交后点「已提交」，看到收录后点「已收录」。显示当天已提交的条数，方便控制每天的手工配额。
  - **Bing、Yandex**：发布时已用 IndexNow 自动推送，记录为「已推送」或「推送失败」，人工确认收录后点「已收录」。
  - 提交或推送超过 14 天仍未收录的，标「超期未收录」。
- **自动生成**：
  - 独立站发布单完成后，发布服务对比构建前后的站点地图，找出新增的链接（商品页、品牌页、品类页等），按站点的收录设置为每个链接生成记录；
  - 导入站点现有商品时，按站点地图为现有链接生成记录。
- **收录设置**（站点管理里新增）：每个搜索引擎是否跟踪、跟踪哪种语言的链接（默认 Google、Bing 跟踪英文，Yandex 跟踪俄文）、Search Console 资源名称。
- **Google 自动查收录（可选）**：站点配置了 Search Console 服务账号（加密保存）时，每天自动查询还没收录的链接，查到已收录就自动更新，记录检查结果；没有配置时全部人工确认。
- **导入现有追踪表**：上传 llm-wiki 的三张追踪表，把已有的提交和收录状态导入，避免重复提交。
- **菜单**：「运营管理」在「发品任务」之后新增「收录任务」。

不做：
- 自动在 Search Console 里提交收录请求（Google 没有对普通页面开放的接口）；
- Bing、Yandex 的收录自动查询；
- 收录后的排名和流量统计；
- 内容更新后自动要求重新提交。

## Capabilities

### New Capabilities
- `product/index-tracking`：收录记录的生成、状态与人工操作、超期提示、收录任务页、站点收录设置、Google 自动查收录、导入追踪表。

### Modified Capabilities
- `system/navigation`：「运营管理」新增「收录任务」。

## Impact

- **数据库**：
  - 新建两张表：收录记录（站点、链接、语言、页面类型、关联商品、搜索引擎、状态、上线 / 提交 / 推送 / 收录时间、最近检查结果、备注）和站点收录设置（引擎、语言、资源名称、服务账号密文）。
  - 新增菜单「收录任务」和「处理收录任务」权限。
- **后端**：
  - 发布单完成和导入时生成记录；
  - 状态操作；
  - 每天的超期标记和 Google 网址检查任务（调用 Search Console URL Inspection API，按配额限速）；
  - 解析 Markdown 追踪表。
- **前端**：收录任务列表（页签、筛选、批量复制和批量标记）、站点管理里的收录设置、导入追踪表。
- **发布服务与站点仓库**：构建结果要输出站点地图里的链接清单，发布服务在发布前后各取一次，算出新增的链接（需要在 `website-publish` 的适配脚本里一起实现）。
- **外部依赖**：
  - Google 自动查收录需要用户在 Google Cloud 建服务账号，并在 Search Console 里把它加为该资源的用户；
  - 生产服务器需要能访问 `searchconsole.googleapis.com`。
- **原型**：收录任务列表、收录设置、导入追踪表，先出 OpenPencil 原型，用户确认后再开发。
- **依赖**：依赖 `website-publish`。

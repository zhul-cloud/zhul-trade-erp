## Why

2026-11-10 用户反馈四条：

1. 客户原本用自己的货代，后来改用我们的货代发货，运费要另外收。原订单往往已经收齐款或已完成，「修改订单费用」改不了。
2. 单据列表只显示客户名称，看不出对接的是谁。
3. 登记未认领到账时，没地方留银行回单。
4. 应付单里未付的被已付的淹没；历史迁移进来的采购单应付都显示「未付」，实际早已付清。

## What Changes

- **费用订单**：在销售订单详情里新建「费用订单」。
  - 只有费用行（如运费），没有型号，关联原订单，客户、币种、事业部、业务员都取原订单。
  - 不走采购、入库、出库、出运。
  - 收款按手动订单走，收款到账即「已完成」。
  - 照常计入应收、收款记录和利润统计，在列表和详情里标「费用订单」。
- **列表显示客户主联系人**：商机、询盘、报价单、形式发票、销售订单、售后单、收款单（待确认、收款记录、多收）、退款申请、客户余额的列表，在客户名称下方显示主联系人。不新增数据库字段。
- **未认领到账附件**：登记未认领到账时可以上传附件（最多 5 个），列表和认领弹窗里可以预览。复用付款水单已有的附件字段和上传组件，不改表。
- **应付单排序**：默认未付、部分付款在前，同一状态内按更新时间倒序。
- **历史迁移应付视为已付**：
  - 范围是历史迁移、下单日期在 2026-11-01 之前、仍未付或部分付款的采购单应付（生产 609 张，全部人民币，合计 ¥4,564,623.02，没有付款核销）。
  - 应付单加「历史迁移视为已付」标记，已付补满、状态改为「已付清」，付款计划各期同步。
  - 以后重算已付时认这个标记，不会变回未付。
  - 不生成付款记录，不影响银行流水和现金类报表。
  - 通过数据库迁移随版本执行，可以回退。
- **采购订单单价可以为 0**（11-10 追加）：样品、供应商赠送、补发等场景。
  - 确认下单时，单价留空仍算没填；填 0 可以下单，二次确认时提示「有 N 行单价为 0」。
  - 单价为 0 的行不计算砍价。
  - 整单合计为 0 时，应付单直接为「已付清」。
- **供应商库按联系人搜索**（11-10 追加）：供应商列表筛选增加「联系人」，同时匹配联系人姓名、电话、微信、邮箱，不改表。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `sales/sales-order`：新增「费用订单」；手动创建订单的「至少一个型号」规则不适用于费用订单。
- `sales/payment-receipt`：未认领到账可以上传、预览附件。
- `finance/accounts-payable`：应付单页默认排序；新增「历史迁移应付视为已付」。
- `finance/order-cost`：费用订单的收入、成本与结算状态口径。
- `master-data/customer-profile`：单据列表显示客户主联系人。
- `master-data/supplier`：供应商列表增加联系人筛选。
- `purchase/purchase-order`：确认下单允许单价为 0；单价为 0 的行不计算砍价；合计为 0 的应付单。

## Impact

- **后端**：
  - `SalesOrderServiceImpl`：新建费用订单；进度、完成与收款联动；采购需求、出库候选排除费用订单。
  - `SalesConstants`：新增来源「费用订单」。
  - 收款相关服务：到账后费用订单自动完成。
  - 订单成本：费用订单没有型号行。
  - 未认领到账登记接口：接收附件。
  - `PayableSyncService`：认「视为已付」标记。
  - `PayableQueryService`：默认排序。
  - 各列表接口：返回主联系人。
- **前端**：
  - 销售订单：详情加「新建费用订单」，列表与详情加「费用订单」标识和关联。
  - `components/DocFields/CustomerCell` 与各列表的客户列。
  - `finance/receipts/UnclaimedTab`。
  - `finance/payables`。
- **数据库迁移 `V1.5.23`**：
  - `fin_payable` 新增 `settled_by_migration` 字段，并对上述 609 张应付补满已付、更新付款计划。
  - 回退：把这批应付的已付、状态和付款计划恢复为未付后删除字段，具体 SQL 写在迁移注释里。
  - 销售订单 `source` 字段注释增加 4（费用订单），不改结构。
- 不新增 `.env` 配置项；不新增菜单。新建费用订单沿用现有「手动创建订单」按钮权限。
- 界面改动（费用订单、联系人显示、未认领附件、应付排序）先出 OpenPencil 原型，经用户确认后开发。

## Why

外贸获客目前发生在四类渠道（阿里巴巴国际站、中国制造网、社媒、独立站），但系统里没有承接这一层的能力：`customer_inquiry.customer_id` 是必填字段，模型假设"已经知道是哪个客户、要买什么"才能建询盘；而这四个渠道进来的第一条消息，往往连客户身份都还不确定，更谈不上产品明细已结构化。业务员目前只能在渠道自己的后台/聊天工具里手工跟进，系统完全看不到这段过程，也就没有转化率、渠道效果这些数据。

**本提案目前是探索阶段的记录，不是已拍板的设计**——用于保存讨论结论，后续决策后再补齐 specs/design/tasks。

## What Changes

- 待决策后补充。已知会新增一个"商机"层，承接线索从进入到赢单/输单的跟进过程；赢单时转化为 `customer`（如不存在）+ `customer_inquiry`，交给现有询盘中心的 AI 拆单流程。
- 本次不改动 `customer_inquiry`/`inquiry_order` 既有行为。

### New Capabilities
- `crm/opportunity`：商机（线索）管理——多渠道线索归集、跟进、赢单转化为客户询盘、输单归档。**范围与数据模型待下方问题决策后确定，当前只是占位。**

### Modified Capabilities
（无——本次不修改任何既有能力的行为；赢单转化只是"创建"新的 customer/customer_inquiry 记录，不改变它们的既有语义）

## 待决策（探索记录，非最终结论）

1. **四个渠道怎么"进"系统？**
   阿里巴巴国际站有官方 open API 可拉取询盘消息；中国制造网基本没有开放 API；社媒（WhatsApp/FB/Instagram/领英等）门槛高，多数场景还是人工摘录；独立站如果是自建的，是唯一能 100% 自主接 webhook/表单 API 的。
   → 起点是"统一手工录入 + 渠道字段"（类似现有客户询盘的人工粘贴模式），还是 v1 就做真实 API 拉取（尤其阿里国际站，需要新增租户级第三方密钥管理这块目前完全没有的基础设施）？

2. **商机 → 客户询盘是否必经之路？**
   现有 `customer_inquiry` 走的是"AI 解析 → 拆单 → 发供应商询价对比"的重路径，服务于"已明确要买什么型号"的场景。多数商机（尤其社媔/独立站早期线索）要反复跟进才有明确采购意向，中间不适合直接进 AI 拆单。
   → 倾向：商机管理和询盘管理是两个独立阶段的漏斗，商机本身不承载产品明细，赢单时才触发创建 customer + customer_inquiry。

3. **归属与跟进节奏**
   `customer_inquiry` 已有 `owner_id`（负责人）。商机是自动分配（按国家/渠道轮询）还是手动认领？是否需要"多久未跟进自动提醒"的 SLA 机制？

4. **四渠道数据形状不一样，要不要在 v1 就区分渠道专属字段？**
   阿里/中国制造网通常带"公司名+国家+具体产品/型号+采购量"；社媔起步可能只有"一个联系方式+一句话"；独立站表单能拿到 UTM/广告来源这类营销归因数据（投放效果分析对贸易公司有价值）。
   → v1 是否只用通用的"原始内容 + 渠道枚举"兜底（类似 `customer_inquiry.raw_content` 的思路），营销归因等渠道专属结构留后续？

**下一步**：这四个问题定了，再回来补齐 proposal 的 What Changes/Impact，然后走 specs/design/tasks。

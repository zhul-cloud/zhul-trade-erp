## Why

11-11 用户反馈两件事：
- 单据里的「来源询盘」不是上一张单据。比如销售订单显示的是询盘号，实际上订单是由形式发票转来的，顺着单据往回查不方便。从来源单据跳过去以后，也没有统一的回去入口。
- 业务员要同时看几张单据时只能开多个浏览器窗口来回切，希望系统内能用标签页切换。

## What Changes

- **来源单号统一**
  - 所有单据把上一张单据统一叫「来源单号」，显示的是上一张单据的编号，例如：
    - 报价单 → 询盘单号
    - 形式发票 → 报价单号
    - 销售订单 → 形式发票号
    - 采购订单 → 销售订单号
  - 详情页的来源单号放在表头，可以点开；有多个来源时全部列出。
  - 列表页的来源列统一叫「来源单号」：只有一个来源时显示该单号，有多个时显示「X 等 N 个」，悬停可看全部，都能点开。
  - 采购、仓库、财务、物流单据里现在叫「来源」「来源订单」「发货单」「售后单 · 订单」等的上一单据列，一并改名并可点开。
- **型号明细去掉来源列**：报价单、形式发票、销售订单详情的型号明细去掉「来源询盘」列（上一版刚加的）。单据号属于表头信息，明细只保留品牌、品类、型号三列。
- **跳转后可返回（全局规则）**
  - 在系统内从一个页面跳到另一个页面后，打开的页面顶部统一显示「← 返回 原页面名称」，点后回到原页面，原页面的筛选、页码、滚动位置保持不变。
  - 直接打开链接或从菜单进入时不显示返回。
  - 商品档案原来单独做的返回入口改用这套统一机制。
  - 这条规则写进项目规范，以后新做的页面和原型都要遵守。
- **菜单标签页**
  - 从左侧菜单打开的页面以标签页显示，同一个菜单只开一个标签，再点菜单就是切过去。
  - 页面内的跳转（列表进详情、点来源单号等）在当前标签内完成，标签名跟着变成当前页面的名称。
  - 首页标签固定、不能关闭。其他标签可以关闭；右键菜单提供刷新、关闭、关闭其他、关闭右侧。
  - 最多同时开 10 个标签，超出时自动关掉最久没用的标签，有未保存修改的标签不会被自动关掉。
  - 浏览器刷新后恢复标签列表和当前标签，其他标签在点开时重新加载。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `system/navigation`：新增三条需求：菜单标签页；跳转后可返回原页面；来源单号的统一规则与显示方式。
- `quotation/quotation`：型号明细去掉「来源询盘」列；表头来源单号（询盘单号）可点开。
- `sales/proforma-invoice`：型号明细去掉「来源询盘」列；表头和列表的来源单号统一。
- `sales/sales-order`：型号明细去掉「来源询盘」列；表头和列表的来源单号统一。
- `product/product`：从单据进入商品详情的返回入口改为全局返回规则，适用于所有来源页面。

## Impact

- **前端**
  - 页面框架（`app.tsx` 的 `childrenRender` 与菜单点击）：新增标签栏、按标签缓存页面、全局返回条，并加一个让页面登记自己标题的钩子。
  - `DocModelCell` 去掉 `docInquiryColumn`。商品详情改用全局返回，`productHref` 不再带 `from` / `fromLabel`。
  - 报价单、形式发票、销售订单的详情和列表页。
  - 采购需求、采购订单、供应商发货、采购入库、暂存、拍摄任务、货运单详情、售后退货、退款申请、应付、报销、收款记录与多收的列名，以及点开来源单号的入口。
- **后端**：只补字段，供前端点开来源单号用：
  - 报价单详情和列表补询盘的 ID 与单号；
  - 形式发票列表补报价单的 ID 与单号。
  - 没有数据库迁移，也没有新增配置项。
- **规范文档**：`AGENTS.md` 和 `.claude/context/ui-design-patterns.md` 增加「跳转页面必须能返回原页面」「上一单据统一叫来源单号」两条规则。
- **原型**：OpenPencil 原型放在 `docs/03-产品原型/03-业务域/11-11来源单号与标签页/`。

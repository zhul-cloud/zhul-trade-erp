## Context

- Excel 渲染（`XlsxRenderer`）把整格数字占位符写成数字单元格；但 openpyxl 转换出的模版单元格是「内联文字」（`t="inlineStr"`），POI 写数字时只加了 `<v>`、没有删掉原来的 `<is>`，生成 `<v>1.0</v><is>${item.no}</is>`：Excel / WPS 优先显示内联文字，LibreOffice 显示数字，所以 PDF、预览正常而 Excel 不正常。同一原因此前已在文字写入上修过（`setText` 先清空）。
- 报价单模版转换时没有保留单元格的富文本，抬头里的小号字体丢失（PI 模版已在上次修正）。
- 字典按平台租户 0 维护、各租户共用，带英文名称 `item_name_en`；前端现有的 `useDictOptions` 只处理整数码值字典。

## Decisions

### 1. 数字单元格先清空再写
`fillCell` 写数字前调用 `setBlank()`，与文字写入一致。用单测直接检查渲染结果的 sheet XML：数字类单元格不含 `<is>`。

### 2. 列宽自适应
展开明细行后，对明细行与费用行里每个有内容的单元格估算显示宽度（中日韩字符按 2 个字符宽、其他按 1 个），列当前宽度不够时加宽，上限 60 个字符宽；合并单元格按合并范围的总宽度判断，不够时加宽范围内最后一列。只加宽、不缩窄，模版里刻意留的宽度不受影响。

### 3. `${fee.no}`
费用行渲染数据加 `fee.no` = 型号行数 + 费用行序号（从 1 起）；报价单与 PI 都提供。

### 4. 文字字典
新增前端 `useDictTexts(dictType)`：返回启用项的编码、中文名、英文名、是否默认。下拉用 AutoComplete（可选可填），保存的是英文名（没有英文名时用中文名）。
- 「交期」字典的编码与货期字典 `inquiry_lead_time` 的编码一一对应（如 `WEEKS_1_2` → `1-2 weeks after payment`），PI 新建时按型号中排序最靠后（最长）的货期找对应项；货期没有对应项时用默认项。
- 「贸易术语地点」只列固定地点（Hong Kong、Fuzhou 等）；DAP 的默认地点取客户国家，不进字典。
- 新建 PI 的默认值在后端生成（交期、付款条件、起运港），前端只在改选贸易术语时联动地点。

### 5. 买方改选范围
`GET /api/v1/sales/pis/{id}/parties` 增加可选参数 `customerId`：不传时为 PI 客户；传入时校验该客户在当前用户的数据范围内（按客户负责人），返回其发票抬头与收货人，并附客户注册信息作为一条「客户注册信息」选项。客户下拉复用现有的客户选择接口。

### 6. 列表的新 / 老客户
三个列表都按来源客户询盘的「新 / 老客户」判断：任一来源询盘为老客户即显示老客户（与报价单详情的判断一致）。总数量为型号行数量之和（PI 取当前展示版本）。

## Risks / Trade-offs

- [列宽按字符数估算，与实际字体渲染略有差异] → 留 2 个字符余量；只加宽，不会把模版排版挤坏。
- [老 PI 的收货人为空] → 只改新建时的默认值，已有 PI 不回填。

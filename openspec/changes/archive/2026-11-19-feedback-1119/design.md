# Design

## Context

- 出运单在新建时就定了货代（`logistics_shipment.forwarder_id`）。货代是不是「客户指定」，看 `supplier.customer_id` 是否为空。
- 登记出运的必填项目前写在 `ShipRequest` 的校验注解里；运费账单按「货代 + 月份 + 已出运 + 未对账」取出运单。
- 利润统计的分组与排序在后端 `ProfitStatsService`，明细一次全部返回。
- 「再下一单」由前端调接口取原订单数据，再预填手动建单表单。

## Goals / Non-Goals

**Goals:** 交客户指定货代的出运单能正常登记、不进对账；利润统计按客户的排序和显示；再下一单能挑型号。

**Non-Goals:**
- 不改发货通知选货代的规则（客户指定货代已经能选）。
- 不改运费分摊的算法。
- 不改再下一单的后端接口。

## Decisions

1. **出运单上记快照 `customer_forwarder`（0/1）**
   - 新建出运单和登记出运时，按货代当时的归属写入。之后修改货代归属，不影响已出运的单据。
   - 运费账单取单时加 `customer_forwarder = 0`。
   - 迁移 V1.5.49 只回填「待出运」的单据（已出运的历史单据保持 0，免得把已经在对账流程里的单据挪出去）。回退：删列。
   - 备选是不存列、每次按货代当前归属判断，但改归属会让历史出运单在对账里忽进忽出，所以不采用。
2. **必填校验从注解移到服务层**
   - `ShipRequest` 去掉 `@NotBlank` / `@NotNull`，保留长度和金额格式校验。
   - 服务层按 `customer_forwarder` 判断：公司货代必填承运商、运单号、运费，提示文案不变；客户指定货代时运费为空按 0 处理。
3. **送货运费沿用 `freight` 字段和国际运费的分摊**：口径就是这票货到客户手上之前我们付的运费，计入订单成本。
4. **利润统计**
   - 按客户分组时改为按收入降序。
   - 分组与订单行补 `customerType`、`customerContact`。分组的新 / 老客户：只要有一张老客户订单就算老客户。
   - 明细分页在前端做（数据已全部返回），每页 10 条。
5. **再下一单**：前端在预填前加选择步骤，按勾选结果过滤型号行和费用行，接口不动。

## Risks / Trade-offs

- **送货运费没有对账入口**：这类出运单没有货代账单，送货运费靠业务员如实登记；随时可改，日志有记录。

## Context

销售订单目前由 PI 转成，内容不可改、只能取消，收款记录挂在 PI 上（`payment_receipt.pi_id`），订单只是展示。这次要把订单变成跟单的主界面：销售日期、现货 / 期货、按型号的采购员与进度、收款进度与付款方式汇总、订单毛利，并支持不经过 PI 手动建单。采购、仓库、物流模块还没有，进度只能人手维护。

## Goals / Non-Goals

**Goals:**
- 订单能回答「什么时候卖的、现货还是期货、每个型号谁在采购、走到哪一步、钱收了多少、赚了多少」。
- 手动建单只填必填项，建好后与转成的订单行为一致（收款、进度、取消）。
- 状态名称与步骤可在字典里调整，不写死在代码里。

**Non-Goals:**
- 不做采购单、入库、发货单据，进度不自动推进。
- 不做订单统计报表（本次只把统计要用的字段存好：销售日期、新 / 老客户、现货 / 期货、线上 / 线下收款）。
- 不允许修改订单的成交内容（仍然走取消重建）。

## Decisions

1. **销售日期**：`sales_order.sales_date`（date）。由 PI 转成时默认取有效水单付款日期与有效到账日期中最早的一个，没有就取当天；转订单弹窗可改，不能晚于当天。存量订单迁移时用同样规则回填。
   - 不用创建时间做统计：客户昨天付款、今天建单的跨月场景会算错。

2. **订单状态 = 字典 + 行进度**：
   - 平台字典 `sales_order_status`（文本码）：`PENDING_PURCHASE` 待采购、`ORDERED` 已下单、`RECEIVED` 已入库、`TO_FORWARDER` 已交货代、`SHIPPED` 已出运、`COMPLETED` 已完成、`CANCELLED` 已取消。三个内置码（待采购、已完成、已取消）在字典页不可停用，代码里只认这三个码，其余步骤顺序全部按字典 `sort_order`。
   - 进度存在型号行上：`sales_order_item.progress_code`；订单级 `sales_order.progress_code` 冗余存「最靠前的行进度」，便于列表筛选，每次改行进度时在同一事务内重算。
   - 原 `status`（1-有效、2-已取消）保留，取消仍走原逻辑；列表显示的订单状态：已取消 → 「已取消」，否则显示 `progress_code` 的字典名称。
   - 「客户已收货」：要求所有行进度都在最后一个启用的进行中步骤（按 sort_order 排在「已完成」之前的最后一个启用项），然后把订单 `progress_code` 置为 `COMPLETED`、记 `completed_at`。行进度不变。
   - 停用某中间步骤后，已经处于该步骤的行仍显示原名称，推进时不再出现这个选项。
   - 备选：订单只有一个整单状态。放弃原因：一单多采购员时各型号进度不同（你确认的场景），整单状态说不清卡在哪个型号。

3. **采购员**：`sales_order_item.purchaser_id`（可空）。转订单时取 `quotation_item.cost_quote_id → sourcing_quote.quoted_by`；没有回价（手填成本）为空。列表筛选用 `exists` 子查询，列表上采购员名称在 Service 层批量组装，不 JOIN 超过 3 张表。

4. **现货 / 期货**：`sales_order_item.stock_type`（1-现货、2-期货）。转订单时货期码为 1（现货）的为现货，其余为期货。订单级 `sales_order.stock_type` 冗余（任一行期货即期货），改行时重算。
   - 假设：「1-2天」这类短货期也算期货（需要向供应商订货）。如果你们口径是「仓库里有就算现货」，转订单后手动改即可。

5. **新 / 老客户**：`sales_order.customer_type`（1-新客户、2-老客户）快照。转订单取来源询盘的 `customer_type`（多个询盘取第一行的）；手动建单按该客户此前是否有有效订单判断。

6. **手动建单**：`sales_order.source`（1-PI 转成、2-手动创建），`pi_id` 为 0。型号行只存型号、品牌、数量、单价、成本价、采购员、现货 / 期货；没有费用、折扣，买方 / 收货人取客户档案快照。汇率取系统汇率，没有汇率时拒绝。编号与转成的订单共用规则。

7. **手动订单的收款挂在订单上**：`payment_receipt` 增加 `so_id`（可空）。
   - PI 收款：`pi_id` 有值、`so_id` 为空（转成的订单仍通过 PI 取收款，不回写 `so_id`，取消重转时不用搬记录）。
   - 手动订单收款：`so_id` 有值、`pi_id` 为空。
   - 未认领：两者都为空（原来只判断 `pi_id` 为空，要改）。
   - 收款服务抽出「收款归属」（PI 或订单），水单、确认、平台收款、认领、作废的校验与金额规则共用；收款状态计算改为按归属汇总。
   - 「收款管理」列表编号一栏：有 PI 显示 PI 编号，否则显示订单编号，点击跳到对应详情。
   - 备选：手动建单时自动生成一张隐藏 PI。放弃原因：PI 是对客户的单据，有版本、有效期、导出，造一张假的会污染 PI 列表与统计。

8. **订单毛利**：详情接口实时计算，不落库。
   - 采购成本 = Σ（行成本价 × 数量），CNY；有行缺成本价时返回缺失个数。
   - 实收人民币 = 有效收款的 `net_amount_cny` 合计。
   - 收款状态「已到账」：毛利 = 实收人民币 − 采购成本；否则预计毛利 = `total_amount_cny` − 采购成本。
   - 中间计算用 BigDecimal 完整精度，结果 HALF_UP 保留 2 位。
   - 与 PI 上已有的「净利润」口径不同（那个是报价时按成本与售价估的），订单上统一叫「毛利」，两者不混用。

9. **付款方式汇总**：详情接口按收款记录的 `payment_method_name` 分组汇总毛额（有效记录），线上在前。

10. **权限**：新增按钮「手动创建订单」`sales:order:create`、「更新订单进度」`sales:order:progress`，挂在销售订单菜单下，授予现有有销售订单菜单的角色；采购员要能更新进度，就需要给采购角色授予销售订单菜单（只读其数据范围内的订单）——本期不改采购角色，由管理员按需配置。

## Risks / Trade-offs

- [未认领判断从 `pi_id is null` 改为两者都为空，漏改一处就会把手动订单收款当成未认领] → 契约测试覆盖：手动订单收款后未认领列表不出现；认领时校验两者都为空并加行锁。
- [订单级冗余字段（进度、现货 / 期货）与行不一致] → 只在一个 Service 方法里改行并重算，测试覆盖批量推进后的订单级值。
- [字典被改乱（比如把「已出运」排到「待采购」前面）] → 通用字典页不做顺序校验；订单侧固定把「待采购」当作第一步、「已完成」当作终点，中间步骤按 sort_order 排，最差只是步骤顺序不符合直觉，不会算错状态。

## Migration Plan

- 新迁移脚本：加字段与索引（`sales_date`、`progress_code`、`stock_type`、`customer_type`、`source` 加索引；行上 `purchaser_id` 加索引；`payment_receipt.so_id` 加索引）、字典、按钮权限。
- 回填存量订单：销售日期按决策 1；行进度「待采购」（已取消订单也填，不显示）；采购员按决策 3；现货 / 期货按决策 4；新 / 老客户按决策 5；`source` = 1。
- 回滚：字段都有默认值，旧代码忽略新字段即可。

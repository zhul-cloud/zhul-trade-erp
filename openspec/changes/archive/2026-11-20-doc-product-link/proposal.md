## Why

接下来要做零售标准的库存模块（库存按型号记 SKU、按批次计价、月结），库存的每一笔进出都必须落到一个确定的商品上。现在只有询盘型号和手动建的销售订单行有 `product_id`，而且只在商品库已有这个型号时才填（本机 21909 个询盘型号只关联了 211 个，3237 个订单行只关联了 1 个）；报价、PI、采购、仓库、售后的明细只存型号和品牌文字，页面靠「品牌 + 型号」现查商品库。原因是商品 ID 要到候选审核建档时才产生，大部分询进来的型号一直停在候选池里。

用户 2026-11-20 决定：询盘确认的型号进入商品候选时就生成 `product_id`，单据一律引用它；之后审核建档、补全资料都沿用这个 ID；审核时发现是重复型号要并入已有商品的，用「商品合并」把单据（以后还有库存）转到主商品。这是库存模块的前置变更。

## What Changes

- **候选即商品**：型号进入候选池时，同时在商品库生成一条「候选」状态的商品（`product_id` 从这里开始被引用）。商品增加建档状态：候选 / 已建档 / 已并入 / 已驳回。品牌没识别的也能生成，按「品牌键 + 归一化型号」唯一（与候选池同一套规则）。
  - 审核建档：同一个 ID 改为「已建档」，补品牌、品类、系列等资料；审核时可以改品牌和型号（候选状态不受「被引用后不可修改」限制）。
  - 改完和已有商品重复，或直接「并入已有商品」：生成一张**商品合并记录**，把所有单据明细改指向主商品，原商品标「已并入 → 主商品」，以后按原 ID 查到的都转到主商品。
  - 驳回：只有还没进入销售订单及之后单据的候选才能驳回；已经成交、采购或出入库过的只能建档、改正或并入。
- **单据明细统一关联商品**：询盘型号、报价、PI、销售订单、采购需求、采购订单、供应商发货、采购入库、到货差异、销售出库、售后单、销售退货、退货入库、采购退货的明细都带 `product_id`，由上一张单据带下来，不再按文字现查。
  - 转销售订单时每个型号必须已有商品（写法不像型号、待回填真实型号的先回填）；手动建单从商品库选。
  - 历史单据一次性回填：能匹配的关联，像型号但商品库没有的先生成候选商品；仍关联不上的列入「待关联」清单，由商品运营处理。
- **商品库只认已建档**：商品列表、发品、内容、SEO、资料完整度、需求热度等只算「已建档」的商品；型号匹配与选择器能找到候选商品，并标「候选」。
- **单据显示**：明细的型号旁对候选商品标「候选」，点开进入候选审核；已并入的显示主商品。

## Capabilities

### New Capabilities
- `product/document-product-link`：单据明细统一关联商品——各单据带 `product_id` 的范围与传递规则、转销售订单前的型号要求、历史回填与待关联清单、单据上的候选标记。

### Modified Capabilities
- `product/product-candidate`：候选进池时即生成候选商品；建档沿用同一 ID；并入改为商品合并；驳回限制；审核可改品牌型号并在重复时转为并入。
- `product/product`：商品增加建档状态与「已并入 → 主商品」；唯一键改为品牌键 + 归一化型号；候选状态商品可改品牌型号；商品合并记录；商品列表与发品等只算已建档。
- `product/product-lookup`：型号匹配与选择器包含候选商品并标「候选」，已并入的转到主商品。
- `inquiry/inquiry-intake`：「确认询盘时自动建档」——进候选池的询盘型号同时关联到候选商品。

## Impact

- **数据库**：
  - `product` 增加建档状态、品牌键、并入目标，唯一键调整。
  - 新增商品合并记录表。
  - 报价、PI、采购需求、采购订单、供应商发货、采购入库、到货差异、销售出库、售后、销售退货、退货入库、采购退货的明细表增加 `product_id`（带索引）。
  - 历史数据回填：候选池现有约 9.6k 条（本机），会各生成一条候选商品。
- **后端**：
  - `ProductArchiver`（进池即建商品）、`ProductCandidateService`（建档、并入、驳回）、商品合并服务。
  - `ProductLookupService`，以及各单据生成时的 `product_id` 传递（PI 转订单、需求生成、下单、发货、入库、出库、售后、退货）。
  - 商品相关查询加建档状态过滤：涉及商品模块与 `supply`、`listing`、`media` 共约 25 个文件。
  - 取消 `DocItemProducts` 的文字现查。
- **前端**：
  - 商品候选页（候选商品编号、引用情况、驳回限制、并入影响确认）。
  - 单据明细型号列的「候选」标记，商品选择器的候选标记。
  - 待关联清单。
- **原型**：`docs/03-产品原型/03-业务域/26-单据统一关联商品/`。
- **后续**：库存模块（仓库档案含货代仓、批次、流水、余额、自动过账、成本调整、月结、台账、并入闲置库存）另开变更。商品合并在库存模块里扩展为库存转移。

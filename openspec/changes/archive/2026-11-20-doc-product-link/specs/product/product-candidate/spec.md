## MODIFIED Requirements

### Requirement: 商品候选池
系统 SHALL 维护平台级的商品候选池，存放商品库中还没有的「品牌 + 型号」。同一品牌（已识别时按品牌 ID，未识别时按忽略大小写与首尾空格的品牌名）加归一化型号（与商品主数据同一套归一化规则）只占一条候选，候选状态为待审核、已建档、已并入、已驳回之一。每次该型号出现都追加一条来源记录，记录来源类型（询盘、采购回填真实型号、采购回价有货、成交，预留手动、导入）、所属租户、来源单据（询盘单与询盘型号、销售订单）与时间。候选保存品牌原文、识别到的品牌、原始型号、建议品类、建议名称与描述（取询盘型号的中英文描述）、首次与最近出现时间。商品库中已有（品牌与归一化型号相同、未删除）的型号不进入候选池。

候选进池时，系统 SHALL 在同一事务内为它在商品库生成一条建档状态为「候选」的商品（品牌键、原始型号、归一化型号、建议品类、名称与描述取自候选），候选记录这个商品 ID；来源询盘型号及其后的单据明细都引用这个 ID（见 `product/document-product-link`）。品牌没识别的候选同样生成候选商品，品牌显示为「待确认品牌：原文」。

建议品类：询盘型号已关联品类（启用、未删除）时直接用它；否则按品类匹配规则由询盘的品类文字得出。品类匹配规则：品类文字与品类的中文名、英文名、编码比较（忽略大小写与首尾空格），依次按三轮，哪一轮有结果就用哪一轮：①精确相等（两级品类都比）；②一级品类名包含品类文字，或品类文字包含一级品类名；③细分品类名包含品类文字，或品类文字包含细分品类名（不足 3 个字的细分品类名只能精确相等或包含品类文字，不因品类文字里含有它而命中）。一轮的命中结果按所属一级品类归并：命中多个一级品类时不建议（留空由审核人选择）；只命中一个一级品类时，其中恰好命中一个细分品类就建议该细分品类，否则建议该一级品类；第②轮命中一级品类后，再在它的细分品类里按第③轮的比较方式找，恰好命中一个就细化为该细分品类。品类文字为空或三轮都没命中时建议兜底品类「其他」。系统启动时，对建议品类为一级品类的待审核候选按上述规则重算一次，结果是该一级品类下的细分品类时更新为细分品类。

#### Scenario: 同一型号多次出现只占一行

- **GIVEN** 候选池里已有 Siemens / 6ES7214-1AG40-0XB0
- **WHEN** 另一张询盘确认时出现型号「6ES7 214-1AG40-0XB0」，品牌写「西门子」（Siemens 的别名）
- **THEN** 不新增候选，原候选追加一条询盘来源，最近出现时间更新

#### Scenario: 品牌没识别也能进池

- **WHEN** 询盘型号的品牌写「Hengstler」，品牌库里没有也没有这个别名
- **THEN** 进入候选池，品牌显示为「待确认品牌：Hengstler」

#### Scenario: 匹配不到的型号归入其他

- **WHEN** 询盘型号的品类文字写「轴承」，或没有写品类
- **THEN** 进入候选池时建议品类为「其他」

#### Scenario: 能确定细分品类时建议细分

- **WHEN** 询盘型号没有关联品类，品类文字写「伺服驱动器」
- **THEN** 建议品类为细分品类「伺服驱动器」（一级「伺服与运动」）

#### Scenario: 优先用询盘型号已关联的品类

- **WHEN** 询盘型号已关联细分品类「中间继电器」，品类文字是「继电器」
- **THEN** 建议品类为「中间继电器」

#### Scenario: 一级品类名优先

- **WHEN** 询盘型号没有关联品类，品类文字写「继电器」（一级「继电器与信号接口」包含它，其下「中间继电器」「固态继电器」等多个细分品类也包含它）
- **THEN** 建议品类为一级品类「继电器与信号接口」

#### Scenario: 同时命中多个品类时留空

- **WHEN** 询盘型号的品类文字同时匹配到两个一级品类
- **THEN** 建议品类留空，审核时由运营选择

#### Scenario: 已有候选细化到细分品类

- **GIVEN** 一个待审核候选的品类文字是「伺服电机」，此前建议为一级品类「伺服与运动」
- **WHEN** 系统重启
- **THEN** 该候选的建议品类更新为细分品类「伺服电机」；已建档、已并入、已驳回的候选不受影响

#### Scenario: 进池即生成候选商品
- **WHEN** 确认的询盘里有 ABB「AX32-30-10-80」，商品库没有
- **THEN** 候选池出现 ABB / AX32-30-10-80，同时商品库生成一条「候选」状态的商品，询盘型号关联到这个商品 ID

### Requirement: 候选审核

系统 SHALL 提供「商品候选」页面审核候选，按待审核、已建档、已并入、已驳回分页签，各页签都把待确认品牌（品牌库里没有、也不是别名）的候选排在最后，其次是还没选品类的，再按可信度从高到低、更新时间倒序；可以按品牌筛选「品牌已确认」或「待确认品牌」，按品类筛选「已选品类」或「未选品类」，方便先批量审核能直接通过的型号。各页签显示条数，按当前的筛选条件统计，与筛选后的列表一致。列表显示每个候选的来源：来源类型（询盘、采购回填真实型号、采购回价有货、成交等）与对应的询盘单号、销售订单号，最近的 3 条，更多的显示条数；租户账号只显示本公司的来源。列表固定显示创建时间、创建人、更新时间、更新人四列（在业务字段之后、操作列之前）。审核操作：
- 通过建档：品牌必须是已有品牌（未识别的品牌可以在审核时就地设为已有品牌的别名，或新建品牌，新建时可修改名称，原文自动成为别名）；品类必须从现有品类中选；系列可选，可选该品牌已有系列或输入名称新建；可修改原始型号、展示型号、商品名称与简短描述（默认取来源询盘型号的中文描述）；生命周期必填，按来源询盘型号里采购最近核实的生产状态自动填写（在产 → 在产；停产 → 已停产，依据自动写「采购询价核实停产」及替代型号；都待查 → 未知），可改，已停产、停产无替代须填写依据。批量通过时生命周期同样自动填写。通过后候选对应的候选商品改为「已建档」并补齐以上资料，商品 ID 不变，候选变为已建档。审核时可以修改品牌与型号（候选状态的商品不受「被引用后品牌与型号不可修改」的限制）；改完后与另一个已建档商品的品牌与归一化型号相同时，提示「将并入 X」并列出引用这个候选商品的单据数，确认后按并入处理。
- 并入已有商品：选择一个已建档商品（如相近写法），确认前列出引用这个候选商品的单据数；确认后按 `product/product` 的「商品合并」把候选商品并入所选商品，候选变为已并入并记录主商品。
- 驳回：只有候选商品还没被销售订单及之后的单据（采购、仓库、售后）引用时才能驳回，否则提示「已有订单使用，只能建档或并入」。原因为不是型号、型号错误或其他（其他须填写说明），候选变为已驳回，候选商品标为已驳回，询盘型号与报价、PI 明细上的关联随之去掉；该品牌与型号以后再出现时只追加来源，不回到待审核。已驳回的候选可以重新打开为待审核。
- 批量通过：勾选品牌与建议品类都已确定的待审核候选，一次通过建档。点「批量通过」时先检查勾选的候选：有还没选品类或品牌待确认的，先列出这些型号及原因，确认后只通过其余的（这些跳过）；全部都不满足时只提示、不提交。
建档时引用候选商品的单据明细不需改动；并入时随商品合并改为引用主商品。审核前若商品库已出现相同品牌与型号的商品，通过建档改为并入该商品。每次审核记录审核人、时间与操作日志。第一期不提供满足条件自动通过。

#### Scenario: 通过建档并回填关联

- **GIVEN** 候选 ABB / AX32-30-10-80 有两条询盘来源
- **WHEN** 运营选品类「接触器」并通过建档
- **THEN** 候选商品 ABB / AX32-30-10-80 改为已建档，商品 ID 不变，候选变为已建档，两个来源询盘型号仍关联这个商品

#### Scenario: 审核时新建品牌

- **GIVEN** 候选品牌为「待确认品牌：B&R Automation」
- **WHEN** 运营在审核时选择新建品牌，名称改为「B&R」，并通过建档
- **THEN** 品牌库新增 B&R，「B&R Automation」成为它的别名，商品建在 B&R 下

#### Scenario: 驳回后不再进入待审核

- **GIVEN** 候选「Contactor, 32A」被以「不是型号」驳回
- **WHEN** 之后又有询盘出现同样的写法
- **THEN** 只追加来源，候选仍为已驳回

#### Scenario: 批量通过跳过品类未定的

- **WHEN** 运营勾选 5 个候选批量通过，其中 1 个没有建议品类
- **THEN** 4 个建档成功，1 个保持待审核并提示「品类未选」

#### Scenario: 列表显示来源

- **GIVEN** 候选有本公司一次询盘 IQ20261002001 与一张成交订单 SO20261008005
- **WHEN** 运营打开商品候选列表
- **THEN** 该行来源列显示「成交 SO20261008005」「询盘 IQ20261002001」

#### Scenario: 按可信度与更新时间排序

- **WHEN** 运营打开待审核页签
- **THEN** 已成交的候选排在采购问到有货的前面，再前于询盘出现的；同一可信度按更新时间从新到旧排列

#### Scenario: 待确认品牌排在最后

- **WHEN** 待审核页签里有品牌已确认的「询盘出现」候选，和待确认品牌的「已成交」候选
- **THEN** 品牌已确认的排在前面；筛选「待确认品牌」时只列出待确认品牌的候选

#### Scenario: 没选品类的排在已选品类的后面

- **WHEN** 待审核页签里有已选品类的「询盘出现」候选，和还没选品类的「已成交」候选，品牌都已确认
- **THEN** 已选品类的排在前面；筛选「未选品类」时只列出还没选品类的候选

#### Scenario: 生命周期自动填写

- **GIVEN** 候选的来源询盘型号被采购核实为停产，替代型号 RI58-O/2048ER
- **WHEN** 运营打开审核
- **THEN** 生命周期默认为「已停产」，依据为「采购询价核实停产，替代型号 RI58-O/2048ER」，通过建档后商品带上该生命周期

#### Scenario: 名称默认中文

- **WHEN** 运营打开审核，来源询盘型号有中文描述
- **THEN** 商品名称与简短描述默认填中文描述

#### Scenario: 改型号后与已有商品重复转为并入
- **GIVEN** 候选 Siemens / 6ES7214-1AG40-0XBO（最后一位写成字母 O）已被 1 张销售订单、1 张采购订单引用，商品库已有 Siemens / 6ES7214-1AG40-0XB0
- **WHEN** 运营在审核时把型号改为 6ES7214-1AG40-0XB0 并点通过建档
- **THEN** 提示「将并入 Siemens / 6ES7214-1AG40-0XB0，2 张单据随之改为引用它」，确认后候选变为已并入，两张单据的明细都引用已有商品

#### Scenario: 已成交的候选不能驳回
- **GIVEN** 候选 ABB / AX32-30-10-80 的候选商品已被销售订单 SO20261120001 引用
- **WHEN** 运营点驳回
- **THEN** 提示「已有订单使用，只能建档或并入」，不驳回

## Context

- 明细台账由库存查询服务按「商品」汇总流水得到：未结账月份实时按业务日期聚合 `inv_move`，已结账月份读 `inv_period_ledger` 快照（每行 商品 × 仓库，仓库 0 为全部仓库合计）。查询条件只有月份、仓库、关键词。
- 销售成本快照 `inv_period_cogs` 每行带商品，没有仓库。
- 商品品类：`product.category_id` 指向 `product_category`，平台共享。品类只有两层：一级品类 `parent_id` 为空，二级品类的 `parent_id` 指向一级。本机 17 个一级、140 个二级；商品有挂一级的、挂二级的，也有没品类的（约 9%）。
- 库存月结的五项汇总已取自全部仓库明细台账的合计（inventory-costing），类目账合计天然与它一致。

## Goals / Non-Goals

**Goals:**
- 类目账、明细账、月结汇总三者同源（都来自同一份明细台账），合计必然相等，不另起一套聚合口径。
- 已结账月份的类目账不随商品改品类而变。

**Non-Goals:**
- 不按二级品类汇总，不做品类树展开。
- 类目账不显示数量合计（不同型号的数量相加没有意义），只列商品数。
- 不新增菜单、权限与接口版本。

## Decisions

1. **类目账在服务端由明细台账再汇总。** 取该月、该仓库全部商品的明细台账（未结账实时、已结账快照，即现有的不分页台账），按商品的一级品类分组求和。
   - 为什么：与明细账、月结汇总同源，合计一致不用额外保证；品类数少（≤ 18 行），不需要分页。
   - 备选：单独写按品类分组的 SQL 聚合 `inv_move`。拒绝：要重复入库、出库、调拨抵消、成本调整这些规则，两套口径容易对不上。

2. **一级品类的解析。** 商品品类的 `parent_id` 为空即为一级；不为空取上级；没有品类或品类已删除记为 0，显示「未分类」。解析放在库存的商品标签服务里，与型号、品牌、品类名一起批量取，避免逐行查询。

3. **快照加品类列。** `inv_period_ledger`、`inv_period_cogs` 各加 `category_l1_id`（bigint，0 为未分类），结账时按当时的商品品类写入。已结账月份的类目账、明细账的品类筛选都用这一列。
   - 为什么：快照的意义就是结账后不变；商品改品类（品类细分、人工调整）很常见，不能读当前品类。
   - 迁移：按商品当前品类回填已有快照行（上线前结过的月份），这些月份结账时间很近，品类基本没变。

4. **销售成本按品类。** 实时月份由当月销售成本明细按商品品类求和；已结账读 `inv_period_cogs` 的品类列。只在「全部仓库」时显示，因为销售成本没有仓库维度。

5. **接口。**
   - `POST /api/v1/warehouse/ledger/category`，入参 `{month, warehouseId}`，返回各品类行与合计行，权限同库存台账（`canAccessMenu('/warehouse/ledger')`）。
   - 明细台账 `LedgerQuery` 加 `categoryId`（一级品类 ID，0 为未分类）。
   - 导出：`/ledger/export` 加 `view` 参数（`category` / `detail`），沿用现有导出。
   - 月结：`GET /api/v1/finance/periods/{month}/category-ledger`；月结导出在库存台账表之前加「类目账」表。

6. **前端。**
   - 库存台账页顶部用分段控件切换「类目账 / 明细账」，切换记在地址参数里（`?view=category`），返回时保持。默认进入明细账，不改变仓库人员的使用习惯。
   - 类目账表头按算式写「期初金额 | + 本月入库 | − 本月出库 | + 在库成本调整 | = 期末金额」，商品数与销售成本放在算式之后、用次要文字色；合计行加粗，标「总账合计」。
   - 点品类行切到明细账，并带上 `categoryId`。明细账加一级品类下拉，品类列表来自现有品类接口，只取一级。
   - 月结详情在「库存台账」之前加「类目账」页签，复用同一个表格组件；点品类打开库存台账页（明细账、月份、品类）。

## Risks / Trade-offs

- [商品数量多时，类目账要先算全部商品的明细台账] → 现有不分页台账本来就给月结用，规模在几千商品以内；后续数据量大再加按品类的月度汇总缓存。
- [回填的旧快照品类取当前品类，与结账时可能不同] → 只影响本次上线前已结账的少数月份，且品类近期没有批量调整；在 PR 说明中写明。
- [未分类占比约 9%，类目账里「未分类」可能金额不小] → 这是数据真实状态，点进去能看到具体商品，促使补全品类；不在本变更里自动归类。

## Migration Plan

- 迁移 V1.5.57：两张快照表加 `category_l1_id`（默认 0）与索引，按商品当前品类回填。
- 回退：删除两列（手动语句写在迁移文件末尾），代码回退到上一版本即可，快照的其他数据不受影响。
- 无新配置项。

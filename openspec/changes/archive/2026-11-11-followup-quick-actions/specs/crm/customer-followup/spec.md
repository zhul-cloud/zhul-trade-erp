## ADDED Requirements

### Requirement: 今日待办分批加载与全选
今日待办 SHALL 按「已逾期」在前、「今天」在后的顺序，先显示 20 个客户；还有没显示的客户时，底部显示「再加载 20 个 · 还有 n 个」，每点一次多显示 20 个。顶部「已逾期 n · 今天 n · 本周还有 n」的数字始终按全部客户计算，不受加载数量影响。按「已逾期」或「今天」筛选后，同样每次 20 个。

批量操作条左侧 SHALL 提供「全选」勾选框：
- 勾上后选中当前已加载、可以勾选的全部客户，最多 50 个；超过 50 个时只选前 50 个，并提示「一次最多选 50 个客户，已选前 50 个」；
- 已加载的客户全部选中时显示为勾上，部分选中时显示为半选；再点一次取消全部选择；
- 加载更多后，新加载的客户不自动选中；
- 「今天已跟进」里的客户不参与全选。

#### Scenario: 先显示 20 个
- **WHEN** 业务员今天有 37 个逾期客户、52 个今天到期的客户
- **THEN** 列表显示 20 个逾期客户，底部显示「再加载 20 个 · 还有 69 个」，顶部仍显示「已逾期 37 · 今天 52」

#### Scenario: 全选超过上限
- **WHEN** 业务员已加载 60 个客户，点「全选」
- **THEN** 选中前 50 个客户，提示「一次最多选 50 个客户，已选前 50 个」

#### Scenario: 加载更多后全选状态
- **WHEN** 业务员全选了已加载的 20 个客户，再点「再加载 20 个」
- **THEN** 新出现的 20 个客户不勾选，「全选」显示为半选

### Requirement: 下一步日期推荐
「记一次跟进」「批量跟进」「快速跟进」的「什么时候」SHALL 默认选好一个推荐日期，并在旁边说明理由，例如「报价后第 7 天」。推荐规则：

| 情况 | 推荐日期 |
| --- | --- |
| 报价后（S4–S6） | 系统提醒节奏中今天之后的下一个节点（第 1、3、7、14 天）；都过了取 7 天后 |
| PI 后（S7） | 客户说的付款日（在今天之后时）；否则按 PI 提醒间隔 |
| 主动开发 D4、D5 | 触达序列中今天之后的下一个节点 |
| 客户经营 | 按客户经营提醒节奏的下一次日期 |
| 其他阶段 | 今天 + 该阶段参考天数（至少 1 天，最多 14 天）；参考天数为 0 或没有时 3 天后 |

勾选的客户情况会调整推荐日期：
- 选了「客户在谈条件」时推荐明天；
- 选了「没回复」时取上表日期与 3 天后中较早的一个。

多张单据一起记时，取各单据推荐日期中最早的一个。业务员手动选过日期后，推荐日期不再自动变化。

快捷选项 SHALL 为：今天、明天、3 天后、下周、2 周后、1 个月后、3 个月后，以及指定日期。所选单据中有报价后的单据、且选择的日期在 30 天及以后时，日期下方提示「隔这么久再跟，可以直接转培育」，并提供「改为转培育」入口。

#### Scenario: 报价后默认日期
- **WHEN** 报价单 11-01 发送，业务员 11-05 打开记跟进
- **THEN** 「什么时候」默认选中 11-08，旁边显示「报价后第 7 天」

#### Scenario: 没回复缩短
- **WHEN** 同一张报价单，业务员勾选「没回复」
- **THEN** 推荐日期改为 11-08 与 3 天后中较早的一个

#### Scenario: 手动选过不再变
- **WHEN** 业务员先点了「2 周后」，再勾选「客户在谈条件」
- **THEN** 日期保持 2 周后

#### Scenario: 长时间提示转培育
- **WHEN** 业务员对一张 S4 报价单选「3 个月后」
- **THEN** 日期下方提示「隔这么久再跟，可以直接转培育」，点「改为转培育」打开转培育弹窗，激活日期带入所选日期

### Requirement: 手动调整阶段
系统 SHALL 允许业务员手动调整跟进对象的阶段，但只能在同一个「判断段」内前进或后退。判断段是指全靠业务员判断、没有单据作依据的相邻阶段：

| 板块 | 可以互相调整的阶段 |
| --- | --- |
| 商机成交 | S1、S2；S4、S5、S6 |
| 主动开发 | D4、D5、D6 |

其他阶段（S3、S7，履约 F1–F6，售后 A1–A6，开发 D1–D3、D7，客户经营 G1–G7）由单据或专门的操作推进，不能手动调整：售后 A1、A2 由签收日期和订单完成状态推导，客户经营阶段由订单与联系记录推导，手动改了也会被下一次同步改回。

入口为跟进对象阶段标签旁的「调整阶段」。弹窗列出本段可选的阶段，并要求选择理由：
- 历史数据阶段不对；
- 系统判断滞后；
- 客户情况变化；
- 其他（必须补充说明，≤200 字）。

保存后 SHALL 在同一事务内：
- 改跟进对象阶段，停留天数从当天重新计算；
- 写一条跟进记录，标题为「调整阶段：S4 → S6」，记下理由、调整前后的阶段，不改下一步和下一步日期；
- 跟进对象属于进行中商机的，商机阶段同步调整，阶段记录写「手动调整：理由」。

不能调整的阶段，阶段标签旁显示「到下一阶段：还差 …」，并给出对应入口，例如 S3「生成报价单后进入 S4 · 去报价」、S6「发送 PI 后进入 S7 · 去开 PI」。

手动调整之后，系统的自动推进仍然只前进不回退，从调整后的阶段开始计算。

#### Scenario: 历史客户跳到谈判
- **WHEN** 迁移进来的客户报价单在 S4，业务员调整到 S6，理由选「历史数据阶段不对」
- **THEN** 报价单跟进对象变为 S6，停留天数为 0；客户时间线新增「调整阶段：S4 → S6 · 历史数据阶段不对」

#### Scenario: 客户情况变化后退
- **WHEN** 商机在 S6，客户说要重新比价，业务员调整到 S5，理由选「客户情况变化」
- **THEN** 商机和跟进对象都回到 S5，商机阶段记录写「手动调整：客户情况变化」

#### Scenario: 单据推进的阶段不能调
- **WHEN** 跟进对象在 S3
- **THEN** 不显示「调整阶段」，阶段标签旁显示「到下一阶段：生成报价单后进入 S4 · 去报价」

#### Scenario: 其他理由必须说明
- **WHEN** 业务员选理由「其他」但不填说明
- **THEN** 提示「请写明调整原因」，不保存

### Requirement: 快速跟进
系统 SHALL 按阶段提供「快速跟进结果」。每个结果预先定好客户情况或阶段答案、下一步文字和下一步日期，用于已经和客户沟通过、只需要在系统里补记的场景：

| 阶段 | 可选结果 |
| --- | --- |
| S1 | 客户回复了（→ S2）；没回复 |
| S2、S3 | 已和客户沟通；没回复 |
| S4 | 客户给了反馈（→ S5）；没回复 |
| S5 | 客户在谈条件（→ S6）；还在比较；没回复 |
| S6 | 还在谈；没回复 |
| S7 | 客户说在安排付款；没回复 |
| F1–F6、A3、A4 | 已同步进度给客户 |
| A1 | 已收到，没问题（→ A2） |
| A2 | 正常使用（→ A5）；还没开始用 |
| A6 | 已评价；婉拒评价；还没评 |
| D4 | 已发出触达（→ D5） |
| D5 | 客户回复了（→ D6）；没回复 |
| D6 | 保持联系；没回复 |
| G4、G6、G7 | 近期没有项目；没回复 |

下一步文字取该阶段 SOP 的默认动作；下一步日期按「下一步日期推荐」，并按所选结果调整。需要补充细节的结果 SHALL 不提供快速记录，只能通过「记一次跟进」填写：有问题（建售后单）、还没收到（要填新的预计送达日）、满意度、出现采购信号、明确拒绝、客户有新需求、聊了新品类。D1–D3、D7、G5 不提供快速跟进。

快速跟进有两个入口：
- **单个**：今日待办客户卡片和跟进列表客户行上的「已跟进」按钮，下拉列出该板块到期单据所在阶段的结果，选一个即保存，作用于这个客户在该板块的到期单据（列表中为本板块全部单据）；所选单据阶段不同时，只列出各阶段都有的结果；没有共同结果时，下拉里提示「单据阶段不同，请用记一次跟进」。
- **批量**：勾选多个客户后，批量操作条上的「快速跟进」。弹窗按阶段分组列出客户数，每组选一个结果（可以选「跳过」）；所有分组共用一个「实际沟通日期」；一次提交，每个客户写一条跟进记录，一个客户失败不影响其他客户，结果列出成功数和失败原因。上限与批量跟进相同（50 个客户）。

快速跟进写入的跟进记录 SHALL：
- 标记为「快速记录」，客户时间线显示「快速记录」标签；
- 记下实际沟通日期：默认今天，可选今天以前最多 30 天，不能选以后；
- 其他效果与「记一次跟进」相同：更新下一步和日期、按结果推进阶段、关闭待办。

团队视图的跟进次数 SHALL 分开显示其中的快速记录数，例如「跟进 42 次（快速 18）」。

#### Scenario: 单个快速跟进
- **WHEN** 业务员在今日待办 ADORA 的卡片上点「已跟进」，选「客户给了反馈」，ADORA 有 2 张 S4 报价单到期
- **THEN** 写入 1 条快速记录，2 张报价单推进到 S5，下一步为 S5 的 SOP 默认动作，日期按推荐规则；ADORA 从今日待办消失

#### Scenario: 批量按阶段分组
- **WHEN** 业务员勾选 12 个客户，其中 5 个在 S4、3 个在 S5、4 个在 A1，点「快速跟进」，S4 选「没回复」、S5 选「跳过」、A1 选「已收到，没问题」，实际沟通日期选 11-07
- **THEN** 9 个客户各写入 1 条快速记录，实际沟通日期为 11-07；A1 的 4 个推进到 A2；S5 的 3 个不变；结果显示「已记 9 个，跳过 3 个」

#### Scenario: 不提供需要细节的结果
- **WHEN** 业务员对 A1 的客户点「已跟进」
- **THEN** 下拉只有「已收到，没问题」，没有「有问题」「还没收到」；需要记录问题或新的送达日时点「记一次跟进」

#### Scenario: 实际沟通日期不能是以后
- **WHEN** 业务员把实际沟通日期选为明天
- **THEN** 日期选择器不能选，保存时以今天为准

#### Scenario: 团队视图区分快速记录
- **WHEN** 业务员本周记了 42 次跟进，其中 18 次是快速记录
- **THEN** 主管在团队视图看到「跟进 42 次（快速 18）」

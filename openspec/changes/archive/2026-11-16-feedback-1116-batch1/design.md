# Design

## Context

- **联系人名翻译**：`ContactNameTranslations` 已经能提交翻译任务、在回调里回填译名，只写仍为空的字段，key 带校验码（`AiTaskKeys`）。编排服务里对应的技能是 `translate-contact-names`，提示词针对人名。
- **字段来源**：画像字段来源存在 `customer_field_source`，按字段 key 记录来源（人工 1、背调 2、迁移 3、跟进 4），不需要改表就能增加新来源。
- **费用单**：现在有公司对公（生成应付，之后在应付付款）和员工垫付（进报销）两种付款方式。
- **私对私付款**：供应商付款已经支持私对私。付款单上有付款账户（`bank_account_id`、`payer_account` 快照）和对方账户快照（`payee_account`）。
- **客户列表**：已有 `profile_mask`（五个模块的完成位）和建档状态筛选。

## Goals / Non-Goals

**Goals:**
- 客户中文名称的翻译不阻塞保存，失败可以重试。
- 私对私费用的账务和现有付款单口径一致：生成应付和付款单，计入付款记录与银行流水统计。

**Non-Goals:**
- 不批量翻译历史客户。历史客户下次修改英文名称时触发；如果需要批量，以后另做。
- 不为对方收款账户建档。支付宝 / 微信账号只作为付款单上的快照，不进供应商收款账户。
- 发货通知只调整布局，不改货代规则（默认选中、校验沿用 UI-095）。

## Decisions

1. **翻译技能**：编排服务新增 `translate-company-names`，提示词按公司名翻译：保留品牌和缩写，后缀按惯例译成「有限公司」等，只输出中文名。
   - 后端新增 `CustomerNameTranslations`，复用 AI 任务与回调；key 为「customer:客户 ID」，带校验码。
   - 回调时再检查一次：中文名称为空或来源仍是「AI 翻译」才写入，避免覆盖期间人工改过的名称。
   - 不复用联系人名技能，因为人名和公司名的译法规则不同。
2. **触发条件**：在客户保存的事务提交后提交任务。新建时英文名称非空，或修改时英文名称变化（去掉首尾空格、忽略大小写比较）才提交。
   - 是否覆盖看中文名称当前的来源：为空或来源是「AI 翻译」才覆盖。
   - key 里带英文名称的摘要，回调时英文名称已经又改过的结果丢弃，避免旧任务晚到覆盖新译名。
   - 登记商机（`createLead`）建的客户同样触发。原来商机登记会把联系人名音译后填进客户中文名称，现在只在没填客户名称时这样做；音译结果的来源也记「AI 翻译」，以后补填英文名称时会换成公司名的译名。
3. **「AI 翻译」按钮**：沿用「生成英文描述」的写法，不在服务端等待：
   - `POST /api/v1/masterdata/customers/name-translation {name}` 提交一个不写客户的翻译任务，返回任务编号；
   - `GET /api/v1/masterdata/customers/name-translation/{taskId}` 查结果，只能查自己提交的；
   - 前端每 1.5 秒查一次，最长 20 秒，超时提示「翻译超时，请稍后再试」，不影响表单。
   - 结果只返回给前端填进输入框，不直接写库；保存时如果中文名称等于这次的译名，来源记「AI 翻译」，否则记「人工」。
   - 这个接口要求有客户新增或编辑权限，并按租户的 AI 配置调用。没有配置 AI 时，点按钮提示「AI 未配置」的原因。
4. **完整度排序与统计**：
   - 排序：按 `BIT_COUNT(profile_mask)` 排，同值按 `update_time` 倒序。
   - 统计：新增 `GET /customers/profile-counts`，返回 `{all, done, pending}`，按数据范围统计，不带其他筛选。
5. **私对私费用单**：沿用公司对公的流程生成应付单，然后在同一事务内调用付款登记逻辑，生成私对私付款单。
   - 付款账户必须是对私账户。付款登记的规则不变：私对私付款需要「付款登记」权限。
   - 付款日期为发生日期，人民币金额用费用单的折算值；幂等键为「FE-费用单ID」。
   - 对方收款方式、户名、账号拼成快照，写入 `payee_account`，例如「支付宝 · 李工 · 138****0000」，账号中间脱敏。
   - 凭证上传在费用单上，保存时复制一份挂到付款单（共用同一个存储文件），作为付款截图。
   - 不需要新表或新字段。
6. **精度与事务**：金额沿用费用单规则，原币、汇率、人民币 HALF_UP 两位。费用单、应付单、付款单、核销在同一事务内完成；付款登记要带幂等键，复用费用单的幂等键。

## Risks / Trade-offs

- [按钮翻译要等编排服务回调] → 前端轮询，不占服务端请求线程；翻译中按钮显示「翻译中」不能重复点。日常翻译走后台任务。
- [AI 译名不准确] → 来源标「AI 翻译」，鼠标悬停可见，人工修改后不再自动覆盖。
- [私对私付款单作废后费用单状态] → 规则与公司对公一致：作废付款单后应付回到未付，费用单就可以作废。

## Migration Plan

- 迁移 V1.5.39 只改 `customer_field_source.source` 的注释（加上 5-AI翻译），不改数据，可以回退；没有配置变化。
- 编排服务新增技能，需要随后端一起发布；后端先发布的话，提交翻译任务会失败并被跳过，不影响保存。
- 回退：回退应用即可，已经写入的中文名称保留。

## Decisions

- **字段**：`customer_contact.name_cn varchar(100) NOT NULL DEFAULT ''`；`customer.contact_name_cn varchar(100) NOT NULL DEFAULT ''`。主联系人同步（`PrimaryContactSync` 两个方向）加上中文名。
- **翻译任务的 key**：现有回调把 key 当客户 ID、写客户中文名称。新增 key 前缀 `contact:<联系人ID>`，回调按前缀区分：`contact:` 写联系人中文名（只写仍为空的），若该联系人是主联系人，同时写客户的主联系人中文名（同样只写仍为空的）；纯数字 key 保持原逻辑。编排服务的技能只按 key 原样返回，不需要改。
- **何时提交**：联系人新增或修改后，中文名为空、英文姓名不为空且不含中文时提交；在事务提交后异步发出（沿用 `ContactNameTranslations.submit` 的做法），租户没配置 AI 时跳过。客户表单保存主联系人时同样处理（主联系人在 `customer_contact` 里有对应记录，用该记录的 ID）。
- **何时提交翻译**：新建联系人、改了英文名、或把已有的中文名清空时才提交；英文名没变、中文名仍为空的再次保存不重复提交（避免每次保存客户都产生一次 AI 调用）。翻译失败后想重试，清空后保存即可。
- **批量导入、历史迁移**：不自动翻译，避免一次产生大量 AI 调用；需要时手动填。
- **对外单据**：PI、报价单等不使用中文名，保持现状。

## 事务边界

联系人保存与翻译任务的创建分开：保存事务提交后才创建 AI 任务；回调在 AI 任务回调自己的事务里更新联系人与客户，两处更新同一事务。

## Context

计算实际成本需要的数据都已经在库里：

| 数据 | 来源 |
|---|---|
| 采购货款 | `purchase_order_item`（挂 `so_item_id`，含人民币单价 `net_price_cny` = 单价 × 下单汇率、目标价、砍价金额）；`purchase_order`（币种、下单汇率、开票成本 `invoice_cost`、费用 `fee_amount`） |
| 合格入库数量 | 采购入库单行（按采购订单行累计合格数，含折价接收） |
| 折价与退货运费 | `receiving_discrepancy`（`discount_amount`、`return_freight`，挂 `po_item_id`） |
| 实付人民币 | `fin_payable` / `fin_payment_allocation`（来源为采购订单的应付与核销，带实付人民币） |
| 运费 | `freight_allocation`（国内、国际运费已经分到 `so_item_id`） |
| 运费账单状态 | 出运单的「已对账」标记 |
| 费用单 | `fin_expense_allocation`（`so_item_id`、`amount_cny`），只取有效费用单 |
| 收入与手续费 | `payment_receipt` 的毛额与毛额折人民币、平台手续费、银行中转差额与到账汇率（结汇后为实际汇率）；订单 `total_amount_cny` |

现在订单详情的毛利在 `SalesOrderServiceImpl.margin()` 里按「采购成本价 × 数量」计算。

## Goals / Non-Goals

**Goals：**
- 一个统一的成本计算服务，订单详情、订单列表、利润统计用同一套口径。
- 每个数字都能追溯到来源单据。

**Non-Goals：**
- 不保存成本快照、不建成本表；不做闲置库存复用、出口退税登记、统计导出。

## Decisions

1. **读时计算，不存快照。** 新增 `finance/service/OrderCostService`：
   - 输入一批订单 ID，按表批量查询（每类数据一次查询，`IN` 订单型号行 ID），在内存里汇总成「订单 → 型号行 → 成本项」；
   - 不存快照的好处：任何上游单据改了（入库冲销、差异重开、付款作废、运费账单确认、费用单作废），下次读取就是新结果，不用到处挂重算钩子。
   - 当前每个租户的订单数在几百以内，统计页按筛选范围一次算完。数量涨到几万单时，再改为保存快照，并在上游事件里重算（见风险）。

2. **外币实际汇率按采购订单算。** 对每张外币采购订单：
   - 实际汇率 =（来源为该采购订单的应付上，已核销金额的实付人民币 + 未付原币 × 下单汇率）÷ 原币合计；
   - 抵扣供应商欠款的核销（`from_credit = 1`）按原付款的人民币折算；退款（`from_credit = 2`）冲减已付原币与人民币。
   - 行货款 = 原币单价 × 数量 × 实际汇率。人民币采购订单的实际汇率为 1。
   - 开票成本 `invoice_cost` 与其他费用 `fee_amount` 分别按各行原币货款比例分到行，再乘实际汇率。

3. **数量分三段。** 每个订单型号行：
   - 合格入库数量（按采购订单行单价，已确定）；
   - 已下单未入库的数量（同样的单价，未结算）；
   - 未下单的数量 = 行数量 − 采购订单行数量合计（采购成本价，未结算；没有采购成本价为 0 并提示）。
   - 采购订单行数量合计超过行数量时，按行数量封顶，多出的不计入，那是供应商多发、进了闲置库存的部分。

4. **收入按毛额，手续费算成本。** 与《成本核算》表一致：
   - 收入 = Σ 到账毛额 × 到账汇率 + Σ 银行中转差额 × 到账汇率；
   - 成本项「收款手续费」= Σ 平台手续费 × 到账汇率 + Σ 银行中转差额 × 到账汇率。
   
   这样毛利率的分母是毛额收入，和历史报表可以直接比较。收入与收款手续费都按型号行金额比例分到行，尾差给金额最大的行。订单上的费用、折扣已经包含在订单合计里，只体现在收入上。

5. **「已结算」的判定集中在一处。** 服务返回每张订单的 `settled` 和 `pending` 列表。`pending` 的取值：
   - 货款没收齐；
   - 收款还没结汇；
   - X 个型号没入库；
   - X 个型号没下采购订单；
   - 外币货款没付清；
   - 国际运费还没对账（出运单不在已确认的运费账单上，或还有型号没出运）。

   人民币采购订单不要求付清，因为金额已经确定。

6. **订单列表按毛利排序。**
   - 不按毛利排序时，先分页，再算当前页订单的成本；
   - 按毛利排序时，先在数据权限范围内取符合筛选条件的全部订单 ID，算完成本后在内存里排序、再分页。现在的数据量可以接受。

7. **砍价统计直接查采购订单行。**
   - 砍价金额、目标价已经存在 `purchase_order_item` 上（下单时按下单汇率折人民币），按维度 `GROUP BY` 即可；
   - 质量索赔按 `po_item_id` 汇总差异折价；
   - 线上店铺的「供应商」维度用「平台 · 店铺名」。
   - 不受付款汇率影响，所以不走 `OrderCostService`。

8. **模块依赖。**
   - `OrderCostService` 放在财务模块，只读采购、仓库、物流、财务的仓储，不调用这些模块的服务，避免循环依赖；
   - 销售模块的订单详情与列表调用它，替换现有的 `margin()`。

9. **菜单与授权。** 迁移新增：
   - 菜单「砍价统计」`/purchase/bargain-stats`、「利润统计」`/finance/profit-stats`；
   - 有「询价分配」菜单（100054）的角色授予砍价统计，有「收款单」菜单（100085）的角色授予利润统计，`ROLE_ADMIN` 两个都授；
   - 两个统计页都不加按钮权限，数据范围为整个租户。订单列表的毛利列沿用订单的数据权限。

## Risks / Trade-offs

- **读时计算的性能**：统计页和按毛利排序要算范围内的全部订单。现在的数据量没问题；超过约 5,000 单、或页面明显变慢时，改为成本快照表加事件重算，接口不变。
- **口径变化**：订单详情的毛利会从「报价成本价 + 净额收入」变成「实际成本 + 毛额收入」，老订单的毛利率会变。这是预期内的变化，上线说明里提一句。
- **系统外采购的型号**：一直按采购成本价计、一直「未结算」。只有在系统里下采购订单，才会变成「已结算」。
- **抵扣核销的人民币**：抵扣供应商欠款的核销，人民币按原付款折算，链路较长。作为单元测试的重点覆盖。

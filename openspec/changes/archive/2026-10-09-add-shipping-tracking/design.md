## Context

- 采购单状态：草稿 / 已下单 / 已取消。已发、未发、合格入库数量不落库，由 `ReceivingQty` 按发货单行、入库单行、差异实时汇总。
- 供应商资料的 `region` 为「省/市/区」文本（可能为空）；线上店铺没有地址。
- 收货仓库在福州，本期只有一个仓库。

## Goals / Non-Goals

**Goals:**
- 采购员一眼看出哪些采购单没发、发了一部分、逾期，并能筛出来催货。
- 发货单有预计到货日期，仓库能提前知道哪些货快到、哪些超时。

**Non-Goals:**
- 不接快递查询接口，不做物流轨迹。
- 不做多仓库（目的地固定为福州仓库）。
- 不发催货提醒消息。

## Decisions

### 1. 发货进度不进采购单状态
- 发货与「下单 / 取消」是两件事，一张单可能一半在途、一半没发；单独算一个进度，不改现有的取消、修改规则。
- 计算：对已下单采购单的每行，取订购数量 Q、已发 S（口径同 `shippedByPoItem`）、合格入库 R（`qualifiedByPoItem`）。
  - 全部行 R ≥ Q → 已入库；
  - 否则全部行 S ≥ Q → 已发货；
  - 否则任一行 S > 0 → 部分发货；
  - 否则 → 未发货。
- 列表筛选与统计在 SQL 中计算：给 `ReceivingQtyMapper` 加按采购单汇总「未发总数、未入库总数、已发总数」的子查询，`purchase_order` 列表用 `apply` 拼条件（只含数字参数与固定 SQL）。
- 逾期未发：`status = 已下单` 且 `expected_ship_date < 今天` 且未发总数 > 0。

### 2. 预计发货日期
- `purchase_order.expected_ship_date DATE NULL`；确认下单接口增加必填参数，校验不早于下单日期。
- 保存采购单（草稿与已下单）可改，已下单的变更计入「修改」日志。
- 存量已下单为空，不参与逾期。

### 3. 预计到货日期与时效表
- `supplier_shipment.expected_arrival_date DATE NULL`。
- 新表 `transit_time`：`tenant_id`、`carrier`、`origin_province`（'' 为该快递默认）、`days`、`remark`、审计字段、`deleted_at`；唯一键 `(tenant_id, carrier, origin_province, deleted_at)` 用应用层校验（软删除后可重建）。
- 全局默认天数存系统参数 `transit.default-days`（默认 3）。
- 估算接口 `GET /api/v1/purchase/shipments/estimate?poId=&carrier=&shipDate=` 返回 `{date, days, basis}`；登记抽屉在快递公司、发货日期变化时调用，用户手动改过日期后不再覆盖。保存时未传预计到货日期则后端按同样规则补上。
- 发货省份：取供应商 `region` 第一个「/」前的部分，去掉「省」「市」「自治区」等后缀后与规则匹配（规则里存短名，如「上海」「广东」「新疆」）。
- 初始规则（新租户与现有租户迁移时写入）：
  - 快递公司默认天数：顺丰 2、京东 2、跨越 2、中通 3、圆通 3、韵达 3、申通 3、极兔 3、德邦 3、EMS 4、供应商送货 1；
  - 福建省内：顺丰 1、京东 1、中通 2、圆通 2、韵达 2、申通 2、极兔 2；
  - 偏远（新疆、西藏）：顺丰 4、中通 6、圆通 6、韵达 6、申通 6、极兔 6、EMS 7。
- 仓库补登的发货单：预计到货日期 = 收货日期。

### 4. 不良数量自动计算
- 前端只让填实收与合格，不良显示为 实收 − 合格；后端以实收、合格为准计算不良（请求里的不良字段不再使用），校验合格 ≤ 实收。

### 5. 订单货物状态
- 不改订单状态与型号进度的口径（订单状态取最慢的型号，用于推进与完成的判断），另算一层件数分布给业务员看。
- 每个订单型号行：Q = 型号数量，O = 已下单数量（`RequirementQty.bySoItem`），S = 已发数量（按 `so_item_id` 汇总，口径同 `shippedByPoItem`），T = 在途数量（在途发货单行按 `so_item_id` 汇总），R = 合格入库（`qualifiedBySoItem`）。
  - 已入库 = min(R, Q)；在途 = T；待发货 = max(0, O − S)；待采购 = max(0, Q − O)。
  - 少发后「不补了」会减少已下单数量，这部分回到待采购，与需求池一致。
- `ReceivingQtyMapper` 增加按 `so_item_id` 汇总已发与在途（含最早、最晚预计到货日期）的查询；订单列表按当前页的订单批量查询。

### 6. 菜单与权限
- 业务设置下新增「快递时效」`/system/transit-times`，按钮 `system:transit-time:edit`；授予内置租户管理员，套餐标准版、旗舰版加入。
- 估算接口只要求「供应商发货」或「采购单」菜单。

### 7. 事务边界
- 确认下单：原有事务内多写预计发货日期。
- 登记 / 修改发货单：原有事务内多写预计到货日期。
- 时效规则增删改：单表事务 + 操作日志。

## Risks / Trade-offs

- 时效表是经验值，不会很准；估算结果只做参考，采购员可以改，后面需要准确时间再接快递查询接口。
- 列表按发货进度筛选要按采购单汇总发货与入库，数据量大时较慢；按 `po_id` 已有索引，本期数据量可接受。

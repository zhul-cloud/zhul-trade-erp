## Context

`SourcingTaskServiceImpl.board()` 一次查出全部未完成任务，在内存里算统计、按页签筛选、按品牌分组后分页。`MyTaskServiceImpl.matching()` 已有按任务编号、询盘单号、品牌、型号匹配的逻辑。

## Decisions

### D1 搜索与采购员筛选
- `board(status, page, pageSize, keyword, purchaserId)`：先算顶部统计（不受筛选影响），再对任务列表套关键词与采购员筛选，页签数字（待分配、询价中、待审核、已回价）按筛选后的任务计算。
- 关键词匹配复用「我的询价」的规则（任务编号、询盘单号、品牌、型号，型号按归一化键匹配），抽成公共方法。
- 采购员：任务当前在办的采购（`active = 1`）里有这个人；「待分配」没有采购，选了采购员时为 0。
- 采购员下拉列出租户内全部采购（现有 `purchasers` 列表只含有负载的人，改为另查一次采购员名单）。

### D2 全部页签
- 新接口 `GET /sourcing-board/all?keyword&purchaserId&state&dateFrom&dateTo&page&pageSize`，按任务创建日期筛选，默认最近 30 天，按更新时间倒序，分页查库（不在内存里全量）。
- 显示状态由任务状态与询盘状态推出：
  - 待分配：任务待分配（含业务员优先处理中的，标「业务员处理中」）；
  - 询价中：任务询价中；
  - 已回价：任务已回价，询盘在询价中 / 可报价；
  - 已报价：任务已回价，询盘已报价 / 成交 / 丢单；
  - 已关闭：任务作废，或询盘已取消。
- 采购员：曾经分配过的采购（含被改派掉的），显示时按当前在办优先。
- 列：任务编号、询盘单号、品牌 · 型号数、采购员、状态、回价时间、创建时间 / 创建人、更新时间 / 更新人（列表页统一规范）。
- 点一行打开现有 `TaskDetailDrawer`。
- 可见范围与询价分配一致（有询价分配菜单权限即可），不另加权限；兼职采购的客户信息隐藏规则沿用现有。

## Risks / Trade-offs

- 「全部」页签不做导出；需要时再加。

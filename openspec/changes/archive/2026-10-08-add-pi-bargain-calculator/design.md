## Context

- PI 型号行保存了采购成本价（CNY）、毛利率红线（`floor_margin`，来自报价单定价策略）、外币单价与小计；整单折扣按百分比或金额，计算口径在 `PiCalculator`：合计毛利率 = 1 − Σ成本 ÷ ((有成本行收入 − 按收入比例分摊的折扣) × 汇率)，费用不计入毛利。
- 现有手工表（`04-成本核算/*.xlsx`，30 多份）格式固定：A1「固定汇率：」B1 汇率；第 2 行表头「型号、数量、成本单价(RMB)、成本总价(RMB)、销售单价(USD)、销售单价(RMB)、销售总价(RMB)、总毛利、让利、折扣、实际毛利、实际毛利率」；型号行用公式；合计行 `实际毛利 = (销售总价 + 让利) − (成本总价 + 折扣)`。较早的表只有「折扣」一列（`实际毛利 = 销售总价 − (成本总价 + 折扣)`）。
- PI 的「修改（出新版本）」「保存」接口已经存在。

## Goals / Non-Goals

**Goals:**
- 在 PI 上算出「还能让多少」，试算点数或目标总价，一键生成带整单折扣的新版本；导出与手工表一致的 Excel。

**Non-Goals:**
- 不保存测算记录（每次打开按当前 PI 现算）；不做按行单独让利（PI 只有整单折扣）；不在报价单上提供测算（报价阶段改单价即可）。

## Decisions

1. **测算在前端算，口径与 `PiCalculator` 一致；后端放一个同口径的 `PiBargain` 工具类，导出时复用，并用单测锁住规格中的数字。** 测算要随输入即时刷新，放前端；两边各写一份公式，用规格场景的数字（1,000 / 5,400 / 6.65 → 97.74、9.7 点）在前后端单测里互相对齐。
2. **整单红线 = 有成本行的红线按收入加权**（没有红线的行按 0%）。「最多还能让」解：设总折扣 D 按收入比例分摊，要求 `1 − C ÷ (R_c × (1 − D ÷ S) × 汇率) ≥ 红线`，得 `D_max = S × (1 − C ÷ ((1 − 红线) × R_c × 汇率))`；再减去当前折扣得到「还能再让」，金额向下取到分，点数 = 再让金额 ÷ S 向下取到 0.1。其中 S 为小计，R_c 为有成本行收入，C 为成本合计。没有任何有成本行时不计算，提示「没有采购成本价，无法测算」。
3. **试算的折扣替换当前折扣**：按点数 → 百分比折扣；按目标总价 → 金额折扣 = (小计 + 费用) − 目标总价。生成新版本时照此写入 PI 版本的 `discount_type / discount_value`，其余内容不变。
4. **「生成 PI 新版本」由前端串起现有接口**：已发送且没有修改中版本 → `POST /revise` 后对新版本 `PUT` 保存折扣；草稿或已有修改中版本 → 直接对编辑中的版本 `PUT`。不新增后端写接口，权限、校验与操作日志沿用现有逻辑。
5. **导出用 POI 生成**：`GET /api/v1/sales/pis/{id}/bargain-export?version=&rate=&discountType=&discountValue=`，按新版手工表的列（含「让利」「折扣」两列，测算的让利写在合计行「折扣」列，按 RMB），型号行与合计行写公式，表头加粗、列宽按内容。销售单价列标题按 PI 币种（如「销售单价(EUR)」）。合计行「实际毛利率」改为除以让利后的收入（`M ÷ (I + K − L)`），与系统和测算抽屉的毛利率一致；原手工表除以让利前的销售总价，让利后会比系统口径偏低。

**精度：** 中间计算不舍入；展示与导出两位小数 HALF_UP；「最多还能让」金额向下取到分、点数向下取到 0.1，保证按它让利后不低于红线。

## Risks / Trade-offs

- [前后端公式不一致] → 同一组场景数字分别写前端单测（Jest）与后端单测。
- [临时汇率与 PI 汇率不同，生成新版本后毛利与测算不一致] → 生成新版本前若测算汇率 ≠ PI 汇率，提示「PI 仍按 6.65 计算，生成后毛利以 PI 为准」。

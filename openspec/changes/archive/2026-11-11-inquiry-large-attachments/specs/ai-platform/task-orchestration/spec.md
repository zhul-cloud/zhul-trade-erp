# Spec Delta

## MODIFIED Requirements

### Requirement: 提交失败与处理超时同样触发结果分发
系统 SHALL 保证任务失败无论发生在哪个阶段——提交给 AI 编排服务时就失败（如网络不通）、AI 编排服务通过 webhook 回调报告失败、或任务长时间停留在"排队中/处理中"没有收到任何回调或进度报告（视为超时）——都统一标记该任务为"失败"并触发与成功/失败回调相同的结果分发，让发起该任务的业务模块都能收到失败通知，不会因为失败发生的时机不同而导致业务方永远收不到通知。超时从最近一次收到回调或进度报告起计算；仍在报告进度的任务超过系统配置的最长处理时长时，同样按超时失败处理。

#### Scenario: 提交阶段失败也会分发结果
- **WHEN** 任务创建后向 AI 编排服务提交时即失败，从未收到受理回执
- **THEN** 系统将该任务标记为"失败"并记录失败原因，并按 skill 标识把这次失败分发给对应的业务处理器，与 webhook 回调失败的处理路径一致

#### Scenario: 长时间无回调视为超时失败
- **WHEN** 一个任务保持"排队中"或"处理中"超过系统配置的超时时长，全程未收到任何 webhook 回调或进度报告
- **THEN** 系统将该任务标记为"失败"（失败原因注明超时），并按 skill 标识把这次失败分发给对应的业务处理器

#### Scenario: 持续报告进度的长任务不被误判超时
- **WHEN** 超时时长为 20 分钟，一个分批解析任务已运行 50 分钟，最近一次进度报告在 3 分钟前
- **THEN** 系统不把该任务判为超时，任务继续处理

#### Scenario: 超过最长处理时长
- **WHEN** 最长处理时长为 180 分钟，一个任务一直在报告进度但已运行 181 分钟
- **THEN** 系统将该任务标记为"失败"（失败原因注明超过最长处理时长），并分发给对应的业务处理器

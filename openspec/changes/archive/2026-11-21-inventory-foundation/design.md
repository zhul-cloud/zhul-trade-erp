## Context

- 现在没有库存表。各个数量都按销售订单型号行从单据现算：
  - 合格入库数由 `ReceivingQtyMapper` 算，含折价接收。
  - 已交货代、已出运由销售出库单与出运单算。
  - 在途按未收货的供应商发货单算。
  - 订单进度、货物状态、可出库数量都建立在这些现算的数上。
- 闲置库存 `stock_hold` 有三个来源：多发暂存、订单部分取消（`PartialCancelHolds`）、售后退货转入。处置方式有退回供应商（直接登记快递，运费不进报销）、报废、转样品，由 `HoldService.handle` 处理。
- 前置变更 doc-product-link 之后，各单据明细都有 `product_id`，可以带过来。商品合并由 `ProductMergeService` 按 `DocumentProductTables` 批量改指向。
- 货代就是供应商表里类型为「服务商」的记录，可以归属客户（客户指定货代）。
- 租户级配置可以存在 `sys_config` 里（带 `tenant_id`）。
- 采购订单行的单价是原币不含税单价，`netPriceCny` 是人民币不含税单价，表头有下单汇率 `exchangeRate`。

## 已定口径（用户 2026-11-20）

| 事项 | 结论 |
|---|---|
| SKU | 按型号，用 `product_id` |
| 成色 | 记在批次上，不进 SKU |
| 计价 | 按批次：订单专属的货按自己的批次出；可用库存按先进先出挑批次 |
| 货代 | 算外部仓，每家货代对应一个货代仓 |
| 模式 | 租户级开关：无货源 / 库存模式 |
| 闲置库存 | 取消，并入可用库存，处置改成标准单据 |
| 逆向 | 流水只增不改，作废、冲销都走反向流水 |
| 台账 | 明细账（流水）+ 进销存汇总台账 |
| 成本调整、月结 | 第三个变更做 |

## Goals / Non-Goals

**Goals:**
- 现有每个改变货物位置或状态的动作，都在同一事务里生成库存流水，并同步余额与预占。
- 任意时刻，库存余额与按单据现算的数一致：契约测试逐个流程比对。
- 闲置库存的功能全部由库存承接，没有遗漏的处置方式。
- 给第三个变更（成本）留好批次单价和流水金额。

**Non-Goals:**
- 订单进度、货物状态、可出库数量仍按单据现算，不改成读库存。
- 不做成本调整、出运结转销售成本、月结（第三个变更）。
- 不做盘点、调拨、多个自有仓、库位、冻结、备货采购、把可用库存分配给其他订单（随库存模式再做）。
- 不做渠道可售库存（参考设计的销售层）。

## Decisions

1. **数据模型。** 新表都是业务表，带 `tenant_id`、软删除，在 `TenantTables` 归为私有（PRIVATE）。
   - `inv_warehouse`：
     - 编码（WH + 序号）、名称、类型（1 自有仓、2 货代仓）、关联货代 `forwarder_id`（货代仓必填，唯一）、状态。
     - 每个租户一个自有仓，上线迁移时建好，名称「公司仓库」。
   - `inv_batch`：
     - 批次号：采购入库单行用「入库单号-行序号」，退货入库用「退货入库单号-行序号」，系统外入库用「SYS + 出库单号-行序号」。
     - 商品、成色（来自销售订单型号行，没有时为空）、来源类型、来源采购订单行、来源入库单行、来源销售订单型号行。
     - 入库单价：原币、币种、汇率、人民币，人民币四舍五入（HALF_UP）到 6 位，金额到 2 位；汇率保留 6 位。
   - `inv_move`（流水，只增不改，不软删除）：
     - 发生时间、仓库、商品、批次、状态（1 合格、2 不良）、操作类型、数量（有符号）、人民币单价、人民币金额（数量 × 单价，HALF_UP 2 位）。
     - 操作类型（用户 2026-11-21 定）：1 入库、2 出库、3 调入、4 调出、5 转入、6 转出、7 预占、8 释放。入库、出库、调入调出、转入转出改结存；预占、释放只改预占，结存不变。业务类型是另一个维度（采购入库、销售出库、冲销……），两者组合覆盖退货、调拨等场景，以后加盘点、调拨单只需加业务类型。
     - 业务类型（见第 3 点）、来源单据类型与 ID、来源明细 ID、反向冲销的原流水 ID、操作人。
   - `inv_balance`：
     - 唯一键：仓库 × 商品 × 批次 × 状态。
     - 字段：结存数量、预占数量。
     - 有 `version` 列；过账时按唯一键 `SELECT … FOR UPDATE`，没有就插入。
   - `inv_reservation`：预占对象 × 批次 × 仓库 × 状态的数量，余额上的预占数量是它的合计。预占对象有两种：
     - 销售订单型号行：这批货是这个订单的。
     - 采购退货单行：「退货待寄出」，寄出时出库，作废时释放。到货差异生成的退货（不良、多发）和库存退回都这样锁住，防止被交货代或其他出库取走。
   - `inv_other_outbound`、`inv_other_outbound_item`：其他出库单的表头与明细（见第 6 点）。
   - 库存模式存在 `sys_config`，键 `inventory.mode`，值 `dropship` 或 `stock`，没有时按无货源处理。
   - 金额字段一律 `DECIMAL`。数量为整数，与单据一致。
2. **过账服务 `InventoryPosting`。**
   - 只给业务服务调用，不对外开放接口。
   - 每个方法在调用方事务里执行（`Propagation.MANDATORY`），写流水、改余额、改预占，余额不能变成负数，否则抛错，整个业务动作回滚。
   - 加锁顺序固定：先锁业务单据（调用方已有），再按 仓库 → 商品 → 批次 → 状态 的顺序锁余额行，防止死锁。
   - 反向冲销按原流水逐条生成数量相反的流水，并记下原流水 ID；同一条流水不能冲销两次。
3. **过账规则（业务类型）。**

   | 动作 | 流水 |
   |---|---|
   | 采购入库验收、直接收货 | 自有仓「采购入库」：每行一个批次，合格数入合格、不良数入不良；合格数按来源订单型号行还需要的数量预占，超出的不预占 |
   | 冲销采购入库 | 按原流水反向，同时释放预占（原规则已限制被出库单用到的不能冲销） |
   | 到货差异 · 折价接收 | 「状态转换」：该批次不良 −N、合格 +N，并按订单型号行预占；重新打开时反向 |
   | 到货差异 · 其他处理方式 | 退货换货、退货不补、多发退回：生成采购退货单时按退货数量做「退货预占」（不良的锁不良，多发的锁合格），寄出时出库；暂存就是留在可用库存；重新打开时随采购退货单作废释放 |
   | 交国内快递 | 「调拨」：自有仓 → 该货代仓，按出库单型号行取货（见第 4 点）；撤销交货代反向 |
   | 直发货代确认 | 生成采购入库单时直接入该货代仓（批次照常），同时预占；生成的出库单已在货代仓，不再调拨 |
   | 登记出运 | 「销售出库」：从货代仓出出运单上各出库单的型号与数量，先出预占给该型号行的批次 |
   | 退货入库验收 | 自有仓「退货入库」：每行一个批次，合格、不良分开，不预占；单价取原订单该型号行销售出库流水的加权单价；撤回入库反向 |
   | 退货去向 · 报废 | 自动生成一张已出库的其他出库单（类型报废） |
   | 采购退货生成、作废 | 按来源批次做退货预占（到货差异来源取入库单行的批次，售后来源取退货批次，库存退回取所选批次与状态）；作废、寄出前减少数量时释放 |
| 采购退货寄出 | 「采购退货出库」：按退货预占出库；采购退货单寄出后不能作废，所以没有反向 |
   | 销售订单取消、部分取消 | 释放预占：超出新的需要数量的预占从后往前释放 |
   | 其他出库单 | 「其他出库」，作废时反向 |
   | 商品合并 | 「商品合并」：原商品各余额行出、主商品入，批次和预占跟着转 |

4. **交货代时怎么取货。** 按出库单的每个型号行，依次取：
   1. 预占给这个型号行的合格批次（先进先出）。
   2. 同一商品没有预占的合格批次（先进先出），取到的先预占给这个型号行。
   3. 还不够时：
      - 无货源模式：自动生成「系统外入库」批次（单价 0，第三个变更再定成本），补足后调拨。对应系统外采购、不需采购（仓库有库存但当时没入账）、历史数据缺入库单这几种情况。
      - 库存模式：报错「库存不足：型号 × 缺 N」，交货代失败。
   - 备选方案：无货源模式允许负库存。不采用，因为负库存会让批次和成本都没有着落。
5. **预占。**
   - 订单预占挂在销售订单型号行上，代表「这批货是这个订单的」；退货预占挂在采购退货单行上。
   - 采购入库时，按来源型号行的需采购数量减去已预占、已交货代的数量算还需要多少。
   - 销售出库、出运按预占出库。出运后预占随流水减少。
   - 订单取消、部分取消时释放，货变成可用库存。
6. **其他出库单。**
   - 内部单据，类型代码 OO（如 `OO20261121001`），按单据页统一规范做表头、明细、详情页、备注和附件。
   - 表头字段：出库类型（报废、转样品、货代丢失、货损）、仓库、出库日期、原因。
   - 明细字段：商品、批次、状态、数量、单价、金额。
   - 丢失、货损只能从货代仓出；报废、转样品从自有仓出。
   - 保存即出库，状态「已出库」；可以作废（填原因），作废时反向冲销，状态「已作废」。
   - 只能从可用（没有预占的合格）或不良库存出。要动预占的货，先取消订单或部分取消。
   - 退回供应商不放在这里，走采购退货单（新来源「库存退回」），快递和运费照常进报销，供应商退款照常登记。
7. **页面与接口。**
   - 接口前缀 `/api/v1/inventory/`：`warehouses`、`mode`、`stocks`（余额汇总与批次展开）、`moves`、`ledger`、`other-outbounds`。
   - 权限码：
     - `inventory:stock:view`
     - `inventory:move:view`
     - `inventory:ledger:view`
     - `inventory:other-outbound:view` / `:edit` / `:void`
     - `inventory:warehouse:view` / `:edit`（含库存模式）
     - `inventory:return-to-supplier`（库存退回）
   - 库存台账按自然月，从流水按月聚合；期初 = 该月之前的流水合计。数据量大以后再加月度快照表，第三个变更做月结时一并加。
   - 库存查询、库存流水、库存台账不是业务单据列表，不加四个审计列：余额显示「最近变动时间」，流水本身就是发生时间和操作人。这和「待关联单据」的例外一样，在 `ui-design-patterns.md` 里登记。
8. **期初迁移。** 上线后由启动任务执行一次（`sys_config` 记完成标记，`TenantScope.platform` 按租户逐个处理，每个租户一个事务，失败的租户记日志、下次启动重试）：
   - 建自有仓；按现有货代建货代仓。
   - 每张有效采购入库单行建批次。在库数量按单据现算：
     - 自有仓合格 = 合格入库（含折价）− 已交货代（按型号行，从最早的批次开始扣）。
     - 自有仓不良 = 未处理完的不良。
     - 货代仓 = 已交货代且未出运。
     - 预占 = 仍属于订单、没取消的部分。
   - 暂存中的闲置库存：按来源找到批次，没有就建「期初」批次，成为可用库存。
   - 退货入库单中已验收、去向未处理或转闲置的部分，按退货批次入库。
   - 以上都生成业务类型「期初」的流水，日期为迁移当天。算出负数的行不入库，记到迁移日志里，列在 PR 说明中。
   - 上线后新单据由过账钩子入账：已有流水的采购入库单、退货入库单不再推算；已有交货代流水的出库单只从批次扣、不再调入货代仓；已出运的按出运状态扣掉。这样期初在上线后补跑（例如首次失败）也不会重复入账。
   - 实现：`InventoryOpening`（启动任务），租户列表在平台范围查询，每个租户 `TenantContext.runAs` + 独立事务；完成标记 `inventory.opening.done=1`。
   - 备选方案：按单据回放全部历史。不采用，因为飞书迁移的历史数据缺入库单、缺出库单的情况很多，回放会产生大量负数和补登。
   - 库存退回的采购退货单与售后来源一样计退款：完成时登记的供应商退款冲减该供应商的应付（`PayableSyncService.returnCreditOf` 含来源「库存退回」）。
9. **闲置库存下线。**
   - `HoldService` 与闲置库存页下线，`/warehouse/holds` 重定向到库存查询（只看可用）。
   - `PartialCancelHolds` 改为释放预占。到货差异暂存、退货去向「转闲置库存」不再写 `stock_hold`。
   - `stock_hold` 表保留只读，退货入库详情里的历史「闲置库存」链接改为显示文字。
10. **事务边界。** 所有过账都在原业务动作的事务里，没有异步：
    - 采购入库、到货差异处理、交货代、直发确认、登记出运、退货入库、去向处理、采购退货寄出、订单取消、商品合并，每个动作要么连同库存一起成功，要么一起回滚。
    - 商品合并跨租户：合并服务已在 `TenantScope.platform` 里，库存转移显式按每个租户的余额行处理。
11. **一致性保障。**
    - 契约测试 `InventoryConsistencyContractTest`：跑完采购入库 → 交货代 → 出运、部分取消、退货、直发、系统外入库各条流程，逐个比对余额与单据现算的数。
    - `InventoryPostingTest`（单元）：覆盖余额不能为负、反向冲销不能重复、加锁顺序。

## Risks / Trade-offs

- **[期初数不准]** 历史数据缺单据，期初可能有负数或对不上。→ 负数不入库并记日志，上线后在库存查询核对；无货源模式下交货代缺货会自动补系统外入库，不会卡住业务。
- **[过账让原动作变慢、变脆]** 每个仓库动作多了几次加锁和写入。→ 余额行按唯一键加锁，单据动作本来就有行锁。过账失败会让原动作失败，所以上线前契约测试要覆盖全部动作。
- **[两套数并存]** 订单进度仍按单据算，库存是另一套。→ 第二步只保证两者一致（测试），第三步成本改读库存；进度要不要改读库存，以后再定。
- **[退回供应商改走采购退货单]** 以前闲置库存的退回只登记快递，现在要先生成采购退货单。→ 多一步，但运费能进报销、供应商退款有地方登记，与其他退货一致。
- **[货代仓数量多]** 每家货代一个仓，库存查询的仓库筛选会很长。→ 筛选按「自有仓 / 货代仓」分组，默认只看有库存的仓。

## Migration Plan

- 迁移 V1.5.55：建 `inv_*` 表；`purchase_return` 加来源「库存退回」需要的批次与状态列；权限与菜单（闲置库存菜单停用，新增 5 个菜单）。
- 期初由启动任务执行，见第 8 点。
- 回退：手动执行回退脚本删除 `inv_*` 表与新增列，恢复闲置库存菜单。上线期间新产生的「暂存」需要人工补回 `stock_hold`，所以回退脚本附一段把可用库存导回 `stock_hold` 的 SQL。

# Design

## Context

- 付款计划在 `fin_payable_installment`，每期有比例、时点、金额、到期日、已付；`PayableQueryService` 已按期次算到期状态（已逾期、7 天内即将到期、待入库）。
- 登记付款抽屉打开时，现在默认付款金额 = 本单全部未付（本单已付清时取同收款方全部未付），再按到期先后自动核销（`autoFill`）。
- 批量付款按「收款方 + 币种」分组，默认金额 = 组内未付合计。

## Goals / Non-Goals

**Goals:**
- 当期应付只在后端算一处，登记付款、批量付款共用，前后端口径一致。

**Non-Goals:**
- 不限制付款金额只能等于当期应付；财务仍可改为任意不超过未付的金额。
- 不改核销顺序、校验和入账。

## Decisions

1. **计算位置**：`PayableVO` 增加 `dueNowAmount`（原币，两位小数）与 `dueNowNote`（如「第 1 期 30% 下单后，11-10 到期」，多期用「；」连接）。按期次计算：到期日不晚于今天 + 即将到期天数（与列表「即将到期」同一常量）的期，取各自未付之和；没有时取核销顺序中第一个有未付的期（「待入库」的期排在有到期日的期之后，与核销顺序一致）；没有付款计划时为全部未付。已付清或已关闭为 0。
2. **为什么用「7 天内到期」而不是「已有到期日」**：「发货前」一期在下单时就以预计发货日期作为到期日，按「有到期日」算会把尾款也算进来，默认就变成全部未付；按「快到期」算才符合「这次该付多少」。
3. **登记付款抽屉**：默认金额 = 本单 `dueNowAmount`；本单没有未付时沿用现有逻辑（同收款方全部未付）。金额旁显示 `dueNowNote` 与「付全部未付」。核销仍按现有 `autoFill`。
4. **批量付款**：组默认金额 = 组内各单 `dueNowAmount` 之和；「付全部未付」改为组内未付合计。组内核销改为两轮：先按各单当期应付、再按剩余未付，都按到期日先后；否则默认金额会全部落在到期最早的那张上（如 A 只到期定金、B 待入库时 A 被多付、B 没付），与说明不符。全部到期时两轮结果与原来相同。
5. **列表返回**：列表分页现在不读期次（到期状态取应付单上的下次到期日）；为给批量付款带出当期应付，分页查出当前页后按应付单 ID 一次读出这一页的期次，每页多一次查询，不逐行查询。

## Risks / Trade-offs

- [财务习惯了默认付全额] → 抽屉明确显示默认金额的组成和「付全部未付」，一次点击即可恢复原习惯。
- [付款条件为空的历史采购订单] → 没有付款计划，默认仍为全部未付，与现在一致。

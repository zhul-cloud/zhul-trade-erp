# 验收记录

本机环境（Docker，测试租户），2026-11-17。测试数据：同一供应商 4 张应付单。
- AP…901 CNY 10,000：30% 下单后（已逾期 7 天）· 70% 发货前（20 天后）
- AP…902 CNY 5,000：100% 入库后 30 天（待入库）
- AP…903 USD 2,400：30% 下单后（5 天前）· 70% 发货前（3 天后）
- AP…904 USD 1,260：100% 下单后（30 天后）

| 验收点 | 方式 | 证据 | 结论 |
|---|---|---|---|
| 登记付款默认当期应付，显示组成 | 本机页面 | AP…901 默认 3,000.00，说明「第 1 期 30% 下单后，11-10 到期」，核销本单 3,000.00 | 通过 |
| 「付全部未付」与「改回当期应付」切换，核销随之变化 | 本机页面 | 10,000.00 ↔ 3,000.00，核销合计始终等于付款金额 | 通过 |
| 都没到期取最早一期（含待入库）；没有付款计划取全部未付；已付清为 0 | 单元测试 + 契约测试 | `DueNowTest`、`PayableContractTest` | 通过 |
| 批量付款每组默认当期应付合计、说明带应付单号、顶部按本次金额合计 | 本机页面 + Jest | USD 组 3,660.00、CNY 组 8,000.00；顶部「USD 3,660.00 · CNY 8,000.00」 | 通过 |
| 批量付款默认金额核销到各单的当期应付 | 本机提交 + 单元测试 | CNY 组付 8,000.00：AP…901 核销 3,000.00（第 1 期付清）、AP…902 核销 5,000.00（付清）；`BatchAllocationTest` | 通过 |
| 全部到期时仍按到期日核销（原场景不变） | 单元测试 + 契约测试 | 2,400 + 1,260 付 3,000 → 2,400 / 600 | 通过 |

## Context

- 回价录入在「我的询价」任务详情：每个型号一组草稿，每条草稿有渠道、店铺或供应商、单价、含税与税率、货况（字典 `inquiry_item_condition`）、货期（字典 `inquiry_lead_time`，码值如 IN_STOCK、WEEKS_4_8）、备注、推荐。保存与提交走 `PUT /api/v1/inquiry/my-tasks/{id}/quotes`，本变更不改这条接口。
- 询价包 Excel 导入（`SourcingExcelServiceImpl`）已有单价与含税写法的解析（`parsePrice`、`TAXED`），本变更复用。
- 店家回复没有统一格式，但任务里的型号是已知的，可以拿已知型号去文字里找，而不是从文字里「猜」型号。

## Goals / Non-Goals

**Goals:**
- 常见的「一行一个型号 + 价格 + 货期」写法一次识别对，包括型号写法与任务里不一致（大小写、空格、横杠）。
- 识别结果可在预览里逐项改，确认后进入草稿，仍由采购保存或提交。
- 待处理与已回价列表按更新时间倒序（待处理超时、紧急置顶）。

**Non-Goals:**
- 不接 AI 识别；格式很乱的回复在预览里手改。
- 不跨任务匹配（只匹配当前打开的任务）。
- 不识别图片报价、不从文字里识别店铺名称（店铺由采购先选）。
- 不改询价包导入。

## Decisions

1. **识别放后端，纯函数 + 预览接口**：`QuoteTextParser.parse(text, models, dicts)` 是不依赖数据库的纯函数，便于用大量样例做单元测试；`POST /api/v1/inquiry/my-tasks/{id}/paste-preview` 只校验任务归属、取任务型号与字典后调用解析器，返回预览行，不落库。前端预览可改，确认后把行转成草稿合并进编辑区，复用现有保存接口。
   - 备选：前端解析。否决：含税规则、字典换算已在后端，放后端能和导入保持一致，也方便测试。
2. **型号匹配**：把任务型号与每行文字都归一化（转大写，去掉空格、`-`、`_`、`/`、`.`），在归一化后的行里找包含的型号，多个命中取最长（避免 `TA25DU-14M` 被 `TA25DU-1` 抢走）。命中后在原行里去掉型号所在片段，再找价格，避免型号里的数字被当成单价。
3. **价格取法**：去掉型号后，按顺序：
   1. 「单价 / 价格 / 报价 / 价 / ¥ / ￥」后的数字，或数字后跟「元 / 块」；
   2. 否则去掉数量片段（数字后跟 台/个/只/件/套/pcs/PCS，或「要 / 数量 / x / ×」后的数字）与货期片段（现货、N 天、N 周、N 个月）后，剩下的第一个数字。
   - 金额允许千分位与小数，两位小数 HALF_UP；0 或负数视为缺单价。
4. **货期换算**：区间取上限换成天数（周 × 7、月 × 30），按 0 / 2 / 3 / 5 / 7 / 14 / 28 / 56 天落到 IN_STOCK、DAYS_1_2、DAYS_2_3、DAYS_3_5、DAYS_5_7、WEEKS_1_2、WEEKS_2_4、WEEKS_4_8，超过为 WEEKS_8_PLUS；目标字典项停用时取最接近的启用项。
5. **整段通用说明**：既没匹配到型号、也没有价格的非空行收集为通用说明，从中识别含税 / 未税、货况、货期，作为各行没写明时的默认；通用说明原文（去重后用空格连接，截到备注长度上限）追加到每行备注。
6. **合并到草稿**：前端按「型号 + 渠道 + 店铺（或供应商 ID）」找已有草稿，有则覆盖单价、含税、税率、货况、货期、备注，否则追加；标记该型号为已修改。已提交且不可编辑的型号由后端预览标出，前端不填。
7. **列表排序与更新时间**：`MyTaskVO` 增加 `updateTime` = max(任务 update_time, 本人在该任务回价的最大 update_time)。待处理：超时 → 紧急 → 更新时间倒序；已回价：更新时间倒序。现有按等级、分配时间的排序去掉（列表上仍显示等级）。

## Risks / Trade-offs

- [价格误判：一行里有多个金额，如「原价 3500 现价 3140」] → 预览突出显示原文与识别出的单价，采购一眼可改；有「单价 / 现价」等字样时优先取字样后的数字。
- [型号互为前缀] → 取最长匹配；仍有歧义时预览提示同一型号多行。
- [整段说明误套用：如末尾一句「部分型号含税」] → 只在行本身没写时套用，预览可改。
- [排序变化影响习惯] → 超时、紧急仍置顶，降低漏处理风险。

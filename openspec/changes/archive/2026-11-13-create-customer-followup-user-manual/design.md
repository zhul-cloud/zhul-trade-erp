## Context

本变更只产出用户文档，不改变客户跟进功能。现有客户跟进需求和页面原型分别位于 `openspec/specs/crm/customer-followup/spec.md` 与 `docs/03-产品原型/03-业务域/03-销售管理/07-客户跟进/`；现有手册以 Markdown 为主，缺少面向新手的图文引导。

## Goals / Non-Goals

**Goals:**

- 将用户手册规范写成可复用的项目文档。
- 用客户跟进作为示例，覆盖员工最常用的端到端流程。
- 使用原型截图并配编号标注、白话说明、填写示例和结果说明。
- 以 Markdown 作为可维护源文件，以 PDF 作为内部转发版本。

**Non-Goals:**

- 不修改前端、后端、数据库、API、权限或生产配置。
- 不为手册额外设计新页面或新业务流程。
- 不把真实生产客户数据、账号、密码或凭据写入手册。

## Decisions

1. **规范与示例分开存放。** 通用规则放在 `docs/05-使用手册/00-用户手册编写规范.md`，客户跟进手册放在独立模块目录，便于后续模块直接复用。
2. **原型截图作为主图源。** 使用客户跟进原型目录中的现有截图；对每张图配简短图注和操作编号，避免让读者在整张页面中寻找按钮。
3. **章节按任务组织。** 每章围绕“我要完成什么”编写，采用“目的 → 页面 → 步骤 → 示例 → 结果 → 常见问题”的固定顺序，而不是按代码或数据表组织。
4. **PDF 使用可维护的渲染链路。** Markdown 作为源文件，使用项目可用的中文字体和 PDF 工具生成发布版；生成后抽取文本并检查页数、标题和图片是否存在。
5. **版本与隐私显式记录。** 手册封面和元信息标注适用版本、角色、更新时间、截图来源；截图不包含真实敏感数据。

## Risks / Trade-offs

- [原型和线上页面可能出现差异] → 手册发布前核对当前页面名称、按钮和权限；差异以线上可用流程为准并更新图注。
- [图片过多导致 PDF 体积或阅读长度增加] → 只保留完成任务所需的关键截图，重复页面用局部裁剪图。
- [中文字体或 Markdown 渲染环境不一致] → 生成后抽取文本并进行页面级检查，必要时固定字体和渲染参数。
- [功能规则过于完整导致新手难读] → 正文只保留完成任务所需内容，复杂规则放入“为什么”和“常见问题”。

## Migration Plan

无运行时迁移。提交文档、图片引用和 PDF 后，后续模块按同一规范新增手册；页面或流程变更时提升手册版本并重新生成 PDF。

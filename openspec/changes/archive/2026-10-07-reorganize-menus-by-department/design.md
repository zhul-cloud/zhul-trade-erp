## Context

- 侧边栏完全由后端 `resource` 表的树（`pid`、`sort`、`name`、`light_icon`、`is_hidden`、`status`）生成，前端按 `/api/v1/auth/menus` 返回的权限路径过滤；`config/routes.ts` 只负责路由与 `access`，其中父级路由的 `access` 目前取分组自身的路径（如 `inquiryMenu = can('/inquiry')`）。
- 后端接口权限大量写成 `@perm.canAccessMenu('<页面路径>')`（如 `/inquiry/customer-inquiries`、`/quotation/quotations`），按路径查菜单再看角色是否拥有。
- 页面面包屑的根名称写死在各页面的 `PageTitle root` 里（「询盘管理」「报价中心」「销售管理」等）。
- 工作台 `/dashboard` 是脚手架演示页，不调用任何接口；商机统计是独立页面 `/crm/opportunity-stats`。
- 单据前缀目前在收款账户页下半部分，读写接口 `/api/v1/system/document-numbering/prefix`，写需要 `system:config:edit`。
- 登记到账只能在 PI 详情里操作（`sales:pi:receipt-confirm`）。

## Goals / Non-Goals

**Goals:**
- 按部门重新分组、改名、排序，所有角色的可访问范围保持不变。
- 工作台换成真实数据的卡片框架，先接入商机统计。
- 给财务（现由总经理兼）一个到账登记入口；单据编号独立成页。

**Non-Goals:**
- 不改任何页面路径与接口路径，不改数据权限规则。
- 不新增「财务」内置角色；不做采购单、发货、应收、价格体系。
- 工作台本次只做商机统计一张卡片，其他卡片后续逐张加入。

## Decisions

### 1. 只动菜单树，不动路径
叶子菜单保留原 `path`（如客户询盘仍是 `/inquiry/customer-inquiries`，只是挂到「业务管理」下），后端 `canAccessMenu` 与前端路由都不用改，书签继续可用。路径前缀与所在分组不一致是可接受的代价。
备选：按新分组改路径（`/business/...`）——要同步改几十处接口权限与前端链接，收益只是路径好看，放弃。

### 2. 分组资源
- 新增分组（type=1）：业务管理 `/business`、采购管理 `/purchase`、财务管理 `/finance`、业务设置 `/settings`。
- 沿用：商品管理（100004）改名「商品资料」，系统管理（100002）、租户管理（100003）、工作台（100001）不变。
- 原分组商机管理、询盘管理、报价中心、销售管理、客户管理、供应商管理改为停用并隐藏（`status = 0`、`is_hidden = 1`，不删除），子菜单改挂新分组。侧边栏只看 `is_hidden`、不看 `status`，只停用不隐藏的话，角色里显式勾过旧分组的会看到空分组。
- 新增菜单：到账登记 `/finance/receipts`、单据编号 `/system/document-numbering`；新增按钮「编辑单据编号」`system:document-numbering:edit`。
- 商机统计（100071）设为 `is_hidden = 1`：权限保留、侧边栏不显示，由工作台卡片进入。

分组排序：工作台 1、业务管理 2、采购管理 3、财务管理 5、商品资料 6、业务设置 7、系统管理 98、租户管理 99（4 预留给单证物流）。组内排序按 proposal 列出的顺序。

### 3. 授权迁移
迁移脚本内按以下规则补授权，保证每个角色调整前后可访问范围一致：
- 新分组不需要单独授权：菜单接口会自动补出已授权页面的全部上级（`MenuServiceImpl.visibleIds`），页面改挂到新分组后，分组随之出现。
- 「到账登记」授给内置租户管理员与拥有「登记到账」按钮（110180）的角色；「财务管理」随之出现。
- 「单据编号」与其编辑按钮授给内置租户管理员与拥有「编辑配置」（`system:config:edit`）的角色；单据前缀写接口改为要求 `system:document-numbering:edit`。
- 标准版、旗舰版套餐加入「到账登记」「单据编号」与编辑按钮。
- 不回收旧分组的授权记录（分组已隐藏，记录保留便于回滚）。
- 顺带修正：菜单接口补上级时原来也会从按钮往上补，只有某页面下按钮的角色会在侧边栏看到这个页面、点进去却无权限（如兼职采购有「查看货源信息」，侧边栏却出现「历史询价」）。改为只从目录与页面往上补，按钮权限码照常返回。

验证方法：`snapshots/snapshot.py` 按 `EffectivePermissionResolver` 的口径（平台角色只看角色授权，租户角色取角色与套餐交集，租户管理员只看套餐）导出每个角色可访问的页面与按钮、侧边栏可见的页面，迁移前后对比。

开发环境福唯租户的「总经理」角色已手动授予「登记到账」；迁移按上面规则自动给它「到账登记」菜单。

### 4. 前端路由与面包屑
- `routes.ts` 父级路由的 `access` 改为「任一子页面可访问」（如原 `inquiryMenu` 改为 `can('/inquiry/customer-inquiries') || can('/inquiry/sourcing-board') || …`），不再依赖已停用分组的路径；同时补齐新分组的父级路由与 `menu.*` 文案。
- 面包屑根名称集中到一个映射（页面路径前缀 → 分组名），各页面 `PageTitle` 不再各自写死。
- 原「兼职工作台」页面标题改「兼职看板」，「分配工作台」改「询价分配」，「我的询价任务」改「我的询价」，以此类推。

### 5. 工作台卡片
- 工作台由若干卡片组成，每张卡片声明所需的菜单权限与数据接口；无权限不渲染，失败只影响自身。
- 商机统计卡片调用现有每日渠道统计接口（传入日期范围、按渠道分组），不新增统计口径；「查看完整统计」跳转 `/crm/opportunity-stats`。
- 没有任何卡片时显示空状态与常用入口。

### 6. 到账登记列表
- 新接口按 PI 数据权限分页查询：默认条件为「已发送 / 已转订单」且（有待确认水单 或 已到账 + 手续费差额 < 合计）；带「全部」开关。
- 排序取最早一张待确认水单的付款日期，没有待确认水单的排在后面。
- 列表行的「登记到账」复用 PI 页的登记到账弹窗与接口；接口权限为「到账登记」菜单或 PI 菜单，加上 `sales:pi:receipt-confirm`。

## Risks / Trade-offs

- [路径前缀与分组不一致，后来者困惑] → 在 `.claude/context/ui-design-patterns.md` 记录「菜单分组与路径无关」，新功能按新分组起路径。
- [停用分组后某角色看不到子菜单] → 父级路由改为「任一子页面可访问」，迁移后用 SQL 逐个角色对比调整前后可访问的页面路径集合。
- [业务员只为看历史询价而出现「采购管理」分组] → 接受；价格体系上线时再评估历史询价的归属。
- [硬编码面包屑遗漏] → 全局搜索旧分组名（询盘管理、报价中心、销售管理、商机管理、客户管理、供应商管理、商品管理），清零为止。

## Migration Plan

1. 迁移前导出每个角色可访问的页面路径集合（SQL 快照）。
2. 执行迁移脚本：新增分组与菜单、子菜单改挂与改名、停用旧分组、隐藏商机统计、补授权与套餐。
3. 迁移后再导出一次，对比两次集合：除新增的「到账登记」「单据编号」外必须完全一致。
4. 回滚：恢复旧分组 `status = 1`，把子菜单 `pid`、`name`、`sort` 改回（迁移脚本旁附回滚 SQL）。

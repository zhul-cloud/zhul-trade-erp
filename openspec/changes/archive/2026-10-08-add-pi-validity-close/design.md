## Context

- PI 状态：1-草稿、2-已发送、3-已转订单、4-已作废；收款状态：1-未付款、2-待到账（有水单未确认）、3-部分到账、4-已到账。
- 报价单状态与客户询盘状态已有联动（`InquiryStatusSync`、`QuotationDeals`）：报价单标未成交 / 回到已发送时，询盘按现有规则重新判断。
- 未成交原因字典 `quotation_lost_reason` 已存在，报价单「标为未成交」弹窗可以复用。
- 工作台按菜单权限显示卡片，数据遵循页面的数据权限（见 system/workbench）。

## Goals / Non-Goals

**Goals:**
- PI 有效期、过期提醒、关闭与重新打开，报价单与询盘状态保持一致。

**Non-Goals:**
- 不做过期自动关闭（只提醒，由业务员决定）；
- 不在导出的 PI 上显示有效期（模版占位符本期不加，需要时另行增加）；
- 不做消息推送，只在工作台与列表提醒。

## Decisions

1. **有效期存在版本上。** `proforma_invoice_version.valid_until`（date），新建时 = PI 日期 + 60 天（常量 `PI_VALID_DAYS`），新版本复制上一版本的值；存量按创建日期 + 60 天回填。过期判断用当前有效版本，没有发送过的草稿不参与。
2. **过期不落库，查询时计算。** 条件：状态已发送、收款状态未付款、`valid_until < 今天`。列表筛选与工作台卡片用同一个查询条件（放在 PI 查询支持类中），保证数量一致；「今天」按服务器所在时区的日期计算。
3. **关闭是新状态 5-已关闭。** PI 表增加 `close_reason`（字典码）、`close_reason_name`（名称快照）、`close_note`、`closed_at`、`closed_by`。前置条件在后端校验：状态已发送、收款状态未付款（没有水单也没有到账）。
4. **报价单的「因 PI 关闭而未成交」可追溯。** 报价单增加 `lost_by_pi_id`：关闭 PI 时被标为未成交的报价单记下 PI ID；重新打开时只恢复 `lost_by_pi_id` 等于该 PI 且仍为未成交的报价单，并清空该字段；业务员之后手动改过状态的报价单不动。
5. **判断报价单是否还有有效 PI / 订单**：有效 PI = 状态为草稿、已发送、已转订单（不含已作废、已关闭）且型号行引用该报价单；有效订单沿用 `QuotationDeals` 现有判断。
6. **关闭弹窗复用报价单的未成交原因组件**（分组展示、「其他」必填说明）。

**事务边界：** 关闭（PI 状态与原因、放弃编辑中版本、来源报价单标未成交、询盘状态同步、操作日志）在一个事务内；重新打开同理。水单上传与到账登记在入口校验 PI 状态。

## Risks / Trade-offs

- [关闭与收款并发：业务员关闭的同时有人上传水单] → 关闭与水单上传都先获取同一把 PI 锁（`zhul:erp:lock:pi:{id}`），锁内再判断收款状态。
- [重新打开时报价单已被别的 PI 用掉或已手动改动] → 只按 `lost_by_pi_id` 精确恢复，不做推断。

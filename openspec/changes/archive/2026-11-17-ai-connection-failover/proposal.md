# Proposal

## Why

AI 设置现在只能单选一种连接方式（Claude / OpenAI × 本公司 API Key / 平台订阅）。选中的方式一旦出问题（Key 失效、额度用完、服务商故障、平台订阅退出登录），询盘解析、翻译等 AI 操作就全部停下，直到有人进设置页改选。用户希望公司把能用的 Key 和平台订阅都配好后，系统按顺序自动挑能用的，执行中途出错也能自动换到下一个，不用人工干预。

## What Changes

- **BREAKING（配置模型）**：去掉「当前使用的连接方式」单选。已配置的连接方式都参与，按顺序使用：
  - **API 组**：本公司 API Key，固定排在前面。
  - **订阅组**：平台订阅，排在后面。
  - API 组全部不可用时才用订阅组。
  - 两组内部的顺序由用户在页面上拖拽卡片调整。
  - 每张卡片有「启用」开关，关掉的不参与。
- **订阅来源不变**：仍是部署者在容器内用 CLI 登录的平台订阅，平台租户直接用，其他公司按套餐授权（`system:ai-config:use-subscription`）。不新增订阅凭证的录入。
- **提交前挑选**：创建 AI 任务时按顺序挑出当前可用的连接方式，作为一个有序列表交给编排服务。跳过的情况：
  - 未配置，或已关闭；
  - 订阅未授权或未登录；
  - 处于暂停中。

  一个可用的都没有时，沿用现有的「AI 未配置 / AI 暂不可用」处理。
- **执行中容错**：某次模型调用因连接方式本身的问题失败时，只重做失败的那一次调用，换列表里的下一个方式；已完成的部分保留，比如分批解析中已完成的批次。
  - 会触发切换的问题：鉴权失败、额度用完、限流或服务商故障且重试仍失败、超时、订阅未登录或达到用量上限。
  - 内容本身的错误不切换：模型返回格式不对、拒答、输入不合法。
- **暂停与恢复**：某个连接方式因上述问题失败后，标记为暂停 10 分钟，这段时间新任务直接跳过它，到时自动恢复。设置页卡片上显示「暂停中」、原因和恢复时间。平台订阅的暂停对所有租户共同生效，因为它是同一个登录。
- **任务记录**：记下实际完成调用的连接方式与模型，以及发生过的切换（方式与原因，不含 Key）。
- **费用提示**：API 组内切换会动用另一家的付费 Key。设置页在 API 组说明里写明「排在前面的出问题时，会自动改用下一家」。
- **数据迁移**：
  - 现有的单选结果转为顺序：原来选中的方式排在所在组第一位。
  - 原来选用平台订阅、同时又存有 API Key 的租户，迁移后关闭其 API 卡片，避免上线后突然改用付费 Key。这类租户的行为保持不变，需要时自行打开。

## Capabilities

### New Capabilities
- `ai-platform/connection-failover`：连接方式的使用顺序、可用性判断、执行中自动切换、失败暂停与恢复、切换记录。

### Modified Capabilities
- `ai-platform/tenant-ai-settings`：
  - 「租户维护自己的 AI 配置」：单选改为分组排序加启用开关。
  - 「未配置时的处理」：按「没有任何可用的连接方式」判断。
  - 「租户使用平台订阅」：订阅随顺序参与，不再单独选用。原来的「所选订阅不可用时不自动切换」改为按顺序自动切换。
  - 「测试连接」：按卡片测试，测试成功时解除暂停。
  - 「平台订阅按套餐授权给公司」：场景从「选用」改为「参与使用」。
  - 「AI 设置页面以连接方式列表呈现」：改为两组可拖拽卡片。
- `ai-platform/model-providers`：「按配置选择模型服务商」改为按任务携带的列表依次使用，每个方式用自己的模型设置。
- `ai-platform/task-orchestration`：「提交任务给 AI 编排服务」改为携带有序的连接方式列表；回调带回实际使用的连接方式和切换记录。

## Impact

- **后端（`modules/aitask`）**：
  - `AiConfigServiceImpl`：`resolveForCurrentTenant` 改为返回有序列表；保存接口改为保存顺序与开关。
  - `AiCallConfig` 与任务提交契约；回调 DTO 增加字段。
  - `ai_task` 增加实际使用的连接方式字段。
  - 新增连接方式暂停状态，存 Redis，按租户与连接方式区分，TTL 600 秒；平台订阅按平台记。
- **数据库**：
  - `sys_ai_provider_config` 增加排序与启用字段。
  - `sys_ai_config` 的单选字段迁移后不再作为调用依据。
  - 迁移脚本含回退语句。
- **编排服务（`scripts/ai-orchestrator`）**：
  - `call_api` 改为按列表依次尝试，并区分「换方式」和「不换」的错误。
  - 任务内记住已失败的方式，回调带回切换记录与实际使用的方式。
  - 测试连接、模型列表接口不变。
- **前端（`pages/system/ai-settings`）**：连接方式改为两组可拖拽卡片，每张卡片带启用开关、状态（可用 / 暂停中 / 未配置 / 未登录）与测试连接；模型设置随选中卡片显示。需要 OpenPencil 原型，经用户确认后才开发。
- **历史决定**：知识库记录的「无可用订阅时不自动切换付费 API」是指订阅失效时不要偷偷改用付费 API。本变更的方向是 API 不可用时退到订阅，不违背这条；但 API 组内部会在多家付费 Key 之间切换，已在上面说明。
- **不涉及**：各连接方式的模型、思考强度、搜索次数仍各自保存；平台订阅的授权规则、登录方式不变。

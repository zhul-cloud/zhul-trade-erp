# Design

## Context

- 报价单、PI 的明细行都有型号、品牌、品类字段；询盘列表的型号、品牌、品类由 `InquiryModelSummary` 汇总，前端用 `ModelCell`、`TagList`、`ModelsModal` 显示。
- 文字报价由 `QuotationDocumentServiceImpl.text` 按默认模版渲染，模版逐行取 `item.conditionEn`、`item.leadTimeEn`（`QuotationRenderModels`）。
- 报价单行有 `costQuoteId` 指向采购回价，回价记有采购报的货期；货期字典 `inquiry_lead_time` 按 sort 排成 9 档（现货、1-2天、2-3天、3-5天、5-7天、1-2周、2-4周、4-8周、8周以上）。

## Goals / Non-Goals

**Goals:**
- 列表一次查询汇总全部行的型号、品牌、品类，不按行逐条查询。
- 文字报价的货况、货期只在渲染时替换，报价单数据与模版不变。

**Non-Goals:**
- 不改正式报价单导出（Excel / PDF）的货况、货期。
- PI 没有文字报价，不加入口。

## Decisions

1. **列表汇总**：分页查到当前页的报价单（PI）后，一次查出这些单的当前版本明细，按单分组得到首个型号（按行号）、品牌、品类去重列表，填入列表 VO；排序仍按型号数。复用询盘列表的汇总规则，不在 SQL 里拼接字符串。
2. **文字报价参数**：`GET /quotations/{id}/text` 增加 `condition`（货况字典值，省略时为全新原装）与 `leadTime`（`shift` 表示按采购货期顺延，省略时同 `shift`；数字为货期字典值）。渲染前在内存里替换每个有货行的货况、货期码值，再交给模版；无货行不处理。
3. **顺延一档**：取该行采购回价的货期码值（没有回价时取行上的码值），在启用的货期字典项中按 sort 找到它的下一项；已是最后一项保持不变；码值为 0（未填）保持为空。字典顺序由数据决定，不在代码里写死档位。
4. **列表入口**：列表点「文字报价」先取报价单详情（与详情页同一接口、同一默认版本），再打开同一个 `TextQuoteModal`；标为已发送沿用详情页的发送确认流程（含供应确认），完成后刷新列表。
5. **改选后重新生成**：下拉改变即重新请求文字；预览框已被手改时先确认「重新生成会覆盖已修改的文字」。

## Risks / Trade-offs

- [模版被租户改成不含货况或货期占位符] → 下拉照常可选，只是对输出没有影响；不额外提示。
- [采购回价被删除] → 退回报价单行的货期。

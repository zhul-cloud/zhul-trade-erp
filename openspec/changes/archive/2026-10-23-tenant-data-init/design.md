## Context

- 新租户由平台在「租户列表」创建，创建时只生成租户记录和管理员账号（`TenantServiceImpl`），没有部门。
- 部门、岗位、角色、汇率都是租户自己的数据，服务层通过 `TenantContext` 取当前租户写入，数据库层没有自动的租户过滤。
- 账号最终可用的菜单 = 角色菜单 ∩ 租户套餐（`EffectivePermissionResolver`），所以预设角色可以带完整的菜单权限，套餐外的自动不可用。
- 现有 `sql/build/init/福唯科技-组织架构初始化.sql` 已整理好福唯的部门、岗位、角色（含 609 条菜单权限），但它会重置已有角色的权限，与「只补缺」不一致。
- 部门管理里标记第一个事业部时，会把已有单据归入该事业部（`BusinessUnitService.mark`）。

## Goals / Non-Goals

**Goals:** 平台一键为租户写入福唯模板的组织架构与初始汇率；只补缺、可重复执行；结果可见。

**Non-Goals:**
- 不提供多套模板选择（以后需要时把预设数据文件扩展为多份）。
- 不预置收款账户、单据编号前缀、上传的单据模板文件（公司各自不同）。
- 不初始化用户（除把租户管理员归入总经办）。
- 不改品牌、品类、系列等平台共用数据。
- 不记录「是否已初始化」状态，按钮始终可点（重复执行只补缺）。

## Decisions

1. **预设数据放在 JSON 文件里，由服务按规则写入。** `resources/tenant-init/fouwell.json` 描述部门树、岗位、角色（数据范围、工作台、菜单编号、自定义部门）；`TenantDataInitService` 逐项「存在就跳过、缺少就新建」，并统计结果。比在 SQL 里写「只补缺」更清楚，也方便返回每类数量。内容从现有初始化脚本转换过来，转换后删除该脚本，避免两份数据不一致。
   - 备选：继续执行 SQL 脚本（把 @tid 换成参数）。不选：SQL 里难以返回结果数量，且「只补缺」的条件要写在每条语句上。
2. **切换到目标租户执行，复用现有服务。** 服务在 `try/finally` 里把 `TenantContext` 设为目标租户，结束后恢复平台租户；事业部标记调用 `BusinessUnitService.mark`（保证第一个事业部的单据归属与部门管理一致），汇率调用 `ExchangeRateService.save`（自动留变更记录）。整个初始化一个事务，任何一步失败全部回滚。
3. **识别规则。**
   - 公司根节点：租户只有一个顶级部门时直接用它（名称可能与租户名称不同）；没有时以租户名称新建；有多个时用与租户名称同名的，都不同名就新建。
   - 其他部门按「上级 + 名称」，岗位按编码，角色按名称；只看未删除的。
   - 新建的事业部才标记，开始核算月份为当月；已存在的部门不改标记。
4. **角色编码。** 新建角色沿用系统自动编码规则（`R` + 数字，与角色管理页新建一致），合伙人角色的自定义部门写入事业部的部门编码。
5. **权限与入口。** 新增按钮资源「数据初始化」（`tenant:list:init`，挂在租户列表下），接口 `POST /api/v1/tenant/tenants/{id}/init-data`，`@PreAuthorize("@perm.has('tenant:list:init')")`，并要求当前账号是平台账号。
6. **界面。** 操作列新增【数据初始化】；确认弹窗列出将写入的内容（部门 13、岗位 18、角色 9、汇率）并说明「已有的不改」；完成后结果弹窗按类显示「新建 N / 已存在 M」，下方是待办提醒。先出 OpenPencil 原型再实现。

## Risks / Trade-offs

- [模板是福唯的，其他公司初始化后带着「阿里国际站事业部」等名称] → 用户已确认使用福唯模板；部门、角色都可在页面上改名或停用。
- [预设菜单编号以后会过时（新增菜单不在预设里）] → 新增菜单时同步更新预设文件；已初始化的租户在角色管理里勾选。
- [第一个事业部的单据归属对已有大量单据的租户是批量更新] → 与部门管理里标记事业部一致，在同一事务内完成。

## Migration Plan

- Flyway 新增按钮资源（附反向 SQL），平台租户管理员自动拥有。
- 发布后：平台创建租户 → 点【数据初始化】→ 在用户管理建用户并分配部门、岗位、角色 → 租户在收款账户里填写账户。
- 福唯生产租户如已手工执行过初始化脚本，再点一次只会补缺的。

## Why

现在的退货只有一张「退货单」，在「仓库管理 → 退货入库」里同时充当退货申请、入库验收和退回供应商的记录。业务员在销售管理里找不到退货，退货和退款之间也没有先后关系；退给供应商的货（售后退货、到货不良、多发）没有单据，只是一个处理结果，查不到货寄没寄出、供应商退没退钱。用户希望参考零售的标准流程，按「售后单 → 销售退货单 → 退货入库单 → 采购退货单」把每个环节都落成单据，销售退货和采购退货分开，便于以后扩展功能和做报表。

## What Changes

- **售后单选择处理方式**：在售后单上选「仅退货」「退货退款」「仅退款」「补发」，分别生成销售退货单、销售退货单 + 退款申请、退款申请、补发订单。原来的「发起退货」「申请退款」按钮由这四个处理方式代替；「登记费用」保留。
- **新增销售退货单（销售管理 → 销售退货）**：沿用编号类型 TH。业务员建好后为「待确认」，可修改；「确认退货」后自动生成退货入库单。退货单显示入库进度与关联的退款申请。
- **退货入库单（仓库管理 → 退货入库）**：新单据，类型代码 RR，由销售退货单确认后自动生成，仓库验收实收与合格数量；验收后采购员逐行定去向（退回供应商、转闲置库存、报废），原规则不变。**BREAKING**：退货入库页不再列「退货单」，改列退货入库单。
- **退货退款**：确认销售退货时按退货数量 × 成交单价生成退款申请（可改金额），默认状态「待验收」，退货入库验收后才进入「待财务处理」；售后单上勾选「先退款」时直接进入「待财务处理」。实收少于退货数量时，退款申请提示财务。
- **仅退款**：沿用现有退款申请（金额手填、不对应型号、平台订单只能原路退回）。
- **新增采购退货单（采购管理 → 采购退货）**：类型代码 PR，一张单退给一个供应商。来源有四种，都自动生成：退货入库后去向选「退回供应商」；到货差异处理选「退货换货」「退货不补」（不良）或「退回供应商」（多发）。采购退货单跟踪寄出（快递、运费与垫付人）、供应商签收、供应商退款或抵扣金额，完成后：
  - 售后来源的退款或抵扣金额冲减所关联采购订单的应付，已付超出部分成为供应商欠款，由财务用现有的欠款退款、抵扣处理；
  - 原订单成本按采购退货单的退款或抵扣金额与运费调整（口径与现在相同）。
- **到货差异**：退货类处理不再在差异上填快递单号与运费，改到生成的采购退货单上填；数量与应付的影响不变。
- **来源单号与菜单**：销售管理增加「销售退货」（售后管理之前），采购管理增加「采购退货」（发货跟踪之后）；来源单号对照表补上新单据。
- **单据结构统一**：销售退货单、退货入库单、采购退货单、退款申请都由表头与明细组成，都有独立的详情页（可从列表、来源单号、售后单打开），方便以后扩展功能与做报表。退款申请新增明细：退货退款按型号逐行，仅退款为一行。
- **备注与附件**：四种单据都可以写备注、上传附件（图片、视频、PDF、Excel），附件都能在弹窗里预览，Excel 以表格显示。
- **单据页统一显示（全局规范）**：单据的列表与详情页以销售订单为标准——客户与来源单号分开两列，品牌、品类、型号的显示，详情页的表头、明细列顺序与布局都按销售订单；本次四种单据照此设计，以后新做的单据也照此执行。
- **存量数据迁移**：现有退货单拆成销售退货单 + 退货入库单，已退回供应商的去向与已处理的到货差异退货补生成已完成的采购退货单；成本、应付与报表数字不变。

## Capabilities

### New Capabilities
- `sales/sales-return`: 销售退货单——从售后单生成、确认、作废、列表页，与退货入库单、退款申请的关联。
- `purchase/purchase-return`: 采购退货单——各来源自动生成、寄出、签收、退款或抵扣、作废、列表页，及对应付与订单成本的影响。

### Modified Capabilities
- `sales/after-sales`: 售后单的处理方式（仅退货 / 退货退款 / 仅退款 / 补发）；结案时未完成单据的判断改为销售退货单、退货入库单、采购退货单与退款申请；售后单详情汇总新单据。
- `warehouse/sales-return`: 原「发起退货」移到销售退货单；「退货入库」改为对退货入库单验收；「退货去向」的退回供应商改为生成采购退货单。
- `finance/refund-request`: 退款申请可由销售退货生成，新增「待验收」状态与先退款开关；新增明细与独立详情页；实收少于退货数量的提示。
- `purchase/receiving-discrepancy`: 退货换货、退货不补、多发退回生成采购退货单，快递与运费在采购退货单上登记。
- `finance/accounts-payable`: 应付金额同步计入已完成的售后采购退货的退款或抵扣金额。
- `finance/order-cost`: 售后退货冲减订单成本的金额与运费改取自采购退货单。
- `system/navigation`: 新增「单据页统一显示」（以销售订单为标准）；列表的来源单号单独一列；菜单框架增加「销售退货」「采购退货」；来源单号对照表补上销售退货单、退货入库单、采购退货单。
- `system/file-attachment`: 新增单据附件与预览（图片、视频、PDF、Excel 在弹窗里预览）。
- `finance/reimbursement`: 退货运费的待报销项改由采购退货单寄出时登记（含售后退货来源）。
- `warehouse/stock-hold`: 售后退货转闲置记录退货入库单，来源列显示退货入库单号。

## Impact

- **数据库**：新增退货入库单、采购退货单及其明细表，退款申请明细表；`sales_return` 状态含义调整；`sales_return_disposition` 关联退货入库单行与采购退货单；`fin_refund_request` 关联销售退货单并新增「待验收」状态与先退款标记；`receiving_discrepancy` 关联采购退货单；新增菜单与按钮权限、编号规则（RR、PR）；一次性数据迁移。
- **后端**：`aftersales` 模块拆分销售退货与退货入库服务；新增采购退货服务（采购模块）；退款申请、到货差异、应付同步、订单成本、报销（退货运费垫付）相关服务调整。
- **前端**：售后单详情的处理方式；新页面「销售退货」「采购退货」及四种单据的详情页；「退货入库」页改造；到货差异处理弹窗；退款申请页签与状态；订单成本明细的来源链接。
- **报表与统计**：退款、订单成本、应付口径不变，只换数据来源；需要回归经营统计、利润统计与应付页。
- **规范**：`.claude/context/ui-design-patterns.md` 新增「单据页统一规范」，仓库 `AGENTS.md` 引用；现有把来源单号与客户、订单合在一列的页面（采购需求、采购订单详情、销售出库、退款申请、发货跟踪）不在本次范围，另行调整。
- **文档**：使用手册新增售后与退货流程章节；需要 OpenPencil 原型经用户确认后再开发页面。

## ADDED Requirements

### Requirement: 单据页统一显示
所有业务单据（报价单、形式发票、销售订单、销售退货单、退货入库单、采购退货单、退款申请等，以及以后新增的单据）的列表页与详情页 SHALL 以销售订单为标准，统一以下显示：

- **列表**：第一列为单号（可点开详情，下面一行为单据日期），固定在左侧；客户单独一列（名称 + 新 / 老客户标记、国家 / 地区、主联系人，分三行，缺哪行不显示哪行）；供应商单据的供应商同样单独一列；来源单号单独一列；型号列写作「型号 · 数量」（显示第一个型号，下面一行「共 N 个型号 · M 件 · 查看」）；品牌、品类各一列，按标签列出单据里的全部品牌、品类；最后是创建时间、创建人、更新时间、更新人与操作列「查看」。
- **详情页表头**：标题行为单号与状态标签，操作按钮在右侧；说明行依次为客户（或供应商）、「来源单号 X」、负责人、创建时间，用「·」分隔。
- **详情页明细**：列顺序为序号、品牌、品类、型号；型号单元格为型号（有商品档案且有权限时可点开商品档案）、订货号、「查看素材」三行；之后是该单据自己的数量、金额等列。
- **详情页布局**：宽屏时左侧为基本信息、明细、备注与附件，右侧为关联单据与操作日志；窄屏时上下排列。
- **备注与附件**：每张单据都有备注（选填，最多 500 字，在详情页随时可改，已作废的单据只读）与附件（见 `system/file-attachment`「单据附件与预览」），在详情页的「备注与附件」卡片里查看和维护。

#### Scenario: 销售退货列表的客户与来源单号
- **WHEN** 业务员打开销售退货列表
- **THEN** 「客户」与「来源单号」是两列，客户列显示名称、国家 / 地区与主联系人，来源单号列显示售后单号

#### Scenario: 采购退货单明细
- **WHEN** 采购员打开采购退货单详情
- **THEN** 明细的列依次为序号、品牌、品类、型号（型号、订货号、查看素材）、数量、来源行、采购订单行

## MODIFIED Requirements

### Requirement: 按部门分组的菜单框架
系统 SHALL 按以下分组与顺序组织侧边栏（括号内为尚未上线、上线时挂入该分组的功能）：
- 工作台
- 销售管理：客户跟进、商机管理、客户管理、询盘管理、报价管理、形式发票、销售订单、销售退货、售后管理（客户跟进是业务员每天的跟进入口，排在最前）
- 采购管理：询价分配、我的询价、询价记录、采购需求、采购订单、发货跟踪、采购退货、供应商库（原「兼职看板」并入工作台的采购员看板）
- 仓库管理：采购入库、销售出库、退货入库、闲置库存、实拍任务
- 物流管理：出运管理、运费账单
- 财务管理：收款管理、退款管理、余额管理、结汇管理、应付管理、付款管理、报销管理、费用管理、其他收入（、应收）
- 商品管理：商品档案、品牌管理、品类管理、系列管理，只放基础资料（价格体系上线后归入商品管理或单独分组，届时再定）
- 运营管理：商品候选、资料任务、营销任务、发品任务、素材管理，运营人员处理的任务（素材管理全公司共用，业务员也可以有它的权限）
- 统计分析：销售统计、询价统计、砍价统计、利润统计、经营统计、商机统计，只读的统计统一放在这里，各业务分组只放业务操作
- 业务设置：定价策略、汇率设置、收款账户、单据模板、编号规则、快递时效、国家资料、通知接收人
- 系统管理：用户管理、角色管理、部门管理、岗位管理、菜单管理、字典管理、系统设置、操作日志、登录日志
- 租户管理（仅平台账号）：租户列表、套餐管理

一级菜单的排序号互不重复，物流管理排在仓库管理之后。侧边栏按当前用户的菜单权限过滤：分组下没有可访问的菜单时整个分组不显示；没有页面的分组与菜单不出现在侧边栏。调整分组不改变各页面的访问地址，原有书签与链接继续可用。

#### Scenario: 业务员的侧边栏
- **WHEN** 业务员（有工作台、客户跟进、商机管理、客户管理、询盘管理、报价管理、形式发票、销售订单、售后管理与询价记录权限）登录
- **THEN** 侧边栏依次为「工作台」「销售管理」（客户跟进、商机管理、客户管理、询盘管理、报价管理、形式发票、销售订单、售后管理）「采购管理」（询价记录）「统计分析」（销售统计），不出现财务管理、业务设置与系统管理

#### Scenario: 采购员的侧边栏
- **WHEN** 采购员（有询价分配以外的采购菜单与供应商库权限）登录
- **THEN** 侧边栏的「采购管理」下依次为我的询价、询价记录、采购需求、采购订单、发货跟踪、供应商库

#### Scenario: 未上线的功能不占位
- **WHEN** 租户管理员登录，而应收功能尚未上线
- **THEN** 「财务管理」下没有应收菜单

#### Scenario: 原地址继续可用
- **WHEN** 业务员打开调整前收藏的询盘单详情链接
- **THEN** 页面正常打开，面包屑显示「销售管理 / 询盘管理 / …」

#### Scenario: 仓库人员的侧边栏
- **WHEN** 内置角色「仓库」的用户登录
- **THEN** 侧边栏只有「工作台」「仓库管理」（采购入库、销售出库、退货入库、闲置库存、实拍任务）、「财务管理」（报销管理）与「运营管理」（素材管理，验货和拍摄时参考）

#### Scenario: 财务的侧边栏
- **WHEN** 有收款管理、结汇管理、应付管理、付款管理、报销管理、费用管理、利润统计权限，没有退款管理、其他收入、经营统计权限的财务登录
- **THEN** 「财务管理」下依次为收款管理、结汇管理、应付管理、付款管理、报销管理、费用管理；「统计分析」下只有利润统计

#### Scenario: 采购员看到报销单
- **WHEN** 有采购订单菜单的采购员登录
- **THEN** 侧边栏出现「财务管理」，下面只有「报销管理」

#### Scenario: 采购负责人看到砍价统计
- **WHEN** 有「询价分配」菜单的采购负责人登录
- **THEN** 「统计分析」下有「询价统计」「砍价统计」；只有采购订单菜单的采购员看不到它们

#### Scenario: 财务看到利润统计
- **WHEN** 有收款管理菜单的财务登录
- **THEN** 「统计分析」下有「利润统计」，排在「经营统计」之前

#### Scenario: 财务看到退款单与经营统计
- **WHEN** 有收款管理菜单的财务登录
- **THEN** 「财务管理」下依次为收款管理、退款管理、结汇管理、应付管理、付款管理、报销管理、费用管理、其他收入；「统计分析」下有利润统计、经营统计

#### Scenario: 运营人员的侧边栏
- **WHEN** 管理员登录
- **THEN** 「商品管理」下依次为商品档案、品牌管理、品类管理、系列管理；「运营管理」下依次为商品候选、资料任务、营销任务、发品任务、素材管理

#### Scenario: 业务员有素材库权限
- **WHEN** 业务员的角色加上了素材管理菜单权限
- **THEN** 侧边栏出现「运营管理」，下面只有「素材管理」

#### Scenario: 物流管理排在仓库管理之后
- **WHEN** 管理员登录
- **THEN** 一级菜单依次为工作台、销售管理、采购管理、仓库管理、物流管理、财务管理……，仓库管理与物流管理的先后每次一致

#### Scenario: 财务人员看到余额管理
- **WHEN** 财务角色的用户登录
- **THEN** 「财务管理」下依次为收款管理、退款管理、余额管理、结汇管理、应付管理、付款管理、报销管理、费用管理、其他收入

#### Scenario: 售后管理与退货入库
- **WHEN** 管理员登录
- **THEN** 「销售管理」最后两项为「销售退货」「售后管理」；「采购管理」的「发货跟踪」之后为「采购退货」；「仓库管理」下依次为采购入库、销售出库、退货入库、闲置库存、实拍任务

#### Scenario: 客户跟进排在销售管理最前
- **WHEN** 有「客户跟进」菜单的业务员登录
- **THEN** 「销售管理」第一项为「客户跟进」，之后依次为商机管理、客户管理……

#### Scenario: 业务设置里的通知接收人
- **WHEN** 有「通知接收人」菜单权限的用户登录
- **THEN** 「业务设置」最后一项为「通知接收人」

### Requirement: 来源单号
每张单据的上一张单据 SHALL 统一称为「来源单号」，显示上一张单据的编号，可以点开（按「跳转后可返回原页面」可返回）。上下游关系如下：

| 单据 | 来源单号 |
|---|---|
| 报价单 | 询盘单号（可多个） |
| 形式发票 | 报价单号（可多个） |
| 销售订单 | 形式发票号；售后补发订单为售后单号；费用订单为原订单号；手动创建的订单显示「手动创建」 |
| 采购需求、采购订单 | 销售订单号（采购订单可多个） |
| 供应商发货单 | 采购订单号 |
| 采购入库单 | 供应商发货单号 |
| 暂存记录 | 采购订单号；售后退货为退货入库单号 |
| 销售出库单 | 销售订单号 |
| 拍摄任务 | 采购入库单号 |
| 出运单 | 销售出库单号 |
| 售后单 | 销售订单号 |
| 销售退货单 | 售后单号 |
| 退货入库单 | 销售退货单号 |
| 采购退货单 | 售后退货为退货入库单号；到货差异为采购入库单号 |
| 退款申请 | 由销售退货生成的为销售退货单号，其他为售后单号（订单详情提出的为销售订单号） |
| 应付单 | 采购订单号或运费账单号 |
| 报销明细 | 对应的费用、运费等单据号 |
| 收款记录、多收记录 | 形式发票号或销售订单号 |

询盘单是链路的第一张单据，没有来源单号，原来的「来源」（询盘来源渠道）不变。

显示方式：
- **详情页**：来源单号放在表头的说明行，写作「来源单号 X」。有多个来源时全部列出，用顿号分隔，每个都能点开。
- **列表页**：来源单号单独一列，标题为「来源单号」，不与客户、供应商、订单等信息合并（见「单据页统一显示」）。只有一个来源时显示该单号；有多个时显示「X 等 N 个」，悬停显示全部单号，每个都能点开。
- **型号明细**：报价单、形式发票、销售订单的型号明细不显示来源单号，统一看表头。采购订单、出运单等一张单据的各行本来就来自不同上游单据的，行上保留来源，列名同样叫「来源单号」。
- 指向下游单据的列（如形式发票列表的「销售订单」）、费用分摊列、汇率等的「来源」不属于来源单号，名称不变。

#### Scenario: 销售订单的来源单号
- **WHEN** 打开由形式发票 PI20261104002 转成的销售订单
- **THEN** 表头说明行显示「来源单号 PI20261104002」，可点开；销售订单列表的「来源单号」列也显示 PI20261104002

#### Scenario: 多个来源
- **WHEN** 一张形式发票合并了报价单 QT20261103001、QT20261103004
- **THEN** 详情表头显示「来源单号 QT20261103001、QT20261103004」；形式发票列表显示「QT20261103001 等 2 个」，悬停可看到并点开两张报价单

#### Scenario: 手动创建的订单
- **WHEN** 打开手动创建的销售订单
- **THEN** 来源单号显示「手动创建」，不可点击

#### Scenario: 采购订单列表
- **WHEN** 采购查看采购订单列表
- **THEN** 原「来源订单」列标题为「来源单号」，显示销售订单号，点开进入该销售订单并可返回

## Why

报价之后，客户有意向时要开 PI（形式发票）确认要买的型号、金额并请客户付款。现在 PI 全靠复制《PI模版.xlsx》手工改：型号和单价从报价单里一行行抄，客户公司抬头、收货人、银行信息每次重填，同一客户从几张报价单里各挑几个型号下单时更容易抄错；PI 改了数量就直接覆盖原文件，改过什么无从查起；客户发来水单、财务确认到账、再转成订单，这几步都没有记录，报价单也不知道最后成交了哪些型号。公司已有 317 份手工 PI，平均每个老客户十几份，量已经大到需要进系统。

## What Changes

- **PI（形式发票）**：独立单据，只负责「确认 + 请款」。两种开法：直接按一张报价单开（带入全部型号，可取消勾选、改数量）；或先选客户，再从该客户多张已发送的报价单里挑型号合并开一张（同一币种）。带入报价单的单价、货况、货期与采购成本快照；买方取客户的发票抬头（Bill To）、收货人取默认收货人（Consignee），都可改选；包含交期、付款条件、起运港、备注、收款银行账户；可加运费、银行手续费等费用行与**整单折扣**（按金额或百分比），净利润与毛利率按折扣后计算、低于红线只提示。
- **PI 多版本**：已发送的 PI 可以修改，修改生成新版本（Rev.2、Rev.3…），**PI 编号不变**，旧版本只读可查、可对比；导出的单据上不显示版本号；转成销售订单后锁定。
- **收款登记**：业务员上传客户的付款水单（截图或 PDF，填写付款金额与日期）；**财务**登记实际到账（金额、日期、银行），到账与 PI 金额的差额可记为银行中转手续费；同一张 PI 可以登记多笔（定金、尾款）。钱记在 PI 上，订单只展示。
- **转销售订单（最小闭环）**：PI 有水单或已有到账即可转成销售订单；订单记录表头、型号行与收款状态（待到账 / 部分到账 / 已到账），**创建后不能修改，只能取消**（写原因、二次确认）后让 PI 出新版本再重新转。取消后已登记的收款随 PI 保留，重新转出的订单继续显示。
- **报价单成交改由订单推进**：报价单开出 PI 后标记「已开 PI」并关联 PI 号；PI 转成销售订单时，报价单按型号行判断变为「已成交」或新增的「部分成交」并关联 PI、订单号；订单取消时退回。不再手动「标为已成交」，「未成交」与「作废」仍手动。
- **全链路单据编号**：统一规则「前缀 + 类型 + 年月日 8 位 + 当日 3 位流水」（如 `FWPI20261006001`），每租户每类单据独立流水；前缀为租户设置（2–4 位大写字母，不含符号，可为空），只加在对外单据（报价单、PI、CI、PL、采购单、借项 / 贷项通知单、对账单）上，与编号一起保存；同一发货批次的 CI 与 PL 共用编号主体。本次落地报价单、PI、销售订单的编号，其余单据按此规则在各自模块实现。
- **全链路追溯**：单据行逐级记录来源行（询盘型号 → 报价行 → PI 行 → 订单行），任一单据可查看来源与去向。
- **收款银行账户**：租户维护多个收款账户（如美元 JPMorgan、人民币账户），开 PI 时按币种默认带出，可改选；PI 模版用 `${bank.…}` 占位符显示。
- **PI 模版生成**：确定 PI 模版的占位符（买方、收货人、PI 信息、银行、型号行含 HS 编码与原产国、费用与折扣行），实现 PI 的 Excel / PDF / 图片导出与实时预览；把公司现有《PI模版.xlsx》改造成占位符版作为福唯租户的 V2。
- **不在本次**：补运费、退款、欠款合并这类调整单据放到后续应收模块（借项通知单、贷项通知单、对账单）；CI、PL、发货、采购单随后续模块实现。

## Capabilities

### New Capabilities
- `sales/proforma-invoice`: PI 的创建（按报价单 / 跨报价单挑型号）、内容（买方、收货人、型号行、费用、整单折扣、银行账户）、多版本、导出与状态。
- `sales/payment-receipt`: 收款登记——业务员上传水单、财务登记到账、多笔收款、到账差额与收款状态。
- `sales/sales-order`: 由 PI 转成销售订单（最小闭环）、订单不可修改只能取消、取消后的回退。
- `system/document-numbering`: 全链路单据编号规则与租户前缀设置、单据之间的来源 / 去向追溯。
- `system/bank-account`: 租户收款银行账户的维护与在单据上的取用。

### Modified Capabilities
- `quotation/quotation`: 「报价单状态」新增「部分成交」，成交由销售订单推进、不再手动标成交，开出 PI 后标记「已开 PI」；「报价单内容与定价」中的编号改为按全链路编号规则生成（带租户前缀）。
- `inquiry/inquiry-intake`: 「客户询盘状态」中「已成交」改为由报价单的已成交或部分成交推进。
- `document/document-template`: 「占位符约定与校验」补充 PI 占位符并校验 PI 模版；「按租户维护与初始模版」改为 PI 已实现生成、银行信息改由系统字段填充。

依赖：`quotation/quotation`、`document/document-template` 来自尚未归档的变更 `add-quotation-pricing`，本变更须在其归档之后归档。客户的收货人、发票抬头直接使用已有的「客户单证主体」（`master-data/customer-party`），不修改其规格。

## Impact

- **数据库**（新迁移脚本）：`proforma_invoice`、`proforma_invoice_version`（版本快照）、`proforma_invoice_item`、`proforma_invoice_fee`、`payment_receipt`（水单 / 到账）、`sales_order`、`sales_order_item`、`tenant_bank_account`、`document_sequence`（按租户 / 类型 / 日期的流水号）；`quotation` 增加「部分成交」状态与 PI 关联、`quotation_item` 增加成交标记；`sys_config` 增加单据前缀；菜单「销售管理 → PI / 销售订单」「系统管理 → 收款账户」与按钮权限（含财务「登记到账」）。
- **后端**：新模块 `com.zhul.erp.modules.sales`（PI、收款、销售订单）；`modules.system` 增加单据编号服务与收款账户；`modules.document` 扩展 PI 渲染；`modules.quotation` 的成交改由销售订单推进（与订单创建 / 取消同一事务）。
- **前端**：`pages/sales`（PI 列表、新建两种方式、编辑与版本、收款登记、销售订单列表与详情）、`pages/system/bank-account`；报价单详情显示「已开 PI / 成交」关联；客户询盘详情显示下游单据。
- **财务口径**：金额一律 `DECIMAL(18,2)`，原币与本位币同时保存，汇率沿用报价单快照（同币种合并）；折扣、到账差额的舍入为两位小数 HALF_UP；收款登记、转订单、取消订单都写操作日志并记录操作人。
- **原型**：在 `docs/03-产品原型/03-业务域/` 下新建「销售管理 / PI 与订单」原型。

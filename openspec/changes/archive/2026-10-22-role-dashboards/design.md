## Context

- **现在的工作台**：前端 `pages/dashboard/index.tsx` 里写死了一个卡片数组（商机统计、过期未收款 PI），按前端菜单权限过滤，各卡片自己请求现有接口。没有「模板」和「角色」的概念。
- **角色**：表 `role` 有 `permission_scope`（数据范围），角色编码是各公司自建的随机编码（如 `R71491664`），只有少数内置角色有固定编码（`ROLE_ADMIN`、`ROLE_PTBUYER`、`ROLE_WH` 等）。数据范围由 `access/data-scope` 计算出「可见的负责人」，各列表接口按它过滤。
- **兼职看板**：前端 `pages/inquiry/part-time-board`、后端询价模块的 `part-time-board` 接口，菜单挂在采购管理下。
- **现有统计口径**：销售统计、利润统计、经营统计、询价统计、砍价统计、商机统计、发品任务与内容任务的计数，看板组件尽量调用这些现有服务，口径保持一致。

## Goals / Non-Goals

**Goals**
- 模板由数据定义（表 + 迁移），角色选模板，新增岗位看板不改代码。
- 组件可插拔：后端一个数据提供者 + 前端一个展示组件，按编码对应；新增组件不改框架和已有组件。
- 组件数据遵循现有菜单权限与数据范围，口径复用现有统计服务。

**Non-Goals**
- 不做拖拽布局、用户自定义看板（以后可在模板之上加个人偏好）。
- 不做经营目标、预算对比（系统里没有目标数据）。
- 不做实时推送，打开或刷新工作台时加载。

## Decisions

### 1. 数据模型

**`workbench_template`**（基础表，所有公司共用，`tenant_id` 固定 0，用 `status` 不用 `deleted_at`）

| 字段 | 说明 |
|---|---|
| `code` | 唯一，如 `boss`、`sales_lead`、`sales`、`purchase_lead`、`purchaser`、`ops_lead`、`general` |
| `name` | 显示名称 |
| `rank` | 职级排序，数字越小越高 |
| `widgets` | JSON 数组 `[{"key":"biz-overview","size":"full"}, …]`，按显示顺序 |
| `sort`、`status` | 列表顺序、启停 |
| 审计列 | 创建时间、创建人、更新时间、更新人 |

**`role.workbench_template`**：varchar(32)，默认 `general`。

**新增岗位看板 = 迁移里插一行模板**，组件从已有组件里选；不改 Java 和前端代码。

### 2. 后端组件框架（模块 `workbench`）

- **`WorkbenchWidget` 接口**：`key()`、`name()`、`menu()`（需要的菜单路径）、`Object load(WidgetContext ctx)`。
- **`WidgetContext`**：公司、当前用户、可见负责人（按数据范围算好的）、周期参数（本月等）。
- **注册**：`WidgetRegistry` 由 Spring 注入全部 `WorkbenchWidget` Bean 组成 `key → 组件`。新增组件 = 新增一个 `@Component` 类，不改注册代码。

**接口**

| 方法与路径 | 说明 |
|---|---|
| `GET /api/v1/workbench` | 当前用户的看板：按用户全部角色取模板（去重），按 `rank`、`sort` 排序，每个模板的组件按菜单权限过滤，并标出默认模板 |
| `GET /api/v1/workbench/widgets/{key}` | 一个组件的数据 |

组件数据接口的校验：组件必须在当前用户的某个模板里且有菜单权限，否则返回无权限；数据范围用当前用户的数据范围（与列表页一致）。

**口径复用**：组件内部调用现有统计服务（销售统计、利润统计、经营统计、询价统计、砍价统计、商机统计、发品与内容任务计数等），不另写一套统计 SQL。现有服务只返回明细的，在服务里补一个汇总方法，原有接口不变。

### 2.1 通用数据块（实现时补充）

- **为什么**：除了照搬原有页面的卡片（商机统计、过期未收款 PI、采购员看板四块），其他组件的后端都返回统一的 `WidgetData`。
- **数据块类型**：metrics（数字行，可带较上月变化与跳转）、todos（待办）、table、bars、funnel、progress（分段进度）、note（说明与胶囊标签）。
- **前端**：用一个通用组件 `blockWidget` 渲染，注册表里只登记标题、图标、色调与「查看更多」链接。
- **好处**：新增组件基本只写后端组件类，再加一行注册。
- **格式化**：数值按 format（money、percent、count）由前端格式化，金额用 `formatAmount`。较上月的变化：金额与个数用百分比，比率用百分点；按 higherIsBetter 着色（费用变大为坏）。

### 3. 前端

- 工作台页请求 `/workbench`。只有一个模板时直接显示；多个时顶部 `Segmented` 切换。上次选择存在浏览器本地（按用户），读不到时用默认模板。
- 组件注册表 `WIDGETS: Record<string, React.FC>` 放在 `pages/dashboard/widgets/index.ts`，每个组件一个文件，自己请求 `/workbench/widgets/{key}`，失败显示重试。
- 后端有、前端还没有的组件编码直接跳过（便于先上后端）。
- 布局：两列网格，`size=full` 占整行。
- 现有的商机统计卡片、过期未收款 PI 卡片改成组件，供通用、老板、业务负责人、业务员模板复用。

### 4. 去掉兼职看板

- **菜单**：删除菜单与按钮权限，并从套餐、角色里去掉。
- **兼职采购**：「兼职采购」角色补上「工作台」菜单，模板为采购员。
- **旧地址**：路由 `/inquiry/part-time-board` 改为重定向到 `/dashboard`。
- **接口**：兼职看板接口的统计逻辑移到采购员看板的组件里，原接口删除。

### 5. 角色模板预设（迁移）

- **内置角色**：`ROLE_ADMIN` → `boss`，`ROLE_PTBUYER` → `purchaser`，其他 → `general`。
- **公司自建角色**：按名称关键词预设一次，规则见规格。之后以角色管理为准，迁移不会再覆盖。

## Risks / Trade-offs

- **组件数量多、查询多**：老板看板约 6 个组件，各自并发请求。每个组件的查询都要走现有索引；汇总类查询限定在本月、近 12 个月范围内。必要时再按「公司 + 组件 + 周期」加 5 分钟缓存。
- **数据范围与模板不一致**：比如老板模板配给了只能看本人的角色，看到的就只是本人数据。这是有意为之：看板只是视图，权限仍以角色的数据范围为准。
- **名称预设可能对错**：只在上线时跑一次，管理员在角色管理里可以改。
- **本地记住切换**：换浏览器后回到默认模板，影响很小。

## Migration Plan

**迁移 `V1.3.5__role_dashboards.sql`**
- 建模板表、插入七个模板。
- 角色表加字段，并预设内置角色与自建角色。
- 删除兼职看板菜单与权限，兼职采购补上工作台菜单。

**反向 SQL**
- 恢复兼职看板菜单与权限，删除角色上的模板字段，删除模板表。

**分阶段上线**（每阶段可单独验收）
1. 框架、模板、角色选模板、去掉兼职看板、通用看板、采购员看板；
2. 业务员、业务负责人看板；
3. 采购负责人、运营负责人看板；
4. 老板看板。

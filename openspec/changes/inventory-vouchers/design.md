## Context

动机见 proposal.md。现状：

- 库存月结（`InventoryPeriodService.close / reopen`）结账时写 `inv_period_ledger`、`inv_period_cogs` 快照，并锁定该月业务日期的库存单据；成本调整总是记在调整当天的月份，不受锁定影响。所以月份结账后，这个月的库存流水（`inv_move`，按 `biz_date` 归月）和成本调整明细（`inv_cost_adjust_item`，按 `adjust_date` 归月）都不会再变。
- 流水金额已是 2 位小数（数量 × 单位成本，HALF_UP），按四个组成部分（货款、开票成本、采购费用、质量索赔）分别记。开票成本、采购费用都在采购订单上，付给同一个供应商，所以四部分都对应应付账款，凭证不必拆开。
- 批次通过 `inv_batch.po_item_id` 找到采购订单与供应商；退货入库、系统外入库、期初批次没有采购订单。
- 供应商已有 `supplier_code`（如 SUP00012）。
- 系统里还没有会计科目和凭证。

## Goals / Non-Goals

**Goals:**
- 凭证金额和库存台账、月结快照同源，当月全部凭证里库存商品的净额加上不生成凭证的变动，正好等于期末减期初。
- 一张凭证只对应一张来源单据的一次动作，T+ 里按摘要的单号能直接对到 ERP 单据。
- 改科目设置不需要重新生成凭证。
- 生成与作废和结账、反结账在同一事务里完成，不会出现结了账没凭证、反结了账凭证还在的情况。

**Non-Goals:**
- 不按商品、仓库、品类做辅助核算；库存商品只记一行合计。
- 不给凭证加备注和附件：凭证由系统按单据生成，来源单据本身有备注和附件，点单号就能打开。
- 不在 ERP 里给凭证编号：导入时由 T+ 编号（见 Open Questions）。

## Decisions

### 1. 凭证记业务项，导出时再取科目编码
分录表存业务项键（如 `STOCK`、`COGS`、`AP`、`RETURN_IN`、`OTHER_OUT:1`、`ADJ_OFFSET:4`）、往来单位（供应商 ID）、方向和金额，不存 T+ 科目编码。导出、页面展示时按当前科目设置解析。
- 备选：生成时就写死科目编码。缺点是会计后来改了科目，要么重新生成，要么旧凭证带着旧科目，容易导错。按月汇总的凭证没有「历史科目」需要保留，所以选择导出时再取。

### 2. 数据来源与分组：按单据动作，不用快照
- 采购入库、销售成本结转、其他出库：取当月 `inv_move`（全部仓库，只取入库、出库类操作；调拨、合格不良转换、预占释放都不计入），按「来源单据类型 + 单据 ID + 业务类型 + 业务日期」分组，每组一张凭证。同一单据同一天重复做同一动作（如撤销后重新出运）会并成一张，金额仍正确。
- 成本调整：按当月 `inv_cost_adjust`（按调整日期归月）每张调整单一张凭证，分录按明细的 `part`、出库单据类型、触发原因汇总。
- 按单据而不按月汇总（用户 2026-11-22 定）：单据量不大，按单据时 T+ 的应付明细账逐笔带单号，和供应商、ERP 都能逐笔对账。
- 快照只存了每个商品的入库、出库合计，没有业务类型和供应商，满足不了按类型、按供应商拆分。但月份结账后流水已锁定，所以直接读流水和读快照结果一致。核对时用快照的期初、期末，算式能对上就说明两边是一致的。

业务类型的归属如下：

| 凭证类别 | 业务类型 → 摘要里的动作（红字为反向动作） |
| --- | --- |
| 采购入库 | PURCHASE_IN 采购入库；PURCHASE_IN_REVERSE 冲销采购入库（红字）；DISCOUNT_ACCEPT 折价接收；DISCOUNT_ACCEPT_UNDO 重新打开折价（红字）；PURCHASE_RETURN_OUT 采购退货（借应付、贷库存） |
| 销售成本结转 | SALES_OUT 出运结转成本；SALES_OUT_UNDO 撤销出运（红字）；RETURN_IN 退货入库（借库存、贷「退货入库」业务项）；RETURN_IN_UNDO 撤回退货入库（红字） |
| 其他出库 | OTHER_OUT 其他出库 · {类型}；OTHER_OUT_VOID 作废其他出库（红字） |
| 不生成凭证 | OPENING、SYSTEM_IN、MERGE（列在核对里作参考） |
| 不计入 | HANDOVER、HANDOVER_UNDO（调拨，全部仓库合计时抵消）、RESERVE、RELEASE |

- 采购退货出库的供应商取采购退货单的供应商。
- 实现时用一个测试锁定这张表：库存流水里所有带金额的业务类型都必须有归属（凭证或「不生成凭证」），以后新增业务类型时测试会失败，提醒补上归属。

### 3. 表结构（迁移 V1.5.58）
- `fin_voucher`：凭证表。字段为租户、月份、类别（1-采购入库、2-销售成本结转、3-其他出库、4-成本调整）、来源单据类型、来源单据 ID 与单号、业务类型（成本调整为空）、凭证日期、摘要、借方合计、贷方合计、状态（1-有效、2-已作废）、关联的 `inv_period.id`，加上审计字段和 `deleted_at`。来源单据列加索引，供单据详情反查凭证。唯一性靠「来源单据 + 业务类型 + 凭证日期 + 有效」在代码里保证（作废的记录保留）。
- `fin_voucher_month`：月份导出记录。字段为租户、月份、导出次数、最近导出人与时间。导出状态是按月的，不放在每张凭证上。
- `fin_voucher_entry`：分录表。字段为凭证 ID、行号、业务项键、往来单位类型（供应商）、往来单位 ID、方向（1-借、2-贷）、金额（DECIMAL(18,2)，可为负）、币种 CNY。
- `fin_voucher_account`：科目设置表。字段为租户、业务项键（唯一）、T+ 科目编码、科目名称。
- 供应商的 T+ 往来单位编码：在 `supplier` 表加 `tplus_partner_code` 列。没填时用 `supplier_code`。
- 四张新表都按 PRIVATE 加进 `TenantTables`。
- 菜单「业务凭证」，按钮权限「生成凭证 / 导出」「科目设置」。新租户预置默认科目：在租户初始化模板里补，存量租户由迁移补。

### 4. 生成与作废挂在结账、反结账的事务里
- `InventoryPeriodService.close` 写完快照后调用 `VoucherService.generate(period)`；`reopen` 调用 `VoucherService.voidAll(period)`。
- 凭证服务放在 `modules/finance/voucher`，只读库存的表，库存模块只依赖它的这两个入口。
- 生成失败会让结账一起回滚：凭证生成只做汇总，失败只可能是代码缺陷，结账不该在没有凭证的情况下成功。
- 手动「生成凭证」只用于已结账、且还没有有效凭证的月份，并加 `zhul:erp:lock:voucher:{tenantId}:{month}` 锁，防止重复生成。

### 5. 核对
- 期初、期末取 `inv_period` 的期初、期末金额（快照合计）。
- 凭证里库存商品的净额 = 当月全部有效凭证中 `STOCK` 行的借方减贷方。
- 不生成凭证的变动 = 当月 OPENING、SYSTEM_IN、MERGE 流水金额，按类型列出。
- 核对每次打开页面时现算，不存表。

### 6. 导出
- 用 POI 生成 xlsx，每月一个文件，里面是该月全部有效凭证，按凭证日期、来源单号排序。
- 列按用户提供的 T+ 凭证导入模板来定（见 Open Questions）。实现上把列映射集中在一个导出类里，模板有出入只改这一个地方。
- 金额：借方、贷方各一列，红字写负数。

## Risks / Trade-offs

- **成本调整的对方科目** → 默认按应付账款处理。「每日核对」「成本口径升级」这两种调整，会计可能希望记到别的科目（比如以前年度损益调整），所以对方科目按触发原因可以分别设置，上线前请会计确认。
- **退货入库冲减主营业务成本，库存月结的「本月销售成本」不扣退货，两边数字不一样** → 凭证下方写明差异；业务项可以改成别的科目。
- **期初、补关联商品不生成凭证** → 核对里单独列出并提示，会计在 T+ 里手工处理。上线当月，T+ 里库存商品的期初余额应该等于 ERP 库存月结的期初，上线后请会计核对一次。
- **外币应付账款在 T+ 里通常做外币核算，这里只导人民币** → 第一期由会计在 T+ 里补外币信息；收付款凭证那一期再一起考虑外币核算。
- **会计在 T+ 里重复导入同一张凭证** → 已导出的月份重复导出时二次确认，并记录导出次数。
- **「每日核对」这类自动成本调整，一天可能就有一张** → 现在单据不多，先每张调整单一张凭证。以后量大了，可以让这几种触发原因按月合并成一张，只改分组规则。

## Migration Plan

- 迁移 V1.5.58：
  - 新建四张表；`supplier` 加 `tplus_partner_code`。
  - 新增菜单与权限，按钮权限授给管理员和财务角色。
  - 给存量租户预置默认科目。
- 已经结账的月份不自动补凭证，由财务在页面上手动「生成凭证」，避免一上线就出现会计不知道来源的凭证。
- 回退：删四张表、删 `supplier.tplus_partner_code` 列、删菜单。库存月结不受影响，代码回到上一版本即可。回退语句写在迁移文件末尾。

## Open Questions

- **T+ 凭证导入模板的列：** 开发导出前，需要用户从自己的 T+ 里导出一份「凭证导入模板」和一份科目表，以此确定：
  - 列名与顺序；
  - 凭证号怎么填（留空由 T+ 编号，还是必须填）；
  - 往来单位填编码还是名称；
  - 科目要不要填到最末级。

  这些只影响导出类，不影响凭证生成和页面。

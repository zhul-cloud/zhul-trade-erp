# Spec Delta

## ADDED Requirements

### Requirement: 共享菜单资源定义写操作仅平台维护
共享菜单资源定义的新增、修改、删除、启停和排序 SHALL 同时校验平台身份与对应维护权限：新增用 `system:menu:add`，修改/启停/排序用 `system:menu:edit`，删除用 `system:menu:delete`。平台超管按既有权限范围规则正常操作；普通租户即使有同名菜单或维护权限也不得写全局资源，不能伪造订阅权限码、停用后重新启用订阅资源或制造授权别名。

#### Scenario: 普通租户尝试恢复订阅资源
- **WHEN** 普通租户直接调用共享资源更新 permission 或 status，包括已停用的订阅按钮
- **THEN** 返回拒绝，资源及角色或套餐授权数据不变，不能恢复订阅使用权

#### Scenario: 普通租户调用其他定义写操作
- **WHEN** 普通租户直接新增、删除、修改排序或修改任意共享资源定义
- **THEN** 均被服务端拒绝，不能靠界面隐藏代替权限校验

#### Scenario: 平台用户缺对应维护权限
- **WHEN** 非超管平台账号有菜单读取但无相应新增、编辑或删除权限
- **THEN** 对应写操作被拒绝，其他已授予操作保持原规则

#### Scenario: 平台管理员正常维护
- **WHEN** 平台超管或有相应维护权限的平台账号提交合法共享菜单资源修改
- **THEN** 正常保存，菜单与权限使用者看到更新；订阅固定资源被停用后，新订阅调用拒绝

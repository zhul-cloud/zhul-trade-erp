# Spec Delta

## MODIFIED Requirements

### Requirement: 创建通用 AI 任务
系统 SHALL 提供与具体业务无关的 AI 任务记录，包含 skill、租户、真实发起人、发起时运行方式、状态、结果、失败原因与开始完成时间，初始排队中。订阅任务创建前校验当前用户使用权限及订阅可用性，持久主体从已认证上下文解析，不信任请求自报用户或 allowed 标志；无可靠主体时拒绝订阅调用。

#### Scenario: 创建任务
- **WHEN** 合法用户发起 AI 处理并指定 skill 和输入
- **THEN** 创建排队中任务，记录服务器确认的 tenantId、requestedBy、审计账号和运行方式

#### Scenario: 通用入口不能省略主体绕过
- **WHEN** 用户通过通用 AI 创建接口尝试订阅，入参不含发起人或自报他人
- **THEN** 服务端仍解析真实账号与用户，不能用 0、sys 或伪造主体跳过权限

### Requirement: 提交任务给 AI 编排服务
系统 SHALL 以 skill、输入、回调地址、持久 taskId 及配置提交 AI 编排，受理后返回 202，结果异步回调。API 使用发起时本租户配置快照，解密 Key 只在本次内部请求内存中；订阅配置在实际启动前由后端按最新授权与平台 profile 重新解析，不信任输入中的模型或 Key。外部提交必须在任务及发起业务事务提交后发生。

#### Scenario: 提交后不阻塞等待
- **WHEN** 后端提交一个任务
- **THEN** 编排服务受理返回确认，不同步等待模型结果

#### Scenario: 任务携带发起时的配置
- **WHEN** API 任务提交后修改配置
- **THEN** 已提交 API 任务使用发起时快照，后续 API 任务用新配置；订阅任务遵循执行前实时解析规则

#### Scenario: Key 不落库
- **WHEN** 检查已提交任务记录、授权响应和后端或编排日志
- **THEN** 不包含 API Key 明文或订阅凭据，订阅授权响应 api_key 为空

#### Scenario: 订阅排队时平台修改模型
- **WHEN** 订阅任务已受理但尚未启动 worker，平台修改对应订阅模型
- **THEN** 执行前授权返回最新平台模型与用量，不使用入队旧 profile

## ADDED Requirements

### Requirement: 订阅执行前实时授权
每个订阅任务 SHALL 在取得串行执行槽后、启动 worker 前，通过受内部共享令牌保护的后端授权关卡。后端从持久 taskId 加载原租户、真实发起人及发起方式，重查该账号当前租户和使用权限、当前运行方式与订阅可用性，再返回有效服务商及平台订阅 profile。失权、主体缺失、已改 API、任务不合法或授权服务故障均拒绝，不启动 worker、不转用 API。

#### Scenario: 撤权发生在排队期间
- **WHEN** 用户创建订阅任务后，平台移除套餐或角色使用权限，任务随后取得执行槽
- **THEN** 内部授权拒绝，订阅 worker 未启动，任务沿既有失败分发回报

#### Scenario: 全局按钮已停用
- **WHEN** 平台停用订阅使用资源而任务尚未启动
- **THEN** 授权关卡拒绝该任务，不被平台超管的通常资源范围豁免绕过全局停用状态

#### Scenario: 租户改回 API
- **WHEN** 已受理的订阅任务等待时，租户将当前运行方式改为 API
- **THEN** 原订阅任务授权失败，不自动改成 API 收费任务

#### Scenario: 伪造授权信息
- **WHEN** 请求附 allowed=true、别人的 tenantId/requestedBy 或自定模型
- **THEN** 这些值不能作为授权依据，后端以持久任务主体和最新配置判断

#### Scenario: 授权服务不可用
- **WHEN** 内部授权请求超时、网络错误、无效响应或共享令牌错误
- **THEN** 拒绝执行并安全失败回调，worker 与模型调用均未开始

#### Scenario: 撤权发生在请求发出之后
- **WHEN** 最后一次授权已通过且模型请求已发往服务商，随后用户被撤权
- **THEN** 不承诺撤回在途服务商请求；之后尚未开始的调用必须重新检查并拒绝，本轮不新增强制终止在途请求机制

### Requirement: 订阅授权复用内部鉴权且不泄露凭据
订阅执行前授权 SHALL 使用现有内部共享令牌，不依赖浏览器权限布尔值或持久用户 token。仅内部正确令牌可获取授权结果；响应只含安全错误码或有效模型配置，不含账号、登录命令、API Key、CLI token。服务端按明确主体查询权限，不向全局上下文回设其他用户身份。

#### Scenario: 内部令牌缺失或错误
- **WHEN** 订阅授权端点收到缺失或错误内部令牌
- **THEN** 返回 401，不返回配置、不调用订阅

#### Scenario: 授权响应模型重新计算
- **WHEN** 内部调用合法且订阅可用
- **THEN** 响应有效 provider、mode=subscription 和平台当前模型/强度/搜索，api_key 为空，原请求 Key 与模型不能覆盖响应

### Requirement: 订阅拒绝保持业务失败处理一致
订阅任务在受理后被执行关卡拒绝 SHALL 使用既有失败回调与结果分发，使询盘等业务退出处理中。附带联系人音译在创建前发现无权或不可用时跳过，预检间状态变化也不得回滚普通业务保存；运行中认证失败结束当前任务，不自动跨服务商重放。

#### Scenario: 排队订阅被拒后询盘结束等待
- **WHEN** 询盘的订阅任务因撤权在执行前被拒
- **THEN** AI 任务失败且询盘收到失败分发，不保持永久处理中

#### Scenario: 音译检查期间撤权
- **WHEN** 联系人音译先预检通过，后创建前授权发生变化
- **THEN** 音译安全跳过或独立失败，不把无权异常传播为商机保存失败

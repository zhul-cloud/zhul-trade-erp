# Proposal

## Why

当前每租户仅有一组 AI Key 和模型，切换服务商或运行方式会串用、覆盖配置；订阅只限平台且无法由平台通过租户权限安全地开放和撤回。需要让各服务商配置独立，并让获授权租户复用服务器上的平台订阅，同时在实际调用前核验当前授权。

## What Changes

- Claude 与 OpenAI（Codex）各自保存 API Key、模型、思考强度及搜索上限；API 与订阅配置分开，保留扩展服务商能力。
- 获 `system:ai-config:use-subscription` 权限的租户可选个人订阅，凭据始终由服务器官方 CLI 保管；普通租户继承对应平台订阅模型与用量设置，只读显示。
- 登录状态区分已登录、未登录、未知；普通租户仅能选已登录服务商，无可用订阅时禁用新选并阻止订阅任务；平台仍可配置未登录服务商并查看登录命令，不自动改为付费 API。
- 订阅使用权限接入现资源、套餐与角色体系，平台可通过套餐撤回授权；保存、测试、模型查询、创建任务及真正启动订阅 worker 前均重查。
- **BREAKING** AI 配置响应改为服务商与运行方式分组的 profile；订阅状态接口向获授权租户开放状态，登录命令仅平台响应包含。
- 页面保留先选服务商、后选运行方式；用真实服务商 logo，顶部状态不显示 Key；保留原有有效用途、模型、计费与限制说明，仅修正因共享与权限语义变更而不准确的内容，避免无意义新增或重复描述，优化排版与阅读层次。先交付 OpenPencil 原型，经用户确认后才开发页面。

## Capabilities

### New Capabilities

无；复用现有 AI 能力边界。

### Modified Capabilities

- `ai-platform/tenant-ai-settings`: 独立配置、继承只读、登录状态、订阅资源权限及页面行为。
- `ai-platform/model-providers`: 授权租户订阅路由、可用服务商解析与失效处理。
- `ai-platform/task-orchestration`: 持久任务主体、执行前实时授权及失败分发。
- `system/navigation`: 共享菜单资源定义的写操作限定平台身份与对应菜单维护权限，封闭订阅授权旁路。

## Impact

影响 AI 设置前后端、配置表与迁移、资源权限、AI 任务服务、编排服务及对应测试。保留现加密方式、官方 CLI 凭据卷、共享回调令牌与业务结果契约；不读真实 Key、生产数据库，不调用付费模型。本轮先完成规划与原型，用户确认原型后再按本 change 任务实施；当前未实现产品代码、未创建 PR、未部署。分支 `codex/ai-provider-subscription-settings` 基于 `origin/release/1.3.0` 的 `5984df8`（生产 tag `v1.3.15`）。

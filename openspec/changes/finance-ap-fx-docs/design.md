## Context

- **应付单** `fin_payable`（AP）：来源 1 采购订单、2 运费账单、3 费用单（公司对公），由 `PayableSyncService` 生成与重算；状态 1 未付、2 部分付款、3 已付清、4 已关闭；付款计划 `fin_payable_installment`；核销 `fin_payment_allocation`。没有备注字段、附件归属和单据日志。详情以抽屉显示（`PayableBody`）。
- **结汇单** `fin_fx_settlement`（JH）：状态 1 有效、2 已作废；`remark varchar(500)`；分摊 `fin_fx_settlement_allocation`。详情与作废都在列表抽屉里。
- 参照：单据页统一规范、`finance-cash-docs`（收款单、退款单、付款单）的做法。

## Goals / Non-Goals

**Goals:** 两张单据有独立详情页、备注附件、操作日志，所有单号能点进详情。

**Non-Goals:** 不改应付生成、付款核销、结汇分摊与作废顺序的规则；不加手工新建应付单；不给生效后的单据开放金额修改。

## Decisions

### 1. 明细取什么

- 应付单的明细是**付款计划**——它本身就是这张应付单按期次拆开的金额；付款记录单独一张卡片，是「钱怎么来的」，不是明细。
- 结汇单的明细是**分摊到的收款单**，按先进先出顺序。

### 2. 应付单的备注附件不受状态限制

应付单是系统按来源单据算出来的，备注和附件只是补充（对账单、发票、和供应商的约定），已付清、已关闭后也常要补发票，所以任何状态都能改。历史迁移的应付单同样可改备注附件（不涉及金额）。

### 3. 应付单日志写在哪

- `PayableSyncService.apply` 是所有金额与状态变化的唯一出口：新建时写「生成应付」；应付金额变化时写「应付金额 A → B」，附当前来源单号；状态由非关闭变为关闭写「关闭」，由关闭恢复写「重新打开」。已付、状态因付款变化不在这里写，由付款一侧写得更具体。
- `PaymentService`：登记付款（含批量）对每张核销的应付单写「付款 PY… 核销 X」，欠款抵扣写「欠款抵扣 X，转入 AP…」并在欠款来源单写「欠款抵扣转出 X 到 AP…」；供应商退款写「供应商退款 PY… X」；作废付款对涉及的应付单写「付款 PY… 作废，恢复未付」。
- 改备注、增删附件在应付单服务写。

### 4. 结汇单作废入口

作废只能在详情页做；按钮对非最新的结汇单不可用，提示「请先作废之后的结汇单 JH…」（后端返回下一张有效结汇单号 `blockingNo`）。

### 5. 权限

- 应付单详情：沿用现有 `GET /payables/{id}` 的权限（应付管理或付款管理菜单）；改备注附件要「应付管理」菜单。
- 结汇单详情：「结汇管理」菜单；改备注附件要「登记结汇」按钮权限（与作废一致）。

## Risks / Trade-offs

- 应付金额变化的日志只能写「来源单号」，写不出是采购订单的哪一行改了价——来源单据自己的日志有细节，应付单链过去即可。
- 已有的历史应付单、结汇单没有日志，详情页日志从上线后开始积累。

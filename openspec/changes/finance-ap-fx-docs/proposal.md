## Why

财务单据统一的第二批：应付单与结汇单。现状：

- **应付单**只能在「应付管理」列表的抽屉里看，没有独立详情页，没有备注、附件、操作日志；采购订单改价、付款核销、付款作废让应付金额与状态变了，单据上看不出来是什么时候、因为什么变的。付款单、采购订单、费用单里提到应付单号时只能跳到列表搜索。
- **结汇单**同样只能在列表的抽屉里看，作废也在抽屉里；没有附件（银行结汇回单无处可传）和操作日志；收款单详情里的结汇单号只能跳到列表。

## What Changes

**两张单据都有独立详情页**

| 单据 | 详情页 | 明细 |
|---|---|---|
| 应付单（AP） | `/finance/payables/:id` | 付款计划（期次、比例 · 时点、到期日、金额、已付、未付、状态）；另列付款记录（核销进来、欠款抵扣、退款，作废的灰显） |
| 结汇单（JH） | `/finance/fx-settlements/:id` | 分摊明细：先进先出分到的收款单（收款单号、到账日期、来源单号 · 客户、分摊外币与人民币、该收款单结汇状态）与合计 |

- 布局与其他单据相同：左边基本信息、明细、备注与附件，右边关联单据、操作日志；
- 应付单详情的操作沿用列表上的「付款」「退款」（有付款登记权限时），结汇单详情的操作是「作废」（只能作废该事业部该币种最新一张，其余灰显并提示先作废哪一张）；
- 付款单、采购订单付款面板、运费账单、费用单、收款单里出现这两种单号的地方，都链接到详情页。

**列表**

- 应付管理列表：单号可点，打开详情页；操作列保留「付款」「退款」（工作队列），去掉抽屉；
- 结汇管理「结汇单」页签：单号可点，操作列改为「查看」，作废移到详情页；「待结汇」页签不变。

**增删改查**

- 应付单由采购订单、运费账单、费用单自动生成和重算，不能手工新建、修改金额或删除（不变）；能改备注、增删附件（如对账单、发票），任何状态都可以。
- 结汇单新建、作废规则不变；有效时可改备注、增删附件（银行结汇回单），作废后只读。金额、汇率、事业部、账户录错就作废重登。

**操作日志**

- 应付单：生成、应付金额变化（附原因所在的来源单号）、关闭与重新打开、付款核销、付款作废、供应商退款、改备注、增删附件；
- 结汇单：登记、作废、改备注、增删附件；
- 原有的通用操作日志照写。

## Capabilities

### Modified Capabilities

- `finance/accounts-payable`：应付单详情页、备注附件与操作日志；应付单页去掉抽屉。
- `finance/fx-settlement`：结汇单详情页、备注附件与操作日志；作废移到详情页。

## Impact

**数据库**

- 迁移 V1.5.32：`fin_payable` 新增 `remark varchar(500) NOT NULL DEFAULT ''`。结汇单已有 `remark varchar(500)`，不改。不建新表。
- 回退：删除 `fin_payable.remark` 列即可，没有其他数据依赖。

**后端**

- `AttachmentService` 新增附件归属 `PAYABLE`、`FX_SETTLEMENT`；
- 应付单、结汇单详情接口补关联单据、日志、附件、可编辑标记；新增改备注、增删附件接口；
- `PayableSyncService`、`PaymentService`、`FxSettlementService` 写 `DocLogs`。

**前端**

- 新建两个详情页，调整两个列表；更新 `DOC_META` 中 AP、JH 的链接。

**不影响**

- 应付生成与重算、付款核销、欠款抵扣、先进先出结汇、作废顺序的规则与金额计算都不变；
- 权限码不变：应付单详情沿用「应付管理」或「付款管理」菜单，结汇单详情沿用「结汇管理」菜单与「登记结汇」按钮权限。

## Context

单据页统一规范（2026-11-11）只规定了列表的列顺序和详情页布局，没规定页面骨架，于是各页面的筛选区各不相同：销售订单、报价单等用 `Form` 网格；采购入库、销售出库、退货、售后、退款、费用等约 15 个单据列表在顶部用 `Segmented` 切状态。`ModelQtyCell`（入库、出库、退货等 6 个列表在用）只显示「共 N 个型号」，不能点开；销售订单自己实现了「查看」弹窗。

## Goals / Non-Goals

**Goals:** 定一份可逐条对照的列表骨架；采购入库、销售出库按骨架改完；`ModelQtyCell` 多型号可点开；列出后续批次的页面清单。

**Non-Goals:** 不新增筛选项、不改列和排序、不改接口；非单据页面（看板、统计、设置类）不在本次范围，以后改动时对照。

## Decisions

1. **状态放进搜索条件栏的下拉**，选项带待办数量；切换状态立即查询（与分段按钮的使用习惯一致），关键词仍按「查询」生效。备选「保留分段按钮、只加标签」没有解决用户提的「状态做到搜索条件栏」。
2. **采购入库的「待收货」保留在状态下拉里**（用户选定）：选待收货时表格换成在途发货单的列，其余与现在一致。
3. **「查看」弹窗用列表行里已有的型号**：入库、出库、退货等列表接口已返回全部型号行（含品牌、品类），弹窗直接复用 `ModelsModal` 一类的展示，不加接口；没有型号行、只有摘要的旧数据仍只显示文字。
4. **分批**：第一批两页 + 公共组件 + 规范；后续每批 3–5 页一个 PR，同一批内只改布局。

### 后续批次清单（按菜单顺序，实施时逐页核对）
- 销售：销售退货、售后单、退款申请
- 采购：采购发货（发货跟踪）、采购退货
- 仓库：仓库退货、暂存
- 财务：费用单、报销单、供应商欠款
- 已符合（只核对）：询盘、报价单、形式发票、销售订单、采购订单、应付单、应收与收款

## Risks / Trade-offs

- 状态从按钮变成下拉，多点一下 → 选项后带待办数量，打开即可看到；从其他页面跳转带状态时仍直接定位。
- 改版期间新旧版式并存 → 每批合并后在 UI 规范里标注已完成的页面。

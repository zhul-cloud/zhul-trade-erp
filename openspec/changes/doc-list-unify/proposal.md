## Why

单据列表的版式不统一：销售订单是「搜索条件卡片（标签在上的网格，状态是下拉）+ 表格」，采购入库、销售出库等页面却在页面顶部用分段按钮切换状态，关键词框没有标签；多个型号的单据在销售订单上能点「查看」看全部型号，在入库、出库、退货等页面只能进详情看。用户 2026-11-20 要求以销售订单为标准，全局统一单据列表与详情的规范（选定：先定规范，再分批改造全部单据列表，采购入库、销售出库先做）。

## What Changes

- **列表页骨架写进 UI 规范**（`.claude/context/ui-design-patterns.md`「单据页统一规范」）：标题区 →（可选）统计卡 → 搜索条件区 → 主内容区。
  - 搜索条件区：标签在上、输入在下的网格，关键词占两格，其后是状态与页面已有的其他筛选项，「重置」「查询」靠右；状态一律放在这里的下拉里，选项后带待办数量（如「待打包 · 2」），不再用页面顶部的分段按钮切换状态。
  - 主内容区：一张卡片，操作行（左：结果数，勾选后为「已选 N 张 · 取消选择」；右：主操作按钮）→ 表格 → 分页。
- **型号 · 数量列可点开**：公共组件 `ModelQtyCell` 在多个型号时显示「共 N 个型号 · M 件 · 查看」，点「查看」弹出全部型号（品牌、品类、型号、数量），可打开详情。用到它的采购入库、采购发货、销售出库、销售退货、采购退货、仓库退货列表一起生效。
- **第一批**：采购入库、销售出库两页改成新骨架；只改布局与状态的位置，筛选项、列、排序、操作不变。
  - 采购入库：状态下拉「待收货 · N / 已入库」，选待收货时表格为在途发货单（列不变），「直接收货」移到主内容区右上。
  - 销售出库：状态下拉「待打包 · N / 待交快递 · N / 已交货代 / 全部」，多选与「合并打包」「交快递」放在主内容区的操作行。
- **后续批次**：其余用分段按钮切状态、或不符合骨架的单据列表逐页对照改造（清单见 design.md），每批一个 PR。
- 不改接口、不改数据库。

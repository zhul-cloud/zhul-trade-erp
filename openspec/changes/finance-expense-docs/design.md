## Context

- **费用单** `fin_expense`（FE）：状态 1 有效、2 已作废；`remark` 为说明；凭证附件归属 `EXPENSE`；分摊 `fin_expense_allocation`（订单型号）；公司对公生成应付（`PayableSyncService.syncExpense`），员工垫付进入待报销。`ExpenseService.update` 在付款或进报销单前可改全部字段，之后只改名称、说明、分摊（`locked`）。
- **其他收入** `fin_other_income`（OI）：状态 1 有效、2 已作废；`remark` 为说明（必填）；凭证归属 `OTHER_INCOME`；`source_type` 非空的是系统生成的汇兑损益，不能手动修改与作废。
- **报销单** `fin_reimbursement`（BX）：状态待付款、已报销、已撤回；各项由待报销项组成（垫付付款单、费用单、快递运费、收到退款等）；登记已付生成报销付款单 PY，付款截图归属 `REIMBURSE`。没有备注。
- 参照：单据页统一规范、`finance-cash-docs`、`finance-ap-fx-docs`。

## Goals / Non-Goals

**Goals:** 三张单据有独立详情页、备注附件、操作日志；费用单、其他收入的修改符合「生效后金额不能改」。

**Non-Goals:** 不改费用分摊、应付生成、报销流程、汇兑损益规则；不加草稿状态。

## Decisions

### 1. 费用单的「改」

修改一律走 `locked` 分支（原来只在付款或进报销单后才走）：名称、类别、分摊月数、所属事业部、关联售后单、分摊、说明、凭证可改；发生日期、币种、金额、收款方、付款方式变化时报错「金额、币种、收款方、付款方式与发生日期不能修改，录错请作废后重新登记」（已付款或已进报销单时提示原有的「已经付款……」等，并说明作废不可用时需先作废付款）。分摊仍可改：它不改金额与核销关系，只改费用落在哪些订单型号上，订单成本随之重算。前端修改抽屉里这些字段只读。

### 2. 其他收入的「改」

日期、金额变化时报错「日期与金额不能修改，录错请作废后重新登记」；类别、事业部、说明、凭证可改。

### 3. 报销单的备注与附件

- 新增 `remark`；附件用已有的 `REIMBURSE` 归属（登记已付时上传的转账截图也在这里），详情页「备注与附件」显示为一组。
- 可编辑：未撤回时，提交人本人或有「报销付款」权限的人。
- 撤回、登记已付、撤销已付的入口移到详情页；列表的批量登记已付保留。

### 4. 日志内容

- 费用单「修改」写变化的字段（名称、类别、事业部、分摊月数、分摊），只改说明与凭证的走「修改备注」「上传附件」；
- 费用单进入、撤出报销单在 `ReimbursementService` 里与付款单的日志一起写。

### 5. 关联单据

- 费用单：应付单（公司对公）、报销单（员工垫付且已提交）、售后单、分摊到的销售订单；
- 报销单：报销付款单、各项来源单据（付款单、费用单、运费账单等）；
- 其他收入：系统生成的汇兑损益关联来源退款单（TK）。

## Risks / Trade-offs

- 收紧费用单与其他收入的修改会让「金额填错」只能作废重开；已付款的费用单要先作废付款单再作废费用单，这是财务规则要求的代价。
- 历史数据没有单据日志，从上线后开始积累。

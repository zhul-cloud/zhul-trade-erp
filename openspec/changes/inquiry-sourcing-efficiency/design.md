## Context

- 待分配池现在按品牌分组，组内按超时、紧急、询盘等级、等待时长排序；等待时长从任务最近一次进入待分配算起，超时从分配算起（`inquiry/sourcing-task`）。
- 我的询价的保存草稿本来就只带改过的型号，提交时连同存过的草稿一起提交。
- 兼职采购的回价逐型号审核，分配工作台按「至少一个型号待审核」放进「待审核」页签。

## Goals / Non-Goals

- 目标：待分配只留今天要处理的；采购在长任务里能快速找到没报价的型号、随时保存；兼职不用再翻已提交的任务。
- 不做：延后不改变任务归属、不通知客户；不做按型号延后（任务是最小分配单位）；不改审核规则。

## Decisions

1. **延后是待分配任务上的一个日期，不是新状态。** 任务状态仍为「待分配」，`defer_until` 大于今天时不进待分配列表、不参与按推荐 / 按规则 / 自动分配。到 `defer_until` 当天 0 点起自然回到列表，不需要定时任务改状态。回到列表时等待时长从 `defer_until` 当天 0 点算起，避免一回来就排在最前。理由：状态机不变，分配、改派、退回的逻辑都不用改。
2. **两种延后入口**：勾选任务后批量操作栏的「延后」；任务行的「延后整张询盘」，一次延后这张询盘下所有待分配的任务（其他状态的任务不动）。日期选项照客户跟进的延后：明天、3 天后、下周一、选日期；原因选填，最多 100 字。
3. **「已延后」放在待分配页签里的切换**，不新增页签：待分配页签右侧显示「已延后 n」，点开按回来的日期分组列出，可以「现在处理」（清空延后日期）或改日期。统计卡片的「待分配」只算今天要处理的，下方提示「另有 n 个已延后」。
4. **延后期间的任务被退回、取消照常处理**：询盘取消时任务照常取消；任务被处理人退回到待分配时清空延后日期。
5. **业务员能看到延后**：询盘详情的任务状态显示「待分配 · 延后到 11-20」，悬停看原因。不另发通知。
6. **型号筛选的「未回价」口径与「只复制未回价的型号」一致**：本人在该型号还没有任何回价记录（草稿、已提交、无货都算已回价）。草稿 = 本人只有草稿记录；已提交 = 本人有已提交或待审核的记录。筛选只在前端对当前任务的型号做，不改接口。
7. **吸顶用 `position: sticky`**，固定的是任务标题行与按钮行，说明文字不固定；每个型号卡片上有未保存的改动时，卡片右上角出现「保存草稿」，调用现有保存草稿接口但只带这个型号。整体「保存草稿」「提交回价」不变。
8. **兼职的「审核中」**：任务里本人没有要做的型号（每个型号都有已提交待审核或已通过的记录，或记为无货），且至少一个型号待审核时，归入「审核中」；有型号被退回、或还有没填的型号时留在「待处理」；全部通过后归入「已回价」。只对回价需要审核的账号显示这个页签。「审核中」的任务照常可以打开查看和修改。

## Risks / Trade-offs

- [延后后忘了] → 到期自动回到待分配，并按正常规则排序；「已延后」按日期分组随时可查。
- [整张询盘延后误操作] → 确认弹窗列出将延后的任务数与型号数；可以在「已延后」里一键「现在处理」。

## Migration Plan

- 迁移：`sourcing_task` 加四列，`defer_until` 加索引。回退：删列。
- 已有数据 `defer_until` 为空，行为不变。

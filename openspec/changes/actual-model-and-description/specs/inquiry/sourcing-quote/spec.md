# Spec Delta

## MODIFIED Requirements

### Requirement: 采购回填真实型号

系统 SHALL 在「我的询价」每个型号上提供「真实型号」输入（≤128 字），建档状态为「待回填真实型号」的型号突出提示填写；离开输入框即单独保存，不随回价的保存草稿或提交，也不受型号「已报给客户」锁定的限制（只受询盘已取消限制）。填写或修改真实型号后，系统按真实型号重新做商品匹配：已有商品则关联，否则进入候选池并记录「采购回填真实型号」来源；该询盘型号原先在其他候选上的来源移到新候选。采购提交有货回价（非无货）时，若询盘型号处于候选中，候选追加「采购回价有货」来源。真实型号与业务员在询盘详情、报价单草稿填写的是同一个值，后填的覆盖先填的；保存后按「单据型号以真实型号为准」带到下游单据，已发给客户或供应商的单据不自动修改、只提示（见报价单、PI、销售订单、采购需求、采购订单的相应要求）。

#### Scenario: 回填后进候选池

- **GIVEN** 询盘型号「Contactor, 32A」为待回填真实型号
- **WHEN** 采购填写真实型号「AX32-30-10-80」后离开输入框
- **THEN** 候选池出现 ABB / AX32-30-10-80 并带「采购回填真实型号」来源，询盘明细显示「真实型号：AX32-30-10-80」

#### Scenario: 有货回价提升可信度

- **GIVEN** 询盘型号对应候选的可信度为「询盘出现」
- **WHEN** 采购提交该型号的有货回价
- **THEN** 候选可信度变为「采购问到有货」

#### Scenario: 已报给客户的型号也能回填

- **GIVEN** 询盘型号「Contactor, 32A」已经报给客户，回价只读
- **WHEN** 采购填写真实型号「AX32-30-10-80」
- **THEN** 真实型号保存成功并进入候选池，回价不变；已发出的报价单内容不变，详情该行提示「真实型号已更新为 AX32-30-10-80」

#### Scenario: 回填后下游草稿跟随

- **GIVEN** 询盘型号 LC2D18B7 已生成报价单草稿，还没有发送
- **WHEN** 采购填写真实型号 LC2D18B7C
- **THEN** 报价单草稿该行型号变为 LC2D18B7C，型号下面显示「客户型号：LC2D18B7」

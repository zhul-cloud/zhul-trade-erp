# Proposal

## Why

用户 2026-11-26 反馈：应付单看不出这笔钱该从公司对公账户付，还是从个人账户付，付款的人每次都要去翻采购订单、问采购员。是否对公目前只能从采购订单的「开票」间接推断，规则没有落在单据上。

## What Changes

- 采购订单单头增加「付款方式」：对公 / 对私。新建时按开票带出默认值（开票 → 对公，不开票 → 对私；线上店铺默认对私），切换「开票」时跟着变，采购员可以手动改；已下单的采购订单也能改，写操作日志。
- 应付单记录付款方式：采购订单的应付取采购订单的付款方式，随采购订单修改同步；货代运费账单的应付取货代默认收款账户的类型，没有默认账户时为「未定」。
- 应付单列表在收款方后增加「付款方式」列（对公 / 对私 / 未定），可按付款方式筛选；应付单详情与采购订单付款面板显示付款方式。
- 登记付款按应付单的付款方式预选：对公预选「公司对公」，对私预选「私对私」，对方收款账户随之只列对应类型；所选应付单付款方式不一致时不预选并提示。仍可改选，改选与约定不一致时提示但不拦截。
- 上线迁移：存量采购订单按「开票」回填付款方式，存量应付单按来源回填。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `purchase/purchase-order`：采购订单增加付款方式（对公 / 对私），按开票带出默认值。
- `finance/accounts-payable`：应付单记录付款方式，列表增加付款方式列与筛选。
- `finance/supplier-payment`：登记付款按应付单的付款方式预选付款方式与对方账户类型。

## Impact

- 数据库：`purchase_order`、`fin_payable` 各加一列付款方式，迁移回填存量数据（可回退：删列即可，不影响其他数据）。
- 后端：采购订单保存与开票切换、应付生成与「应付金额同步」、运费账单应付生成、应付列表查询与筛选、登记付款初始化数据。
- 前端：采购订单单头与付款面板、应付单列表与详情、登记付款抽屉（`finance/payables/components.tsx`）。
- 与 `feat/ui-redesign` 分支同样改动应付列表、采购订单详情与付款面板，合并时需处理冲突。

# Design

## Context

- 付款方式现在只存在于付款单上（公司对公 / 员工垫付 / 私对私，见 `finance/supplier-payment`「登记付款」），应付单和采购订单上都没有「应该怎么付」。
- 采购订单有「开票」（是 / 否）；供应商收款账户有类型（对公 / 对私）与默认账户；应付单的收款方类型有供应商、线上店铺、货代。
- 货代运费账单生成的应付没有采购订单，只能从货代的收款账户推断。

## Goals / Non-Goals

**Goals:**
- 应付单上直接看到并能筛选「对公 / 对私」，登记付款时少选一步、少选错。

**Non-Goals:**
- 不把付款方式做成强校验：实际怎么付仍由财务决定，约定只做预选和提示。
- 不改变员工垫付的规则：采购员在采购订单付款面板登记的仍是员工垫付，对私的应付也可以由员工垫付。
- 不改付款单本身的三种付款方式。

## Decisions

1. **付款方式存在采购订单上，应付单冗余一份。** 采购订单是约定付款方式的地方（采购员最清楚供应商要对公还是对私）；应付单冗余一列是为了列表筛选和运费账单这类没有采购订单的应付。采购订单修改付款方式时，按现有「应付金额同步」的同一事务更新对应应付单。
   - 备选：应付列表实时联查采购订单 —— 运费账单的应付没有采购订单，筛选也要跨表，放弃。
2. **默认值跟着开票走，手动改过就不再跟。** 新建采购订单按开票带出；采购员切换开票时，若付款方式还是系统带出的值就跟着变，手动改过的保持不动（前端记录是否手动修改，保存时只存结果）。线上店铺默认对私，因为平台订单一般由个人账户付款。
   - 备选：只在新建时带出一次 —— 采购员常在之后才勾开票，会留下错误的默认值。
3. **应付的付款方式取值为对公 / 对私 / 未定。** 采购订单的应付一定有值；费用单的应付按费用单的付款方式（公司对公、私对私）；运费账单的应付取货代默认收款账户类型，没有默认账户时为「未定」，财务登记时自己选。
4. **登记付款只预选、不拦截。** 所选应付单付款方式一致时预选（对公 → 公司对公，对私 → 私对私）；不一致或都是「未定」时不预选，提示「所选应付单付款方式不一致」。财务改选与约定不同的方式时，在付款方式下方提示「这张应付单约定对私支付」，仍可提交。

## Risks / Trade-offs

- [存量回填按开票推断可能不准（不开票但实际对公付的供应商）] → 回填后采购员可在采购订单上改，应付随之同步；上线说明里提醒采购员核对进行中的采购订单。
- [货代换了默认账户，已有运费账单应付不跟着变] → 只在生成应付时取一次，与付款单账户快照的思路一致；需要时财务登记时改选即可。

## Migration Plan

1. Flyway 迁移 V1.5.61.4（`feat/ui-redesign` 已占用 1.5.62，本批用 1.5.61.x 小版本，保证以后合并时版本顺序正确）：两张表加列（`tinyint`，1-对公、2-对私，应付另有 0-未定），存量采购订单 `invoice_required=1` 回填对公，否则对私，线上店铺回填对私；存量应付按来源采购订单回填，运费账单应付按货代默认账户回填，费用单应付按费用单付款方式回填。
2. 回退：删除两列即可，付款单数据不受影响；PR 说明写明迁移版本号。

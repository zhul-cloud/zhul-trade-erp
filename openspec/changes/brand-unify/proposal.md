# Proposal

## Why

同一品牌在单据里有多种写法：采购订单里有的是「施耐德」，有的是「Schneider Electric」；三菱也是中英文混用。品牌库本身已经统一（Schneider Electric、Mitsubishi Electric 各一个品牌，中文写法是别名），询盘确认时也认出了品牌，但单据存的仍是客户原文，一路带到报价单、订单、采购单。

2026-11-18 查生产库：销售订单 1676 行中 554 行是能按别名认出的其他写法、585 行认不出（其中 378 行为空）；询盘 12362 行中 2635 行是别名写法、4882 行认不出（其中 2275 行为空）。认不出的写法里有拼写变体、「未知品牌」、多个品牌写在一起等。

## What Changes

- **单据存正式品牌名**：询盘确认（含追加）时，能按品牌名或别名认出的写法存正式品牌名（「施耐德」→ Schneider Electric），认不出的照旧存原文。之后生成的报价单、PI、销售订单、采购需求、采购订单沿用这个名称。
- **存量统一（迁移）**：能认出的写法统一改成正式品牌名，包括询盘型号、销售订单、采购需求、采购订单，以及报价单草稿或修改中版本、PI 正在编辑的版本。已发给客户的报价单、PI 不改。品牌为空的行按商品档案补上品牌，查不到的保持为空。迁移不更新单据的更新时间，免得列表顺序被打乱。
- **待确认品牌并入单据里认不出的写法**：品牌页「待确认品牌」除供应商主营产品的待确认名称外，也列出询盘、销售订单、采购订单里认不出的写法，显示出现在哪些单据、各多少行，并给出建议：
  - 相近品牌：去掉符号后相同、互相包含或拼写只差 1～2 个字母，点击建议直接设为该品牌的别名。
  - 不是品牌：「未知品牌」「N/A」之类，或几个品牌写在一起。
- **设为别名 / 新建品牌后统一单据**：把单据里这个写法换成正式品牌名，范围与迁移相同。支持勾选多个写法批量设为同一品牌的别名。确认弹窗列出会改的单据行数。
- **标为不是品牌**：不再出现在待确认列表里，单据保持原样，需要时由业务员在询盘里改。可批量。
- **不做品牌合并**：原型 C3、C4 的「合并到…」不开发。生产库只发现一对重复品牌（Reliance Electric 只有 1 个商品），通用合并要改十几张表并处理唯一键冲突，代价不值。这对品牌用现有功能处理：把商品的品牌改为 Reliance，删除 Reliance Electric，再把它加为 Reliance 的别名。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `product/brand`：待确认品牌并入单据写法、建议、批量设为别名、标为不是品牌；确认后统一单据品牌写法。
- `inquiry/inquiry-intake`：确认询盘时认出的品牌存正式品牌名。

## Impact

- **数据库**：迁移 V1.5.46（不可完全回退）。
  - 新表 `brand_text_ignored`：平台级的「不是品牌」写法。
  - 存量单据品牌写法统一、空品牌补齐。
  - 回退只能删表；写法统一与补空不回退，因为只是把同一品牌换成正式名、补上商品档案的品牌。
- **后端**：
  - `PendingBrandService` 汇总单据写法并给出建议（`BrandSuggest`）；单据写法的汇总与统一由 `BrandDocTexts` 完成，是有意的跨租户操作，仅限平台账号。
  - 新接口 `POST /api/v1/masterdata/pending-brands/alias-batch`、`/ignore`。
  - 询盘确认用 `PriceKeys.brandText` 存正式品牌名。
- **前端**：品牌页「待确认品牌」页签改为独立组件 `PendingTab`，含来源筛选、搜索、勾选批量、建议、确认影响。
- **原型**：`docs/03-产品原型/03-业务域/17-品牌统一/`（C1、C2、C5 采用；C3、C4 不做）。
- **风险**：设为别名会改各公司单据里的写法。品牌库是平台共用的，同一写法在各公司都应认成同一个品牌，所以按平台统一处理。

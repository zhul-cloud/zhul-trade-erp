## MODIFIED Requirements

### Requirement: 货代管理
系统 SHALL 在「物流管理 → 货代管理」单独维护货代与快递公司（统称货代），不再放在供应商管理里。货代的字段：
- 编码（自动生成，不可修改）、名称（必填，≤100 字符）、简称（≤50 字符）；
- 联系人、联系电话、联系邮箱、地址；
- 体积系数（正整数，默认 5000，用于按计费重分摊运费）；
- 收款账户（与供应商收款账户相同的规则）；
- 归属客户（选填，见「客户自有货代」）、状态（启用 / 停用）、备注。

列表按「列表页统一规范」显示：默认按更新时间倒序，固定显示创建时间、创建人、更新时间、更新人；可按名称（同时匹配简称）、归属（全部 / 公司货代 / 客户指定）、状态筛选。货代可以停用，不能删除已被出库单、出运单、运费账单或付款引用的货代。

已有供应商类型为「服务商」的记录就是货代，原样出现在货代管理里，付款、运费账单、出库单与出运单的引用不变。

每家货代（公司货代与客户指定货代）SHALL 对应一个货代仓（见 `warehouse/inventory`「仓库档案」）：新建货代时在同一事务内自动建仓，仓库名称随货代名称变化；货代停用时，货代仓里还有库存的给出提示「货代仓还有 N 件货」，仍可停用。

#### Scenario: 新增货代
- **WHEN** 物流专员在货代管理新增货代「深圳捷运国际物流」，体积系数 6000
- **THEN** 货代保存成功，出现在货代列表第一行；供应商管理的列表里没有它

#### Scenario: 已有的服务商
- **GIVEN** 升级前供应商「顺丰速运」的类型为服务商
- **WHEN** 用户打开货代管理
- **THEN** 列表里有「顺丰速运」，它以前的出库单、运费账单、付款照常显示

#### Scenario: 新建货代自动建仓
- **WHEN** 物流人员新建货代「深圳捷运国际」
- **THEN** 仓库档案里多一个货代仓「深圳捷运国际」，类型「货代仓」，关联这家货代

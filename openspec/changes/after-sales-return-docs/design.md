## Context

- 售后模块（`modules/aftersales`）现在有 `after_sales`、`sales_return`（TH，状态 1 待入库、2 待处理、3 已处理、4 已作废）、`sales_return_item`（含实收、合格数量）、`sales_return_disposition`（去向，含退回供应商的供应商、快递、运费、供应商退款、冲减成本）、`fin_refund_request`（RA，状态 1 待审批、2 待财务处理、3 已执行、4 已驳回、5 已撤回）。入口在 V1.4.3 建的菜单「仓库管理 → 退货入库」（100121，按钮 `warehouse:return:receive`、`purchase:return:dispose`）。
- 到货差异 `receiving_discrepancy` 的退货类处理（3 退货换货、4 退货不补、6 退回供应商）把快递、运费、垫付人（`return_payer_id`）记在差异上；报销的待报销项「退货运费」（`source_type` 3）以差异 ID 为来源。
- 应付同步：应付金额 = 采购订单合计 − 差异折价；供应商欠款已有退款、抵扣、退到员工三种处理。
- 订单成本「售后退货冲减」取 `sales_return_disposition.cost_cny` 与 `freight_cny`。
- 动机见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 售后 → 销售退货单 → 退货入库单 → 采购退货单，每一步都是独立单据，状态互相联动，都在同一事务内生成。
- 退给供应商的货统一进采购退货单，售后来源的供应商退款或抵扣接入应付与供应商欠款。
- 存量数据迁移后，订单成本、应付、退款、报销的数字不变。

**Non-Goals:**
- 不做采购员主动新建的采购退货单（没有来源的退货），本期只有四种自动来源。
- 不做闲置库存退给供应商（闲置库存处置方式不变）。
- 不改退款单（TK）、客户余额与退款冲减收入的规则。
- 不做退货入库单的库位、批次管理。

## Decisions

### 0. 每张单据都是「表头 + 明细」，都有独立详情页

本变更涉及的四种单据都按同一结构建：

| 单据 | 表头 | 明细 | 详情页 |
|---|---|---|---|
| 销售退货单 TH | `sales_return` | `sales_return_item` | `/sales/returns/:id` |
| 退货入库单 RR | `return_receipt` | `return_receipt_item`（去向 `sales_return_disposition` 挂在明细行下） | `/warehouse/returns/:id` |
| 采购退货单 PR | `purchase_return` | `purchase_return_item` | `/purchase/returns/:id` |
| 退款申请 RA | `fin_refund_request` | `fin_refund_request_item`（新建） | `/finance/refunds/requests/:id` |

- 表头金额 = 明细合计，在服务层保存时校验，不靠前端。
- 详情页用 `usePageTitle` 登记单号为标签页标题，有未保存修改的用 `useTabDirty`；状态操作（确认、验收、寄出等）都在详情页，列表只放查看与少量快捷操作。
- 来源单号、售后单详情的单据汇总都链接到这些详情页，不再用列表加 `?id=` 打开抽屉。
- 备注：表头字段 `remark`（varchar(500)），详情页随时可改，已作废只读，改动写操作日志。
- 附件：复用业务附件表 `biz_attachment`（所属单据类型新增 销售退货单、退货入库单、采购退货单、退款申请），不另建表；每单最多 20 个。退货入库的验收照片也存在这里（不再单独存）。
- 显示按全局规范（销售订单为标准）：列表用 `CustomerCell`、`SourceNos mode="cell"`、品牌 / 品类 `TagList`、「型号 · 数量」列；详情页明细用 `docBrandColumns` + `DocModelCell`，表头说明行用 `SourceNos mode="inline"`；布局为左主右侧栏（与销售订单详情相同的网格）。
- 理由：每个环节都有完整单据，后续加库位、部分到货多次入库、按型号统计退货率、按供应商统计退货金额时，直接在明细上扩展，不用再拆表。

### 1. 销售退货单沿用 `sales_return` 表，退货入库单新建表

- `sales_return` 保留编号 TH、售后单、订单、客户快递、说明、作废原因；状态改为 1 待确认、2 待入库、3 已入库、4 已作废；新增 `handling`（处理方式：1 仅退货、2 退货退款）、`confirmed_at` / `confirmed_by`。
- 新表 `return_receipt`（RR）：`sales_return_id`、`so_id`、`after_sales_id`、状态（1 待入库、2 待处理、3 已处理、4 已作废）、收货日期、验收人、验收说明、负责人（采购员）、撤回原因；新表 `return_receipt_item`：`return_item_id`、`so_item_id`、型号、品牌、退货数量、实收、合格、说明。验收字段从 `sales_return_item` 移到这里（迁移时复制，原列保留只读，下个版本再清理）。
- `sales_return_disposition` 增加 `receipt_id`、`receipt_item_id`、`purchase_return_id`；退回供应商的快递、运费、供应商退款列改为只读的历史字段，新数据写在采购退货单上；`cost_cny` 仍用于转闲置的冲减。
- 备选：把入库字段继续留在 `sales_return_item`，只加一个「入库单」视图。没采用：用户要求每个环节都是单据，以后扩展（库位、部分到货多次入库）需要独立的入库单行。

### 2. 采购退货单放采购模块，新建两张表

- `purchase_return`（PR）：供应商、来源类型（1 售后退货、2 到货不良 · 退货换货、3 到货不良 · 退货不补、4 多发退回）、采购订单（可空）、负责人、状态（1 待寄出、2 已寄出、3 已完成、4 已作废）、寄出日期、快递公司与单号、运费（CNY）、垫付人、签收日期、退款或抵扣金额（采购订单币种）、汇率与人民币金额、说明、作废原因、`after_sales_id`、`so_id`（售后来源）。
- `purchase_return_item`：`purchase_return_id`、来源行（`receipt_item_id` 或 `discrepancy_id`）、`so_item_id`（售后来源）、`po_item_id`、型号、品牌、数量。
- 到货差异增加 `purchase_return_id`；差异上的快递、运费、垫付人列保留为历史，新数据不再写。
- 包结构 `com.zhul.erp.modules.purchase.purchasereturn`，服务只通过各模块的服务接口回调差异、退货入库与应付，事务边界在采购退货服务的方法上。

### 3. 状态联动都在发起动作的事务内完成

| 动作 | 同一事务内 |
|---|---|
| 确认销售退货单 | 生成退货入库单；退货退款时生成退款申请（待验收或按审批开关） |
| 作废销售退货单 | 作废待入库的退货入库单；撤回未执行的退款申请 |
| 验收退货入库单 | 销售退货单 → 已入库；待验收的退款申请 → 待审批 / 待财务处理 |
| 撤回入库 | 销售退货单 → 待入库；未执行的退款申请 → 待验收 |
| 去向选退回供应商 | 按供应商分组生成采购退货单 |
| 到货差异选退货类处理 | 生成采购退货单；重新打开时作废待寄出的采购退货单 |
| 采购退货单寄出 | 运费进入垫付人的待报销 |
| 采购退货单完成 / 重新打开 | 售后来源：重算采购订单应付、订单型号行成本 |
| 作废采购退货单 | 来源回到待处理（退货入库单行未处理数量增加、状态回到待处理；差异按重新打开处理） |

并发：同一售后单、同一退货入库单、同一采购订单的写操作用 Redisson 锁 `zhul:erp:lock:after-sales:{id}`、`zhul:erp:lock:return-receipt:{id}`、`zhul:erp:lock:po:{id}`，按「售后单 → 退货入库单 → 采购订单」的顺序加锁。

### 0.1 附件预览

- 把销售订单的附件列表与上传（`OrderFiles.tsx`）、仓库的预览（`warehouse/components.tsx` 的 `usePreview`）提取为公共组件 `src/components/DocFiles/`（附件卡片 + 预览弹窗），新单据都用它；销售订单改为引用公共组件，行为不变。
- 预览：图片（同一单据多张左右切换）、视频、PDF 沿用现有方式；Excel 新增在前端解析显示为表格（引入 SheetJS `xlsx` 依赖，只读取、不执行公式与宏，单个工作表最多显示 1000 行，超出提示下载查看）。
- 后端：业务附件允许的类型加 Excel（按文件内容识别 xlsx / xls），格式校验与大小上限沿用现有规则。
- 备选：后端把 Excel 转成 PDF 再预览。没采用：需要在服务器装 Office 转换工具，部署变重；前端解析足够看清退货确认表这类简单表格。

### 4. 退款申请增加「待验收」与明细

- 新表 `fin_refund_request_item`：`request_id`、行类型（1 退货型号、2 其他）、`so_item_id`、`sales_return_item_id`、型号、数量、成交单价、项目名称、金额（订单币种 DECIMAL(18,2)）、说明。由销售退货生成时每个退货型号一行；仅退款与订单详情提出时一行「退款」，可以加行。
- 存量退款申请迁移为一行「退款」明细，金额等于原申请金额，迁移后比对每张申请明细合计等于表头。
- `fin_refund_request` 新增状态 0 待验收（数字保持现有 1–5 不变，避免改历史数据），新增 `sales_return_id`、`refund_first`（先退款）。
- 进入下一步时按当时的审批开关决定是「待审批」还是「待财务处理」。
- 金额精度：Σ（数量 × 成交单价）中间保持完整精度，最后 HALF_UP 两位，不超过可退金额。可退金额的计算口径不变（已到账减已退售后退款减其他未结束的申请，待验收的申请也算占用）。

### 5. 应付与成本的金额口径

- 售后来源采购退货单的退款或抵扣金额用采购订单币种录入；人民币金额 = 原币 × 采购订单汇率，HALF_UP 两位，汇率保留 6 位小数。没有采购订单时币种为人民币、汇率 1。
- 应付金额 = 采购订单合计 − 差异折价 − Σ已完成售后采购退货的退款或抵扣（原币），在采购退货完成、重新打开、重新完成的事务内重算；已付超出部分按现有「供应商欠款」处理。
- 订单成本：退回供应商的冲减从 `sales_return_disposition.cost_cny` 改为读采购退货单的人民币金额（只算已完成的），运费读采购退货单的运费（寄出即计入）；转闲置仍读 `cost_cny`。
- 已结算的订单成本按现有规则重算展示，不修改已锁定的凭证。

### 6. 菜单与权限

- 新菜单「销售管理 → 销售退货」`/sales/returns`（售后管理之前），按钮复用售后单的处理权限（能处理售后单的人才能确认、作废），不另设按钮。
- 新菜单「采购管理 → 采购退货」`/purchase/returns`（发货跟踪之后），按钮「维护采购退货单」`purchase:purchase-return:edit`。
- 原菜单「退货入库」100121 路径不变，页面改列退货入库单；按钮「退货验收」「退货去向处理」不变。
- 迁移时：有「售后管理」的角色与租户套餐加「销售退货」；有「退货去向处理」或「到货差异处理」按钮的角色与套餐加「采购退货」及其按钮。
- 编号规则新增 RR、PR，格式与 TH 相同（前缀 + 日期 + 3 位流水）。

### 7. 前端

- 售后单详情：顶部操作改为「处理方式」按钮组（仅退货、退货退款、仅退款、补发）+「登记费用」；退货类打开同一个选型号弹窗，退货退款多一个「先退款」勾选与退款信息区。
- 新页面 `pages/sales/returns`（列表）与 `pages/sales/returns/detail`；`pages/purchase/returns`（列表）与 `pages/purchase/returns/detail`（寄出、完成、作废、重新打开）。
- `pages/warehouse/returns` 改为退货入库单列表，新增 `pages/warehouse/returns/detail`（验收、撤回入库、去向）；去向的退回供应商只选供应商与采购订单。
- 新增退款申请详情页 `pages/finance/refunds/request-detail`，执行、驳回、撤回在详情页也能操作。
- 到货差异处理弹窗去掉快递、运费、垫付人字段，处理后提示「已生成采购退货单 PRxxx」并可点开。
- 来源单号统一用 `SourceNos`，链接到第 0 节的详情页。

### 8. 实现与原型的差异（2026-11-11 记录）

- 退款明细、原因、去向在「确认退货」时逐行填写，不在售后单的选型号弹窗里填；选型号弹窗只显示预计退款（数量 × 成交单价）。理由：确认前还可能改数量，确认时再定金额不用改两次。
- 原型里采购退货单「修改寄出信息」没有实现：已寄出的采购退货单不能作废，「重新打开」只针对已完成，所以寄出后快递或运费录错目前改不了，待用户决定是否本期补接口。
- 售后单详情保留原有的处理时限、处理方案、跟进记录布局，新增「处理方式」卡片与「售后单据」卡片，原费用卡里的逐张单据列表移到「售后单据」卡片。
- 原采购订单是线上店铺采购（`supplier_id` 为 0）时，退货入库去向「退回供应商」显示店铺名，提交 `supplierId` 0 并带原采购订单，生成的采购退货单显示店铺名；没有带店铺采购订单时提交 0 仍按「供应商不存在」拒绝。
- 退款单没有详情页，「售后单据」里的退款单链接到退款列表并按单号筛选；退款列表、应付列表支持地址带 `keyword` 筛选（按单号跳转时不限日期）。

## Risks / Trade-offs

- [状态联动跨三个模块，容易漏改一处] → 联动只在第 3 节表格列出的服务方法里做，每一行都写集成测试覆盖合法与非法转换。
- [存量退货单迁移出错影响订单成本] → 迁移前后对每张订单计算「售后退货冲减 + 退回运费」合计，脚本比对不一致即中止；本地用生产数据副本先跑。
- [售后退货运费以前不进报销，现在寄出时选垫付人会进报销] → 迁移的历史运费不设垫付人，不进待报销；新单默认垫付人为当前采购员，可以选择「公司支付」（不进待报销）。
- [到货差异的退货运费以前在差异上，报销单引用差异 ID] → 迁移时把报销明细 `source_type` 3 的 `source_id` 改为对应采购退货单 ID，并比对迁移前后每人待报销合计不变。
- [退款申请「待验收」状态值为 0，与「默认值 2」不同] → 新状态只由销售退货生成时显式写入，列表与统计按状态名映射，补契约测试。
- [采购退货单退款金额用采购订单币种，个别外币采购订单] → 汇率取采购订单汇率并显示人民币折算，不额外取实时汇率。

## Migration Plan

迁移版本 V1.5.25（下一个可用版本，开发时再确认）：

1. 建表 `return_receipt`、`return_receipt_item`、`purchase_return`、`purchase_return_item`、`fin_refund_request_item`；加列（`sales_return.handling` 等、`sales_return_disposition.receipt_id / receipt_item_id / purchase_return_id`、`fin_refund_request.sales_return_id / refund_first`、`receiving_discrepancy.purchase_return_id`）。
2. 存量销售退货单：状态 1 待入库 → 销售退货单 2 待入库 + 退货入库单 1 待入库；2 待处理 → 3 已入库 + 退货入库单 2 待处理；3 已处理 → 3 已入库 + 退货入库单 3 已处理；4 已作废 → 4 已作废（不生成入库单）。处理方式按是否有关联退款申请判断（有为退货退款，否则仅退货）。退货入库单编号按创建日期补发 RR 号，入库字段从 `sales_return_item` 复制。
3. 去向为退回供应商的 `sales_return_disposition`：每条生成一张已完成的采购退货单（来源售后退货，运费、快递、供应商退款搬过去，垫付人为空），回写 `purchase_return_id`；应付不追溯冲减（历史退款已在成本里体现，财务另行处理过），在采购退货单上标「历史迁移，未冲减应付」。
4. 已处理且处理方式为 3、4、6 的到货差异：每条生成一张已完成的采购退货单（来源按处理方式），搬运快递、运费、垫付人；报销明细 `source_type` 3 的 `source_id` 改指采购退货单。
5. 存量退款申请各补一行「退款」明细。
6. 新增菜单、按钮、编号规则、角色与套餐授权。
7. 校验：每张订单的售后退货冲减与运费合计、每人待报销合计、每个采购订单应付金额在迁移前后一致，每张单据明细合计等于表头，不一致则迁移失败回滚。

回退：迁移在一个事务里执行（建表除外），失败自动回滚；上线后需要回退时，旧版本代码读不到新状态，需要随版本一起回退并执行反向脚本（删除新表与新增列的数据、恢复 `sales_return.status`），反向脚本随 PR 提供，不自动执行。

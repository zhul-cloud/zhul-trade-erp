# Spec Delta

## MODIFIED Requirements

### Requirement: 采购退货页
「采购管理 → 采购退货」SHALL 列出采购退货单，按数据范围（负责人或采购订单的采购员在当前用户可见范围内）显示。「状态」下拉：待寄出、已寄出、已完成、已作废（清空为全部；待寄出、已寄出附数量；默认待寄出，从别的单据带单号跳来时为全部）；筛选：供应商、来源类型、负责人、关键字（采购退货单号、采购订单号、来源单号、型号、快递单号）。列：采购退货单号、来源单号（退货入库单号或采购入库单号）· 来源类型、供应商、采购订单、型号摘要、快递单号、运费、退款或抵扣、负责人、状态，以及创建时间、创建人、更新时间、更新人；按更新时间倒序。菜单显示待寄出的数量。

采购退货单 SHALL 由表头与明细组成：表头记录单号、供应商、来源类型、采购订单、负责人、寄出与签收信息、运费与垫付人、退款或抵扣金额、状态；明细每行记录来源行（退货入库单行或到货差异）、采购订单行、型号、品牌、数量。采购退货单 SHALL 有独立的详情页（`/purchase/returns/:id`，标签页标题为单号），寄出、完成、作废、重新打开都在详情页操作。

采购退货单详情 SHALL 显示表头、明细、寄出与签收信息、退款或抵扣、关联的应付单与销售订单（售后来源）、操作日志。采购订单详情 SHALL 列出它的采购退货单。

#### Scenario: 状态下拉带数量
- **WHEN** 有 2 张待寄出、1 张已寄出的采购退货单，采购员打开采购退货
- **THEN** 默认列出待寄出的 2 张，「状态」下拉显示「待寄出 · 2」「已寄出 · 1」

#### Scenario: 按供应商查退货
- **WHEN** 采购员在采购退货页筛选供应商「深圳工控」
- **THEN** 列出退给深圳工控的所有采购退货单，包括售后退货与到货差异来源的

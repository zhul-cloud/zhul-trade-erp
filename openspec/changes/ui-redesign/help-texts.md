# 帮助文字清单

列表页的帮助图标（ⓘ）里写什么，逐条取自现有代码的脚注、卡片副文字或注释，不另编。改到某页时先在这里补行，再画原型、写代码。

- **来源**：写明取自哪段代码，方便以后核对。
- **改写原则**：去掉「点表头可排序」这类界面上看得出来的话，其余业务口径保持原意。

「还差：…」（成本未结算的原因，取自后端 `OrderCostCalc` 的 `pending`）是状态信息，照常显示在标题下方，不收进帮助图标。

操作提示（悬停显示，取自 `detail.tsx` 按钮的 `title`）：
- 「客户已收货」置灰时：所有型号都出运后才能确认收货。
- 「部分取消」在订单已完成时置灰：订单已完成，请走售后。
- 实现时置灰按钮外包一层可聚焦的元素再挂提示（antd `Tooltip` 包 `span`），键盘用户也能读到原因。

原型假设当前用户是业务员：有售后权限，没有 `finance:refund:edit`（所以显示「申请退款」而不是「登记退款」），也没有 `sales:order:delete`（「更多」菜单里没有「删除订单」）。有删除权限、订单没完成、不是迁移订单时，「更多」菜单最下方加红色的「删除订单」。

## 登记到账弹窗

代码位置：`zhul-erp-frontend/src/pages/sales/pi/dialogs.tsx`（`ConfirmReceiptModal`）、`receiptDialogs.tsx`（`PaymentMethodSelect`、`FxEstimateHint`）。

| 位置 | 帮助文字 | 来源 |
|---|---|---|
| 到账金额（外币时） | 人民币先按最近一次结汇的汇率估算，标「未结汇」；结汇后由财务在「结汇管理」登记结汇单，系统按先进先出确定实际人民币 | `FxEstimateHint`，原来是表单中间的一段灰字 |

照常显示、不收进帮助图标的：
- 到账金额下方的结果：「本次到账后结清」「本次到账后还差 …」「多收 …，将记为预收」，以及差额不超过容差时的「差额记为银行中转手续费（视为结清）」勾选框，或「差额不超过 … 时可记为手续费」。这些是随输入变化的反馈。
- 页脚左侧「到账记录保存后不能修改，登记错误时作废后重新登记」：提交前要知道的不可撤销信息，放在提交按钮旁边。
- 「可能收错账户」警告、多收确认框：警告与确认原样保留，只换样式和位置。

# 统计卡片清单

从前端代码整理（2026-11-20，`feat/ui-redesign`，已合入 develop f79ac93f），按 `specs/system/interface-style`「统计卡片的去向」分类，分类由产品负责人确认。

- **类别与去向**：
  - 状态类：数字并入状态下拉的选项；
  - 条件类：转为快捷筛选；
  - 指标类：转为页头下方的汇总行。
- **口径**：取自卡片上的说明文字，或卡片对应的代码。只有标题、看不出口径的标「待核实」，改到该页时读接口补上。
- **能否筛选**：条件类卡片要求列表接口已经有对应的筛选。
  - 「已有」：现在点卡片就能筛选；
  - 「待核实」：改到该页时核对接口。
  - 接口没有对应筛选的不加后端，这张卡按指标类放进汇总行。

## 与 spec 场景的冲突（请产品负责人决定）

- **询价分配**：待分配、询价中、待审核是任务状态，按新规则应并入状态（这里是页签）。但卡片按全部任务统计，页签数字随搜索变化，两者口径不同；spec「页签保留」的场景仍按快捷筛选写。请产品负责人定：并入页签（口径改为随搜索），还是作为例外保留为快捷筛选（口径不变）。我倾向保留为快捷筛选，主管看全局数量的习惯不变。
  - 2026-11-22 处理（任务 7.2）：按「可合理假设就说明并继续」先改为汇总行，口径不变（按全部任务），页签数字照旧随搜索变化；不做成快捷筛选，免得和页签重复。改动见 `specs/inquiry/sourcing-task` 增量，用户看 7.2 时一并确认
- **收款管理**：spec「页签保留」的场景写的是「没有另外的统计卡片」，但「收款单」页签里有线上、线下、合计三张卡。我的建议是把这三张卡改成该页签内的汇总行，同时把 spec 场景改成「统计卡片改为页签内的汇总行」。

## 不属于列表统计卡片的

这些不按本表转换，按统计页、详情页、工作台的原型分别处理：
- **统计分析**：销售、询价、砍价、利润、经营统计，以及供应链团队看板的覆盖率指标。
- **详情页摘要**：采购订单详情、客户档案经营等级、客户跟进记录、定价策略抽屉、运费账单详情抽屉、需求覆盖详情的「优先级依据」。
- **工作台**：商机统计、采购员看板等组件。

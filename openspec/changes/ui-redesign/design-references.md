## 二、本项目设计原则（总纲）

1. **先给答案，再给操作。** 每页第一眼是用户来这一页要找的东西（列表看数据、详情看状态和金额、工作台看要处理的事），筛选和设置往后放。
2. **一屏一个视觉重点。** 每个页头、弹窗、分区最多一个实底主按钮、一个最大的数字。
3. **颜色只表达「能点」和「要注意」。** 主题色给主操作和选中状态，语义色给状态和告警，其余用中性灰。
4. **层级不超过三层。** 页面底、浮起卡、卡内凹格；卡里不套带阴影或描边的卡。
5. **对齐出秩序。** 文字左对齐，数字右对齐，同一列小数点对齐，卡片内边距与表格首列对齐，同一行卡片等高。
6. **数字要精确、可比、带币种。** 等宽数字、千分位、两位小数、币种代码；同一列同一币种时币种写在表头。
7. **紧凑的表格，宽松的卡片。** 兼顾一屏信息量和消费级观感。
8. **已生效的条件永远看得见。** 筛选、排序、视图状态都在界面上显示，能一键清除。
9. **主操作始终触手可及。** 长详情页页头吸顶，长表格横向滚动条吸底，批量操作跟着勾选出现。
10. **每个数据视图都有六种状态。** 加载、刷新中、空、无结果、错误、无权限，都单独设计。
11. **反馈及时，并且能挽回。** 成功用轻提示，失败就地说明原因和改法；能撤销的给撤销，不能撤销的提前写明。
12. **说人话，少说话。** 不写常识性说明，不把字段名或枚举值直接展示给用户；口径放帮助图标。
13. **深色不是浅色反过来。** 层级越高表面越亮，用边框代替阴影，大块彩色浅底在深色下单独核对。
14. **以真实环境验收。** 以 Windows 浏览器 1366×768 和 1440×900、浅深两色、默认琥珀加一种冷色主题为准，不以原型渲染为准。

## 三、对标检查表（每个页面验收用）

做完一个页面后，和标杆模板并排截图，逐项检查，未达标的改到达标再交用户。

**观感**

## 五、付费模板实测基准（2026-11-28，UI-117）

用户要求「查询网上优质付费模板后给出标准」。两个调研代理在 BrowserOS 里以 1440×900、DPR 1 实测 8 个付费模板的看板、列表、详情三类页面（同一测量脚本：字号字重、表头与行、卡片、按钮、标签、首屏结构、主栏侧栏比例），本项目按同一脚本量销售订单列表与详情。演示站自带预填的演示账号，只点登录、不输入密码、不改数据。

测过的模板：Minimal UI（MUI）、Devias Kit Pro（MUI）、Berry（MUI，官方演示在 berrydashboard.com）、Materio Pro（Vuetify）、Metronic 8.3（Bootstrap）、Vuexy（HTML）、Catalyst（Tailwind Plus）、Untitled UI React（PRO）。Untitled UI 的公开演示没有详情页。

| 项目 | 8 家共识（范围） | 本项目实测 | 结论 |
|---|---|---|---|
| 正文字号 | 14（Materio、Vuexy 15） | 14 | 达标 |
| 页面标题 | 18–24，600（Devias 32/500 是例外） | 20/600 | 达标 |
| 卡片、分区标题 | 16–18，500–600 | 16/600（D26） | 达标；中文不用 500（检查表 #7） |
| 字重 | 大量 500（拉丁字体） | 400/600（`cjk-weight` 把关） | 有意不同：微软雅黑 500 显示成常规 |
| 表头 | 高 44–57；12–14；次要灰；无底或很浅（#F9FAFB–#F6F7FB）；不加竖线 | 高 48，13/400，次要灰，#F9FAFB | 达标 |
| 表格行高 | 纯文字 50–57；两行或带头像 66–84 | 单行 48、两行 64 | 达标（偏紧凑，ERP 合理） |
| 单元格左右内边距 | 16–24（Catalyst 0，靠卡片留白） | 12 | 偏紧，见下方取舍 1 |
| 行分隔线 | 1px，极浅（#E3E8EF–#F1F1F4 或 5–20% 灰） | 1px #E5E8EB | 达标 |
| 卡片 | 圆角 6–20（众数 8）；阴影很轻或 1px 细描边 | 圆角 10；与 Minimal 同款双层柔和阴影 | 达标 |
| 页面底 | 两派：纯白靠阴影（Minimal、Devias、Untitled）／浅灰加白卡（Berry、Materio、Vuexy、Catalyst） | #F4F6F8 浅灰加白卡 | 达标（浅灰派） |
| 外边距、卡片间距 | 24 为主（20–32） | 16 | 偏紧，见下方取舍 1 |
| 侧栏宽 | 256–300 | 260 | 达标 |
| 按钮 | 高 36–40，圆角 6–8，14 | 36，圆角 8，14 | 达标 |
| 状态标签 | 高 20–24，圆角 4–6（或全圆），12–13；浅底深字（底为字色约 16%），没有实底 | 24，圆角 4，12，浅底深字 | 达标 |
| 表格里的主题色 | 6 家行内几乎不用；单号深色加粗或下划线，悬停才变色 | 墨色单号，悬停主题色下划线（D23、`zhul-link-doc`） | 达标 |
| 数字列 | 金额右对齐（Metronic、Berry、Catalyst 及各家详情明细）；8 家都没用等宽数字 | 等宽、右对齐、千分位 | 高于模板（检查表 #8 保留） |

| 详情页合计 | 最多 16/600 或加粗，不放大 | 16/600 | 达标 |

**结论**：字阶、表格、卡片、按钮、标签、颜色用量都在 8 家的共识范围内；数字排版高于模板。差距在两处尺寸取舍，需要用户拍板（对比图另出）：

1. **留白**：外边距与卡片间距 16、单元格左右内边距 12，比模板主流的 24 和 16–24 紧一档。紧凑是为了 1366 宽下 16 列表格少横滚；放宽观感更接近消费级模板，但 1366 下每张表约少放一列。
2. **列表首屏**：表头落在 y≈408，比主流模板低 70–150px。原因是表格上面叠了页头、汇总、搜索区、操作行四层；可选方向是把汇总并进页头一行（用户管理页的写法）或收矮搜索区。

审核发现的其余问题（字重、标题、单号颜色、空状态、D75 余项、金额排版等）属于「规则已有、页面没跟上」，按 UI-117 直接整改，不需要另定标准。

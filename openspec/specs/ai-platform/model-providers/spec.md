# ai-platform/model-providers Specification

## Purpose
约定 AI 编排服务调用哪家模型服务商、每类任务用哪个模型和多大思考强度，以及这些配置的取值、默认值与配置错误时的表现，使部署方只改配置就能切换服务商和模型。

## Requirements

### Requirement: 按配置选择模型服务商
AI 编排服务 SHALL 按每个任务携带的租户 AI 配置选择模型服务商，可选 `claude`、`openai`，留空时为 `claude`。服务商适用于 API 方式和平台租户的订阅方式；部署环境变量 `AI_ORCHESTRATOR_MODE=stub` 时为假数据服务，不调用任何服务商，忽略任务携带的配置。同一个编排服务实例可以同时为不同租户使用不同服务商。

#### Scenario: 未配置服务商时使用 Claude
- **WHEN** 后端提交一个询盘解析任务，携带的配置为 API 方式、服务商留空
- **THEN** 编排服务调用 Claude 完成解析，并按原有契约回调结果

#### Scenario: 切换到 OpenAI
- **WHEN** 租户在系统中把服务商改为 `openai` 并填写 OpenAI 的 Key，随后提交询盘解析
- **THEN** 编排服务调用 OpenAI 完成解析，回调结果的结构与使用 Claude 时一致，编排服务无需重启

#### Scenario: 假数据模式不受服务商影响
- **WHEN** `AI_ORCHESTRATOR_MODE=stub`，任务携带的服务商为 `openai` 且 Key 为空
- **THEN** 编排服务照常返回固定假数据，不调用任何服务商，也不因缺少 Key 报错

### Requirement: 按任务配置模型并提供推荐默认值
AI 编排服务 SHALL 用任务携带的解析模型执行询盘解析，用翻译模型执行型号描述翻译与联系人名音译。模型留空时使用当前服务商的推荐默认值，API 与订阅方式相同：Claude 为解析 `claude-opus-5-5`、翻译 `claude-haiku-5-5`；OpenAI 为解析 `gpt-6.1-sol`、翻译 `gpt-6-luna`。填写的模型名原样传给当前执行器，不做校验，不默默替换模型。

#### Scenario: 留空使用推荐模型
- **WHEN** 任务携带的配置为服务商 `openai`，两个模型都留空
- **THEN** 询盘解析使用 `gpt-6.1-sol`，两类翻译使用 `gpt-6-luna`

#### Scenario: 指定模型
- **WHEN** 任务携带的配置为服务商 `claude`、解析模型 `claude-sonnet-5-5`
- **THEN** 询盘解析使用 `claude-sonnet-5-5`，翻译仍使用推荐的 `claude-haiku-5-5`

#### Scenario: 模型名与服务商不匹配
- **WHEN** 任务携带的配置为服务商 `openai`、解析模型 `claude-opus-5-5`
- **THEN** 解析任务回调失败，失败原因带有服务商返回的错误信息

#### Scenario: 订阅模型默认值
- **WHEN** 平台租户使用订阅方式，模型留空
- **THEN** 与 API 方式相同：Claude 使用 `claude-opus-5-5` / `claude-haiku-5-5`，Codex 使用 `gpt-6.1-sol` / `gpt-6-luna`

### Requirement: 按任务配置思考强度
AI 编排服务 SHALL 按任务携带的解析与翻译思考强度调用服务商，可选 `low`、`medium`、`high`、`xhigh`、`max`，留空均为 `medium`，取值原样传给当前服务商。携带的取值不在可选范围内时，该任务回调失败并说明可选值，不影响其他任务。

#### Scenario: 默认中等强度
- **WHEN** 任务携带的两个思考强度都留空
- **THEN** 询盘解析与翻译都以 `medium` 强度调用服务商

#### Scenario: 解析使用更高强度
- **WHEN** 任务携带的解析思考强度为 `high`
- **THEN** 询盘解析以 `high` 强度调用，翻译仍为 `medium`

#### Scenario: 非法取值
- **WHEN** 任务携带的翻译思考强度为 `fast`
- **THEN** 该任务回调失败，失败原因包含可选值列表；编排服务继续处理其他任务

### Requirement: 各服务商完成相同的解析能力
无论使用哪家服务商，询盘解析 SHALL 支持图片与 PDF 附件、对每个提取到的型号联网搜索验证、按后端约定的 JSON 结构返回结果，并受任务携带的最大搜索次数约束：该次数按每次模型调用计算，内容只需一次调用时即为整次解析的上限，分批解析时每个核验批各自适用；翻译任务不联网搜索。服务商返回的结果缺少约定的必填字段或无法解析时，任务回调失败。Claude API SHALL 在保留全部业务字段的前提下适配结构化输出约束；可选字段未给出时保持缺失语义，已给出的空串、0、空数组保持原值，必填字段为 null 或类型错误时失败，不编造默认业务值。此适配 SHALL 不改变订阅模式或 OpenAI API 的调用与回调行为。

#### Scenario: OpenAI 解析带 PDF 的询盘
- **WHEN** 服务商为 `openai`，后端提交一条带 PDF 型号清单的询盘解析任务
- **THEN** 编排服务把 PDF 交给模型识别并逐个型号联网搜索，回调的结果包含与 Claude 相同的分组、型号、置信度等字段

#### Scenario: 可选字段未给出
- **WHEN** OpenAI 返回的某个型号没有给出替代型号等可选字段
- **THEN** 回调结果中该型号不包含这些字段，与 Claude 未给出时的表现一致，后端照常处理

#### Scenario: 租户自定搜索上限
- **WHEN** 租户把最大搜索次数设为 5，提交一条含 10 个型号、只需一次调用的询盘解析
- **THEN** 本次解析最多发起 5 次联网搜索

#### Scenario: Claude API 保留完整字段和空值语义
- **WHEN** Claude API 返回合法结果，原可选字段以 null 表示未给出，其他可选字段为显式空串、0 或空数组
- **THEN** 回调中只移除 null 字段，其他值原样保留，所有现有业务字段仍可返回

#### Scenario: Claude API 拒绝非法结构化结果
- **WHEN** Claude API 返回缺失必填字段、必填字段为 null、字段类型错误或无法解析的内容
- **THEN** 任务失败回调，不以默认值补齐，不静默回退订阅或其他服务商；结构校验错误的日志和回调不包含完整业务输出或非法字段值

#### Scenario: API 调用后订阅契约保持不变
- **WHEN** 同一编排服务实例先执行 Claude API 任务，随后执行 Claude 或 Codex 订阅任务
- **THEN** 后续订阅收到与 API 调用前相同的业务 Schema 和执行参数，并沿用原结果校验与回调行为

### Requirement: 部署者个人订阅模式
编排服务 SHALL 在任务携带的运行方式为 `subscription` 时，按携带的服务商使用官方 Codex Python SDK（`openai`）或原版 Claude Code CLI（`claude`）执行。订阅方式用于平台租户以及获平台授权使用订阅的公司的任务（授权与可用性由后端在创建任务前检查，编排服务按任务携带的配置执行），不使用 API Key，不自动回退 API 或改用其他服务商；部署者本人通过容器内官方 CLI 登录，项目不代收 token，不向租户下发任何凭据。

#### Scenario: Codex 订阅无 API Key
- **WHEN** 平台租户或获授权公司的任务携带订阅方式、服务商 `openai`，容器内已由部署者完成 ChatGPT 登录
- **THEN** 编排服务通过官方 Codex SDK 执行任务，并使用原回调契约

#### Scenario: 缺少个人订阅登录
- **WHEN** 任务携带订阅方式但容器内对应 CLI 未登录
- **THEN** 任务失败回调明确提示在容器内通过官方 CLI 登录，不转用 API

#### Scenario: 登录状态持久保存
- **WHEN** Docker 按默认 Compose 运行订阅服务，部署者在容器内完成官方 CLI 登录后停止、重启、重建容器或重新构建镜像
- **THEN** 认证保存在专用 HOME 的 Docker 命名卷中（属主 10001、权限 0700，不在 `storage/` 备份范围内），无需重新登录；删除该卷或执行官方退出命令后才需重新登录；不挂载或复制宿主个人目录

### Requirement: 订阅任务隔离与完整结果
订阅任务 SHALL 与 API 方式一样可以同时执行多个，不因已有订阅任务在执行而失败；每个任务使用独立临时工作目录与 Linux 进程组，禁用 shell/编辑、外部 MCP/hooks/插件及交互审批；图片/PDF 必须实际处理；单次订阅调用的附件仍不超过 25MiB、图片与 PDF 页合计不超过 20，超出时按「超出单次请求上限时分批解析」分批调用，不因附件大而失败；只有完整且符合 JSON Schema 的结果可以成功回调。

#### Scenario: 多个订阅任务同时执行
- **WHEN** 一个订阅任务尚未完成时，又有其他订阅任务提交到同一编排服务实例
- **THEN** 新任务立即开始执行，不因前一个任务在执行而失败；各任务使用各自的临时工作目录和进程组，结果分别回调

#### Scenario: 超时或子进程异常
- **WHEN** 订阅调用超时或 CLI 返回不完整结果
- **THEN** 服务终止本次调用的整个进程组，不留下继续占用额度的子进程；分批解析时按「分批互不影响」只影响这一批

#### Scenario: 搜索阈值
- **WHEN** 一次订阅调用观察到第 N 个不同搜索/网页操作事件，N 为任务携带的最大搜索次数
- **THEN** 这次调用被保守终止（操作开始时可能已有在途请求，不宣称硬计费上限），同一批改为不联网重新提取，型号置信度为「待核实」，任务不因此失败

#### Scenario: 真实图片与扫描 PDF
- **WHEN** 任务含受支持图片或未加密 PDF
- **THEN** 图片转换及 PDF 逐页渲染后输入模型；单次调用超过 25MiB 或 20 张图片/页时分批调用；不支持、损坏的文件或页明确列出，不静默丢失

#### Scenario: 300 页扫描件
- **WHEN** 订阅方式解析一个 300 页的扫描 PDF
- **THEN** 编排服务分成每批不超过 20 页的多次订阅调用，合并后回调，不因页数超过 20 而失败

### Requirement: 诊断元数据不影响有效业务结果
AI 编排服务 SHALL 将可选请求标识等诊断元数据与业务结果分开处理。服务商返回完整、合法的结构化内容时，缺少请求标识不应导致任务失败；有请求标识时可记录用于排错。业务拒答、超时、截断、非法 JSON 或 Schema 不符仍按既有规则失败。

#### Scenario: 流式结果没有请求标识
- **WHEN** Claude API 流式返回完整且符合业务 Schema 的结果，但解析后的消息对象和响应头没有请求标识
- **THEN** 服务正常返回结果并成功回调，不因诊断元数据缺失报错

#### Scenario: 请求标识来自流式响应
- **WHEN** Claude API 返回合法结果且流式响应头带 request-id，而解析后的消息对象没有同名私有属性
- **THEN** 服务可记录该响应头请求标识并成功返回结果

#### Scenario: 诊断兼容不掩盖业务错误
- **WHEN** API 返回拒答、截断、非法内容或调用超时
- **THEN** 任务仍按既有失败规则处理，不以缺少请求标识为由忽略错误

### Requirement: 解析前的附件预处理
询盘解析 SHALL 在送入模型前按类型处理附件：图片缩放压缩；PDF 逐页判断，有文字层的页提取文字，扫描页渲染为图片；Excel 按工作表与行转为文字。附件先完整取到编排服务的临时磁盘再处理，任务结束后删除。API 与订阅方式、各服务商使用相同的预处理结果。

#### Scenario: 图纸 PDF 混有扫描页
- **WHEN** 一个 PDF 的前 10 页是导出的表格、后 5 页是扫描件
- **THEN** 前 10 页以文字送入模型，后 5 页渲染为图片送入模型

#### Scenario: 高分辨率照片
- **WHEN** 询盘附件是一张 60MB 的铭牌照片
- **THEN** 照片缩放压缩后送入模型，原文件不变

### Requirement: 超出单次请求上限时分批解析
预处理后的内容超出单次模型请求的大小、页数或文字量上限时，编排服务 SHALL 按页或行分成多批，每批不超过上限，批次并行提取型号；全部批次完成后按确认型号合并去重（数量相加，并注明每处出现的文件与页码或行号），再把去重后的型号分成每批不超过 10 个联网核验。最大搜索次数按每次模型调用计算，每个核验批各自适用，不按整个任务合计。

#### Scenario: 分批后合并
- **WHEN** 一个 400 页的扫描 PDF 分成多批解析，同一型号在两批中各出现一次
- **THEN** 回调结果中该型号只有一行，数量为两处之和，并带两处出现位置

#### Scenario: 每个核验批各自适用搜索上限
- **WHEN** 租户最大搜索次数为 20，分批合并后共有 120 个型号
- **THEN** 型号分成 12 个核验批（每批 10 个），每批最多搜索 20 次，整次解析最多 240 次

### Requirement: 分批互不影响
分批解析时，任何一个文件、页、批次的失败 SHALL 只影响它自己：文件取不到或无法读取、某页损坏、某个提取批重试后仍失败时，在结果中列出文件与页码或行号范围及原因，其余内容照常返回；某个核验批失败或达到搜索上限时，这批型号不联网核验、置信度为「待核实」，其余照常。只有所有内容都没能提取出型号时，任务才失败。

#### Scenario: 某一批始终失败
- **WHEN** 第 7 个提取批重试 2 次后仍失败
- **THEN** 回调结果包含其他批次的型号，并列出第 7 批对应的文件与页码范围未解析

#### Scenario: 核验批达到搜索上限
- **WHEN** 第 2 个核验批达到最大搜索次数，仍有 15 个型号未核验
- **THEN** 这 15 个型号置信度为「待核实」，第 1、3 批的核验结果照常返回，任务成功

#### Scenario: 一个附件取不到
- **WHEN** 询盘有 3 个附件，其中一个下载失败
- **THEN** 另外 2 个附件照常解析，结果列出「《报价单.xlsx》无法读取」

#### Scenario: 全部内容都无法解析
- **WHEN** 询盘只有一个加密 PDF，没有文字内容
- **THEN** 任务失败，原因写明该文件已加密、无法读取

### Requirement: 解析进度报告
分批解析期间编排服务 SHALL 定期向后端报告进度（已完成批数 / 总批数）与当前阶段（读取附件、提取型号、合并去重、联网核验），报告不改变任务的结束状态，任务结束后到达的进度报告被忽略。

#### Scenario: 报告进度
- **WHEN** 一个任务共 12 批，已完成 5 批
- **THEN** 后端收到进度 5/12，询盘「解析中」显示该进度

#### Scenario: 报告阶段
- **WHEN** 提取型号全部完成，开始联网核验
- **THEN** 后端收到阶段「联网核验」，询盘详情显示前三个阶段已完成、联网核验进行中；总批数加上核验批数后进度条回落时，阶段说明当前在做什么

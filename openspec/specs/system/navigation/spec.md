# system/navigation Specification

## Purpose
菜单框架按部门组织侧边栏：每个部门的人打开系统先看到自己部门的一组菜单，组内按业务流程先后排列；同时约定菜单命名规则，让以后新增的模块按同一框架挂进来。

## Requirements

### Requirement: 按部门分组的菜单框架
系统 SHALL 按以下分组与顺序组织侧边栏（括号内为尚未上线、上线时挂入该分组的功能）：
- 工作台
- 业务管理：商机、客户、客户询盘、报价单、PI、销售订单
- 采购管理：兼职看板、询价分配、我的询价、历史询价、供应商（、采购单）
- （单证物流：发货、CI / PL）
- 财务管理：收款管理（、应收、对账单）
- 商品资料：商品、品牌、品类、系列（价格体系上线后归入商品资料或单独分组，届时再定）
- 业务设置：定价策略、汇率、收款账户、单据模版、单据编号
- 系统管理：用户、角色、部门、岗位、菜单、字典、系统设置、操作日志、登录日志
- 租户管理（仅平台账号）：租户、套餐

侧边栏按当前用户的菜单权限过滤：分组下没有可访问的菜单时整个分组不显示；没有页面的分组与菜单不出现在侧边栏。调整分组不改变各页面的访问地址，原有书签与链接继续可用。

#### Scenario: 业务员的侧边栏
- **WHEN** 业务员（有工作台、商机、客户、客户询盘、报价单、PI、销售订单与历史询价权限）登录
- **THEN** 侧边栏依次为「工作台」「业务管理」（商机、客户、客户询盘、报价单、PI、销售订单）「采购管理」（历史询价），不出现财务管理、业务设置与系统管理

#### Scenario: 采购员的侧边栏
- **WHEN** 采购员（有询价分配以外的采购菜单与供应商权限）登录
- **THEN** 侧边栏的「采购管理」下依次为我的询价、历史询价、供应商

#### Scenario: 未上线的功能不占位
- **WHEN** 租户管理员登录，而采购单、发货、应收功能尚未上线
- **THEN** 侧边栏没有「单证物流」分组，「采购管理」与「财务管理」下也没有采购单、应收菜单

#### Scenario: 原地址继续可用
- **WHEN** 业务员打开调整前收藏的客户询盘详情链接
- **THEN** 页面正常打开，面包屑显示「业务管理 / 客户询盘 / …」

### Requirement: 菜单命名规则
菜单名称 SHALL 遵循：分组叫「部门或领域 + 管理」（「商品资料」「业务设置」除外）；叶子菜单直接用对象或单据名称，不加「列表」「管理」等后缀，不超过四个字；面向某个岗位的处理入口按「谁做什么」命名（如「询价分配」「我的询价」「兼职看板」），不重复使用「工作台」。页面标题与面包屑使用与菜单相同的名称。本次改名：商机列表 → 商机，客户列表 → 客户，供应商列表 → 供应商，商品列表 → 商品，品牌管理 → 品牌，品类管理 → 品类，系列管理 → 系列，分配工作台 → 询价分配，我的询价任务 → 我的询价，兼职工作台 → 兼职看板，汇率设置 → 汇率，用户管理 → 用户，角色管理 → 角色，部门管理 → 部门，岗位管理 → 岗位，菜单管理 → 菜单，字典管理 → 字典，租户列表 → 租户，套餐管理 → 套餐。

#### Scenario: 页面标题与菜单一致
- **WHEN** 采购负责人点击「采购管理 → 询价分配」
- **THEN** 页面标题为「询价分配」，面包屑为「采购管理 / 询价分配」

### Requirement: 调整菜单后权限不变
菜单重新分组 SHALL 不改变任何角色能访问的页面与操作：原来能访问某页面的角色，调整后仍能访问且能在侧边栏看到它；新增的分组自动授给拥有其下任一菜单的角色，并加入包含这些菜单的租户套餐。

#### Scenario: 调整后仍能访问
- **WHEN** 调整前拥有「客户询盘」「报价单」权限的角色登录
- **THEN** 侧边栏「业务管理」下显示客户询盘与报价单，打开后与调整前一样可用

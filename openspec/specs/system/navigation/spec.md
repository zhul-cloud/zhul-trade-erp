# system/navigation Specification

## Purpose
菜单框架按部门组织侧边栏：每个部门的人打开系统先看到自己部门的一组菜单，组内按业务流程先后排列；同时约定菜单命名规则，让以后新增的模块按同一框架挂进来。

## Requirements

### Requirement: 按部门分组的菜单框架
系统 SHALL 按以下分组与顺序组织侧边栏（括号内为尚未上线、上线时挂入该分组的功能）：
- 工作台
- 销售管理：客户跟进、商机管理、客户管理、询盘管理、报价管理、形式发票、销售订单、销售退货、售后管理（客户跟进是业务员每天的跟进入口，排在最前）
- 采购管理：询价分配、我的询价、询价记录、采购需求、采购订单、发货跟踪、采购退货、供应商库（原「兼职看板」并入工作台的采购员看板）
- 仓库管理：采购入库、销售出库、退货入库、闲置库存、实拍任务
- 物流管理：出运管理、运费账单
- 财务管理：收款管理、退款管理、余额管理、结汇管理、应付管理、付款管理、报销管理、费用管理、其他收入（、应收）
- 商品管理：商品档案、品牌管理、品类管理、系列管理，只放基础资料（价格体系上线后归入商品管理或单独分组，届时再定）
- 运营管理：商品候选、资料任务、营销任务、发品任务、素材管理，运营人员处理的任务（素材管理全公司共用，业务员也可以有它的权限）
- 统计分析：销售统计、询价统计、砍价统计、利润统计、经营统计、商机统计，只读的统计统一放在这里，各业务分组只放业务操作
- 业务设置：定价策略、汇率设置、收款账户、单据模板、编号规则、快递时效、国家资料、通知接收人
- 系统管理：用户管理、角色管理、部门管理、岗位管理、菜单管理、字典管理、系统设置、操作日志、登录日志
- 租户管理（仅平台账号）：租户列表、套餐管理

一级菜单的排序号互不重复，物流管理排在仓库管理之后。侧边栏按当前用户的菜单权限过滤：分组下没有可访问的菜单时整个分组不显示；没有页面的分组与菜单不出现在侧边栏。调整分组不改变各页面的访问地址，原有书签与链接继续可用。

#### Scenario: 业务员的侧边栏
- **WHEN** 业务员（有工作台、客户跟进、商机管理、客户管理、询盘管理、报价管理、形式发票、销售订单、售后管理与询价记录权限）登录
- **THEN** 侧边栏依次为「工作台」「销售管理」（客户跟进、商机管理、客户管理、询盘管理、报价管理、形式发票、销售订单、售后管理）「采购管理」（询价记录）「统计分析」（销售统计），不出现财务管理、业务设置与系统管理

#### Scenario: 采购员的侧边栏
- **WHEN** 采购员（有询价分配以外的采购菜单与供应商库权限）登录
- **THEN** 侧边栏的「采购管理」下依次为我的询价、询价记录、采购需求、采购订单、发货跟踪、供应商库

#### Scenario: 未上线的功能不占位
- **WHEN** 租户管理员登录，而应收功能尚未上线
- **THEN** 「财务管理」下没有应收菜单

#### Scenario: 原地址继续可用
- **WHEN** 业务员打开调整前收藏的询盘单详情链接
- **THEN** 页面正常打开，面包屑显示「销售管理 / 询盘管理 / …」

#### Scenario: 仓库人员的侧边栏
- **WHEN** 内置角色「仓库」的用户登录
- **THEN** 侧边栏只有「工作台」「仓库管理」（采购入库、销售出库、退货入库、闲置库存、实拍任务）、「财务管理」（报销管理）与「运营管理」（素材管理，验货和拍摄时参考）

#### Scenario: 财务的侧边栏
- **WHEN** 有收款管理、结汇管理、应付管理、付款管理、报销管理、费用管理、利润统计权限，没有退款管理、其他收入、经营统计权限的财务登录
- **THEN** 「财务管理」下依次为收款管理、结汇管理、应付管理、付款管理、报销管理、费用管理；「统计分析」下只有利润统计

#### Scenario: 采购员看到报销单
- **WHEN** 有采购订单菜单的采购员登录
- **THEN** 侧边栏出现「财务管理」，下面只有「报销管理」

#### Scenario: 采购负责人看到砍价统计
- **WHEN** 有「询价分配」菜单的采购负责人登录
- **THEN** 「统计分析」下有「询价统计」「砍价统计」；只有采购订单菜单的采购员看不到它们

#### Scenario: 财务看到利润统计
- **WHEN** 有收款管理菜单的财务登录
- **THEN** 「统计分析」下有「利润统计」，排在「经营统计」之前

#### Scenario: 财务看到退款单与经营统计
- **WHEN** 有收款管理菜单的财务登录
- **THEN** 「财务管理」下依次为收款管理、退款管理、结汇管理、应付管理、付款管理、报销管理、费用管理、其他收入；「统计分析」下有利润统计、经营统计

#### Scenario: 运营人员的侧边栏
- **WHEN** 管理员登录
- **THEN** 「商品管理」下依次为商品档案、品牌管理、品类管理、系列管理；「运营管理」下依次为商品候选、资料任务、营销任务、发品任务、素材管理

#### Scenario: 业务员有素材库权限
- **WHEN** 业务员的角色加上了素材管理菜单权限
- **THEN** 侧边栏出现「运营管理」，下面只有「素材管理」

#### Scenario: 物流管理排在仓库管理之后
- **WHEN** 管理员登录
- **THEN** 一级菜单依次为工作台、销售管理、采购管理、仓库管理、物流管理、财务管理……，仓库管理与物流管理的先后每次一致

#### Scenario: 财务人员看到余额管理
- **WHEN** 财务角色的用户登录
- **THEN** 「财务管理」下依次为收款管理、退款管理、余额管理、结汇管理、应付管理、付款管理、报销管理、费用管理、其他收入

#### Scenario: 售后管理与退货入库
- **WHEN** 管理员登录
- **THEN** 「销售管理」最后两项为「销售退货」「售后管理」；「采购管理」的「发货跟踪」之后为「采购退货」；「仓库管理」下依次为采购入库、销售出库、退货入库、闲置库存、实拍任务

#### Scenario: 客户跟进排在销售管理最前
- **WHEN** 有「客户跟进」菜单的业务员登录
- **THEN** 「销售管理」第一项为「客户跟进」，之后依次为商机管理、客户管理……

#### Scenario: 业务设置里的通知接收人
- **WHEN** 有「通知接收人」菜单权限的用户登录
- **THEN** 「业务设置」最后一项为「通知接收人」

### Requirement: 菜单命名规则
菜单名称 SHALL 遵循以下规则，新增或调整菜单时逐条对照：

- 一级菜单（分组）统一 4 个字，叫「领域 + 管理」，只有设置类分组（「业务设置」「系统管理」「租户管理」）与只读的「统计分析」例外；「工作台」单独一项，是唯一不足 4 个字的菜单，不再用作其他菜单的名称。
- 二级菜单统一 4 个字，按页面内容归入下列一类：
  - 单据与业务对象：「对象 + 管理」，如收款管理、询盘管理、客户管理；外贸固定说法与已是 4 个字的单据直接用，如形式发票、销售订单、采购订单、运费账单；
  - 库存作业：「业务来源 + 入库或出库」，成对命名，如采购入库、销售出库；
  - 基础资料与设置：「对象 + 管理 / 设置 / 档案 / 库」，如品牌管理、汇率设置、商品档案、供应商库、闲置库存；与上级分组同名时换说法（商品管理下叫「商品档案」，租户管理下叫「租户列表」）；
  - 处理入口：页面上要做分配、录入等操作的岗位入口，用「对象 + 动作」或「我的 + 对象」，如询价分配、我的询价、发货跟踪；
  - 任务：「内容 + 任务」，如资料任务、营销任务、实拍任务；
  - 看板与统计：「对象 + 看板」「对象 + 统计」，如商机统计；岗位看板统一放在「工作台」，不再单独做菜单。
- 统计统一归「统计分析」分组，各业务分组只放业务操作；岗位看板是岗位的待办入口，放在工作台（按角色的工作台模板显示）。看板与统计 SHALL 只读：只展示数字、图表与待办，点击后跳到对应页面处理，页面上不做分配、录入、审批等业务操作；需要操作的页面不能叫看板或统计。
- 页面里对单据本身的称呼（详情标题、按钮说明、提示与报错文字、导出文件名）用单据名称，如「收款单」「PI」「出运单」「采购入库单」，不随菜单名改。
- 改名只改显示的名称，页面访问地址、权限码、单据编号前缀与类型代码不变。

本次改名：素材库 → 素材管理，商机 → 商机管理，客户 → 客户管理，询盘单 → 询盘管理，报价单 → 报价管理，PI → 形式发票，供应商发货 → 发货跟踪，供应商 → 供应商库，出运单 → 出运管理，收款单 → 收款管理，退款单 → 退款管理，结汇单 → 结汇管理，应付单 → 应付管理，付款单 → 付款管理，报销单 → 报销管理，费用单 → 费用管理，商品 → 商品档案，品牌 → 品牌管理，品类 → 品类管理，系列 → 系列管理，汇率 → 汇率设置，用户 → 用户管理，角色 → 角色管理，部门 → 部门管理，岗位 → 岗位管理，菜单 → 菜单管理，字典 → 字典管理，租户 → 租户列表，套餐 → 套餐管理。

#### Scenario: 页面标题与菜单一致
- **WHEN** 财务点击「财务管理 → 收款管理」
- **THEN** 页面标题为「收款管理」，面包屑为「财务管理 / 收款管理」，页面说明与提示文字里对单据的称呼仍为「收款单」

#### Scenario: 看板只读
- **WHEN** 兼职采购在工作台的采购员看板点击一条待处理任务
- **THEN** 跳到「我的询价」中的该任务进行录入，看板本身没有录入或分配的按钮

### Requirement: 调整菜单后权限不变
菜单重新分组或改名 SHALL 不改变任何角色能访问的页面与操作：原来能访问某页面的角色，调整后仍能访问且能在侧边栏看到它；新增的分组自动授给拥有其下任一菜单的角色，并加入包含这些菜单的租户套餐。

#### Scenario: 调整后仍能访问
- **WHEN** 改名前拥有「客户询盘」「报价单」权限的角色登录
- **THEN** 侧边栏「销售管理」下显示询盘单与报价单，打开后与改名前一样可用

### Requirement: 页面标题跟随菜单管理
列表页的标题、面包屑的分组与页面名称、详情页面包屑里返回列表的那一级、工作台的常用入口与「查看更多」链接文字 SHALL 取「菜单管理」里对应菜单的当前名称，不在页面代码里另写一份。在菜单管理里修改菜单或分组名称后，刷新页面即全部生效；详情页自己的标题（单据编号、客户名等）不受影响。

#### Scenario: 在菜单管理改名后页面跟着变
- **WHEN** 管理员在菜单管理把「收款管理」改名为「收款登记」并刷新页面
- **THEN** 侧边栏、浏览器标签、收款页面的标题与面包屑都显示「收款登记」

#### Scenario: 分组改名后面包屑跟着变
- **WHEN** 管理员在菜单管理把分组「财务管理」改名为「财务中心」并刷新页面
- **THEN** 收款页面与收款相关详情页的面包屑第一级显示「财务中心」

#### Scenario: 详情页返回列表的面包屑
- **WHEN** 业务员打开一张报价单详情
- **THEN** 面包屑为「销售管理 / 报价管理 / 报价单号」，点击「报价管理」回到列表

### Requirement: 菜单资源只能由平台维护
菜单与按钮资源是所有租户共用的全局配置。新增、编辑、删除、启用/禁用、调整排序 SHALL 同时满足：能访问菜单管理页面、拥有对应按钮权限（新增菜单、编辑菜单、删除菜单；启停与排序属于编辑），并且是平台账号（`tenant_id = 0`）。不满足时返回 403，数据不变。菜单管理页只对平台账号显示新增、编辑、删除按钮，租户账号只能查看。

#### Scenario: 租户管理员不能改菜单
- **WHEN** 租户管理员所在套餐包含菜单管理及其新增、编辑、删除按钮，直接调用接口修改某个菜单的名称、权限码、状态或排序，或新增、删除菜单
- **THEN** 每个请求都返回 403，菜单数据不变

#### Scenario: 平台账号没有按钮权限
- **WHEN** 平台账号能进入菜单管理页面，但没有「编辑菜单」权限，调用排序接口
- **THEN** 返回 403，排序不变

#### Scenario: 平台管理员照常维护
- **WHEN** 平台超级管理员调整某个菜单的排序
- **THEN** 保存成功

### Requirement: 菜单标签页
从左侧菜单打开的页面 SHALL 以标签页显示在顶栏下方的标签栏里，规则如下：
- 点菜单时，这个菜单还没有标签就新建一个并切过去；已经有标签就直接切过去，标签里当前显示的页面保持不变。同一个菜单只有一个标签。
- 页面内的跳转（列表进详情、点来源单号、点型号进商品档案等）在当前标签内完成，不新开标签。标签名显示当前页面的名称：列表页是菜单名，详情页是页面登记的名称（如单据编号）。
- 切到别的标签再切回来，原页面的筛选条件、页码、滚动位置、表格里已展开的内容和没提交的表单都保持不变，不重新请求数据；标签的右键菜单提供「刷新」，用来重新加载当前页面。
- 首页标签（工作台；没有工作台权限时是菜单里第一个能打开的页面）固定在最左边，不能关闭。其他标签可以用关闭按钮或鼠标中键关闭，右键菜单还提供「关闭其他」「关闭右侧」。
- 关闭有未保存修改的标签时，先按该页面原有的离开提示确认。
- 最多同时开 10 个标签。再开新标签时，自动关掉最久没用的一个；固定标签和有未保存修改的标签不会被自动关掉。
- 浏览器刷新后恢复标签列表和当前标签。当前标签立即加载，其他标签在点开时才加载，原来的筛选和未提交的表单不保留。
- 退出登录或切换账号后清空标签。恢复标签时，当前账号无权访问的菜单对应的标签不再恢复。
- 标签太多放不下时，标签栏可以横向滚动，当前标签自动滚到可见位置。
- 在新窗口打开的链接（如「去商品档案新建」）仍然打开浏览器新窗口，不进标签栏。

#### Scenario: 同时看订单和报价单
- **WHEN** 业务员在「销售订单」标签打开订单 SO20261105003，再点菜单「报价单」，筛选出客户 ACME 的报价单后切回「销售订单」标签
- **THEN** 「销售订单」标签仍显示 SO20261105003，标签名为 SO20261105003；再切到「报价单」标签，ACME 的筛选结果和页码仍在

#### Scenario: 再点已打开的菜单
- **WHEN** 「销售订单」标签当前显示订单详情，用户再点左侧菜单「销售订单」
- **THEN** 切到这个标签，仍显示订单详情，不新开第二个「销售订单」标签

#### Scenario: 超过 10 个标签
- **WHEN** 已开 10 个标签，其中最久没用的是「应付账款」且没有未保存修改，用户再点一个新菜单
- **THEN** 「应付账款」标签被关闭，新菜单的标签打开

#### Scenario: 关闭有未保存修改的标签
- **WHEN** 「报价单」标签里的草稿有未保存修改，用户点这个标签的关闭按钮
- **THEN** 弹出原有的离开提示；选择取消时标签保留，修改不丢失

#### Scenario: 浏览器刷新
- **WHEN** 开着工作台、销售订单、报价单三个标签，当前是报价单，用户按 F5
- **THEN** 三个标签都还在，当前标签仍是报价单；点开销售订单标签时重新加载该页面

### Requirement: 跳转后可返回原页面
在系统内从一个页面跳到另一个页面（点单号、点来源单号、点型号、从工作台或列表进入详情等）后，打开的页面 SHALL 在页面标题上方显示「← 返回 原页面名称」，规则如下：
- 原页面名称取原页面登记的名称，如「返回 销售订单 SO20261105003」；列表页取菜单名，如「返回 报价单」。
- 点返回后，回到当前标签里的上一个页面，上一个页面的筛选、页码、滚动位置保持不变。
- 连续跳转可以一层层返回，例如销售订单 → 形式发票 → 报价单，在报价单点返回回到形式发票，再点返回回到销售订单。
- 从菜单进入、直接在地址栏打开链接、从新窗口打开时没有原页面，不显示返回入口。页面自己原有的「返回列表」类入口统一由这个返回入口取代。
- 返回只在系统内的页面之间进行，不跳到站外地址。
- 新做的页面以及原型，凡是可以跳转到别的页面的地方都 SHALL 遵守这条规则，不另做返回入口。

### Requirement: 来源单号
每张单据的上一张单据 SHALL 统一称为「来源单号」，显示上一张单据的编号，可以点开（按「跳转后可返回原页面」可返回）。上下游关系如下：

| 单据 | 来源单号 |
|---|---|
| 报价单 | 询盘单号（可多个） |
| 形式发票 | 报价单号（可多个） |
| 销售订单 | 形式发票号；售后补发订单为售后单号；费用订单为原订单号；手动创建的订单显示「手动创建」 |
| 采购需求、采购订单 | 销售订单号（采购订单可多个） |
| 供应商发货单 | 采购订单号 |
| 采购入库单 | 供应商发货单号 |
| 暂存记录 | 采购订单号；售后退货为退货入库单号 |
| 销售出库单 | 销售订单号 |
| 拍摄任务 | 采购入库单号 |
| 出运单 | 销售出库单号 |
| 售后单 | 销售订单号 |
| 销售退货单 | 售后单号 |
| 退货入库单 | 销售退货单号 |
| 采购退货单 | 售后退货为退货入库单号；到货差异为采购入库单号 |
| 退款申请 | 由销售退货生成的为销售退货单号，其他为售后单号（订单详情提出的为销售订单号） |
| 应付单 | 采购订单号或运费账单号 |
| 报销明细 | 对应的费用、运费等单据号 |
| 收款记录、多收记录 | 形式发票号或销售订单号 |

询盘单是链路的第一张单据，没有来源单号，原来的「来源」（询盘来源渠道）不变。

显示方式：
- **详情页**：来源单号放在表头的说明行，写作「来源单号 X」。有多个来源时全部列出，用顿号分隔，每个都能点开。
- **列表页**：来源单号单独一列，标题为「来源单号」，不与客户、供应商、订单等信息合并（见「单据页统一显示」）。只有一个来源时显示该单号；有多个时显示「X 等 N 个」，悬停显示全部单号，每个都能点开。
- **型号明细**：报价单、形式发票、销售订单的型号明细不显示来源单号，统一看表头。采购订单、出运单等一张单据的各行本来就来自不同上游单据的，行上保留来源，列名同样叫「来源单号」。
- 指向下游单据的列（如形式发票列表的「销售订单」）、费用分摊列、汇率等的「来源」不属于来源单号，名称不变。

### Requirement: 单据页统一显示
所有业务单据（报价单、形式发票、销售订单、销售退货单、退货入库单、采购退货单、退款申请等，以及以后新增的单据）的列表页与详情页 SHALL 以销售订单为标准，统一以下显示：

- **列表**：第一列为单号（可点开详情，下面一行为单据日期），固定在左侧；客户单独一列（名称 + 新 / 老客户标记、国家 / 地区、主联系人，分三行，缺哪行不显示哪行）；供应商单据的供应商同样单独一列；来源单号单独一列；型号列写作「型号 · 数量」（显示第一个型号，下面一行「共 N 个型号 · M 件 · 查看」）；品牌、品类各一列，按标签列出单据里的全部品牌、品类；最后是创建时间、创建人、更新时间、更新人与操作列「查看」。
- **详情页表头**：标题行为单号与状态标签，操作按钮在右侧；说明行依次为客户（或供应商）、「来源单号 X」、负责人、创建时间，用「·」分隔。
- **详情页明细**：列顺序为序号、品牌、品类、型号；型号单元格为型号（有商品档案且有权限时可点开商品档案）、订货号、「查看素材」三行；之后是该单据自己的数量、金额等列。
- **详情页布局**：宽屏时左侧为基本信息、明细、备注与附件，右侧为关联单据与操作日志；窄屏时上下排列。
- **备注与附件**：每张单据都有备注（选填，最多 500 字，在详情页随时可改，已作废的单据只读）与附件（见 `system/file-attachment`「单据附件与预览」），在详情页的「备注与附件」卡片里查看和维护。

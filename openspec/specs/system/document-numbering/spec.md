# system/document-numbering Specification

## Purpose
全链路单据编号让询盘、报价、PI、订单、发货、发票、装箱单与应收单据使用统一可读的编号，并让任何一张单据都能查到来源与去向，做到全链路可追溯。

## Requirements

### Requirement: 单据编号格式
系统 SHALL 按「前缀 + 类型代码 + 年月日（8 位）+ 当日流水（3 位）」生成单据编号，每个租户、每种单据类型、每天独立流水，从 001 开始，同一天超过 999 时扩为 4 位；编号只含大写字母与数字，生成后不能修改，并发新建不会重复。类型代码：客户询盘 IQ、报价单 QT、PI 为 PI、销售订单 SO、采购单 PO、发货批次 SH、商业发票 CI、装箱单 PL、借项通知单 DN、贷项通知单 CN、对账单 ST。同一发货批次的 CI 与 PL 共用同一个「年月日 + 流水」主体（如 `FWCI20261010001` 与 `FWPL20261010001`）。本次实现报价单、PI、销售订单的编号，其余单据由各自模块按此规则生成。

#### Scenario: 当天第一张 PI
- **WHEN** 前缀为 FW 的租户在 2026-10-06 新建当天第一张 PI
- **THEN** 编号为 FWPI20261006001

#### Scenario: 并发新建
- **WHEN** 两名业务员同时新建 PI
- **THEN** 得到两个不同且连续的编号

### Requirement: 租户单据前缀
系统 SHALL 允许租户在「系统设置」中设置单据前缀：2–4 位大写字母，不能含数字、空格或任何符号，可以为空（需要「系统设置」编辑权限）。前缀只加在对外单据上：报价单、PI、商业发票、装箱单、采购单、借项通知单、贷项通知单、对账单；客户询盘、销售订单、发货批次等内部单据不加。前缀在生成编号时与编号一起保存；修改前缀只影响之后新建的单据，已有单据编号不变（含已有的不带前缀的报价单）。

#### Scenario: 设置前缀
- **WHEN** 管理员把单据前缀设为 FW
- **THEN** 之后新建的报价单编号如 FWQT20261006001、PI 编号如 FWPI20261006001，销售订单仍为 SO20261008001

#### Scenario: 前缀含符号
- **WHEN** 管理员把前缀设为「FW-」
- **THEN** 系统拒绝并提示「单据前缀只能是 2–4 位大写字母」

#### Scenario: 修改前缀不影响旧单
- **WHEN** 前缀由 FW 改为 FOW
- **THEN** 已有的 FWPI20261006001 不变，之后新建的 PI 为 FOWPI…

### Requirement: 全链路追溯
系统 SHALL 在单据行上逐级记录来源行：报价行记录询盘型号，PI 行记录报价行，订单行记录 PI 行（后续采购、发货行记录订单行）。客户询盘、报价单、PI、销售订单的详情 SHALL 展示「来源 / 去向」链路：可从任一单据跳到上游与下游单据，并能查到某一型号从询盘到订单经过的每张单据。按编号搜索时，输入带前缀或不带前缀的编号都能找到。

#### Scenario: 从询盘看到订单
- **WHEN** 业务员打开客户询盘 IQ20261001003，其型号已报价、开 PI 并转成订单
- **THEN** 详情的去向链路显示报价单 FWQT20261005001 → PI FWPI20261006001 → 订单 SO20261008001

#### Scenario: 按客户水单上的编号搜索
- **WHEN** 财务在 PI 列表搜索「PI20261006001」
- **THEN** 能找到 FWPI20261006001

# ERP 审查与整改总入口

`audit/` 统一保存本项目审查发现、后续所有修复任务的进度、验证结果与最终验收。开始或接续整改先读[问题状态台账](09-remediation/issues.md)、关联任务记录和最新源码 / PR，再按[整改流程](09-remediation/README.md)推进；同一任务持续更新同一文件，进度不重复写入 Wiki。

- [问题状态台账](09-remediation/issues.md)：每个永久 ID 的唯一当前状态、负责人和任务记录入口。
- [整改流程与状态门槛](09-remediation/README.md)：认领、协作、验证、合并、发布及关闭要求。
- [修复记录模板与命名](09-remediation/tasks/README.md)：按实际任务建档，可同时关联多个问题 ID。

## 审查基线与阅读边界

以下发现及原专题证据为 **2026-11-01** 审查基线：`docs/erp-audit` / `09da3dc3c790c8c1b729cad8d195a66944d7546e`。原审查只交付 Markdown / CSV，未修产品、升级依赖、改真实业务数据、提交推送、发版或写 Wiki；这些是当次审查记录，不代表后续仓库或整改状态。

三轮审查基线共 **98 个唯一主题**：业务22、前端36、AI可靠性6、身份/对象权限10、运行与迁移7、依赖11、文档与测试保障6；基线优先级为 **P1 31、P2 60、P3 7**。主题含已复现错误、静态确认、条件风险、规范偏差、升级治理与清理候选，**不等于98个已实测业务 BUG**；依赖主题可能包含多个公告或共享 BOM 升级路径，npm107个受影响包记录也不是107个独立漏洞。以上数量保留为历史基线，不随整改状态更新。

前两轮为54+8=62主题；第三轮沿现有主题去重补充，新增主题逐条列于本表。第三轮新增36主题，用5份逐路径台账覆盖全部3315个Git跟踪路径，按path并集核对无遗漏、无多余；正文完整阅读、资源结构审查、历史535份Markdown结构/引用检查分别标注。页面清单含88次组件注册/85个唯一组件入口，主审已在真实BrowserOS＋本机fake API逐注册完成正常渲染，并检查20个重定向；不表示所有页面状态、角色组合、写入或外部接口已验收。

分轮测试数量、环境、证据层级和清理结果见[验证总览](06-verification/00-验证总览.md)。不将重跑或新探针累加成一次全量回归；错误行为见证通过表示观察到缺陷，资源清理也不表示整改完成。后续修复验证独立记入对应任务，不改写旧批次结果。

优先处理跨租户、会话及敏感数据边界（SEC主题、BUS-002、AI-003），角色误写（UI-012/014），再并行修复资金/库存/分配和分页一致性。新增迁移工具缺口须先确认历史执行适用范围；DOC-006是当前规范意图与实现漂移待确认，不能直接据旧条款补造历史财务数据。UI-013不认定权限扩大；tenant0全局字典允许编辑是现行PRD设计，SEC-010仅确认其他非0私有租户对象缺口。

## UI-010｜P2｜菜单标题解析仍按旧 status 规则，和当前侧栏约定冲突

- **证据状态：静态确认 + 两个真实菜单函数的内存 mock 实测。未操作真实菜单或浏览器。**
- **触发：**菜单管理将已有页面或其父分组设 `status=0`，保留 `isHidden=0`；当前账号仍获分配相应菜单。刷新进入该页面。
- **实际：**当前侧栏 `toProLayoutMenu` 按权限与 `isHidden` 渲染，不看 `status`，符合仓库“隐藏菜单用 is_hidden，侧边栏不看 status”的当前约定。页面标题工具 `findMenu` 则仍跳过 `status=0` 节点及其子树。于是同一菜单出现在侧栏中，`MenuName/MenuLink/useMenu` 却拿不到标题/分组，造成标题或面包屑返回链接文本为空。`menuName.test.ts` 仍将停用菜单排除作为断言，单独跑现有测试不能证明两套规则一致。
- **期望：**菜单树可见性与标题查询采用一致且符合当前规范的规则。若未来改变 status 业务含义，前后端和测试必须整体对齐，而非各处各自解释。
- **证据：**[侧栏过滤规则](../../zhul-erp-frontend/src/utils/menuOrder.ts#L66)、[标题查询额外跳过 status=0](../../zhul-erp-frontend/src/utils/menuName.tsx#L39)、[现有旧语义测试](../../zhul-erp-frontend/src/utils/menuName.test.ts#L68)、[菜单管理可切状态](../../zhul-erp-frontend/src/pages/system/menu/index.tsx#L302)、[后端菜单树不按 status 过滤](../../zhul-erp-backend/src/main/java/com/zhul/erp/modules/system/service/impl/MenuServiceImpl.java#L47)、[后端有效菜单键](../../zhul-erp-backend/src/main/java/com/zhul/erp/modules/system/service/impl/MenuServiceImpl.java#L280)、[当前导航约定](../../.claude/context/ui-design-patterns.md#菜单分组与命名2026-10-07-确立2026-10-12-统一修订)。平台管理员的有效资源不受限，构成明确可触发场景；此处不是“停用后权限仍可用”的独立安全结论。
- **影响：**所有采用菜单树取标题/面包屑的页面；停用父分组可能使整组页面失去名称上下文。
- **建议：**共用菜单判定规则，移除不符当前约定的分支，并更新旧测试语义。增加同一树同时经过侧栏和标题函数的一致性用例，覆盖隐藏、停用、父分组和重命名。
- **验收：**`status=0,isHidden=0` 页面在侧栏保留且标题/返回链接名称正确；`isHidden=1` 的行为按约定一致；正常页面无回归。

实测方法：用已有 TypeScript 在内存编译真实 `menuName.tsx`、`menuOrder.ts`，Node VM mock React/Umi/icons 导入；向两个导出函数传同一树（财务分组 + `status=0,isHidden=0` 收款页面）及允许路径。实际 `toProLayoutMenu` 返回包含“收款管理”的子菜单，`findMenu('/finance/receipts')` 返回 `undefined`。没有网络或文件产物。

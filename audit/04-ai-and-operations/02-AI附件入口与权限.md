# AI 通用任务附件入口与权限

基线：`09da3dc3c790c8c1b729cad8d195a66944d7546e`。

## AI-003 · P1 · 普通认证用户可通过通用 AI 入口指定 URL / 本地附件路径

**状态：确认（静态跨服务调用链）；AST 内存 mock 证明不受约束参数到达读取函数。未实际进行内部请求、读取主机附件或调用模型。**

- **成立条件：** 用户有有效登录态，其租户已配置可用 AI；订阅模式仍需满足租户套餐授权等现有校验。目标 URL 要在编排服务运行环境可达，本地路径要在该容器/进程权限下存在且可读。不能据此称为未认证访问，也不能断言可读取宿主机任意文件。
- **触发条件 → 实际 / 期望：** 用户直接调用 `POST /api/v1/ai-tasks`，使用询盘解析 skill 并在 `input.attachments[].url`、`attachmentPaths` 或 `rawAttachmentPath` 放入自选引用。后端透传后，编排服务用 URL 打开或本地文件打开读取；没有要求这些引用来自用户有权访问的业务附件。期望用户只能触发已授权业务动作，附件由后端按当前租户和单据归属签发，不接受任意网络/文件引用。
- **证据链：** [AiTaskController.create](../../zhul-erp-backend/src/main/java/com/zhul/erp/modules/aitask/controller/AiTaskController.java#L41) 无菜单/按钮 `PreAuthorize`；[全局安全](../../zhul-erp-backend/src/main/java/com/zhul/erp/framework/security/SecurityConfig.java#L57) 对该非白名单端点仅要求 authenticated。[CreateAiTaskRequest](../../zhul-erp-backend/src/main/java/com/zhul/erp/modules/aitask/dto/CreateAiTaskRequest.java#L9) 只要求 skillId 非空，input 为 Object 原样透传。[Java 编排请求](../../zhul-erp-backend/src/main/java/com/zhul/erp/modules/aitask/service/impl/AiOrchestratorClientImpl.java#L57) 从 inputJson 构建 input，并由后端附服务间令牌；所以编排服务的共享令牌不能阻止此合法后端转发路径。[process_job](../../scripts/ai-orchestrator/server.py#L536) 从 input 收集上述 refs/paths，仅对本地路径 `isfile`，L557 直接逐个读取。[_read_attachment](../../scripts/ai-orchestrator/server.py#L271) 对 dict 直接 `urllib.request.urlopen(ref['url'], timeout=120)` 并全量 `read()`，对字符串直接 `open(ref,'rb').read()`；无 host/scheme 白名单、允许路径根、重定向目标限制或响应体大小上限。
- **业务影响：** 可绕开业务附件的租户/归属检查，借编排容器发起其网络环境内的请求；可读本地 PDF/图片可能作为解析附件送到所配置的 AI 服务商。URL scheme 未限定，攻击面不仅是 HTTP。全量读取还存在对大响应或大文件的内存/线程消耗风险。此处确认的是读取能力与权限边界缺失，不声称已取得任何真实内部响应、凭据或完整文件。
- **类型检查的实际边界：** [_attachment_data](../../scripts/ai-orchestrator/server.py#L280) 确有图片/PDF 扩展名检查，不能声称“任意格式都必然能成功送入模型”；但读取在类型检查前已发生，URL 扩展名来自请求的 ext。合法可读图片/PDF 可继续进入 [call_parse](../../scripts/ai-orchestrator/server.py#L433) / 模型输入链路。
- **安全内存验证：** AST 只提取生产 `_read_attachment`、`process_job`，将 urlopen、open、isfile、AI 调用及回调全部替换为 fake。输入使用 `.invalid` URL 和虚构 fixture 路径；观察 **2 个 URL（http、file）+ 2 个本地路径** 未被拒绝即到达 mock 读取函数，4 份 fixture 字节到达 mock 解析函数。真实网络、本地附件和 SDK 调用均为 0。该验证证明参数传递/缺少校验，不能替代真实权限与部署可达性验证。
- **修复方向：** 限制/移除联调用通用创建路由，或为其补齐业务权限与结构化输入校验；常规任务只传由后端签发、绑定租户/单据的附件引用，禁止客户端自选本地路径。编排侧仍需 scheme/host/端口/路径根及重定向校验、下载大小上限。正常 [询盘 parseInput](../../zhul-erp-backend/src/main/java/com/zhul/erp/modules/inquiry/customerinquiry/service/impl/CustomerInquiryServiceImpl.java#L645) 本来就会把已归属询盘的附件签发临时链接，且相对链接可补成内部 backendBaseUrl。因此白名单应容纳经过验证的内部后端签名下载地址，不能简单禁止一切内网地址而破坏正常流程。
- **验收方法：** 无 AI 操作权限用户即使租户已配置 AI，通用提交也应拒绝；正常业务用户只能使用其有权单据的附件。用网络/文件 fake 测试非法 scheme、未授权 host、白名单 host 跳转至其他目标、超大响应和路径穿越，在读取前阻断；允许正常内部签名链接，且过期/跨租户附件不能获取。部署验证只用专门的无敏感 fixture 和隔离服务，不访问真实内网资源或凭据。

## 反证与未覆盖

- [AiConfigService.resolveForCurrentTenant](../../zhul-erp-backend/src/main/java/com/zhul/erp/modules/aitask/service/impl/AiConfigServiceImpl.java#L120) 对未配置 AI 或无订阅授权的租户会拒绝；这减少成立范围，没有补上用户业务权限和附件归属校验。

### 本轮新增错误行为的可复核见证

|---|---|---|
| BUS-003 | PI 到账 100，SO-A 退款 60，取消并同 PI 重转 SO-B，再退款 100 | 新可退额度 100；两 SO 有效退款 SQL 合计 **160** |

## AI 真实 SDK / mock 测试

在本机缓存 `zhul-erp-ai-orchestrator:local` 镜像中运行现有 `python -m unittest discover -v`：容器名 `audit-ai-tests`，`--rm --network none --read-only`，只读挂载当前编排源码，`/tmp` 为临时文件系统、HOME 指向临时空目录，不挂载旧AI配置或登录卷。**53/53 测试通过**，包括真实 Anthropic SDK MockTransport 流式协议、图片/PDF转换、进程超时与子进程清理、HTTP服务间鉴权。

首轮唯一失败是测试自建的 fake python 无法在默认 noexec 的 tmpfs 执行，随后 shell 找到了真实 python 导致入口测试等服务超时。只把审计 `/tmp` 标为 exec 后重跑全套通过；没有修改产品逻辑或测试源码。这是环境适配，不应报作产品故障。

额外用实际 `call_parse` 配 fake Anthropic stream：前5次 pause_turn，第6次 end_turn，每次模拟250秒（单次均小于 SDK 的900秒 timeout）；源函数仍成功返回合法结果，总模拟1500秒，超过Java watchdog默认1200秒。实际等待/网络/模型费用均为0。此结果验证“单请求期限不等于整任务期限”的控制流，不声称真实云端已经耗时1500秒；与 AI 可靠性报告的迟到回调风险相关。

# 整改流程与状态门槛

[总入口](../README.md) · [问题状态台账](issues.md) · [任务模板与命名](tasks/README.md)

`audit/` 保存本项目审查及后续所有缺陷修复任务的进度和结果，包括原98项以外的新发现；新功能继续走现有 OpenSpec，不将此处扩展为全项目开发日志。[issues.md](issues.md) 是问题当前状态的唯一台账；原专题保留审查时的发现、条件与证据，[08-coverage](../08-coverage/README.md) 的文件审查状态也不表示问题已修复。任务记录承载过程和证据，不再复制一份当前状态表或另建重复周报。

## 日常使用

1. **核对再认领。** 读最新台账、关联任务、专题及最新源码 / PR，确认已有修复、适用条件和授权范围。多 AI / 多人协作以具体 ID、任务及分支确认关联，不能仅凭同目录或相似标题判断是同一任务。
2. **记录范围与所有权。** 在台账登记负责人、任务文件和更新时间；在任务记录登记实际工作分支、起点 commit、关联 ID 和边界。一个任务可覆盖多个 ID；同文件或同模块写入先明确负责人及分支，避免重复修复、覆盖他人改动。
3. **按现有规范实施。** 提案、UI 原型、分支、测试和发布继续遵循 [AGENTS.md](../../AGENTS.md)、[Git Flow / 版本规范](../../docs/06-部署运维/11-分支与版本规范.md) 和其中引用的 OpenSpec 流程，不在此另造规则。授权记录进度不等于授权自动修复、合并或发布；具体行动按用户委托及既有权限执行。
4. **有证据再更新。** 实施、测试、合并、部署、目标环境验收分别记录。阶段、阻塞或结果发生变化时更新同一任务文件，并回写台账对应行；只做过代码修改、创建 PR 或 PR 已合并都不能直接记为已关闭。
5. **关闭或继续跟进。** 按下表逐 ID 判定。未覆盖的分支、环境、数据修复、回归或验收保持明确待办；失败、回滚或发现复发时重开并保留历史。

编辑共享台账 / 任务前重新读取最新文件，提交保存前核对是否有并发变化；有变化先重读、合并相关行，禁止用旧副本覆盖。接续他人任务注明本轮作者及实测证据，区分“对方报告”与“本轮验证”。

## 状态与证据门槛

| 状态 | 含义与进入条件 |
| --- | --- |
| 待认领 | 尚无已确认负责人；初始化不代表已重新核实当前源码仍有缺陷。 |
| 处理中 | 负责人和任务记录已登记，已确认范围，正在调查、实施或处理测试失败。 |
| 待验证 | 已有可定位的实现 / 文档变更，记录代码版本、待验证场景与未覆盖项；尚不能声称验证通过。 |
| 待合并 | 适用测试和审查已完成，任务中有结果与证据，明确待合并 PR / 分支及目标分支。 |
| 已合并待发布 | 已记录目标分支与 merge commit，待目标版本 / 环境发布；开发分支合并不代表线上生效。 |
| 已发布待验收 | 目标版本 / 环境的部署成功已有证据，待实际验收；合并触发部署不等于部署成功。 |
| 已关闭 | 关联范围已按原问题与修复验收要求验证，适用合并、部署、合回同步及目标环境验收均有证据，并记录验收人和日期。 |
| 暂缓 | 有明确阻塞 / 决策理由、负责人、下一步及恢复条件；不是完成或无风险。 |
| 不适用 | 有版本 / 环境 / 业务条件判定证据、理由及确认人；不得因未复现、未测试或暂不处理直接判为不适用。 |

状态按实际事实推进，不要求为无关步骤走空流程。无需运行发布的纯文档项，可在任务中将部署 / 环境验收注明 `N/A` 及理由，完成适用审查、验证和必要合并后关闭。涉及多个 ID 时逐 ID 记录结果，不能以一个测试通过替全部条目关闭。同一问题复发沿用原 ID，不新建重复主题。重开时更新当前状态，并在原任务事件记录追加原因、日期、作者及后续范围，不删除原关闭与验收历史。

## 证据与验收边界

- 验证记录包含命令或操作、环境、代码 commit / 版本、预期与实际结果，分清通过、失败、跳过和未执行；mock、隔离数据库、真实浏览器及目标环境证据不能相互替代。修复前的缺陷见证通过不能作为修复通过。
- 优先链接持久测试源码、PR、CI 运行和必要的精简证据；临时探针注明内容与清理结果，不保留敏感数据或完整工具日志，也不将审查时已清理的临时文件当成可重跑测试。
- 跨分支修复分别记录落入的分支 / commit 与尚待合入范围。生产修复须按现有规范确认 `main`、`develop` 及适用活动 `release/*` 的合回同步条件；某一分支合并或上线不能代替其他必要分支同步。最终关闭还需目标环境功能 / 权限 / 数据边界验收及明确剩余范围；需历史数据修复时先确认适用范围和授权。
- 新发现先核对是否属于已有 ID；独立问题按对应类别下一个未使用编号追加永久 ID、专题证据与台账行，不重排、不复用旧 ID。合并治理路径可共用任务文件，保留各 ID 的判断与结果。

## 实施与验证结果

- **UI-044**：预览原来按 96 dpi、质量 0.7 渲染整页 A4，不裁边，放大后模糊、下方大片空白；PDF 保持 A4 页面，内容少时同样大片空白。UI-042 当时只改了图片导出。现在：
  - 预览按 200 dpi、质量 0.85 渲染，按图片导出同一规则裁边（四周留 2%，最后一页隔着大片空白的页码行去掉）；各页左右取同一边界，放大查看时每页缩放比例一致。
  - 报价单、PI 的 PDF 改为裁到正文（用户 2026-11-09 确认接受非 A4 尺寸）。新建原点为 (0,0) 的页面，把原页面作为矢量表单平移贴入，文字仍可选中；不直接改页面框，因为 macOS 预览不认原点非零的页面框（实测内容错位）。报关、物流单证和模板预览仍用标准纸张。
  - 位置：`DocumentConverter.toTrimmedPdf()`、`alignedBoxes()`、`contentBox()`、`renderPages()`；`QuotationDocumentServiceImpl`、`PiDocumentServiceImpl` 的 PDF 导出。
- **UI-045**：销售订单列表的第一个型号设了不换行但没有截断，超长时溢出盖住品牌列；询盘列表的型号格同样如此。出运、入库、出库、退货列表的「型号 × 数量」行没有截断，没有空格的长型号也会溢出。现在统一用 `EllipsisText` 单行省略，截断时悬停显示全文（与 UI-041 规范一致）。

## 第 7 条反馈的判断（未登记新 ID）

用户反馈「客户跟进、商机成交、S1 新商机数据不正确，跟进或延后后不更新」。核对代码：

- 「商机成交」卡片大数字是客户数，阶段数字是单据数，口径不同，所以对不上。
- 阶段数字统计还在该阶段的单据；跟进与延后只改下一步日期、不改阶段（`FollowupService.record()`、`snooze()`），所以阶段数字本来就不变。
- 跟进与延后会正确改写下一步日期，节奏刷新不覆盖业务员定的日期（`FollowupSync.refreshCadence()` 只处理来源为系统的）；但同一客户有几十张单据时，跟进一张只少一条待办，看起来像没变化。

用户确认这几项随第 5、6 条「按客户分组跟进」一起重新设计口径，不单独修复。

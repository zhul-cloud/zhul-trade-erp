# 修复记录模板与命名

[整改流程](../README.md) · [问题状态台账](../issues.md)

按实际修复任务创建 `YYYY-MM-DD-主ID-短英文.md`，例如 `2026-11-01-UI-001-upload-race.md`。不要预建所有 ID 的空文件。一个任务可覆盖多个 ID；台账的相关行指向同一记录。调查、实施、验证、合并、部署及返工持续更新同一文件，不再按天复制任务或新增同用途周报。任务记录保留过程与结果，问题的唯一当前状态维护在 [issues.md](../issues.md)。

下方模板按实际需要填写；未执行 / 未确定应明写，`N/A` 附理由。链接使用相对路径或可长期访问的 PR / CI 地址，避免只在执行者机器上可用的临时路径。

| 命令 / 操作与证据 | 环境、commit / 版本 | 预期 | 实际 | 结论 |
| --- | --- | --- | --- | --- |
| <持久测试源码、CI 或操作证据链接> | <mock / 隔离库 / 浏览器 / 目标环境及版本> | <预期行为> | <实际观察> | <通过 / 失败 / 跳过 / 未执行；原因> |

失败与未覆盖场景单列说明；不要只写“测试通过”。临时探针记录方法与清理结果，持久回归优先落入正常测试源码。仅保存必要、脱敏的证据，避免凭据、真实敏感业务数据、完整工具日志和无用途的大体积输出。

| <关联 ID> | <原触发、拒绝 / 正常对照、回归范围> | <部署版本 / 环境、操作或 CI 链接；N/A 写理由> | <确认人及日期> | <按证据逐 ID 判定；未覆盖项> |

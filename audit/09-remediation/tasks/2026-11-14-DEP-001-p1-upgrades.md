## 原因与实施

- **DEP-001 POI**：5.2.5 → 5.5.1（5.x 当前稳定版；6.0.0 是大版本，不跨）。传递依赖随之升级：xmlbeans 5.3.0、commons-compress 1.28.0、commons-io 2.21.0、commons-collections4 4.5.0。commons-codec、log4j-api 仍由 Boot 3.2.5 管理（1.16.1、2.21.1），逐个核对 POI 5.5.1 字节码里调用的 codec / log4j 方法在这两个版本都存在（codec 只用 `DigestUtils.md5(byte[])`）。5.5.1 读到同名条目重复的 OOXML 抛 `InvalidZipException`（IOException 子类），询价结果导入与模版上传原有处理都能接住。
- **DEP-002 Tomcat**：用 `tomcat.version` 把 Boot 3.2.5 自带的 10.1.20 覆盖为 10.1.61（core / el / websocket 一起）；Boot 整体升级（DEP-007）时删除这一覆盖。10.1.42 起 multipart 默认最多 50 个分段、每段头部 512 字节；在真实内嵌 Tomcat 上实测 512 字节放不下约 130 个汉字以上的文件名（旧版不限制，属于升级回归），新增 `TomcatMultipartConfig` 把每段头部放宽到 2048 字节（Windows 文件名上限 255 个字符全中文约 765 字节）；分段数沿用默认 50（单次最多导入 20 个文件）。
- **DEP-003 axios**：业务代码和 Umi 的 `request`（`.umi/plugin-request` 生成代码按 `require.resolve('axios')` 引用）都用同一份 axios。改为项目直接依赖 `^1.21.1`，并用 `overrides: { axios: "$axios" }` 让 `@umijs/plugins` 也用这一份；锁文件里只剩一份 axios 1.21.1，不再是开发依赖。核对 0.x → 1.x 的行为差异：查询参数里 null / undefined 都不发送、数组与普通值解码后一致，只有对象参数拼法不同；用 TypeScript 类型检查器扫描全部 `params`，没有对象字段（3 处声明为 `object` 的下载函数实际只传数字和字符串）。请求拦截器展开请求头、401 刷新后重放的写法在 1.x 下可用。
- **BUS-037（审查外新发现）**：询价结果导入 `parseInto` 只接 IOException。文件是 zip 但内容损坏（工作簿 XML 不合法）时 POI 抛 `POIXMLException`（运行时异常），整批预览直接返回「系统错误」，同批正常文件也看不到结果。改为同时接 POI 的格式类异常（`POIXMLException`、`OpenXML4JRuntimeException`、`UnsupportedFileFormatException`、`EmptyFileException`），只拒绝这一份文件。

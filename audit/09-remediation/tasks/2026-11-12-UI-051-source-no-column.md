## 实施

用户确认：退款的来源单号取退款申请、销售订单另列；出运单的来源单号取所装销售出库单、销售订单另列。

| 页面 | 原来 | 现在 |
| --- | --- | --- |
| 售后管理 `sales/after-sales/index.tsx` | 「客户 · 来源单号」 | 「客户」（`CustomerCell`）；「来源单号」= 销售订单，放在负责人前，没有订单显示「—」 |
| 退款管理 `finance/refunds/index.tsx` | 「订单 · 客户」 | 「客户」；「销售订单」（不挂订单照旧显示）；「来源单号」= 退款申请，点开申请详情，余额提现与历史迁移的没有申请显示「—」 |
| 发货跟踪 `logistics/shipments/index.tsx` | 「来源单号 · 订单」（N 张销售出库单 + 订单号） | 「销售订单」（`SourceNos` 多个显示「A 等 N 个」）；「来源单号」= 销售出库单，放在业务员前，点开出库列表按单号筛好 |
| 采购入库·发货单 `warehouse/receipts/index.tsx` | 「采购订单 · 采购对象」 | 「采购对象」；「来源单号」= 采购订单，放在采购员前，点开采购订单详情 |
| 采购入库·入库 | 「采购订单 · 采购对象」 | 「采购订单」（可点开）、「采购对象」两列；原有「来源单号」（发货单）不变 |

后端 `LogisticsVO` 增加 `outboundNos`，`LogisticsShipmentService` 列表组装时填入，不增加查询。

顺带修复：背调前检查（#269）与批次 M（#270，UI-022「不用只绑点击的 `<a>`」）先后合入 develop，背调卡片的「展开 / 收起」和检查清单的「去补充」两处 `<a onClick>` 让 develop 上的 `src/actionLinks.test.ts` 失败；改为 `<button type="button" className="zhul-link">`。

## 设计原则与流程

本节是所有界面工作的总纲，优先于后文的具体规格；后文与本节冲突时，按本节修正后文。

### 原则

0. **用户体验和观感优先。** 每个设计决定先问：第一眼观感如何、阅读顺序与使用习惯是否顺、日常高频使用是否省力。对比度、令牌、实现便利是约束，不是出发点；冲突时列出取舍请用户定。
0b. **不迎合，求最优。** 收到「不好看」「不立体」之类的反馈，先找根因（多半在令牌、公共组件或通用规则），再对照参考设计（至少三家，优先官方设计系统的令牌与规范，如 Ant Design、Atlassian、GitHub Primer、Material 3）定方案并写明依据；用户或评审的具体说法与最佳实践冲突时直接指出，不照做也不顺着改。对比图里标出推荐项和理由。
1. **先给答案，再给操作。** 每页第一眼是用户来这一页要找的东西（列表看数据、详情看状态和金额、工作台看要处理的事），筛选和设置往后放。
2. **一屏一个视觉重点。** 每个页头、弹窗、分区最多一个实底主按钮、一个最大的数字；看板要有主角卡或明确的第一眼区域，不让每张卡分量相同。
3. **颜色只表达「能点」和「要注意」。** 主题色给主操作和选中状态，语义色给流程状态与告警，其余用中性灰；属性和分类一律中性。
4. **层级不超过三层。** 页面底、浮起卡、卡内凹格（中性浅底、无边框无阴影）；卡里不套带阴影或描边的卡；一组可以各自点进去的数字不再外包卡片，标题直接落在页面底上。
5. **对齐出秩序。** 文字左对齐，数字右对齐，同一列小数点对齐，卡片内边距与表格首列对齐；同一行的卡片等高，或组合后等高（一张高卡对两张叠放的矮卡），不用瀑布流。
6. **阅读从左上开始。** 卡片的类别图标、名称放左上，数值紧随其下；不把识别信息放到右侧末尾。
7. **数字要精确、可比、带币种。** 等宽数字、千分位、两位小数、币种代码；同一列同一币种时币种写在表头（整表同币种可写在卡片标题旁），单元格只写数字。
8. **紧凑的表格，宽松的卡片。** 表格内部讲密度（见「圆角、间距、尺寸」的行高），卡片外部留白。
9. **已生效的条件永远看得见。** 筛选、排序、视图状态都在界面上显示，能单独清除、能一键重置。
10. **主操作始终触手可及。** 长详情页页头吸顶，长表格表头吸顶、横向滚动条吸附视口底部，批量操作随勾选出现。
11. **每个数据视图都有六种状态。** 首次加载、重新查询、空、无结果、错误、无权限，各自单独设计（见「说明文字」）。
12. **反馈及时，并且能挽回。** 成功用轻提示，失败就地说明原因和改法；能撤销的给撤销，不能撤销的提前写明。
13. **说人话，少说话。** 不写常识性说明，不把字段名、枚举值、技术编码展示给用户，口径放帮助图标；删减后看不懂，说明布局要重新设计。
14. **深色不是浅色反过来。** 层级越高表面越亮，用边框代替阴影，大块彩色浅底在深色下单独核对。
15. **以真实环境验收。** 以 Windows 浏览器 1366×768 和 1440×900、浅深两色、默认琥珀加一种冷色主题为准，不以原型渲染为准（中文字重、滚动条、截断只在真实环境里出现）。

### 流程（新做或改动任何界面）

1. **定页面类型**：列表、详情、表单弹窗还是看板，套用对应骨架和公共组件。
2. **先找公共组件**：通用写法用 `src/components` 里的公共组件；没有而又会在多处出现的，先抽成公共组件再用，并在 `lint:ui` 加规则防止各页回到各写一份。
3. **广泛参考，总结成自己的**：在 `design-references.md` 的参考里找同类做法，至少对照三家，取共性、写明为什么这样选；不照搬一家，也不只看用户点名的那一个。
4. **把反馈当成一类问题**：用户或评审指出一处，先在全站找出同类问题一起处理，并把结论补成本文的通用规则，不只修被点到的那一处。
5. **补依据**：业务字段、状态、关键词范围、统计口径、帮助文字只取自代码或用户，先补到依据表（`status-colors.md`、`search-scope.md`、`stat-cards.md`、`help-texts.md`）。
6. **画原型**：用 OpenPencil，按真实内容区宽度（带侧栏）、真实状态和数据画，浅深两色都画；要表达悬停、展开、空、告警等状态。
7. **设计评审**：交 UI 设计师角色代理评审，第一标准是体验观感、阅读顺序与使用习惯；代理的建议同样要用这些标准去质疑，不照单全收。
8. **对标验收**：和标杆（如 Vuetify 商店 `store.vuetifyjs.com` 的商业模板、Materio、Vuexy、shadcn）并排截图，按 `design-references.md` 的对标检查表逐条判定，达标后再交用户确认；视觉取舍先出对比图（切换主题色与深浅）给用户选。
9. **实现与复审**：用户确认原型后才写页面；写完交独立审核者复审，并在 Windows 浏览器按检查表实测。
10. **存放**：原型存到 `docs/03-产品原型/{域}/`，界面改造相关的放 `界面改造/`。

## 设计令牌

### 主题模式与主题色

- **模式**：跟随系统、浅色、深色三选一；没有选过时按浅色显示。每人的选择保存在本机浏览器。

### 层级与表面

层级不超过三层（原则 4），三层的明暗必须拉开、顺序固定（2026-11-24 确立并落地，D38；起因是采购需求分组卡的表头和页面底色融成一片）。色值见上表：浅色页面 `#F4F6F8` → 表头 `#F9FAFB`、凹格 `#F7F8FA` → 白卡；页面上次要文字 `#637381` 对比度 4.51。

| 层 | 用在 | 规则 |
|---|---|---|
| 页面底（最深） | 内容区背景、标题与页签直接落在上面 | 比卡内任何浅灰都深；页面上的次要文字对比度不低于 4.5:1 |
| 卡内浅灰（居中） | 表头、凹格、分组头、行悬停 | 介于页面底与白卡之间：**不得等于或深于页面底**，否则贴到卡边时像卡片破了洞、露出页面 |
| 白卡（最亮） | 卡片、侧栏、顶栏、弹出层 | 浅色不加边框，靠阴影和与页面底的明暗差分开 |

- 直接放在页面底上的控件（分段控件的轨道、页面级标签条）用比页面底深一档的灰，不用页面底色本身。
- 小控件不受「比页面浅」限制：状态标签、快捷筛选、图标底圆、细进度条用中性标签灰 `neutralSoft`（比页面深）可以；但卡内成块的格子（风险格、凹格、分组块）一律用 `inset`。
- 分组卡片（如采购需求按订单）：每组一张与主卡同级的白卡，浮在页面底上；卡头白底加分隔线，表格收进卡内四周留 16，表头与主列表同一种浅灰圆角条（D39）；不在白卡里再套描边小卡。
- 新加底色先对照这三层，不新造介于其间又贴近页面底的灰；需要强调的分组用语义浅底，不用更深的灰。
- **主题色浅底只表示「选中、当前」**（2026-11-24 用户确认，D42）：选中的行、选项、快捷筛选，已选 N 项的批量操作条，当前菜单、当前步骤，搜索命中，头像，返回条；另有两处固定例外：漏斗终点的图标块（D41），工作台数字卡与通知类型的图标块按色族着色（D1–D3）。状态标签 `Pill` 只有 `tone="selected"` 用主题色浅底；旧的 `tone="accent"` 已按 status-colors.md 并入信息色，新写的属性标签用 `gray`。说明文字用公共 `Callout`（中性浅底、左侧图标；需要用户处理的提示 `tone="action"`，图标用主题色），数字、汇总块（合计、应付、摘要）用卡内凹格 `inset`，属性胶囊（步骤号、类别、档位）用中性 `neutralSoft`。奶油色在白卡上对比度只有约 1.05，拿来做内容块既显平，又会被看成「被选中」。lint:ui `primary-soft` 检查写死的 `background: …primarySoft`，选中类用法写例外。
- **一组数字各自成卡时**（如销售统计漏斗，D41、对比图 R9）：标题落在页面底上，每个数字一张白卡浮在页面上，靠图标、数字大小、比例条区分，不靠每项一个颜色；同一个量在先后环节的递减（漏斗）只用主题色深浅：终点用图表色 `palette.chart`，其余步骤用它的浅色 `palette.chartSoft`（2026-11-24 更正：原为中性灰，与「只分两类时优先主题色」冲突）。放不下一排时按行均分（`useBalancedCols`，与 `MetricGrid` 同一算法），每行等宽、比例条可跨行比较，每行第一张不画箭头。不在一张白卡里铺一排同色色块。
- **先分清是「量」还是「类别」再决定配不配色**（2026-11-24 更正，R11）：同一个量的大小、递减（漏斗、比例条、热力）不按项分色，否则会被误读成不同类别；不同的类别、阶段、指标家族（跟进板块、工作台指标）要有固定颜色做小面积识别，只用在图标块（浅底 + 原色图标），卡片、数字、文字仍中性。一组卡片全灰会像未加载或禁用，没有专业感。D41 的「不靠每项一个颜色」只适用于前一种。
- **组件一律跟主题色，只有多色组件例外**（2026-11-24 用户指出，对照优秀模板：除了需要多色的组件，其他组件都跟主题色）：按钮、开关、进度条、完整度、步骤条、选中态、链接都用主题色（填充类用图表色 `palette.chart`，它就是主题色在图表里的版本）；只有本身要区分多个类别或状态的组件用多色——图表系列、状态标签（成功、警告、错误）、类别图标块（跟进板块、工作台指标家族）、密码强度这类状态条。**进度条、完整度只用主题色一种颜色，程度用深浅表示（越完整越实），完成或达标时也不换成绿色**；lint:ui `progress-color` 检查写死的 `strokeColor`，确属状态的写例外。不要为了对比度把进度条改成固定的蓝、绿：浅主题色对比度不足时靠旁边的数字补足（与 `chartPrimary` 的约定一致）。
- **同一内容只分两类时优先用主题色深浅**（2026-11-24 用户提出、评估采纳）：两类没有好坏之分时（本期 / 往期、漏斗终点 / 其余、已到账 / 待到账、线上 / 线下），一类用主题色（填充 `palette.chart`），另一类用它的浅色 `palette.chartSoft`，不用灰、也不用另一种色相。边界：两类里有一类代表风险（逾期、缺货、亏损）时，那一类仍用状态色，颜色在传达「要处理」。三类及以上的类别（货物 6 段、跟进板块）才用图表系列色或类别色。数字卡的中性（灰）家族图标块像禁用，改用主题色。
- **流程链路（第 1 步 → 第 n 步）**用公共 `FlowStrip`（客户跟进、供应链跟进，D46、对比图 R10）：白卡等宽排一行，放不下按行均分，不横向滚动；步骤卡的图标块按步骤用固定色（图表系列色前五个，不随主题色变，R11 方案 B），卡片、数字、阶段标签中性，入口卡（今日待办）图标块中性；当前查看的卡主题色内描边；回环说明写在标题行右侧，不画进度轨道。卡片最小宽度按最长名称算，名称不截断。
- `Callout` 只放在白卡、弹窗里；直接落在页面底上的提示（如客户详情「在公海」）改白底，否则中性浅底和页面底几乎同色。
- 卡里的记录列表（收款记录、按付款方式等）用小标题 + 分隔线列出，每条两行（名称、状态在左，金额右对齐；日期、方式、操作人在第二行），不套描边小卡；卡头已有的状态，进度条里不再重复（R8-2）。
- 详情页头一律用公共 `PageHeader` 直接放在页面上，不包卡（商品详情也是，R8-4）；标题字段可能为空时给回退值（商品：展示型号 → 原始型号）。只读、被引用这类正常状态用页头右侧中性胶囊加帮助图标，不用整条警告；警告条只留给需要处理的问题。
- 主从两栏（如字典管理，R8-1）：左栏一行只放名称（单行 36 高、超长省略）；编辑、删除收进行尾「…」（`RowActions` 的 more），悬停、选中或键盘聚焦时出现，不能做的项置灰写原因；分组标题带数量；新增用描边图标按钮，整页只留右侧一个主按钮；进入页面默认选中第一项。
- 依据：Ant Design 令牌页面 `colorBgLayout #f5f5f5`、卡片 `colorBgContainer #ffffff`、表头 `headerBg #fafafa`（卡内灰比页面浅）；GitHub Primer、Atlassian 是页面白、卡内灰深一档的另一种做法，两种都不会出现「卡内灰比页面深」。
- 深色按「越高越亮」：页面最暗，卡片、卡内浅灰依次变亮。

**状态色**（2026-11-24 用户看过对比图 R18 决定，D53）：原色成功 `#22C55E`、警告 `#FFAB00`、信息 `#00B8D9`、错误 `#FF5630`、中性 `#637381`（深色 `#A0A0A0`），用于标签底、进度条、圆点、角标、图标底块。**写成文字时（标签字、红绿金额、逾期提醒）也直接用原色**，浅色、深色相同（深色错误字为 `#FF6A47`）；中性标签字 `#56636F`。更正原因：之前为了对比度用参考模板的 dark 档（`#118D57`、`#B71D18`、`#006C9C`），单看清楚，但一页里几处一起出现就发沉、压抑，用户看过对比图后接受原色的低对比度（绿 2.3:1、红 3.2:1、信息 2.4:1）。因此状态色文字只用于加粗的短标签、金额和带说明的提醒，不靠颜色单独传达意思；长句提示用正文色加图标。**橙是例外**：原色 `#FFAB00` 与琥珀主题的链接色 `#FDA92D` 几乎同色，提醒文字会被当成链接，文字保留 `#B76E00`，标签底仍用原色浅底（对比图 R19，用户选 B）。同理，绿、红、信息的原色和当前主题链接色色相相差不到 20° 时（红主题的错误红、青绿与天蓝主题的信息蓝），该主题下文字改用深一档（`#B71D18`、`#006C9C`），由 `buildPalette` 自动判断（2026-11-24 独立审核发现）。状态标签为「浅底 + 文字色」，浅底为原色 16% 叠在卡片上（浅色、深色相同）。正文、表头等深灰文字仍不低于 4.5:1。各状态归哪种语义色，以 `status-colors.md` 为准。

**图表系列色**（2026-11-24 改为参考模板原色，对比图 R14）：浅色 `#1877F2` 蓝、`#FF5630` 橙红、`#00B8D9` 青、`#8E33FF` 紫、`#22C55E` 绿、`#919EAB` 中性灰；深色另配同色相的一组 `#1877F2`、`#E5482A`、`#00A3C2`、`#8E33FF`、`#1EAE53`、`#919EAB`（`seriesFor(mode)`）。顺序和两组颜色都经 dataviz 调色板校验（色盲可分、饱和度、正常视力相邻可分全部通过）；原来为了深浅底都 ≥3:1 压成的中间调（`#2F9E99`、`#B87A14`、`#2E9A62`）饱和度不足、相邻难分，显得发暗，已弃用。原色对白底不到 3:1 的（青、绿）旁边都要有文字、图例或悬停数值。主题色作为第一个系列时，去掉色相最接近的一个（`chartDrop` 为序号）：琥珀、红去橙红，青绿去青，天蓝、宝蓝去蓝，紫去紫。第一个系列取 `palette.chart`（`chartSeries()` 的第一个），跟主题色走：浅色为原色，深色为深色链接色。琥珀原色在白底只有 1.93:1，是用户看过对比图后选定的例外（2026-11-22），用到它的图表都要在旁边或悬停提示里写数值。数字卡色族（蓝、紫、青）同样用这几个原色，浅底 16%。

**图表只亮一处**：一张图里只有要看的那一处（本期、最终结果）用 `palette.chart`；往期柱、漏斗的中间级用它的浅色 `palette.chartSoft`（浅色 32%、深色 40%），不用灰（2026-11-24 更正：灰色让图表显得没生气，两类内容优先用主题色深浅区分）。排行占比条是单一数量，整条用 `palette.chart`。数值靠坐标网格、重点柱顶数值、悬停提示和读屏文字传达，不靠颜色。需要区分多个系列时才用上面的图表系列色。

**涨跌与盈亏**：按方向着色，上涨与盈利同色、下跌与亏损同色；变化配上下箭头，盈亏不配。每人在主题设置里选「涨红跌绿」（默认，排在前面）或「涨绿跌红」。逾期、低于红线、不良等告警始终为错误色，不受这个设置影响。

### 字体与字号

- 中文用系统字体；英文和数字用 Public Sans（作为前端依赖打包）；型号用等宽字体。表格里的数字、金额、汇率、数量用等宽数字（`font-variant-numeric: tabular-nums`）并右对齐。
- **字阶**只用 12（辅助）、13（表格副行、标签、表头）、14（正文、表格主行）、16（卡片标题）、20（页面标题）、24（数字卡数值），看板主角数字可用 28；相邻层级至少差 2px 或一档颜色。页面标题 20/600，卡片标题 16/600，数字卡数值 24/600。
- **字重**：中文只用 400 和 600（Windows 上中文落到微软雅黑，只有 400/700 两档可见，500 会显示成常规、600 显示成粗体）；拉丁字母和数字可用 400/500/600。层次优先靠字号和颜色，不靠中文 500。
- 菜单 16px/400，行高 40；页签 14，撑满顶栏 64 高、文字垂直居中，选中用主题色字加底线区分。

### 圆角、间距、尺寸

- 圆角：按钮、输入框、对话框 8；卡片 10；状态标签 4；快捷筛选、提示胶囊为全圆角。
- **间距刻度**只用 4、8、12、16、20、24、28、32。外边距 16：侧栏、顶栏、内容区之间都是 16；卡片内边距 20–24，卡片间距 16；落在页面底上的分组之间 24–28，比卡片间距大一档，否则分组和卡片分不开。
- **尺寸**：按钮高 36，输入框高 40。表格：表头 48（13 号次要色），单行 48，两行内容（如「单号 · 日期」）60–64。验收标准：列表在 1440×900 首屏至少 8 行、1366×768 至少 5 行。

### 焦点框

- 浅色：2px 主题色描边，外侧再加 2px `#637381`（对白底 4.88:1）。单靠主题色不满足焦点指示 3:1 的要求，琥珀只有 1.93:1。
- 深色：2px 深色链接色。
- 以上只用于按钮、链接、开关、页签等按 Tab 才出现的键盘焦点。
- 输入框、下拉、日期等输入类控件鼠标点进去就会获得焦点，用轻的写法：边框换主题色（深色用链接色），外加 3px 主题色 28% 光晕，不加灰圈。插入光标本身也指示焦点。
- 带图标或清除按钮的输入框只在外框画，里面的输入区不画，否则会出现框中框。

## 颜色怎么用

- **颜色只表达功能。** 底色、卡片、边框、普通文字只用中性灰阶。彩色只用于五类：
  1. 主题色：主操作、选中状态、独立的文字链接。表格里的单号、来源单号默认用墨色 600，悬停时主题色加下划线（表格外的单号用 `zhul-link-doc`，同样墨色）；「查看」这类行内文字链接悬停才着色——表格里的主题色面积越小，警告色越醒目。墨色只用于导航类链接；表格里的动作不用墨色文字：放进 `RowActions`，确需文字的（如「去下单 →」）加 `zhul-link-action` 保持链接色；
  2. 状态与提醒：状态标签、标红标橙的提醒、警告条、校验错误、危险操作；
  3. 图表系列；
  4. 默认 Logo；
  5. 工作台与统计里区分各项的图标底块。
- **图标底块**：色 12%（深色 16%）浅底配同色图标。数字卡按指标的含义分家族取色，同一家族在所有看板里同色：蓝（成交、销售）、紫 `#8B5CF6`（利润，只用于此）、青（收款）、中性（支出、应付）；不用主题色（6 种主题色里有 4 种会和家族色或状态色撞色），不用成功绿（默认涨红跌绿，绿色会被读成下跌）。待处理类数量用信息色。错误、警告色只在该项处于告警时使用，数量为 0 时用中性色。
- **属性与状态分开**：彩色标签只表达流程状态和告警；属性、分类（如现货 / 期货、客户类型）一律中性标签；每行彩色标签不超过 2 个。
- **主题色实底上的文字**（主按钮、Logo 首字、实底标记、选中的步骤圆点、勾选框的勾）一律用 `palette.onPrimary`：白字对主题色不足 3:1 时取同色相最深一档（琥珀为深琥珀棕 `#4A2E00`，6.5:1；D54，对比图 R17。不用偏蓝的近黑 `#212B36`，压在暖色上像黑字），其余主题色为白。不在主题色底上写死白色。
- **不用渐变和发光**（用户上传的 Logo 图片除外）。
- **警告不用纯文字**：琥珀主题下，纯文字的警告色和链接色分不开。凡是提醒（如「未指定」「1 个型号未指定」「还有型号没下采购订单」）都做成带图标的浅底标签；纯文字的主题色只留给可点击的内容。备注这类不是提醒的信息，用中性浅底加消息图标。

## 页面外壳

- **侧栏**：悬浮白卡片，宽 244，内边距 14。顶部是 Logo（主题色实底方块加白色首字）和系统名（主题色 20/700）。
  - 菜单项高 40、圆角 8，图标 20。图标统一用 lucide 线性图标（线宽 2，与参考站的 mdi outline 同类），「菜单管理」里存的 antd 图标名由 `src/utils/menuOrder.ts` 的对照表换成 lucide；对照表里没有的名称才退回 antd 图标。新增菜单图标时在对照表里补一行。
  - 展开的父级：中性浅底，主题色字。
  - 选中的子项：主题色浅底、主题色字，前面一个实心小圆点；未选中的子项是空心小圆点。
- **侧栏顶部**：Logo 左侧与菜单图标列对齐；右边两行是站点名和公司名（12px 次要灰，外观全平台统一，公司名是唯一能看出当前所在公司的地方），过长单行省略、悬停看全文；最右是收起按钮（`panel-left-close`）。
- **收起侧栏**（照参考站，2026-11-21 用户要求）：64 宽图标栏，只有 Logo、一条分隔线和各菜单组图标（20），当前所在的菜单组为主题色浅底，栏里不放按钮。鼠标移上去或键盘聚焦到侧栏时，整个侧栏以浮层展开（带文字和分组，内容区不移动），Logo 右侧为「固定展开」按钮（`panel-left-open`）；移开或焦点离开后收回。固定展开后按钮为「收起」（`panel-left-close`）。
- **顶栏**：悬浮白卡片，高 64。左侧是标签页栏：页签撑满顶栏高度、文字垂直居中，选中为主题色字加底部 2px 主题色线；首页标签带 `house` 图标、不可关闭；关闭按钮图标 14、可点区域 24；未保存的标签在名称后带一个正文色小圆点。标签放不下时超出部分截断，末尾「全部标签」按钮显示没露出来的数量（如「+4」），下拉列出全部标签，头部写「已打开 N / 10，再打开会关掉最久没用的标签」。
- **顶栏右侧**依次为主题设置、语言、通知、头像，都是只有图标的按钮，有 `aria-label` 并悬停显示名称：
  - 主题设置：`swatch-book` 图标（不用明暗图标），点开弹出层，含模式（跟随系统 / 浅色 / 深色，分段选择）、6 种主题色（圆形色块，选中带对勾和外圈）、涨跌颜色（涨红跌绿在左、为默认；选中靠单选圆点，卡片用中性边框）。三项都保存在本机浏览器，选中统一用主题色表示。
  - 语言：下拉列出各语言名称，不用国旗；当前语言为主题色浅底加对勾。
  - 通知：角标为未处理待办加未读知会，12px，错误色底白字。
  - 头像：主题色浅底加首字；菜单打开时外加 2px 主题色圈。菜单头部为姓名、角色标签（管理员 / 成员）、公司名，下面是「退出登录」（点后弹原有确认框）。侧栏底部不再放用户卡。
- **跳到主要内容**：按 Tab 时第一个出现在页面左上角，主文字色，焦点框照「焦点框」。
- 页脚不变。
- **返回条**：标签页里栈中多于一页时，内容区顶部显示主题色浅底胶囊「← 返回 上一页标题」。
- **不显示面包屑**。页面名称跟随菜单管理（`src/utils/menuName.tsx`）。

## 说明文字

- **按场合放置，不按字数一刀切**：
  - 随输入变化的结果（如「本次到账后结清」「多收 …，将记为预收」）直接显示在字段下方；
  - 提交前必须知道的不可撤销信息（如「到账记录保存后不能修改」）放在提交按钮旁；
  - 口径、匹配规则等背景知识放进帮助图标。
- **输入框提示**只放最常用的至多三项（如「订单编号、客户、型号」），完整范围放进标签旁的帮助图标。关键词搜索的完整范围以 `search-scope.md` 为准。
- **不写常识性说明**：如「点击进入对应列表」「保存后生效」「点击可跳转」。可点的数字和链接带右箭头或主题色，已经说明能点。
- **确认弹窗和警告条的文字原样保留**，只换样式和位置。
- **数据视图的六种状态**（公共组件 `EmptyState` 等统一实现）：
  - 首次加载：骨架屏，延迟 300ms 出现，形状与真实行一致，加载中不显示「共 0 条」；
  - 重新查询（翻页、筛选）：保留旧数据，顶部 2px 进度条；
  - 空（首次使用）：说明原因或下一步，有可做的操作时给一个按钮；
  - 无结果（筛选后）：写「没有符合条件的…」并给「清空筛选」；
  - 错误：说明原因加「重试」，保留已填的条件；
  - 无权限：锁形图标，写明需要的权限，不能显示成空。
  地方小就只用一行文字，不在卡片里再套框。
- 各页帮助图标里写什么，以 `help-texts.md` 为准；改到某页时先补表，再画原型、写代码。

## 列表页统一规范

**骨架**（自上而下）：页头（标题 + 主操作）→ 汇总行 → 搜索条件区（一行）→ 主内容区（操作行含快捷筛选）。表格之上的部分越矮越好，首屏要能看到足够多的行（见「圆角、间距、尺寸」的验收标准）。公共组件在 `src/components/ListLayout/`：`FilterCard`、`FilterField`、`MainCard`，以及 `PageHeader`、`SummaryBar`、`QuickFilters`、`HelpTip`。

- **汇总行**：页头下方一行指标，每项是「名称 + 数字」，可带一行副文字。口径从名称看不出的，名称旁加帮助图标。宽度不够时副文字整段隐藏（不截断、不换行），只有页面别处也能看到的副文字才能这样隐藏。
- **搜索条件区**：一行。常用条件的名称放在输入框内作前缀（如「订单状态 全部 ▾」），关键词占两格，其后是状态与页面自己的常用筛选项；其余收进「更多筛选」（按钮显示生效数量）。「更多筛选」收起时，里面已生效的条件以可删除的胶囊显示在快捷筛选位置（如「品牌：西门子 ×」）。「更多筛选」为主题色文字按钮，「重置」为中性描边，「查询」为主按钮。名称作前缀后，文本框的提示不再重复名称、不写「全部」（`FilterField` 自动去掉），只写名称以外的说明（搜索范围、格式示例）；关键词的帮助图标在框内右侧。
- **状态一律放在搜索条件区的下拉里**：选项后带数量（如「待打包 · 2」，为 0 时只写名称；「全部」不是状态，不带数量），切换立即查询。页签式的分组（如收款管理）保留。
- **其他条件点「查询」才生效**，关键词输入框回车也查询。例外：商品档案以查找型号为主，沿用输入即搜（防抖）和选了就生效，「查询」按钮不等防抖立即按当前关键词查。
- **统计卡片的去向**：
  - 状态类：数字并入状态下拉；
  - 条件类：转快捷筛选，前提是接口已有对应筛选；
  - 指标类：转汇总行。

  各页的归类以 `stat-cards.md` 为准。
- **主内容区**：一张卡片，依次是操作行、表格、分页。
  - 操作行：左侧为结果数，勾选后变为「已选 N 张 · 取消选择」，勾满一页时提示可「选择全部 N 张」；快捷筛选放在结果数右侧同一行；右侧为批量操作。
  - 操作行最右侧是「列」按钮（列设置，`useColumnSettings`，D55）。
  - 表格超宽时在卡片内横向滚动：首列（单号）固定在左，操作列固定在右。

**通用规则**：
1. **默认按更新时间倒序**（`update_time DESC`）。例外：有人工排序字段的页面（菜单树、商品分类、职位、按字母序的品牌 / 系列）保留原排序；客户管理按经营等级 S→C、再按潜力评级降序（2026-11-04 确认）；销售订单按销售日期倒序、同一天新建的在前（2026-11-17 确认）。
2. **「创建」「更新」两列默认收进列设置，必须能打开**（2026-11-24 更正，对比图 R15 方案 B，D55）：每列两行，人名在上、短时间在下（当年写「11-21 10:20」，跨年写「2025-11-21」），悬停显示完整时间；顺序固定，紧邻业务字段之后、操作列之前。系统写入的显示「系统」，不显示账号或邮箱。
   更正原因：原规则「固定显示」加上单据页的品牌、品类、来源单号等列，34 个列表里有 26 个在 1366 宽下要横向滚动（最宽 2556px），挤出屏幕的反而是状态、金额这些要看的列。现在列表默认只显示做判断和操作需要的列（身份、状态、金额、进度、操作），其余列（含创建、更新）放进工具栏右侧的「列」按钮，用户勾选显示、拖动排序、可恢复默认，按登录用户、按页面记在本机。参照 Linear、Notion、Odoo、NetSuite。
   - 用法：`const cols = useColumnSettings('页面标识', columns, { hidden: ['品牌', '品类', …] })`，表格用 `cols.columns`、`tableScrollX(cols.columns)`，按钮 `cols.settings` 传给 `MainCard` 的 `settings`。`hidden` 写列名或列标识；「创建」「更新」总是默认收起，不用写。固定在左右两侧的列（单号、操作）始终显示，不进设置。
   - 默认显示的列加起来不超过 1043px（1366 宽屏幕上的表格区），每个页面新增或改列后在 1366 宽下量一遍，不横向滚动。
   - lint:ui `column-settings` 把关：页面用了 `auditColumns` / `proAuditColumns` 就必须接 `useColumnSettings`。
3. **完整时间格式** `yyyy-MM-dd HH:mm:ss`（悬停、详情页、导出用）：前端用 `src/utils/format.ts` 的 `formatDateTime()`，ProTable 的 `valueType: 'dateTime'` 默认格式已符合；后端 VO 直接暴露 `LocalDateTime`。
4. **记住每页条数**：用 `src/utils/pageSize.ts` 的 `usePageSize(默认值)` 或 `usePagination(默认值)`，按页面路径存在本地；同页多个分页表格传第二个参数区分。
5. **1366×768 下正常显示**（audit UI-041），不要求手机：
   - 表格用 `scroll={{ x: tableScrollX(columns) }}`（`src/utils/tableScroll.ts`），不写死总宽，不用 `'max-content'`；
   - 每列都写 `width`；长文本单行省略并悬停显示全文（`ellipsisRender` / `EllipsisText`），确实需要两行显示的（如简介）用两行省略并带 `title`；
   - 金额、数量不折行，表头不换行；人名、日期、品牌品类这类短文本在窄列里也不能折行；
   - 单元格最多两行（主信息 14 号一行 + 次要信息 12 号一行，行高 60–64，D21）：多条内容只显示第一条，第二行「等 N 个 / 张」悬停看全部（同来源单号）；明细件数等放悬停卡（如销售订单「货物」：进度条＋已出运/总件数，下面一行提醒，2026-11-24 用户选定）；
   - 页面的主列表表格用默认尺寸，不写 `size="middle"` / `"small"`（中号的上下 12、左右 8，行高规则不生效）；中号只给详情明细、弹窗和卡片里不分页的汇总表；
   - 内容再长也不折行：第一行、第二行都单行省略并悬停看全文（如采购需求描述列的 `DescRemarkCell`：描述一行、「备注：…」一行）；
   - 单元格里的提醒用 12 号文字，可带图标，不用 24 高的标签：逾期、超时用错误色（`status-colors.md`「逾期 错误」），其他需要留意的（还有型号没下采购订单）用警告色；类型、新老客户等属性写成次要色文字，不用标签；
   - 包住表格的网格用 `minmax(0, 1fr)`，弹性子项设 `minWidth: 0`。
6. **例外页面**：登录日志、操作日志等审计日志页不适用（只按操作时间倒序）；纯占位页面不适用。库存查询、库存流水、库存台账也不适用（2026-11-21，inventory-foundation）：库存查询与台账是按商品 × 仓库、按月汇总的数，没有单行的创建 / 更新人；库存流水只增不改，显示「发生时间」倒序加操作人。三页默认排序分别为最近变动倒序、发生时间倒序、按商品。

后端的 `createBy` / `updateBy` 来自各表的 `create_by` / `update_by`（自动填充，见 `.claude/rules/coding.md`「建表规范」），VO 补齐即可。

| 组件 | 属性 | 说明 |
|---|---|---|
| `PageHeader` | `title`、`tags`、`sub`、`extra` | 页头：左侧标题（20/600，`h1`），右侧操作；每个页头最多一个主按钮，其余用文字按钮或收进「更多」菜单。列表页不传 `title`，取当前页面的菜单名称；详情页 `title` 为单号，`tags` 放状态标签，`sub` 为下一行副信息（客户 · 来源单号 · 负责人 · 创建时间） |
| `SummaryBar` | `items: SummaryItem[]` | 汇总行。每项 `label`、`value`；金额传 `currency`，按 `formatAmount` 显示；口径写 `help`；副文字写 `sub`，只有页面别处也能看到的副文字才设 `subHideable`（宽度不够时整段隐藏） |
| `FilterCard` | `onSearch`、`onReset`、`more`、`moreCount`、`quick`、`layout` | 搜索条件区，默认一行（`layout="line"`）：常用项写在 children，按钮固定在第一行右侧，窄屏时只有条件换行；其余放 `more`（「更多筛选」展开），`moreCount` 为其中生效的条件数；`quick` 只为还没迁的页面保留，新页面把快捷筛选放主卡操作行。条件多、需要名称在上逐项说明的统计页用 `layout="grid"` |
| `FilterField` | `label`、`span`、`help` | 搜索条件的一项。一行模式下名称自动放进输入框作前缀（穿过 `Form.Item` 找到 antd 的 Select、Input、InputNumber、DatePicker、RangePicker、Cascader、TreeSelect；其他控件名称放在框左侧）；控件自带前缀（关键词的搜索图标）时不放名称，帮助图标放框右侧。关键词 `span={2}`（220–360），日期范围至少 300（去掉日历图标，两个日期不截断），其余 140–220，统计期间这类组合控件 `span="auto"` 按内容宽度；放得下就排一行（弹性布局按最小宽度排，余量均分），1366 宽下常用的 4 个条件也排一行（视口不到 1400 时「更多筛选」只显示图标和生效数量）；仍放不下时次要条件收进 `more`。完整搜索范围写在 `help`（以 `search-scope.md` 为准） |
| `QuickFilters` | `options`、`value`、`onChange`、`label` | 快捷筛选，多选，点一下选中、再点取消；前提是接口已有对应筛选。数量写在选项的 `count`（名称后等宽加粗，不写「·」），需要处理的数量（逾期、缺货）加 `danger`，不为 0 时用错误色；各页不再自己拼「名称 · 数量」 |
| `MainCard` | `left`、`right`、`quick`、`chips` | 主内容区：操作行（左侧结果数或「已选 N 张」，后面是快捷筛选 `quick`（不写「快捷筛选」字样）与已生效条件胶囊：「更多筛选」收起时，`FilterCard` 自动把里面已生效的条件（表单字段或受控控件的值，下拉显示选项名称、日期按天）做成「品牌：西门子 ×」交给同一页的主卡，点 × 去掉条件并重新查询，页面不用另写；不在「更多筛选」里的条件（如从别的页面带来的「只看某商品」）用 `chips`（`{ key, label, onRemove }`）自己传；右侧批量操作）+ 表格 |
| `Section` | `title`、`help`、`meta`、`extra`、`id` | 详情页分区：卡片标题 18/500，`meta` 为标题旁的计数（如「4 个型号 · 23 件」），`id` 加在标题上用于页内定位 |
| `CardTitle` | `children` | 自己画卡片头部时用的标题（18/500，同 `Section`）；旧的通用 `Card`（`crm/opportunity/components`）外观已与 `Panel` 一致 |
| `HelpTip` | `title`、`label` | 帮助图标，只在鼠标悬停时显示；`title` 不是纯文字时写 `label` 给读屏。表单项用 `Form.Item` 的 `tooltip={{ title, icon: <Info size={14} /> }}`，图标与 `HelpTip` 一致 |
| `Panel` | `style`、`as` | 卡片外框（圆角 10，浅色阴影、深色边框），以上组件都用它 |

「更多筛选」收起时只隐藏、不卸载里面的条件；条件值仍建议受控，方便「重置」一起清空。

状态下拉沿用 `doc-list-unify` 的写法：放在 `FilterCard` 里，选项带数量（如「待打包 · 2」），切换立即查询。

### 通用组件

各页都会用到的写法统一用下面的公共组件，不在页面里各写一份（ui-redesign C1–C8）：

| 用途 | 组件 | 用法 |
|---|---|---|
| 分页 | `usePagination(20, scope, total)`（`src/utils/pageSize.ts`） | `pagination={pager}`。下拉显示「每页 20 条」，与页码同高 32；默认 20 条、记住个人选择；页码有省略号时才显示跳页；传 `total` 时不超过 10 条不显示分页。总数传 `MainCard` 的 `count`（单位 `unit`，默认「条」；`loading`），加载中为 0 或还没有总数时组件自己不显示，页面不拼「共 N 条」；不传 `showTotal`；ProTable 默认会显示「第 1-20 条/总共 N 条」，要关掉。没有主卡的子表、主卡左上角另有用途的页面才自己写总数 |
| 国家 | `CountryText`、`CountryFlag`（`src/components/CountryText`） | `<CountryText value={r.country} />`：国旗 + 中文名，悬停英文名；`value` 为保存的英文名，也认两位代码和中文名。国旗图片由 `config/config.ts` 的 `copy` 复制到 `/flags/` 再用 `<img>` 加载：SVG 不能经 CSS 或 `import` 引用，打包器会把它转成 React 组件 |
| 客户名下一行 | `CustomerCell`、`CustomerSubLine`（`src/components/DocFields`） | 列表的客户列和详情客户卡共用「新 / 老客户 · 国旗 国家 · 主联系人」；客户名单行省略、悬停看全名 |
| 空状态 | `EmptyState`（`kind`：`empty`、`noResult`、`error`、`forbidden`；`compact`）、`listEmpty()` | 表格、下拉没写空状态时全站自动用它（`AppTheme` 的 `renderEmpty`）。列表页至少用 `locale={{ emptyText: tableEmpty('没有符合条件的订单，换个筛选条件试试', loading) }}`（加载中不显示；一句话按「，」「；」拆成标题与说明，提到筛选、条件的为无结果）；能区分出错、有没有筛选的页面用 `listEmpty({ loading, error, filtered, onRetry, onClear, noun, empty })`：加载中不显示、出错给「重试」、有筛选给「清空筛选」、否则写首次为空的原因和下一步。只有出错时读屏播报 |
| 操作列 | `RowActions`、`rowActionsWidth(n)`（`src/components/RowActions`） | `inline` 最多 2 个常用图标（32，间距 8），本行不适用的写假值留出空位；其余放 `more`、点击走 `onMore(key)`，危险项自动排到末尾，不能做的项写 `disabledReason`（菜单里置灰并写原因）。列宽用 `rowActionsWidth(图标位数)`（「更多」算一位，3 位为 136），计入 `tableScrollX`；操作列里的点击不会触发行点击。例外：审批、审核、工作队列（退款审批的通过/驳回、商品资料采纳/改选/忽略、待审品牌、客户跟进）每行一个主要动作，保留文字按钮；要显示进度的长操作（生成凭证）保留按钮 |
| 危险确认 | `useConfirmDanger()`（`src/components/ConfirmDanger`） | `confirm({ title, content, okText, cancelText, width, onOk })`：标题是写明对象的问句（「删除客户「ABC」？」，不写「确认删除」「确认要…吗」），内容只写后果，按钮写动作（默认「删除」，不加「确认」），需要劝阻时取消写「再想想」或「留下」，默认焦点在「取消」；放弃未保存修改也用它；左侧 40 圆错误浅底图标，删除为垃圾桶、其余为警告三角。危险实底按钮深色下用深色字（亮红底上白字只有 2.7:1） |

## 单据页统一规范

所有业务单据（询盘、报价、形式发票、销售订单、各类退货单、入库单、退款申请，以及以后新增的单据）的列表与详情**以销售订单为标准**（`src/pages/sales/orders/index.tsx`、`detail.tsx`，原型 `docs/03-产品原型/界面改造/` 的 A、B 组）。主规范见 `openspec/specs/system/navigation`「单据页统一显示」。

**列表**：骨架见「列表页统一规范」。列顺序按「先给答案」排：身份 → 当前状态 → 金额 → 进度 → 明细 → 次要信息（2026-11-24 用户选定方案 B，D40；1366×768 下不横向滚动就能看到状态、金额与进度）：
1. 单号 · 日期：单号链到详情，下面一行单据日期，现货 / 期货等属性接在日期后（「2026-11-18 · 现货」，不单占一列），固定在左；需要的标签（如「费用订单」）放单号下面。
2. 对方：客户单独一列（`CustomerCell`：名称一行，下面一行「新 / 老客户 · 国家 / 地区 · 主联系人」，都是文字，不用标签）。供应商单据的「供应商 / 采购对象」、费用类的「收款方」同样单独一列。
3. 当前状态：订单状态、PI 状态、「状态 · 发货进度」等。
4. 金额：合计、未付等单据最关键的金额，按「金额显示规范」，右对齐。
5. 进度：收款进度、收款状态、付款、货物、有效期、预计发货日期、下一期到期等。
6. 明细：型号 · 数量（第一个型号，等宽、单行省略，下面一行「共 N 个型号 · M 件 · 查看」；单据自己没有专门弹窗时用 `ModelQtyCell`），然后品牌、品类各一列（`TagList`：纯文字，前两个用「、」连接，其余收成「+N」，悬停看全部）。
7. 次要信息：毛利、砍价、开票、付款条件、运单号、币种等。毛利等盈亏按涨跌颜色。
8. 来源单号：单独一列（`SourceNos mode="cell"`）。
9. 负责人，然后是「创建」「更新」两列（`auditColumns()`），最后是操作列。默认只显示 1–5 和操作列（以销售订单为准：单号、客户、状态、合计、收款、货物、操作），6–9 默认收进列设置（D55）。操作列固定在右，用 `RowActions`（图标 size 32、图标 18，悬停显示名称）。

**详情页**：
- **页头**：标题行为单号加状态标签（20–22/600），操作按钮在右。
  - 一个主按钮，常用的次要操作用文字按钮，低频操作和危险操作收进「更多」菜单。从左到右依次为文字按钮、「更多」、主按钮（主按钮在最右，照原型 B1；`MoreActions` 不排序，危险项写在菜单最后）。
  - 说明行依次为客户（或供应商）、来源单号（`SourceNos mode="inline"`）、负责人、创建时间，用「·」分隔。
  - 用 `usePageTitle` 登记单号。
- **布局**：
  - 宽屏时上方分两栏：左侧为基本信息、进度与关联单据（来源 / 去向）；右侧宽 340，为收付款与毛利等财务汇总。两栏高度尽量相近。
  - 下方通栏依次放明细、金额与条款、费用、备注与附件、成本等宽内容。
  - 窄屏时上下排列。
- **信息卡**：客户、订单信息、买方、收货人等用 tonal 信息卡，排成 2×2。
- **明细**：
  - 列顺序为序号、品牌、品类（`docBrandColumns`）、型号（`DocModelCell`：型号可点开商品档案、订货号、查看素材）、描述（定宽，过长折行）、该单据自己的数量与金额列。
  - 需要横向滚动时，勾选列到型号列固定在左，状态或进度列固定在右，列顺序不变。
  - 型号以真实型号为准：和客户型号不同时，下面一行灰色小字「客户型号：…」；已发出的单据提示「真实型号已更新为 …」，报价单、形式发票用带图标的警告标签，采购订单用错误标签。
  - 型号备注：中性浅底标签加消息图标、修改人与时间，可编辑时有铅笔；没有备注时显示「+ 备注」。
- **备注与附件**：每张单据都有备注（最多 500 字）和附件，放在「附件与备注」卡片里，已作废的单据只读。附件用 `src/components/DocFiles/`，可预览、可下载。
- **独立详情页**：每张单据都是「表头 + 明细」，都有独立详情页（`/xxx/:id`），不用列表抽屉代替。

## 表单弹窗结构

参考站 Dialog 组件：宽 600（双栏字段多时用 640，沿用旧规范），圆角 8，三层深阴影，遮罩为墨色 50%（深色为近黑）。

- **结构**：
  - 标题行：18/500，右侧关闭图标；
  - 内容区：内边距 20–24；
  - 页脚：左侧可放提交前必须知道的说明，右侧依次为「取消」（次要灰文字按钮）和提交（主按钮）。
- **字段**：标签在上，不用浮动标签。
  - 同一行最多两个等宽字段（间距 16）。短字段并排；长字段和需要注意力的字段独占一行。
  - 必填红星在标签前。
  - 随输入变化的反馈直接显示在对应字段下方；跟某一行有关的警告跨两栏放在那一行下方，文字原样。
- **分组**：字段多、分属不同主题时按业务属性分组，组标题 14/600。字段不多时不加组标题，按逻辑顺序排列。
- **开关字段**：放在所属分组末尾，单独一行，标签在左、开关在右。
- **复杂新建流程**：字段超过约 6 个、或分属不同主题时，用分步向导，不做长弹窗。

## 交互模式

- **分步向导**：复杂的新建流程（字段超过约 6 个、或分属不同主题）不做长弹窗。整页无侧栏，顶部步骤条，右侧实时预览，底部固定操作栏；每步用人话提一个问题；必填步骤尽量少，其余都可跳过；能创建的时点越早越好，退出不丢内容。
- **详情页原地编辑**：卡片原地编辑、独立保存；有未保存修改时底部浮出保存条，并用 `useTabDirty` 登记。
- **完整度与待补清单**：用分段进度条（一段对应一个模块）表示还差多少，下方列出可点击的待补项和预计用时；列表里用小进度条和缺项快捷筛选。
- **危险操作**：二次确认，写明后果，并提供更温和的替代（如「改为停用」）。

## 工作台

- **页头**：问候语；一人有多个看板时，右侧是分段切换。
- **布局**：按行排，12 栏栅格，同一行组件间距 16、行与行间距 24（标题离上一张卡 24、离自己的卡 12，看得出标题属于哪张卡），同一行卡片等高；不用瀑布流（参差不齐，体验差）。
  - 每个组件在注册表登记高度档（含标题）：S 180（卡片 144，等于一排数字卡）、M 340（卡片 304，等于两排数字卡）、L 500，内容按档位设计：数字卡组 S 一排、M 两排；列表 M 档 5 行、每行 52；图表撑满卡片。卡片里不滚动，超出条数时标题右侧给「查看全部（N）」。
  - 实现：`src/pages/dashboard/layout.ts` 的 `LAYOUT` 登记每个组件占几栏（`span`）和高度档（`tier`），`layoutRows` 按模板顺序装行：放不下或高度档不同就换行（同档才配成一行），一行没占满时最后一个组件补满整行（落单的改为整行宽版）。没登记的整行组件占 12 栏、半行占 6 栏。组件顺序在模板（`workbench_template`）里改，前端不另排序。
  - **同一行组件的标题位置一致**：标题一律放在卡片外的页面底上（标题 24 + 间距 12 + 卡片），白卡组件和透明数字卡组都这样，所以同一行的卡片从同一条线开始、到同一条线结束。不允许同一行里有的标题在卡外、有的在卡内，那样底边对齐也会看着一高一矮。
  - 档位固定，骨架屏、出错和正常状态同高，加载完成、刷新都不改变布局：骨架只画两行，出错用一行的空状态加「重试」；数字卡组每排张数固定，放不下（每张不到 150）才减少，卡宽不到 180 时用紧凑版（内边距 16、图标块 32、名称 13，卡高不变）。视口小于 1200（内容区约 900）时改为单列，高度随内容。
  - 标题行固定 24 高、不折行，右侧说明太长时单行省略、悬停看全文。
  - 白卡里混排数字与列表、图表时，数字用卡内凹格（中性浅底、无边框无阴影、圆角 8、数值 20/600），不套描边小卡；只有数字的组件自动按数字卡组显示。卡里的表格不套描边框，用行间分隔线、行高 46。
  - 要处理的事排在最前面（如业务员看板第一行是待办和过期未收款），结果和进行中的往后。
- **卡片标题行右侧的链接**（「经营统计」「查看全部 N」）：`MoreLink`，平时次要色，悬停才用链接色，不和主按钮抢主题色。
- **待办的颜色**：后端给的 tone 是语义名，前端按原型 D1 换成底块色（`BlockWidget.tsx` 的 `todoTone`）：blue（待确认的询盘、待下单的需求）为信息色，violet（订单待出运、待供应商发货）为固定蓝（图表系列色第一个，不随主题色变），不告警的 orange（PI 待收款）为主题色，red、告警的 orange 为错误、警告色且数量为 0 时为中性。每个指标的图标和家族色由后端随指标下发（同待办的 icon 与 tone），前端不按名称查表。
- **列表行**（如「我的待办」）：照参考站列表，无底色、行间分隔线。左侧是 38 尺寸、圆角 8 的彩色图标底块，中间是名称和说明，右侧是数量和右箭头。需要提醒的项数量大于 0 时，数字用该项的颜色。
- **指标**用「数字卡」公共组件（见「组件标准」）；一组数字卡不外包卡片，标题行直接落在页面底上。
- **风险类组件**用 2×2 小格（图标、名称、数量），全为 0 时数量为灰色、标题旁绿点「全部正常 · 截至 时:分」，有风险时该格为状态浅底、左侧 3px 色条、彩色数量和箭头，标题旁红点「N 项需要处理」，位置不变（`widgets/boss.tsx` 的 `RiskAlertsWidget`）。
- **主角卡**（老板看板第一行，D28）：28/600 大数字、涨跌胶囊、近 12 个月柱图（虚线网格与纵轴刻度，只亮本月、柱顶写数值，往期浅灰，0 画 2px 短柱）、底部一句结论；经营概览在同一看板有主角卡时不重复显示成交额。
- **漏斗**：每级两行（名称、数量与「→ 比例」，下面 8 高细条），只有最后一级用图表色；比例超过 100% 不显示；底部一句结论。
- **排行**：列表而不是表格；头像（业务员首字、客户圆形国旗）、名称、对第一名的 4 高占比条，右侧金额与第二个数。

## 金额显示规范

- 所有金额显示为「币种代码 + 空格 + 金额」：两位小数、千分位，如 `CNY 4,120.00`、`USD -12.30`；空值显示「—」。不用 `¥`、`$` 等符号。
- 前端统一用 `src/utils/format.ts` 的 `formatAmount(value, currency)`，不要在页面里自己拼字符串或用 `toLocaleString`；表格里的金额右对齐、等宽数字。
- 金额输入框用币种代码做前缀（如 `InputNumber` 的 `prefix="USD"`），表头写成「单价（CNY）」这类带币种的名称。
- 同一列、同一张表都是同一币种时，单元格只写数字（`formatMoney`），币种写在表头；整张表都是同一币种、列又多时写在卡片标题旁「金额单位 CNY」（如订单成本明细）。每格都带「CNY 」既占宽、窄列还会折行（S12、P5）。
- 例外：对外单据与文字报价的币种写法以单据模版为准。

## 汇总数字按算式排（2026-11-21 确立，首版落地于库存月结）

几个汇总数字之间有加减关系（期初 → 期末、应收 → 余额这类）时，按算式排，让人一眼能对上：

- 主行只放算式里的数，按顺序排，卡片之间标 `+` `−` `=`（列表页把符号写进表头，如「+ 本月入库」「− 本月出库」「= 期末库存金额」）；结果放最后、字重最重。
- 每一项的口径必须和算式一致，不能把不进算式的部分混进来（如「本月成本调整」只取调到库存金额的部分，叫「在库成本调整」）。改完用真实数据核一遍主行能不能算平。
- 不进算式、但值得看的数（销售成本、单据合计及其分项）放主行下面一行小字作参考；列表页放在算式列之后，用次要文字色。
- 同一组数字在列表、详情、确认弹窗里用同一套排法和名称。参考原型：`docs/03-产品原型/03-业务域/28-库存三期-成本与月结/` 的 P1、P1b、P2。

## 标签页与返回

- 从菜单打开的页面各占一个标签（`src/components/PageTabs/`），同一菜单只有一个标签；页面内跳转在当前标签里入栈，返回出栈。首页标签固定；最多 10 个标签，超出时自动关闭最久没用的，固定标签和有未保存修改的除外。
- 返回入口由框架的返回条统一提供（栈里多于一页时显示「← 返回 上一页标题」）。页面不再自己写「返回」按钮，链接地址不带 `from` / `fromLabel`；错误页、空状态里的「返回列表」可以保留。
- 详情页用 `usePageTitle(完整标题, 标签短名)` 登记，例：`usePageTitle(`销售订单 ${o.soNo}`, o.soNo)`；没登记时用菜单名或「菜单名详情」。
- 有未保存修改的页面用 `useTabDirty(dirty)`，返回、关闭标签前确认；不要用 `history.block`。
- 隐藏标签里的页面不卸载：定时轮询用 `useTabActive()` 在页面不可见时暂停；全局事件只对可见元素生效。
- 浏览器后退按浏览器记录走，可能跨标签；手册里引导用户用返回条。

## 可访问性与规范补充

- **对比度**：正文不低于 4.5:1，大字（≥24px，或 ≥18.66px 加粗）不低于 3:1；靠边界识别的控件，边界不低于 3:1。浅色下主题原色作按钮和链接的偏低值，是照参考站的已知取舍（见「主题模式与主题色」）。
- **禁用与只读**：禁用、停用的行不用透明度变淡，状态靠文字或标签表达。只读保持正常文字色并加锁形图标；禁用才降低对比度。置灰按钮的原因外包一层可聚焦的元素再挂提示（antd `Tooltip` 包 `span`），键盘用户也能读到（来自复审建议）。
- **焦点**：所有可交互元素都有可见焦点（见「焦点框」）。帮助图标只在鼠标悬停时显示，按用户决定豁免这一条。Tab 顺序与视觉顺序一致；固定的顶栏、保存条、浮层不能遮住获得焦点的元素；每页提供「跳到主要内容」链接。
- **交互目标**：不小于 24×24px，相邻目标间距不小于 8px。拖拽排序要有「上移 / 下移」替代。
- **动效**：悬停 150ms、展开收起 200ms、弹窗 250ms，只用位移和透明度；遵守 `prefers-reduced-motion`。
- **表单**：失焦时校验，错误显示在字段下方，并说明原因和改法；提交后有两个及以上错误时，页顶显示可聚焦的错误汇总。
- **数据表格**：可排序的列显示排序图标并带 `aria-sort`；表头吸顶；行首复选框选中后出现批量操作（不含批量删除）；被截断的文字悬停显示全文；每页超过 50 行做虚拟滚动。
- **数据视图**：要有加载（骨架屏）、空、无结果、失败（原因加重试）四种状态。
- **响应式**：最低按 1366×768 验收，不要求手机。断点 1440 / 1280 / 1024：1024 以下侧栏收成 64px 图标栏；内容区最宽 1600，超宽居中。

## 消费级质感

- **层次与留白**：见「设计原则」第 2、4、8 条；标题、数字与正文之间字号落差明显；少用分隔线和边框，靠底色差和柔和阴影分层。
- **状态齐全**：可交互元素有默认、悬停、按下、聚焦、禁用；数据视图有加载、空、错误。原型里至少画出空状态和一个悬停或聚焦状态。
- **即时反馈**：操作成功用 Toast 或行内提示，不弹窗告知；输入实时校验；危险操作二次确认并写明后果。
- **文案说人话**：站在用户视角，错误信息说明怎么办；不把字段名、枚举值、技术编码直接展示给用户。
- **效率**：Esc 关闭；回车提交，到账这类不可撤销的记录除外（来自复审建议）；常用操作不超过两次点击；记住上次的筛选条件和每页条数。
- **评审**：按「设计原则与流程」的第 7–9 步：UI 设计师评审、对标检查表验收、独立审核者复审；可用 Impeccable critique（Operate 模式）辅助，只采纳对实际操作有好处的建议，不为分数牺牲体验。

## OpenPencil 作图注意

- **工具**：所有 UI 设计和原型都用 OpenPencil。pencil MCP 连不上时用 `op` 命令行；命令行也不可用时，请用户解决工具问题，不能跳过原型直接写页面。原型经用户确认后才开发。
- **以脚本和 PNG 为准**：
  - 原型由脚本生成。`.op` 存盘再打开会走样（根画板高度、底色、排版），不能当源文件改。
  - 界面改造的原型改 `docs/03-产品原型/界面改造/生成脚本/` 里的脚本，再运行 `python build.py`：它清空画布、跑全部脚本、还原颜色、导出 PNG、保存、校验颜色并停止服务，任何一步失败都会停下，不删旧图。
- **自动改色**：OpenPencil 会把低对比度的文字和图标自动改成近黑 `#17191D`。节点要写 `name: 'fill=<色值>'`，生成后用 `fixfill.py` 还原，再用 `checkop.py` 校验。
- **图标对齐**：和中文并排的图标外包一层高 s+2、底对齐的框，视觉上下移约 1px。
- **其他要点**：
  - 不用 `rgba()` 做纯色填充和文字色，换算成等效 hex；
  - `layout: none` 的根节点只渲染第一个子节点，悬停、弹窗等状态单独画一张；
  - 脚本模式出错不会提示：脚本外包一层 try/catch，出错时插入一个名为 `SCRIPT-ERROR` 的文本节点，跑完检查它；
  - 只加 `--file`、不起无界面服务时能写文件，但导出的 PNG 是空白，导出前先 `op start --headless --file <.op 绝对路径>`；
  - 画板高度先量实际内容再定，不要估算。
- **无界面服务用完要停**：`op start --headless` 会一直挂着，导出保存后执行 `op stop`。

## 复用方式

新页面设计按「设计原则与流程」一节的流程执行。

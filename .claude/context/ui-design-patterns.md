# 前端 UI 设计规范（业务后台页面）

## 状态：已确认（首版落地于用户管理页，2026-08-27）

来源：`docs/03-产品原型/00-用户域/用户管理.op`（可编辑设计稿）及同目录下的
`用户管理-列表页.png`、`用户管理-新增弹窗.png`（效果参考图）。新建后台管理页面
（客户、订单、供应商、商品……）时，优先复用本文档定义的结构和 Design Token，
保持全站视觉统一，减少重复设计决策。

统计卡片等场景可扩展辅助强调色，如新增类指标用紫色 `#7C3AED` / 浅底 `#F3E8FF`。
**遇到不支持 `rgba()` 字符串的渲染场景（如 OpenPencil 画布填充色），一律换算成
等效纯色 hex，不要用带透明度的字符串做纯色填充**——这是踩过的坑：透明度混合
后的纯色可以用 rgba，但普通不透明填充必须是纯 hex。**这个坑不止发生在填充色上
——OpenPencil 渲染器里 `rgba()` 用在文字/图标颜色（`fill`）上同样不生效**（会渲染成
接近全黑、几乎不可读，而不是预期的半透明白），所以 `siderText` / `siderTextMuted`
这两个 token 在 OpenPencil 设计稿里必须换算成等效纯色再使用：`siderText`
(rgba(255,255,255,0.75)) → `#BFC5CA`，`siderTextMuted`(rgba(255,255,255,0.45))
→ `#737E89`。（询盘单模块设计时发现并修正，2026-09-03）

- 卡片圆角 12px，按钮/输入框圆角 8px，标签（tag）圆角 6px，胶囊状态圆角用 `height/2`

## 页面外壳（所有后台页面通用）

- **左侧导航 Sider**：宽 240px，深色背景 `siderBg`，顶部 Logo（图标+"烛龙ERP"）+
  导航树；一级菜单/分组用图标+文字，二级子菜单缩进（左 padding 52px）；
  **当前激活项用纯色 `primary` 背景块 + 白色加粗文字**，不要用低透明度色块
  （对比度不够、在深色底上几乎看不清）。
- **顶部 Header**：高 64px，白底，左侧面包屑（父级 / 当前页，当前页加粗），
  右侧搜索/通知图标 + 用户头像（圆形，纯色底+姓名首字）+ 用户名。
- **内容区**：浅灰背景 `bg`，padding 24，内部各块纵向 gap 16。

## 列表页结构（自上而下）

1. **页面标题区**：主标题 22px/700 + 一句话说明 13px/textSub，帮助新用户理解本页作用。
2. **统计卡片行**（可选，视业务是否有汇总指标）：3–4 张等宽卡片横排，每张卡片内部：
   图标胶囊（36×36，圆角10，浅色底+对应强调色图标）+ 指标名 → 大号数值(28/700) →
   一行强调色 hint（占比/环比等）。用于列表页顶部给出概览，比纯表格更有信息量。
3. **筛选卡片**：白底卡片，横向排列筛选项，每项 = label(13px) + 输入框/下拉(36px高)，
   末尾接"查询"（实心 primary 按钮）+"重置"（描边按钮）。**筛选项≤4个时单行放下即可
   （参考用户管理页）；超过4个或含日期范围等宽字段时，改为多行网格排列**（每行3–4项，
   项与项之间横向 gap 24+、行间 gap 16–20），"查询"+"重置"固定放在筛选区末尾（多行时
   放最后一行右侧，或单独一行右对齐），不要让筛选项逐项独占一整行纵向堆叠——那样会
   把筛选卡片拉得过高，扫读效率差。
4. **操作行**：左侧"共 N 条记录"说明文字，右侧主操作按钮（如"新增X"，实心 primary+图标）。
5. **表格卡片**：白底卡片，表头浅灰底 `#FAFAFA`；行高按内容复杂度取 40–60px；
   **多字段拼一列**：如"用户名+昵称"合并为一个"用户"列，左侧圆形头像（姓名首字，
   按行序号从调色板取色）+ 右侧姓名(13/600)与副名(12/textSub)纵向堆叠，
   比拆成多列更省横向空间、更易扫读。状态/角色类字段用胶囊标签（浅底+对应色文字），
   不要用纯文本。操作列放文字链接（primary 色，危险操作如"删除"用 danger 色），
   用 gap 12 横排，不加分隔符。
6. **分页器**：卡片底部横条，左侧"共 N 条"，右侧页码按钮（28×28 圆角6，当前页实心
   primary，其余描边）。

## 表单弹窗结构（新增/编辑类）

**核心原则：字段必须按业务属性分组，禁止把所有字段拉平堆成一条长表单。**
字段一多，纯瀑布式排列会让用户找不到重点、输入体验差。

- 弹窗宽度按分栏字段数调整：单列表单 480–560px，双栏表单建议 640px。
- 结构：Header（标题+关闭图标，底部分割线）→ Body（分组内容，可滚动）→
  Footer（右对齐"取消"+"确定"按钮，顶部分割线）。
- **分组（section）**：每组 = 图标(15px, primary色) + 组标题(14/600) 一行，
  下方 1px 分隔线，再下方是该组的字段内容。分组命名按语义，例如：
  - 用户表单：基础信息 / 组织信息 / 账号设置
  - 商品表单：基础信息 / 规格信息 / 物流信息 / 价格信息……
  - 订单表单：客户信息 / 商品明细 / 收付款信息……
- **字段行（fieldRow）**：同一行内可放 1–2 个等宽字段（横向 gap 16），根据字段
  重要性/长度决定独占一行还是两两并排——短字段（如用户名/昵称、部门/岗位）并排，
  长字段或需要更多注意力的字段（如角色、密码说明）独占一行。
- 必填字段 label 后加红色 `*`；下拉类字段用输入框造型 + 右侧 `chevron-down` 图标。
- 开关类字段（如"启用状态"）不放进 grouped 字段区，作为独立一行放在其所属分组
  末尾，label 左 + Switch 控件右（space_between）。

### 形状与字体

- 圆角：卡片 16，控件 10，向导大输入框 14，弹窗 20，胶囊 = 高度 / 2
- 中文 Noto Sans SC；**等宽 IBM Plex Mono 只用于大写小标签**（栏目标识如 `PRODUCT MASTER`、指标卡标识如 `NO_IMAGE`，字号 12，字距 2–3）
- 页面标题 28/700，向导标题 32/700，卡片标题 16/600，正文 14，说明 12–13，指标数字 40/800（可用渐变填充）

### 使用纪律（来自 ui-ux-pro-max 与对比度核对）

- **渐变只出现在这些地方**：Logo、主按钮、卡片顶部细线（仅重点卡片）、关键数字、完整度进度条、向导背景。**数据表格、表单、正文保持平整的深色面**，保证读数清楚
- 每个页面只有一个渐变主按钮（一屏一个主操作），其余按钮用次按钮或文字按钮
- 蓝色 `#3B82F6` 在卡片上作小字是 4.73:1，勉强达标但余量很小：文字和链接统一用 `#60A5FA`（6.84:1）及更浅
- 白字渐变按钮两端色都要不低于 4.5:1：`#3B82F6` 上的白字只有 3.68:1，不能用作按钮渐变的端点
- 弱文字不低于 `#94A3B8`；每个可交互控件的焦点框必须可见；遵守减少动效
- 图标统一 Lucide，不用 emoji 当图标（应用场景里的 emoji 是数据）
- OpenPencil 里半透明色一律换算成不透明纯色（描边 = 白 9% 叠在卡片上）

### 外壳

- 侧栏 240 宽；Logo 是蓝 → 靛 → 青渐变方块；当前项用强调色浅底 + `#60A5FA` 加粗文字；底部是当前用户卡
- 顶栏 60，透明；右侧是带 `⌘K` 提示的搜索框、通知、头像
- 内容区内边距 28，卡片间距 20；向导页背景是蓝色极光

### Ant Design 落地（前端）

以 `theme.darkAlgorithm` 为默认、`defaultAlgorithm` 并存，提供主题切换并记住选择。令牌参考：`colorPrimary` `#2563EB`，`colorLink` 深色 `#60A5FA` / 浅色 `#1D4ED8`，`colorBgBase` `#0B1220`，`colorBgContainer` `#111A2C`，`colorBorder` `#64748B`（控件边界），`colorBorderSecondary` `#1E293B`，`borderRadius` 10，`borderRadiusLG` 16；主按钮的蓝 → 靛渐变用自定义样式实现。**品牌主色仍为蓝色系，由 Ant Design 默认的 `#1677FF` 调整为 `#2563EB`，并增加蓝 → 靛 → 青渐变用于强调**，会影响全站，随外壳升级一起落地。

### 可访问性与规范补充（2026-09-19，ui-ux-pro-max 审查后补充）

审查依据：ui-ux-pro-max 的 200 多条规则，加上对原型 1400 个文字节点的对比度、字号和描边的逐项计算。修复后：小于 12px 的文字 88 处 → 0，控件描边 1.51:1 → 3.12:1，文字对比度问题只剩品牌字母标（Logo 类，可豁免）。

**色彩与对比**
- 正文对比度不低于 4.5:1，大字（≥24px，或 ≥18.66px 加粗）不低于 3:1；需要靠边界识别的控件，边界不低于 3:1
- **停用 / 禁用行不用透明度变淡**：文字用次文字色（≥4.5:1），状态靠开关、标签这类文字或图标表达
- **只读和禁用要能区分**：只读保持正常文字色并加锁形图标；禁用才降对比度
- 深浅色主题成对设计，每一对前景 / 背景都单独核对对比度

**字体与数字**
- 文字最小 12px。字号阶梯：`12 / 13 / 14 / 16 / 20 / 24 / 28 / 32 / 40`（13 是高密度表格的正文，40 只用于指标数字）；不再新增其它字号
- 中文标题字距为 0，不用负字距（英文和数字标题可以用 -0.2 到 -1）
- **表格里的数字、金额、汇率、数量一律等宽数字并右对齐**（实现时用 `font-variant-numeric: tabular-nums` 或 IBM Plex Mono），避免列宽抖动

**交互目标与焦点**
- 网页交互目标不小于 24×24px（开关 40×24），相邻目标间距不小于 8px
- **所有可交互元素都要有可见焦点**：2px `#60A5FA` 描边加 2px 外环；固定的顶栏、保存条、浮层不能遮住获得焦点的元素
- Tab 顺序与视觉顺序一致；每页提供「跳到主要内容」链接；只有图标的按钮必须有文字名称（`aria-label`）
- **拖拽必须有替代**：排序除了拖动手柄，还要有「上移 / 下移」按钮，键盘和单指都能操作

**动效**
- 时长令牌：悬停 150ms，展开收起 200ms，弹窗 250ms，退出为进入的 60–70%；只用位移和透明度，不动画宽高
- **必须遵守 `prefers-reduced-motion`**：开启时关闭非必要动效，数据立即可读

**表单**
- 校验在失焦时触发，错误显示在字段下方，并说明原因和怎么改
- **提交后有两个及以上错误时，页顶显示可聚焦的错误汇总**，每条链接到对应字段，同时保留字段内提示

**数据表格**
- 列头可排序的要显示排序图标并带 `aria-sort`；表头吸顶；行首有复选框，选中后出现批量操作条（批量启用 / 停用、导出，不含批量删除）
- 被截断的文字悬停显示完整内容；每页超过 50 行要做虚拟滚动
- 必须设计四种状态：**加载**（骨架屏，不用长时间转圈）、**空**、**无结果**、**失败**（原因加重试）

**响应式与布局**
- 断点 `1440 / 1280 / 1024`：1024 以下侧栏收成 64px 图标栏；表格横向滚动并固定首列；内容区最大宽度 1600，超宽居中
- 主题与图标：图标统一 Lucide，界面图标不用 emoji（用户录入的 emoji 内容除外）；品牌字母标属于 Logo，不受对比度限制

### 交互模式

- **复杂的新建流程用分步向导**：字段超过约 6 个、或分属不同主题时，不做长弹窗。整页无侧栏，顶部步骤条，右侧实时预览，底部固定操作栏；每步用人话提一个问题；必填步骤尽量少，其余都可跳过；能创建的时点越早越好，退出不丢内容
- **详情页用单页卡片，不用 Tab**：主栏 2/3 放内容卡片，侧栏 340 放状态和元信息；每张卡片头部有状态徽章，空卡片写明"填了有什么用"并给一个主操作；卡片原地编辑，独立保存；有未保存修改时底部浮出深色保存条
- **完整度 + 待补清单**：用分段进度条（一段对应一个模块）表示"还差多少"，下方列出可点击的待补项和预计用时；列表里用小进度条和缺项快捷筛选，让新人知道从哪里开始补
- **空状态**不写"暂无数据"：说明原因或规则，给下一步操作
- **危险操作**二次确认，写明后果，并提供更温和的替代（如"改为停用"）

## 消费级质感（2026-09-19 追加，所有原型必须满足）

后台页面同样要有消费级互联网产品的质感。**这一节叠加在上面的 Token 和结构之上，不替换它们**：颜色、字号、圆角、阴影仍用本文档的值，不新增颜色。

- **层次与留白**：一屏一个重点；标题、数值与正文之间字号落差要明显；卡片内边距不小于 20，少用分割线和边框，靠底色差和浅阴影分层。
- **状态齐全**：可交互元素要有默认 / 悬停 / 按下 / 聚焦 / 禁用；数据视图要有加载（骨架屏）、空（一句话说明 + 主操作）、错误（原因 + 重试）三态。原型里至少画出空态和一个悬停或聚焦态。
- **即时反馈**：操作成功用 Toast 或行内提示，不弹窗告知；输入实时校验，错误显示在字段旁，不等提交后集中报错；危险操作二次确认并写明后果。
- **文案说人话**：站在用户视角，错误信息说明怎么办；不把字段名、枚举值、技术编码直接展示给用户。
- **动效有意图**：弹窗、Tab 切换、列表增删的过渡 150–250ms ease-out；原型里用标注说明，不炫技。
- **效率**：回车提交、Esc 关闭；常用操作不超过两次点击；搜索与筛选优先，记住上次筛选条件。
- **可扫读**：主图缩略、头像、胶囊标签、图标统一用 Lucide；颜色只用来表达状态，不做装饰。

## OpenPencil 作图注意（2026-09-19 商品域原型踩到）

- **弹窗画板**：`layout: none` 的根节点只会渲染第一个子节点，「底页 + 遮罩 + 弹窗」叠放的做法画不出来。沿用询盘单的约定：根节点当遮罩、弹窗居中；遮罩用不带透明度的纯色（如 `#B4BAC4`），不要用 `rgba()`。
- **脚本模式的错误会被吞掉**：`op design @x.js` 中途报错时不会提示，只是后面的节点没建出来。脚本外包一层 try/catch，出错时插入一个名为 `SCRIPT-ERROR` 的文本节点，跑完检查它。
- **图标**：`circle-help` 会渲染成一个点、`tag` 是实心的，避免使用。
- **画板高度**：先按内容搭，再用 `op layout` 量出实际内容高度回填，不要估算，否则底部内容会被裁掉。

## 复用方式

新页面设计时：

1. 先确定这一页是"列表页"还是"表单/弹窗页"，套用对应结构骨架。
2. 颜色、字号、圆角、阴影直接抄本文档 Token，不要现场调新值。
3. 表单字段先按业务属性分组命名（参考上面的分组示例），再决定每组内字段怎么
   两两并排，禁止拿到字段列表就从上到下平铺。
4. 用 OpenPencil（`op design` / `op insert`，见项目内 openpencil-skill）出设计稿，
   产物统一存到 `docs/03-产品原型/{域}/{页面名}.op` + 对应 `.png` 效果图。
